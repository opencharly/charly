## Scope delivered

### 1. `host_build_deploy_entity_resolve.go` kind-switch dissolved

The old handler was a literal `switch req.Kind { "", "deploy", "bundle" | "k8s" | "android" | "vm" }`
with per-kind lookup bodies (`findK8sSpec`, `findAndroidSpec`, inline `LoadUnified`+`resolveVmViaPlugin`)
— tell #2 of the boundary law's self-test ("a switch on a kind word... is BY DEFINITION an R-item").

New shape, genuinely kind-blind:

- **Tree-vs-template routing is by DATA SHAPE** (`len(req.TreeJSON) > 0`), never by inspecting
  `req.Kind`'s value — every `deploy`/`bundle` caller threads the tree; every `k8s`/`android`/`vm`
  caller doesn't (verified against every live call site).
- **Template-body extraction is DATA-indexed**: `uf.ProjectTemplates().ByKind(req.Kind)[req.Name]` —
  a new generic accessor on `spec.ProjectTemplates` (`spec/spec/loadmodel.go`), mirroring the existing
  `uf.PluginKinds[...]` pattern. This is a genuine, safe GENERALIZATION: k8s previously got
  namespace-qualified lookup (via `ProjectTemplates`) while vm/android didn't (bare `uf.VM()`/
  `uf.Android()`) — an inconsistency I could not preserve while also removing the kernel-side
  per-kind branch, so vm/android now gain the SAME namespace-qualification k8s already had (additive,
  proven safe: `ProjectTemplates`'s own doc guarantees qualified keys never collide with bare names).
- **Provider dispatch is registry-keyed by DATA**: `providerRegistry.ResolveKind(req.Kind)` (was
  hardcoded `"local"` in the old `invokeSubstrateTemplateResolve`) + a generically-built
  `SubstrateTemplateResolveRequest` JSON shape (`{kind:{kind:body}}`, matching the CUE-generated
  wire shape for any of the 5 substrate words) + a generic `{"resolved":...}` reply-field extraction
  (all 5 `*ResolveReply` CUE types share that JSON shape). Zero concrete-kind Go code in the kernel.
- **Reply shape unified**: deleted the one-off `#AndroidEntityResolution` wrapper (its
  credential-threading justification was already stale per its own CUE doc) — `android` now ships
  its `EntityJSON` unwrapped, exactly like `k8s`/`vm`. Updated `candy/plugin-adb/preresolve.go`
  accordingly (one less unmarshal step).
- CUE schema updated (`spec/schema/seam.cue`) + regenerated (`task cue:gen`, clean single-purpose
  diff both times).
- Dead code removed as a direct consequence: `charly/k8s_config.go` (whole file — `findK8sSpec`'s
  only caller was the deleted switch case), `findAndroidSpec`/`lookupAndroidSpec`,
  `resolveK8sViaPlugin`, the `ResolvedK8s`/`ResolvedAndroid` in-package aliases (zero remaining
  callers after the above).
- Fixed a genuine R1 documentation divergence found while touching the CUE doc: the seam's own
  doc block still described a "local" kind:<word> arm as live — that arm was RETIRED in K4 unit A
  (candy/plugin-bundle/node_resolve.go's `lookupLocalTemplate` reads the resolved-project envelope
  directly now). Swept the stale claim from the CUE doc + the request field comment.
- Two tests previously drove the deleted helpers directly (`TestFindK8sSpec_NamespaceQualified`,
  `TestLoadUnified_AndroidNodeForm`'s `lookupAndroidSpec` call) — rewrote the k8s one to exercise
  the actual production entry point (`hostBuildDeployEntityResolve`) end-to-end (stronger coverage:
  it now proves the real kind-blind dispatch works, not a since-deleted helper), and the android one
  to call `resolveAndroidViaPlugin` directly (the still-live building block `lookupAndroidSpec` used
  internally, preserving exact prior semantics — no namespace qualification, matching the original).

# 2026.206.0920 — Cutover 1: plugins-for-everything, part 1 — build/check/deploy/credential cone capability out of core

The first cutover of the "plugins-for-everything, 100%" program: every cone's
UNBLOCKED capability (the code that needed no loader-keystone refactor to move)
relocates from `charly/` core into its owning plugin candy, importing only the
sdk. **Net core non-test reduction: −2,612 LOC** (55 files, +330/−2942; 11
`charly/` files deleted). Consumes the sdk contract leg (this repo's gitlink
repoints to the merged sdk commit; B2 producer-first).

## Build cone → `candy/plugin-build`
- The privileged builder-bootstrap step (`privileged_runner.go`, `RunPrivileged`)
  moves into `candy/plugin-build`, deduped into `sdk/buildkit`.
- `InitConfig` / capability-aggregation / `envd`-removal / 7 pure build helpers
  repoint to `sdk/buildkit` + `sdk/kit`; `FilterBox` relocates to
  `sdk/deploykit` (pure over the resolved box graph).
- `charly/init_config.go`, `charly/layer_capabilities.go`,
  `charly/privileged_runner.go` deleted.

## Check cone → `candy/plugin-check`
- Image-preflight discovery (`check_image_preflight.go`), the container-network
  probe, and `resolveCheckApk` move into `candy/plugin-check` /
  `sdk/kit.ResolveCommittedApk`.
- `CHARLY_BIN` stamping + runtime check-var resolution delegate to
  `sdk/kit.StampCharlyBin` / `NewRuntimeCheckVarResolver`.
- `charly/check_image_preflight.go`, `charly/runtime_config_values.go`,
  `charly/shell_profile.go` deleted.

## Deploy cone → `candy/plugin-substrate` / `plugin-deploy-pod` / `plugin-adb`
- **`#DeployTraits.bracketed_lifecycle` (P9, SDD).** The Start/Stop "needs the Q1
  resource-arbiter bracket" signal now derives from the DECLARED substrate trait
  resolved by word from the provider registry
  (`deployTraitsFor(word).BracketedLifecycle`) — `plugin-substrate` declares it
  true for `pod`, false elsewhere. The per-word `lifecycleStartPlanHooks` map
  stays purely the host-side opts-marshaling mechanism; the bracket SIGNAL is
  declared data (boundary-law: consult by trait, never by kind-word map presence).
- **`externalizedDeploySubstrates` (task #21)** derives from `deployTargetWords`
  (CUE-derived from `spec.ResourceKinds`) via `setFromSlice`, replacing the
  hand-written per-kind map literal — the same un-gameable-self-test leak class
  `resourceKindSet` already avoids.
- **Android google-play credentials** resolve peer-to-peer in `candy/plugin-adb`
  (`credential_shim.go`) via a direct `InvokeProvider(verb:credential)` call — the
  same pattern `candy/plugin-vm` uses for `verb:arbiter`/`verb:gpu`/`verb:egress` —
  instead of the host pre-resolving them behind the `deploy-entity-resolve` seam.
  `spec.AndroidEntityResolution` drops its google-play credential fields.

## Credential / enc cone → `candy/plugin-deploy-pod`
- Pod start/stop enc-ensure / enc-unmount / tunnel plan-building ports to
  `candy/plugin-deploy-pod` over `InvokeProvider`; the now-unused
  `credentialAwaiter` interface is deleted (R1 dead-code).
- `charly/container.go`, `charly/pod_lifecycle_resolve.go` deleted.

## Settings / Config cone → `candy/plugin-settings`
- The runtime-config subsystem (`GetConfigValue`/`SetConfigValue`/`ListConfigValues`/
  `ResetConfigValue`/`RuntimeConfigPath` + `resolveSettingsGet`) ports from
  `charly/runtime_config_values.go` + `charly/host_build_settings.go` into
  `candy/plugin-settings/config.go` — almost entirely pure
  `kit.LoadRuntimeConfig`/`SaveRuntimeConfig` file I/O + validation. The three
  credential-store touches (`vnc.password.*` + `secret_backend`) dispatch
  `verb:credential` directly via `InvokeProvider`.
- **The "settings" HostBuild seam is RETIRED** — `command:settings` (compiled-in) holds
  a real reverse-channel `*sdk.Executor` at `Invoke(OpRun)`, so the plugin owns its config
  I/O with nothing left for core to do (`clean` keeps its separate "retention" seam).
- `charly/host_build_settings.go`, `charly/runtime_config_values.go` deleted; the stale
  "settings HostBuild seam" descriptions in `candy/plugin-settings/charly.yml`, the root
  `charly.yml` check-commands-local bed plan, and `charly/provider_command_test.go` are
  updated to the plugin-owned architecture (R5).

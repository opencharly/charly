# 2026.206.1300 — K1 keystone: LoadUnified/ApplyDiscover → sdk/loaderkit

K1 keystone (task #24), the charly consumer leg (B2 step 3+ — consumes the sdk
producer leg, `sdk` gitlink repointed to `v0.2026206.1046`). `charly`'s
`LoadUnified` — the top-level entry point every command reaches to load a
project's `charly.yml` — and the standalone `ApplyDiscover` walk become thin
wrappers delegating to the new `loaderkit.LoadUnified`/`loaderkit.RunDiscover`,
extending the seam-injection pattern `spec.WalkSeams`/`spec.MaterializeSeams`
already established by the prior K1-unit-1 Materializer seam.

**Net: −312 core LOC** (66 files, +799/−1111).

## The move

- `LoadUnified(dir)` is now a ~15-line wrapper building a `loaderkit.LoadSeams`
  (11 callback fields: `RunBootstrapPhase`, `WalkProject`,
  `MaterializeLoadedProject`, `FlattenBundleVenues`, `FoldMembers`,
  `StampBundleDescents`, `ValidateEphemeral`, `ValidateCheckBeds`,
  `ValidateAndroidDevices`, `ValidateMembers`, `ValidatePreemptible`) from
  charly-core's existing host-coupled functions and delegating to
  `loaderkit.LoadUnified`. `gateSchemaVersion`/`normalizeV4Aliases` relocate
  fully (zero registry coupling).
- `ApplyDiscover(uf, rootDir)` now calls `loaderkit.RunDiscover(rootDir,
  uf.Discover, hostWalkSeams())` then the shared `foldDiscoveredManifests`
  (R3 — the SAME per-manifest fold loop `materializeLoadedProject`'s own
  discovered-manifest step uses, previously near-duplicated inline).
  `applyDiscoveredManifest` is deleted entirely (fully replaced).
  `hostWalkSeams()` factored out of `hostWalkProject` so both the
  whole-project walk and the standalone discover walk build their
  `spec.WalkSeams` from one place.
- `foldMembers`/`validateMembers` are threaded through UNMOVED, per the
  standing FINAL/K5 ruling in `bundle_members.go`'s own header comment.
- `uf_box_generic.go`/`uf_candy_generic.go` deleted — their content already
  lived in `sdk/loaderkit/unified_file.go` since K1 unit 1; this lands the
  `git rm` that unit 1's own commit claimed but never actually staged.

## Disclosed structural changes

- **`UnifiedFile.PluginKinds` consolidation**: the 5 dedicated
  `VM`/`Pod`/`K8s`/`Local`/`Android` fields collapsed into the generic
  `PluginKinds[disc][name]` map (banked from `feat/k1-loader-materialize`,
  predates this branch). Behavior-preserving — proven by two independent
  byte-equivalence methods (a canonicalized-JSON dual-checkout harness over
  two real project fixtures, and the orchestrator's materialized-Containerfile
  diff across 4 real images).
- **Task #22 stays open.** `validateCheckBeds`'s vm/local/android case
  collapse (a prior commit) is a partial mechanical simplification only — the
  `pod` vs. vm/local/android split remains a hardcoded word-list switch. A
  fully trait-driven collapse was considered and rejected (no existing P9
  `DeployTraits` bit distinguishes `{vm,local,android}` from `{k8s}`); closing
  it needs a new schema trait, tracked as its own follow-on SDD cutover.

# 2026.210.0644 — #55 Phase A2 (consumer leg): repoint charly + 85 plugins onto the published `github.com/opencharly/spec` module

The IMPORT-PURITY phase (#55) extracts the kernel↔plugin wire contract — the
generated param structs, the protobuf transport, the CUE ingress schema, and the
shared schema-concatenation helper — into its OWN module,
`github.com/opencharly/spec` (Phase A1: spec `main` `11dcd6d2`, tag
`v0.2026210.518`). This is the superproject half of Phase A2: charly core and
every plugin candy stop reaching those packages through the sdk module and
consume the dedicated spec module directly. It pairs with the sdk leg
(`refactor(sdk)!: #55 Phase A2`), which deletes the moved dirs from the sdk
contract module and repoints sdk's OWN kept packages onto spec.

## The `spec` submodule

`spec/` is added as a superproject git submodule
(`git@github.com:opencharly/spec.git`), pinned at `11dcd6d2`. `.gitmodules`
gains the stanza; the repo-root `go.work` gains `use ./spec` (emitted by
pluginsgen, beside `use ./sdk`).

## Import repoint (573 .go files)

```
github.com/opencharly/sdk/{spec,proto,schema,schemaconcat}
  → github.com/opencharly/spec/{spec,proto,schema,schemaconcat}
```

across `charly/*.go` (241) and every `candy/plugin-*/*.go` (332). The `proto`
rewrite is boundary-guarded so it never corrupts `sdk/protocol` (no Go import of
that path exists). Grep self-test: zero residual
`github.com/opencharly/sdk/{spec,proto,schema,schemaconcat}` anywhere in
`charly/`, `candy/`, or `sdk/`.

## Module wiring

- `charly/go.mod`: `require github.com/opencharly/spec v0.2026210.518` +
  `replace github.com/opencharly/spec => ../spec` (mirroring its sdk pattern;
  in-tree resolution via the replace, the require version for out-of-tree
  consumers).
- Every `candy/plugin-*/go.mod` (85): `require github.com/opencharly/spec` +
  `replace github.com/opencharly/spec => ../../spec`, then `go mod tidy`
  per-module so each is standalone-consistent. Two plugins that previously
  carried no `go.sum` (`plugin-cmd`, `plugin-ssh`) gain one for spec's
  transitive graph.
- `charly/internal/pluginsgen/main.go`: emits `use ./spec` in `go.work`, adds a
  `spec/go.mod` bootstrap guard (a fresh non-recursive clone gets a clear
  `git submodule update --init spec` error), and updates the header comment.
- `taskfiles/Cue.yml`: the base-schema→spec generation and the per-plugin params
  loop now run from the `spec` submodule (`cd spec && task cue:gen`,
  `spec/internal/schemagen`, pin-equality against `spec/Taskfile.yml`), since
  the schemagen generator + CUE schema moved there.

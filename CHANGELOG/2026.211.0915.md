## Why a seam collapse (not a node-thread)

The resolvers read BOTH the per-host deploy overlay AND the PROJECT config (LoadUnified →
ProjectBundleConfig — the fallback every pod bed's first `charly config` hits, since key≠image
and beds pass no explicit ref). The pod plugin (candy/plugin-deploy-pod) is out-of-process, so
it cannot call the DeployStateHost-seam-backed loader directly — but it CAN reach both
placement-invariantly: per-host via the EXISTING `pod-config-load-deploy` seam, PROJECT via the
new shared `loaderkit.LoadUnifiedViaExecutor` (the proven plugin-bundle loader-over-executor
pattern). So the bespoke resolve-ref seam is redundant and dies.

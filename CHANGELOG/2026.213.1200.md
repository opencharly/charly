# 2026.213.1200 — R1 fix: namespaced-box candy-ref collection runs unconditionally (coneK1load regression)

The `coneK1load` namespaced-box fold (`charly/host_build_buildengine.go`,
`collectNamespaceScanEntries`) guarded the namespace-scoped reachability walk
with `if len(scanned) > 0`. A namespace that VENDORS NO local candies but whose
boxes pin remote candies (the `distro-fedora` case: every candy is an
`@github.com/opencharly/charly/candy/<name>:<tag>` ref) has `scanned` empty, so
the guard skipped `CollectRemoteRefsOpts` → `downloads` nil → the plugin's
fix-point fetched nothing → the box candy refs never entered `rp.CandyModels` →
"candy not found" on every fedora namespaced box (`charly box validate` failed
hard).

## Root cause (R1, bisect-confirmed)

`origin/main`'s deleted `fillNamespacedBoxes` (`charly/resolved_project_host.go`)
ran `scanSeamsFor(sub, opts).CollectRemoteRefs(scanned)` UNCONDITIONALLY —
`CollectRemoteRefsOpts` walks `sub.Box` (the namespace's boxes) to collect the
boxes' candy `@`-refs, independent of whether the namespace has ANY local
candies. The coneK1load relocation introduced the `len(scanned) > 0` guard,
dropping the box-candy-ref collection for candy-less namespaces. Bisect
(1ce0975d good → dfc544ba bad, 70 commits) pinpointed first-bad = b367e5d5
(coneK1load).

## Fix

Removed the guard; `CollectRemoteRefsOpts(sub, ...)` now runs UNCONDITIONALLY,
byte-identical to origin/main's `scanSeamsFor(sub, opts).CollectRemoteRefs`.
`FinalizeScannedCandies` / `withLocalRawRefs` are nil/empty-safe (range over nil
is a no-op), so an empty `scanned` degrades to a boxes-only walk — exactly
origin/main's shape. Verified: `charly box validate` exit 0, not-found 5→0
(stable on re-run); namespaced-box unit tests pass; build + vet clean.

## Super-leg mechanics (the producer-bump cascade + the test-harness fix)

- **Producer-bump cascade — 85 candy go.mod retidied.** The spec leg bumped the contract
  module `v0.2026211.754` → `v0.2026213.1726`; every candy `go.mod` still pinned the OLD spec
  version, so an out-of-process `go build` (the path `buildPluginBinary` takes, GOWORK=off) hit
  `go: updates to go.mod needed; to update it: go mod tidy` under `-mod=readonly` — the sdk dep
  now requires the newer spec than the candy declares. `GOWORK=off go mod tidy` across all 85
  candies bumps each `require github.com/opencharly/spec` to `v0.2026213.1726` (one line each;
  `go.sum` unchanged because spec is local-`replace`d). This is the plan's "retidy all 85 plugins
  on a spec bump" cascade, and it is what makes every candy build standalone again.
- **`copyCandyFixReplace` test-harness fix (`charly/plugin_kind_prescan_e2e_test.go`).** The
  external-kind/step/structkind e2e tests stage a candy into a temp project and build it OOP via
  `buildPluginBinary`. The helper rewrote go.mod's `replace github.com/opencharly/sdk => ../../sdk`
  to an ABSOLUTE path but NOT the sibling `replace github.com/opencharly/spec => ../../spec`; the
  relative `=> ../../spec` resolved to `<temp>/spec` (nonexistent), failing the staged build with
  `reading ../../spec/go.mod: no such file or directory`. The helper now rewrites BOTH replaces to
  their absolute repo-submodule dirs. (The candies gained the `spec` replace when spec became a

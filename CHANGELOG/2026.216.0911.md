# 2026.216.0911 — `--repo` could not reach out-of-process command verbs


`charly --repo opencharly/charly mcp serve` printed `Usage:` — unknown verb —
from any directory that was not already a charly project. From inside a project
the same command worked, so the flag appeared to work only where it was not
needed.

ROOT CAUSE. `prescanProjectCommandWords()` is what puts an out-of-process
command word into the Kong grammar, and it asked `projectDirPreParse()` for the
project. That resolver knew `CHARLY_PROJECT_DIR`, `-C`/`--dir`, and cwd — but
not `--repo`. Since `kong.Parse` freezes the grammar before main()'s post-parse
`--repo` chdir, a verb living only in the `--repo` target was never registered.
Reading `charly.yml` worked, because that happens after the chdir; finding the
verb did not.

The blast radius was every command word not baked into the binary. The packaged
build bakes nine (candy clean doctor feature preempt secrets settings udev vm),
so those resolved anywhere; `mcp`, `bundle`, `status`, `agent`, `tmux`, `tui`
and the rest needed a local checkout. That is the opposite of what `--repo` is
for: it exists so someone with no checkout can run a documented command.

THE FIX. `projectDirPreParse()` now also resolves `--repo` and
`CHARLY_PROJECT_REPO`, via the same `ResolveProjectRepo` main() uses. This
matches the existing design rather than restructuring startup — the function
already answers "which project dir, before parse"; it simply did not know about
one of the three ways to say it.

Resolution can clone, so it is attempted only when the flag or env var is
present. A failure returns "" and falls through to cwd: main() resolves the same
spec moments later and reports the error properly, so a broken --repo must not
also silently take the local grammar away.

PROVEN BY MUTATION, end to end. Neutering only the new arm:

  MUTANT    charly --repo opencharly/charly mcp serve  -> exit 80  (unknown verb)
  RESTORED  charly --repo opencharly/charly mcp serve  -> exit 124 (serving)

both run from /tmp, a directory with no charly.yml.

Unit coverage in plugin_command_prescan_repo_test.go pins the argv scanning
(both `--repo <spec>` and `--repo=<spec>`, argv[0] skipped) and the precedence
chain, including that a bare invocation falls back to cwd rather than "" — an
empty return would silently disable the prescan and drop every project-provided
verb from the grammar.

Regression-checked the paths this touches: in-project bare, `-C <project>`,
`--repo` with a read-only verb, and a bad `--repo` spec exiting 1 rather than
panicking. `go test ./...` in charly green (201s).

FOUND BY a requirement that every command in the documentation must run as
written. Two doc pages had been weakened to say "-C a project you already have",
which was documenting around the bug instead of fixing it. They go back to
`--repo` in the docs leg.

# 2026.217.0030 — the `config` secret backend is gone, and the quadlet stops asking for a name

The consumer half of the sdk change of the same name. Two things land together because neither is
complete alone: the quadlet's autostart decision becomes a capability the secret layer computes,
and the `config` secret backend — pinning every credential to plaintext
`~/.config/charly/config.yml` — is removed.

## Supported backends

Encryption passphrases come from the environment, the system keyring via Secret Service, or a
forwarded GPG agent. **Quadlet autostart is served by Secret Service alone** — not because the
emitters check for it by name, but because it is the backend that can unlock with no human
running a command. The supported set is now an *outcome* of that property rather than a list any
code carries.

## What changed

| Candy | Change |
|---|---|
| `plugin-deploy-pod` | computes the capability (`resolveEncUnattendedUnlock`) and threads it into BOTH `QuadletConfig` sites, replacing `secretBackendIsKeyring()` |
| `plugin-settings` | `secret_backend` accepts only `auto` and `keyring`; `config` is rejected with a message naming what to use instead |
| `plugin-secrets` | `resolveSecretBackend` normalizes through `kit.NormalizeSecretBackend`; the unreachable `case "config"` store selection is deleted; five remediation hints stopped prescribing the removed value |
| `plugin-doctor` | two `InstallHint`s stopped prescribing it, and the now-unreachable "config file (explicit)" OK branch is deleted |
| `plugin-pod` | `pluginResolveSecretBackend` normalizes through the same helper, so the backend it reports and the backend that selects the store cannot diverge |

The capability is asked only when a deploy HAS encrypted volumes. A deploy without them
autostarts unconditionally, so probing the credential store for it would be a pointless round
trip — and, on a locked keyring, a needless probe.

## Migrating a host that already carried `secret_backend: config`

**Not through `charly migrate`.** `secret_backend` lives in the runtime config
`~/.config/charly/config.yml`, while `charly migrate` processes the project `charly.yml` and the
per-host deploy overlay `~/.config/charly/charly.yml` — a different file it never opens. The
migration therefore belongs where the value is READ, which is also the only place that can catch
the `CHARLY_SECRET_BACKEND` override no validator ever sees.

Both readers coerce it to `auto`, once, with a notice. Nothing becomes unreachable: `auto` still
falls back to the config file when no keyring is present, so an already-configured host keeps
resolving the credentials it has. What the operator loses is the ability to PIN charly to the
plaintext store.

**One measured regression.** On such a host, with no passphrase stored, `charly config mount`
used to fail immediately — the removed backend took a fail-fast path. It now classifies as
`unavailable` and polls to `EncMountDeadline`: **120.09s measured**, then the same actionable
error. Bounded, and already what the default `auto` setting does on any keyring-less host; the
pin was the only way to opt out. Recorded rather than smoothed over.

## Coverage

`TestResolveEncUnattendedUnlock` asserts both arms plus the short-circuit, and counts credential
store calls — the wiring assertion, because a capability that never asks would still return the
right answer for two rows by accident. `TestSetConfigValue_SecretBackend` asserts the rejection
and that the message names both supported values.
`TestResolveSecretBackendRemovedConfigCoercesToAuto` and its env-override sibling are the
migration gates.

Mutation-proven red before being cited: a capability returning a constant (four rows fail), one
ignoring `hasEncrypted` (the short-circuit row fails), a validator that accepts `config` again,
and a `resolveSecretBackend` that stops normalizing.

## Tests that pinned the removed backend

Several used `secret_backend: config` purely to force the config-file store deterministically.
They now reach it the way a headless host does — an `auto` probe against an unreachable session
bus — which is better isolation than the pin was. `charly/credential_await_unlock_external_test.go`
does the same, and its plugin subprocess inherits the arrangement.

`TestPluginEncMount_NoShortCircuit_WhenOneUnmounted` is where the regression above first
surfaced: it went from instant to 120.09s. It now shrinks `EncMountDeadline` rather than skipping
the wait, so the retry path is still exercised.

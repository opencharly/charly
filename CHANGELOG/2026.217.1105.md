# 2026.217.1105

**The README becomes the landing page, and three generator gaps close** — opencharly.ai's home
page stops being a hand-maintained copy of `README.md` and becomes a projection of it, so the two
cannot drift. Along the way the generator gained the checks that would have caught the drift it
was accumulating, and the README's account of candy polymorphism was corrected against the schema
it describes.

## The landing page is generated, not copied

`candy/plugin-docs/gen_landing.go` projects the superproject `README.md` into the site's
`index.md`, rewriting `https://opencharly.ai/foo/` links to site-relative `/foo/` on the way
through. Roughly two thirds of the old hand-authored landing page was a paraphrase of the README;
every paraphrase was a place the two could disagree, and they had.

`gen_grievances.go` publishes `GRIEVANCES.md` to `/grievances/` on the same principle, mirroring
how `VISION.md` already reaches `/vision/`.

## Three gaps in the generator itself

- **A removed generator was invisible.** The generator only ever wrote; it never removed. A page
  whose generator was deleted survived forever, and `task docs:drift` reported "already up to
  date" while the generator no longer produced the page at all — measured, not theorised, by
  deleting the `generateGrievances` call and watching the drift gate pass. `prune.go` clears every
  page carrying the generated header before regeneration, so whatever does not come back shows up
  in git as a deletion.
- **Sidebar links were checked by nothing.** The site link gate walks the content tree, and the
  Starlight sidebar lives outside it in `astro.config.mjs`. A dead sidebar `link:` built green and
  rendered on all 852 pages. `links_sidebar.go` resolves every sidebar target against the pages
  the run actually emitted, and a config it cannot find is an error rather than a skip.
- **The prune count called every page stale.** The run line reported "N stale pages cleared" for
  a number that is simply the previous run's entire output — 829 of the 833 came straight back.
  The comment above it invited a cleared-vs-written comparison that could never balance, because
  four generated pages (`reference/providers.md`, grievances, landing, vision) are not among the
  five families the line counts. Both now say what is true.

## The README said candies accumulate roles. They do not.

The page claimed *"layer", "box" and "plugin" are cumulative, not a choice between three types* —
that a candy gains roles as fields are added. `spec/schema/node.cue:75` defines
`#CandyValue: (*#Candy | #Image)`, a closed two-arm disjunction: adding `base:` to a candy that
declares `package:` is rejected by `charly box validate`, in both directions. Layer and box are
mutually exclusive. Only `plugin:` is genuinely additive, and only within the layer arm.

The counts were stale in the same section and are now read off the tree: **137 provider words
across 86 plugin candies, 58 of them compiled into the binary**. The class table gained the row
that makes its column reconcile with the 137 above it — it listed six classes summing to 129, and
a reader who added them up caught the generator's own catalog contradicting the sentence
introducing it.

# 2026.217.1642 — the agent roster inherits the operating model

This file's "Agents, Workflows & Teams" section named a concrete topology: "a
persistent most-capable-model orchestrator (currently **Fable 5**) driving
cost-scaled teammates and fresh `pr-validator`s (currently **Sonnet 5**)".

Every agent definition pins `model: inherit` — the roster runs whatever model
the operating session runs, under any harness. The names were prose describing
a historical default: false the moment an operator runs one model for both
roles (the point of `model: inherit`), and a standing invitation to spend on a
second, expensive model when none is needed. They are gone. The tier split is
expressed by which model the operator chooses to run the session on; the only
place a model is ever named is an explicit per-spawn `model:` override.

The companion detail lives in
`plugins/internals/skills/agents/references/orchestration-model.md`, updated in
the same change (plugins#133).

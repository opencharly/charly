# 2026.218.0015 — the excerpt checker lands, and the README excerpts tell the truth

`scripts/verify-doc-excerpts.py` — excerpted from the closed charly#211, where it had been
developed and never landed — enforces the excerpt-integrity rule: every fenced YAML block in the
hand-authored docs pages is either a verbatim excerpt of a committed source or a declared synthetic
template, and an unclassified block is a FAILURE. An earlier version silently skipped what it did
not recognise and reported "116/116 verify verbatim" while quoting a `plan:` that never existed in
any revision; this one fails on the unclassified instead.

Two fixes were required for it to run green against the tree it checks:

- The landing page is now the generated `index.md` (a projection of `README.md`, which the checker
  already reads), so the stale `docs/src/content/docs/index.mdx` reference is gone.
- The README's check-group block showed `check-group-vm` nested under `group:` with trailing
  inline comments; the real `charly.yml` entry has it as a sibling of `group:` with no such
  comments. The block now carries the canonical form (the same bytes as `concepts/02`), and the
  box/fedora block's trailing `# a CONTAINER` / `# a VM GUEST` comments became comment-only lines,
  which the checker skips.

The landing page projection regenerates from this README, so the docs leg (docs#14) carries the
matching `index.md`; this PR and docs#14 land in that order.

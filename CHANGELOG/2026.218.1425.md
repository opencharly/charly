# 2026.218.1425 — amending a PR is allowed; force-push stays forbidden on any branch

Policy correction (operator directive): amending a `feat/` branch before its first push is a
normal authoring action and must not be treated as forbidden. `CLAUDE.md`'s landing step no
longer lumps `--amend` in with the forbidden force-push — force-push on ANY branch and direct
pushes to `main` stay forbidden (`main` only fast-forwards via the validator's squash-merge; a
pushed `feat/` branch advances only by adding commits). The `.claude/hooks/pre-push-gate.sh`
header gains a comment-only clarification that local `git commit --amend` is not gated (the
gate gates force-pushes, never local amend) — no logic change. Mirrors the git-workflow skill
wording in the plugins leg (opencharly/plugins#141).

# 2026.223.2150 — AgentTeams Unit 2: the Higress AI gateway candy on the cachyos core box

The fourth foundation candy of the AgentTeams cutover: `candy/agentteams-higress` re-declares the whole Higress stack (apiserver, controller, pilot, envoy gateway, console) as five rootless supervisord services, composed into the `agentteams-core-app` box. Every binary and asset is `extract:`ed from `higress/all-in-one:2.2.1` (apiserver, higress controller, pilot-discovery, pilot-agent, envoy, supercronic, yq → `/usr/local/bin/`; `/app`, `/opt/data/defaultConfig` seed resources, `/var/lib/istio/envoy` bootstrap template), and every start script is charly-owned — the five scripts wait on the dependency chain, generate the mTLS cert chain into a uid-1000-writable `/etc/certs`, render the mesh config from the seeded ConfigMap into `/etc/istio/config`, point the gateway access log at stdout, and run the log-rotation cron — no sudo, no upstream install script.

**Root-cause fix landed with the candy:** the gateway's 8080 listener was not materializing because the upstream image bakes `/etc/istio/pod/labels` (`app="higress-gateway"` / `higress="higress-system-higress-gateway"`) which the istio-agent folds into envoy node-metadata `LABELS`; without it the pilot can never match the proxy to the Gateway resource's `higress: higress-system-higress-gateway` selector, so no gateway listeners are generated. The candy now writes that file (`write:` step, charly-owned), and the LDS 8080 listener + the gateway→console proxy on `:8080` are both proven live.

The bed (`check-agentteams-core-pod`) extends with four Higress checks: the apiserver answers `https://127.0.0.1:18443/version`, the gateway is healthy (`curl -sf http://127.0.0.1:15021/healthz/ready`), the gateway serves the console on its ingress port (`http://${HOST_PORT:8080}/` → 200 — the check that FAILS without the labels fix), and the console answers on `:8001`. Rootless throughout: the five services run as the image user (uid 1000) with `working_directory: /` (matching the upstream `directory=/`), the privileged paths the upstream scripts write at runtime are pre-created uid-1000-writable at build time, and the Arch JVM default is pinned (`archlinux-java set java-26-openjdk`) so the console jar runs on `jre-openjdk`.

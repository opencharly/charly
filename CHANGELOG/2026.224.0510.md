# 2026.224.0510 — AgentTeams Unit 3: the controller candy, top composition, manager image, and the pod bed

The controller layer of the AgentTeams cutover: `candy/agentteams-controller` builds the `agentteams-controller` + `agt` binaries from the pinned AgentTeams v1.2.2 source (CGO on for the controller, off for `agt`), downloads the kube-apiserver v1.31.3 binary, installs the CRD manifests + builtin agent trees, and runs the controller as a rootless supervisord service on `:8090` with the kine-backed embedded kube-apiserver. The charly-owned `start-controller.sh` resolves the shared credentials from the `/data` volume (the same self-provisioned MinIO root password and Matrix registration token the minio/matrix candies persist), derives `AGENTTEAMS_CONTROLLER_URL` from the container's own hostname, and execs the controller — no upstream install script, no root.

The top composition `candy/agentteams` composes the five foundation candies (minio, matrix, element, higress, controller) into one box, and the `agentteams` box (`base: cachyos.cachyos`) carries it. The `agentteams-manager` box (`tag: manager`) composes the `agentteams-manager` layer — the openclaw gateway runtime built from the pinned upstream source commit (the matrix channel extension is NOT in the npm openclaw package and the published `@openclaw/matrix` package is broken, so the source build is the only complete path), plus `mc` and the `agt` REST client, with the charly-owned `start-manager.sh` waiting for the controller's in-container services, syncing the manager workspace from MinIO, rendering `openclaw.json` from the template, and execing the openclaw gateway.

The `check-agentteams-pod` bed replaces `check-agentteams-core-pod`: it binds the host rootless podman socket into the box (`volume: {type: bind}`), pins `AGENTTEAMS_MANAGER_IMAGE` to the pre-built `ghcr.io/opencharly/agentteams-manager:manager` (the manager image is built as a PREREQUISITE of the R10 procedure — `run:` steps never execute during a bed run, the bed env is a static map, and the controller's `ensureImage` requires the exact ref), and adds the manager-spawn check: the controller creates the default Manager CR and the check polls `/api/v1/managers` until the manager reaches `"phase":"Running"` — proving the controller can spawn the manager container through the bound socket from the pre-built image.

**Two RCA'd build fixes landed with the manager image.** (1) The openclaw build's `scripts/pnpm-runner.mjs` re-execs pnpm via `node $npm_execpath` when the basename matches pnpm; the nodejs candy's standalone pnpm is a self-contained ELF binary, so `node <elf>` failed with a SyntaxError. The build now installs the JS pnpm (`npm install -g pnpm@10.32.1`, matching the repo's `packageManager` pin) and puts it first on PATH — the same path upstream's `openclaw-base` takes. (2) The openclaw build's `runtime-postbuild` stages the bundled plugins' runtime deps with a bare `npm install`, and `@whiskeysockets/baileys` depends on `libsignal` from a git URL; npm 11+ disables git deps by default (`allow-git=none` → `EALLOWGIT`), while upstream's NodeSource node 22 (npm 10) has no such gate — the build now exports `npm_config_allow_git=all` for the trusted pinned-source build. Both were reproduced in the exact cachyos build environment before fixing.

**Root-cause fix landed with the cutover:** `charly box list services` only ever listed candies with `port_relay` (openclaw) and never service-declaring candies. RCA: `listServices` read the aggregate `has_init` bool, which the resolution pipeline NEVER populates — `PopulateCandyInitSystem` fills the per-init-system `init_systems` map, and `CompleteCandyRunOps` folds the aggregate into `HasContent`, not `HasInit`. The predicate now reads `init_systems` (non-empty = at least one init system triggers), reconstructing the `HasAnyInit()` predicate the comment always intended. Regression test `TestListServices_InitSystemsPredicate` guards it: a candy whose only trigger is the dead `has_init` field must NOT be listed.

**The manager crash-loop, root-caused and fixed across three repos.** The controller's `dockerCreatePayload` sends no Cmd/Entrypoint when it spawns the manager container, and charly images bake NO OCI command (the deploy-time init injects it) — so the spawned manager ran bare `bash` (the base image's default `/usr/bin/bash`), exited 0, and restarted forever. Two secondary defects compounded it: `$(hostname)` evaluated empty inside the pod (no `hostname(1)` binary), and the container's default hex-ID hostname was not resolvable on the charly network. The fix is an explicit, zero-blast-radius surface — **box-authored OCI packaging**:

- **spec**: `#Box`/`#ResolvedBox`/`#ResolvedBoxView` gain opt-in `entrypoint:`/`cmd:` fields (baked into the image's OCI config; `cmd: []` clears a base image's inherited default command). Schema tests + `TestGenReproducible` guard the wire.
- **sdk**: the Containerfile emitter writes `ENTRYPOINT`/`CMD` (with an auto-`CMD []` when an entrypoint is declared without a cmd, so the entrypoint runs bare — the blast-radius guard test asserts a default box ships NO baked command); the quadlet path emits `HostName=<name>` and the direct-run `charly start` argv emits `--hostname <name>`, giving the in-container hostname = the charly-network DNS name under EVERY deploy path (`sdk/deploykit/quadlet.go`, `candy/plugin-deploy-pod/config_setup_helpers.go` `buildStartArgs`, with parity tests on both).
- **main**: the `agentteams-manager` box declares `entrypoint: [supervisord, -n, -c, /etc/supervisord.conf]` (the baked `/etc/supervisord.conf` is assembled at build time, so the entrypoint needs no runtime assembly), and `start-controller.sh` derives `AGENTTEAMS_CONTROLLER_URL` from `${HOSTNAME}` (bash's builtin hostname var — no `hostname(1)` binary — which the quadlet `HostName=`/direct `--hostname` make the charly-network-resolvable name). The manager image's OCI config is verified to carry the entrypoint with `Cmd: null` (base `["/usr/bin/bash"]` cleared).

**The R10 caught a regression in that fix, root-caused in turn:** the first quadlet emission wrote `Hostname=` (lowercase), which podman's quadlet does NOT support — the quadlet key is `HostName=` (camelCase), and quadlet SKIPS an entire unit over an unsupported key, so `charly start` failed with `systemctl: unit not found` (exit 5). The emission now writes the valid `HostName=` key (mapped by quadlet to podman's `--hostname`), the golden test pins it byte-exact, and the quadlet generator is verified to produce the `.service`.

R10 gate: `charly check run check-agentteams-pod` (disposable) — PASS (zero warnings), with the manager-spawn check proving the controller reaches the manager's `Running` phase through the bound rootless podman socket.

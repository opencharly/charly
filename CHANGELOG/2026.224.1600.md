# 2026.224.1600 — AgentTeams Unit 6: the VM substrate + machine-venue extract

The AgentTeams box now deploys on the `vm:` substrate, not just `pod:`. The controller's rootless podman socket is provisioned inside the guest by charly's own systemd init (no supervisord in the VM — the init-polymorphism path renders per-service systemd units), and the Manager/Worker images are delivered into the guest's podman store via the new `charly vm cp-box --domain <name>` (`podman save | scp | podman load`, rootless). The bed proves the full controller-spawns-manager → create-worker → room end-to-end sequence in-guest.

- **Machine-venue `extract:` materialization (spec → sdk → main).** On a machine venue the built image filesystem is never used — the install plan executes over the venue's own filesystem — so a candy's `extract:` entries could never reach a VM. This cutover adds the host-engine `ExtractStep` to the InstallPlan IR (spec), the `RunVenueExtractStep` execution body that pulls the source image with charly's own podman machinery and materializes the extracted content into the venue (sdk), and the `extract` step dispatch in `RunHostStep` (main). The higress binaries — which exist ONLY in the `higress/all-in-one:2.2.1` image — now land on the VM cleanly. This is the spec contract (#24) + sdk execution (#130) consumed by the main repo's dispatch.
- **Volume refactor (per the operator's directive).** Every agentteams candy now owns a **home-relative** volume at a freely configurable location (`~/.agentteams/minio`, `~/.agentteams/matrix`, `~/.agentteams/higress`, `~/.agentteams/controller`; element — a static nginx — carries no volume) instead of all sharing a fixed `/data`. Each candy is installable alone or in any combination with others; the matrix registration token is self-provisioned into its own volume.
- **Venue-dependent network.** The controller's spawn network and controller URL are venue-dependent: `pasta` + `host.docker.internal` on machine venues, `charly` + `$HOSTNAME` on container venues (the guest kernel lacks the bridge module netavark needs — RCA'd).
- **Rootless in the VM.** The controller candy enables the rootless user session for uid 1000 (subuid/subgid + linger), installs rootless podman packages (podman, crun, netavark, slirp4netns, fuse-overlayfs), and gates the host-socket bind on the pod venue — everything unprivileged, nothing deployed as root.
- **Init-polymorphism restart parity (fix).** The systemd service template now defaults `Restart=always` for unset/always/unless-stopped (parity with supervisord's `autorestart=true` default); `on-failure`/`no` map through. The envoy gateway service declares `restart: always` to recover from the upstream V8 WASM segfault (bounded probe loops, no blind retry).
- **Machine-venue install fixes (sdk + main).** `write:` creates parent dirs on machine venues; the arch `pacman -Syu` before package install (fresh cloud-image guests would otherwise hit a partial-upgrade).

# 2026.225.1452 — release-binary workflow: CalVer binary + welded plugins for amd64/arm64

Phase 1 of the nFPM packaging cutover (spec → sdk → plugin → main): the main repo gains a NEW
`release-binary` GitHub workflow that publishes the CalVer-stamped `charly` binary + the 9 welded
command plugins as GitHub release assets — the BINARY SOURCE the per-distro package repos
(`opencharly/charly-{alpine,arch,fedora,ubuntu,debian,openwrt}`) consume in Phase 2. Additive:
the old `release-packages.yml` workflow + the `pkg/*` submodules stay until the Phase 3 cutover.

**1. `.github/workflows/release-binary.yml`** — on a `v*` tag push (or `workflow_dispatch`), one
`ubuntu-latest` job:

- Builds the amd64 `charly` binary natively (`CGO_ENABLED=0`, CalVer-stamped via
  `-ldflags "-X main.BuildCalVer=$(bash scripts/calver.sh)"`).
- Builds the 9 welded command plugins (`scripts/host-command-plugins.txt`) for amd64 + generates
  each `.providers` manifest via `charly __plugin-providers <candy-dir>` (the amd64 binary runs on
  the runner).
- Cross-compiles the arm64 `charly` binary + the 9 plugins; the arm64 `.providers` files are COPIED
  from amd64 (the manifests are arch-independent word lists — the arm64 binary cannot run on the
  amd64 runner to regenerate them).
- Stages `charly-candy-charly.yml` (the charly candy's charly.yml — the `packaging:` source the
  distro workflows pass to the `charly generate-packages` plugin).
- Verifies both binaries report the CalVer: the amd64 via a runtime `version` call, the arm64 via
  `go version -m` (an aarch64 ELF cannot execute on the amd64 runner — the `-ldflags` build
  setting is read back from the embedded module build info instead).
- Publishes the assets via `softprops/action-gh-release@v3` (tag-guarded): `charly-linux-amd64`,
  `charly-linux-arm64`, `charly-plugins-linux-amd64.tar.gz`, `charly-plugins-linux-arm64.tar.gz`,
  `charly-candy-charly.yml`.

**2. `scripts/calver.sh`** — the `charly_calver()` function (CalVer `YYYY.DDD.HHMM` derived ONLY
from the HEAD commit's UTC date, so every binary built from the same commit reports the identical
version), copied verbatim from `pkg/arch/calver.sh` (which stays until Phase 3). The `task
build:binary` ldflags injection now reads it from `scripts/calver.sh`.

**3. `scripts/host-command-plugins.txt`** — the 9-plugin list (plugin-secrets, plugin-udev,
plugin-preempt, plugin-feature, plugin-vm, plugin-doctor, plugin-clean, plugin-settings,
plugin-candy), copied verbatim from `pkg/host-command-plugins.txt` (which stays until Phase 3).

**4. `taskfiles/Build.yml`** — the `binary` task's `CALVER=$(bash pkg/arch/calver.sh)` →
`scripts/calver.sh`. The `pkg:*` tasks stay until Phase 3.

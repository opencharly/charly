# 2026.225.1821 — keep the pre-commit-gate lint cache on the root fs

The pre-commit-gate hook's golangci-lint run forced `GOCACHE` into a
`tempfile.TemporaryDirectory` under `/tmp` and left Go's `$WORK` at the default
`/tmp`. On hosts where `/tmp` is a small tmpfs (or a sandbox caps its writes),
the lint build exceeds the quota and the gate fails environmentally — a clean
tree cannot commit. This redirects the lint temp dirs to a per-user root-fs
cache (`~/.cache/charly-gate-lint/`) and sets `GOTMPDIR`/`TMPDIR` so Go's build
work and golangci-lint's own temp files follow.

- **`.claude/hooks/pre-commit-gate.sh`**: `lint_staged_go` creates
  `~/.cache/charly-gate-lint/` and runs each module's golangci-lint inside a
  `TemporaryDirectory` rooted there, with `GOCACHE`/`GOLANGCI_LINT_CACHE`/
  `GOTMPDIR`/`TMPDIR` set to subdirs it creates first. The subdir creation is
  load-bearing: golangci-lint v2 locks at `$TMPDIR/golangci-lint.lock`, and a
  missing TMPDIR makes the lock open fail with ENOENT, which golangci-lint
  reports as "parallel golangci-lint is running" — a false positive that blocks
  every commit on hosts where the dir does not pre-exist. The cache-root
  creation is fail-open: a HOME that cannot be written falls back to the system
  temp dir (the pre-fix behavior) rather than blocking the commit.
- **`.claude/hooks/gate_test.py`**: a red/green pair proving the lint cache
  lands on the root fs — with `HOME` redirected to a temp dir, a lint-clean Go
  commit passes the gate AND `~/.cache/charly-gate-lint/` is created under the
  redirected HOME (the pre-fix hook never created it). 37 cases, 0 failures.

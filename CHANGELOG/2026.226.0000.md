# 2026.226.0000 — read AGENTTEAMS_MATRIX_DOMAIN from the venue instead of hardcoding it

The `agentteams:` check verb's worker room alias baked in
`matrix-local.agentteams.io:8080`, and the agentteams-controller never
accepted `AGENTTEAMS_MATRIX_DOMAIN` — so a deploy that set the var (as
`candy/agentteams-matrix`'s docs promise) moved the homeserver's
`CONDUWUIT_SERVER_NAME` while the controller kept registering accounts
against the old domain, and every manager/worker reached `phase=Failed`
with the homeserver itself healthy (`/versions` 200) — the symptom pointed
nowhere near the cause.

- **`candy/plugin-agentteams/verb.go`** — `venueMatrixDomain` reads
  `AGENTTEAMS_MATRIX_DOMAIN` from the live venue over the executor (the
  same channel the admin SA token comes through), falling back to the
  shared default; the worker room alias uses it instead of the hardcoded
  default.
- **`candy/agentteams-controller/charly.yml`** — the var joins `env_accept:`
  and is exported at the entrypoint with the `${VAR:-default}` form, and is
  **removed from the service `env:` map**. That last half is the load-bearing
  one: the service env map is rendered as supervisord `environment=`, which
  per the candy's own design rule overrides the pod's `charly config -e`
  overrides — so a var left there defeats the deploy override. The mechanism
  that matters: an accepted env var reaches the controller by being (a)
  listed in `env_accept:` AND (b) `export`ed in the entrypoint script AND
  (c) absent from the service env map, so the entrypoint's `:-` default
  fires and a deploy-level value wins.

The confirming `check-agentteams-pod` bed passes on the default-domain
path (manager + Worker Running, worker room alias resolvable at the
default domain, worker-list verb working) — 65/0/9 live, fresh-rebuild
leg green, zero warnings. A non-default domain cannot be bed-tested:
AgentTeams v1.2.2's `createRoom` requires a `canonical_alias` power level
the registration token does not grant (M_FORBIDDEN), so the bed env
override was reverted — there is no coverage that fails without this
change, stated honestly. The first revision of this cutover left the var
on the service env map, which the pr-validator caught (the deploy override
could not win); the rendered supervisord fragment is the artifact that
proves the fix — `AGENTTEAMS_MATRIX_DOMAIN` no longer appears in its
`environment=` line.

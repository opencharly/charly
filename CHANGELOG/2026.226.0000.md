# 2026.226.0000 — codify the sandboxed-/tmp Go + golangci-lint environment constraints

Codify the environment constraints discovered while working under the sandbox's
capped `/tmp` quota: Go builds and tests must set `GOTMPDIR`/`TMPDIR` to a
root-filesystem scratch dir (e.g. `/home/atrawog/.cache/go-tmp`) so the sandbox
quota does not abort them, and the golangci-lint v2 "parallel" error is a
missing-`TMPDIR` false positive, not a real lint failure. The
`candy/charly-internals` skill content gains the constraint, and the `plugins`
gitlink bumps to the merged skill-env-constraints leg.

The cutover also unwires the PreToolUse Bash gates from Claude Code. State the
trade accurately, because an earlier revision of this entry did not: both
scripts DO block what they exist for. Measured directly — `git commit
--no-verify`, a `core.hooksPath` override, `git push --force` and a direct push
to `main` each exit 2 with a BLOCKED message, while a non-git command exits 0.
This removes a WORKING local backstop; it is not a no-op cleanup.

What is accepted in exchange: the hooks ran before EVERY Bash tool call to
catch a narrow set of git invocations, and most of the discipline they encode
is judged for every harness by the fresh `pr-validator` at merge and by branch
protection. The exception, stated plainly because it is a real loss: branch
protection covers `main` alone (no rulesets, no other protected branch), so a
`feat/` branch force-push — which the rulebook forbids everywhere — now has no
server-side block under Claude Code, and the validator cannot substitute since
it inspects a branch already rewritten. Under this harness the agent is the
enforcement for those mechanics. The change is made at the SOURCE —
`candy/charly-hooks/charly.yml`'s `pre-commit-gate` / `pre-push-gate` entities
drop their `trigger:`/`matcher:` keys, adopting the AUX form already used by
`gitcmd` / `gate-test` — and `.claude/settings.json` is then regenerated by
`charly marketplace generate`, which owns that file's hook wiring
(`candy/plugin-marketplace/emit_hooks.go`). Editing the generated file alone
would have been undone by the next regeneration. Both scripts are still
emitted to `.claude/hooks/`, and `.reasonix/settings.json` — hand-maintained,
not generated — still wires them, so the other harness is unaffected.

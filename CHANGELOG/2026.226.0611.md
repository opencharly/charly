# 2026.226.0611 — Unit 2 cutover: the `agentteams:` check verb + the env-var doc divergences

The north-star's Unit 2 gap cutover (the approved factory plan, `PROGRAM/factory-north-star.md`): the compiled-in `candy/plugin-agentteams` now ALSO serves the declarative `agentteams:` check verb — the controller-probe counterpart of the `charly agentteams` command. The verb is HOST-BASED (the mcp pattern): the provider resolves the controller's in-venue :8090 to a host-routable address over the reverse channel (a published port on the pod substrate, a live `ssh -L` forward on the vm substrate), pulls the admin SA token from the venue over the executor, and probes with the SAME `apiClient` the command uses (R3 — one REST surface covers the CLI and every bed). The stateful bed assertions in `check-agentteams-pod` / `check-agentteams-vm` are rewritten from raw curl sequences + host-side compiled-in CLI steps to `agentteams:` verb steps.

- **`candy/plugin-agentteams`** (compiled-in): `providers: [command:agentteams, verb:agentteams]`. The verb's method + method-exclusive modifiers ride the desugared plugin input, validated at runtime against the served `#AgentTeamsInput` schema (`schema/agentteams.cue`, self-contained — no base refs; `params/cue_types_gen.go` generated by `task cue:gen`). Methods: `status` (controller health + resource counts), `manager-running` (poll until a manager reaches Running; `name:` pins one), `worker-running` (create the named Worker CR — idempotent on a 409 — poll until Running WITH its Matrix room provisioned, then resolve the room alias via the homeserver's public directory API on :6167), `worker-list`. The provider implements the typed `spec.CheckVerbProvider` contract (`Reserved()`/`RunVerb`) so the COMPILED-IN placement dispatches in-proc with the live host CheckContext (no broker); the OUT-OF-PROCESS placement runs the SAME core via the pb Invoke envelope with the broker attached (placement-invisible, F8). Skips under `charly check box` (no live controller on a disposable `podman run --rm`).
- **`charly/planrun_adapter.go` + `charly/plugin_dispatch_reverse.go` + `charly/provider_checkenv.go`**: the compiled-in verb dispatch legs — `hostVerbResolver.RunVerb`, the `executorReverseServer.InvokeProvider` OpRun branch, AND `runPluginVerb` (the `plugin:` verb's host-side dispatch — the path the `<word>: <input>` sugar desugars to) now recognize a compiled-in `pb.ProviderServer` that ALSO implements `spec.CheckVerbProvider` and thread the live host CheckContext in (the mcp pattern's `sdk.NewCheckContext` is out-of-process-only). The `runPluginVerb` leg was the R10-gate catch: without it a compiled-in verb candy fell through to `invokeVerbProvider`'s Invoke envelope, which loses the live host context and fails with "no go-plugin broker" (RCA'd live on the `agentteams:` bed steps). The reverse-server branch restructures the OpRun condition so a non-verb provider falls through to the default dispatch unchanged.
- **`charly.yml`**: `check-agentteams-pod` and `check-agentteams-vm` — the raw in-guest curl manager/worker/room sequences and the host-side `charly agentteams status`/`worker list` CLI steps are replaced by `agentteams:` verb steps (manager-running, worker-running, status, worker-list). The VM bed's comment documents the verb's host-based exception to the in-guest probe pattern.
- **`candy/agentteams-controller/charly.yml`**: the two env-var doc divergences fixed (R1/R2) — `AGENTTEAMS_WORKER_IMAGE` is now in `env_accept:` (it was overridable but container-env only), and `AGENTTEAMS_DEFAULT_WORKER_RUNTIME` is now implemented (exported with an `openclaw` default in the entrypoint; it was documented-only, consumed by no code — a phantom).

## Unit 6 — the snapshot/hydrate round-trip bed

`check-agentteams-snapshot` (`disposable: true`, pod substrate) proves the round-trip against a
live AgentTeams deploy: the controller's worker is captured into a hydration bundle, the bundle is
applied back, and the worker is still listed afterwards. `candy/agentteams-snapshot` carries the
charly toolchain into the bed's pod.

**The bed was blocked on a defect it found by being built.** `agentteams-worker` died at
`STEP 24/47` with `rc-update: command not found` — `EmitInitAssembly` was rendering the
`use_packaged:` unit list through every ACTIVE init rather than the resolved one, so an OpenRC
enable command landed in a supervisord container on an Arch base. Filed as `charly#313`, fixed in
`opencharly/sdk#143`, and the sdk gitlink advances `1e038a0c → f9feb20` (tag `v0.2026230.1339`)
here. That defect was a live regression on `main` from `ca76c354` onward, not a latent one.

**Three further defects were found by RUNNING the bed, none visible from reading it:**

- The bed deploys the `agentteams` box while the toolchain candy had been composed into
  `agentteams-worker` — a different box. The check runs `charly agentteams snapshot|apply` INSIDE
  the controller pod (it serves on `127.0.0.1:8090` and refuses connections from outside), so the
  binary must be in that pod. Fixed with `add_candy:` on the DEPLOY: `agentteams` is a production
  composition and does not carry a development toolchain to satisfy a check.
- The check asserted a worker nothing creates. A `run:` step cannot seed it — `check live` runs
  verify-only and skips mutating steps by contract — so the self-asserting check establishes its
  own precondition, creating the worker only if absent (a second create returns HTTP 409).
- The bundle layout was an unverified assumption: the step globbed `*.yaml`; the snapshot writes
  `workers.yml`, `teams.yml`, `humans.yml`, `snapshot.yml`. The corrected assertion also
  discriminates better — it names the artifact and the worker rather than grepping `Worker` across
  any yaml.

The step now discriminates at each link: an empty bundle fails the `test -s`, a bundle missing the
worker fails the `grep`, and an apply that drops it fails the final list.

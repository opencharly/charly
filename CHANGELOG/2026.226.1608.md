# 2026.226.1608 — adopt the sdk's nFPM packaging kit + the localpkg download leg; fix the qemu `vm start` idempotency

The main repo adopts the sdk's nFPM packaging cutover (sdk `8f52bf7`, spec `4cff4d0`): the `localpkg:` candy map and the `charly box pkg` / `task pkg:*` native-package build are replaced by the `charly generate-packages` plugin (nFPM, `sdk/packagekit`) + the per-distro package repos; the deploy-time localpkg path downloads the published package from the distro repos instead of building from `pkg/<fmt>` source; and the qemu `vm start` idempotency bug is fixed and proven on the debian bed.

**1. The sdk/spec adoption.** `sdk` → `8f52bf7` (the `sdk/packagekit` nFPM driver + the localpkg download leg + the plugin-based `localPkgBuildContext`), `spec` → `4cff4d0` (the `packaging:` candy schema + the `local_pkg` build-field removal + the `LocalPkgInstallStep` IR download-leg change). Every plugin's `go.mod`/`go.sum` bumps the sdk pin; the box/* submodule pointers bump to their stamp-only migration PRs.

**2. The localpkg source-build machinery is removed.** The `local_pkg` `pkg_glob`/`source_sentinel`/`build_template` fields and the `dep_builder: aur` wiring are gone from the embedded `charly/charly.yml`; the `task pkg:*` release-artifact tasks + the package test matrix comment are gone from `taskfiles/Build.yml`; the `download_template` URLs switch to the per-distro package repos' stable "latest" copies (`charly-arch`/`charly-debian`/`charly-fedora`/`charly-alpine`). The `check-charly-vm` bed's localpkg auto-resolve witness becomes a `copy: bin/charly` binary-install witness (the plugin-based localpkg proof returns with the nFPM cutover's Phase 3 check beds); the `check-exampledeploy` bed's F3 build-channel leg is removed with the source-build machinery it drove.

**3. The qemu `vm start` idempotency fix.** The qemu backend's already-running guard is now `qemuAlive` (read `<stateDir>/qemu.pid` → `Signal(0)` → `/proc/<pid>/cmdline` contains `qemu-system`), making `vm start` a clean no-op for a running VM — load-bearing for the rebuild path (`vmRebuild`). The bug this fixed: the backend used to blindly re-execute the stored command, so after `vm create` the guard started a SECOND QEMU, which failed to lock the pidfile (`Resource temporarily unavailable`) and corrupted the VM's state — every `charly check run <vm-bed>`'s `update` step failed with this error, even running sequentially. `vm list` now shares the same probe (R3). **Proven on the debian bed: `check-debian-debootstrap-vm` PASS (steps=9, exit 0), including the previously-failing `update` step.**

**4. The candy skill docs** (`candy/charly-internals`, `candy/charly`, `candy/charly-vm`, `candy/charly-build`, `candy/charly-check`, `candy/charly-core`, `candy/charly-distros`, `candy/charly-image`, `candy/github-runner`) update the `task pkg:*` / `charly box pkg` references to describe the removal; the `pkg/` + `opencharly-git` references remain transitional until the Phase 3 pkg/ removal cutover — the source the plugins repo's regenerated skills are generated from.

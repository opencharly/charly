# 2026.227.0114 — declare the charly `packaging:` metadata section

The charly candy's `candy/charly/charly.yml` now declares the `packaging:`
section — the single source of native-package metadata for the `charly
generate-packages` plugin (`sdk/packagekit`). The per-distro package repos
(charly-alpine/arch/fedora/ubuntu/debian/openwrt) download this candy's
`charly.yml` from the release and pass it to the plugin as `--candy`; this PR
unblocks their Phase 2 first publish.

## What landed

- **Deps** transcribed from the three legacy `pkg/*` files (arch PKGBUILD,
  fedora spec, debian control), which stay as fixtures until the Phase 3
  removal.
- **Variants** (3-way): `default` = the 7 everyday welded plugins (packages as
  `charly`); `full` = all 9 (+udev, preempt → `charly-full`); `minimal` =
  doctor/clean/settings (`charly-minimal`).
- **All six nFPM formats** present (a format passed to `--formats` but absent
  from `packaging.formats` is a hard error in sdk/packagekit `BuildInfo`).
- The `copy: bin/charly` run step remains the binary source for image builds;
  the localpkg transition to build from this section lands with the Phase 3
  cutover.

## The completeness gate

`charly/packaging_test.go` asserts the section parses into `spec.Packaging`
with every dep/optdep/suggest/variant-plugin entry a plain package name, and
that every dependency declared in the three legacy `pkg/*` files is present in
the section — a dep added to a PKGBUILD/spec/control but not here fails CI.
`charly box validate` passes on the fresh R9 binary.

## Program context

This is the `nFPM Packaging Cutover` program's metadata-landing step
(`PROGRAM/nfpm-packaging-north-star.md`), consumed by the Phase 2 distro
workflows and the Phase 3 main-repo cutover.

Revised against the tree, claim by claim, before a line was written. Every

Two defects were caught by that audit and fixed rather than published:

- **`helm_chars:` was a typo** for the real deploy field `helm_charts:`, which
  the k8sgen emitter renders as a kustomize `helmCharts:` transformer entry. A
  binding document naming a field that does not exist teaches the wrong
  identifier to every teammate it reaches.

  The claim-keyed sweep (R1) traced it to its ORIGIN: `CHANGELOG/2026.225.2248.md`
  — the unit 2 entry — carried the same typo four times, and that is where the
  north-star draft inherited it. Confirmed a typo and not a rename: `helm_chars`
  has never existed as an identifier in `spec` (`git log -S` over the whole
  history returns nothing), the schema field is and always was
  `spec/schema/deploy.cue`'s `helm_charts?: [...#HelmChart]`, and line 9 of that
  same CHANGELOG spells it correctly. All four occurrences are corrected here —
  the narrative is untouched, only the false identifier. Leaving it would have
  guaranteed a second propagation; it had already caused the first. Post-fix,
  `helm_chars` returns zero hits across the superproject, `plugins`, `spec`,
  `sdk`, and `docs`.
- **The kubeconfig claim was imprecise** — stated as a fixed path, it is a
  precedence chain (an operator-set `KUBECONFIG` wins, else the k3s guest
  default).
- **A security claim in the Trust boundaries section was false.** The draft
  asserted "the forge MCP endpoint binds loopback/stdio and is never routable
  from PROD Workers or spikes" as a property that holds. It does not:
  `charly mcp serve --listen` defaults to `:18765`
  (`candy/plugin-mcp/command.go:41`), which binds every interface — the default
  IS the exposure. A binding document that describes a security property the
  code does not have is worse than silence: a reader hardens nothing because
  they believe it is already hardened. Restated as the REQUIREMENT it is, with
  the default named; unit 7 absorbs the listener alongside the
  `--disposable-only` filter (both are the same license), and a matching
  anti-pattern is added.

Substantive content changes:

- A new **Trust boundaries** section: who holds which surface. Replicator and
  Fixer run INSIDE the spike (the boundary is the security model, not a tool
  allowlist); Forgemaster holds the disposable lifecycle only; PROD has no
  agent-held write path; credentials come from a pre-minted budget-capped pool.
- Units 2 and 3 recorded as landed, with commits and CHANGELOG names; the helm
  flavor rewritten from "charly has no helm word today" to the landed
  `check-helm-vm` pattern.
- The `charly mcp serve` scoping restated as a **named gap** rather than a
  prompt-level promise, and "a spike forging a spike" replaced by the two
  structural anti-patterns that supersede it (a spike reaching the forge host's
  charly; handing any agent the full `charly mcp serve` surface).

Structural change — **the unit list renumbers from six to nine**. Two
load-bearing gaps were named in the prose but had no unit and no measured-state
box, so neither was anyone's work:

- `charly box load` (unit 5) — the nested-store image-delivery verb the
  containment spike named. Verified absent from `charly box --help`; today it
  forces a hand-run `podman save | podman --remote load` pipeline (R4). It
  blocks the native spike.
- `charly mcp serve --disposable-only` (unit 7) — verified absent from the
  source. The Forgemaster's entire trust boundary rests on it, and unit 8
  deploys a Forgemaster.

Unit 8 (the Factory proper) is marked as decomposing into ordered sub-units,
since it is too large for one honest gate.

# 2026.227.1145 — carry box/fedora with RPM Fusion OpenPGP verification

The `box/fedora` gitlink moves to `49fdb231` (distro-fedora `v2026.227.1110`),
which reconciled all 158 candy pins to charly `v2026.227.0914` so the RPM Fusion
release packages install with their **OpenPGP signatures verified**.

This entry records when THIS repository began carrying that content — a fact
recorded nowhere else. distro-fedora's own `CHANGELOG/2026.227.1110.md` records
why the candy changed; the two answer different questions.

## What this bump does and does not do

It does **not** fix the superproject. The superproject's `candy/rpmfusion` is a
LOCAL candy at `2026.227.0830`, and a local candy shadows the `@github` ref, so
builds resolved from this root already installed the release packages verified.

What it changes is the content a **recursive clone** carries. Resolved as its own
project root — the consumer case — the old gitlink pinned
`rpmfusion:v2026.201.0706`, which resolves to candy `2026.144.1443`, the pre-fix
version that installed both release packages **unverified**. The new gitlink
pins `v2026.227.0914` → candy `2026.227.0830`, the fixed one.

## The proof, and a probe that did not prove what it claimed

The security property is discriminating only when resolution has no local candy
to shadow with — which is reachable here by pointing the project root at the
submodule:

```
$ CHARLY_PROJECT_DIR=box/fedora charly check box fedora-nonfree
Image: ghcr.io/opencharly/fedora-nonfree:2026.227.1131
  PASS  check the RPM Fusion free signing key is in the rpm database, proving the
        release packages were verified rather than trusted blind  [rpmfusion-key-imported]
7 steps: 6 passed, 0 failed, 1 skipped
```

An earlier revision of this change instead offered
`grep -c "skipped OpenPGP" image-build.log → 0` from the `check-docs` bed. That
number was **vacuous**: 114 of 122 build steps were cache hits and the log
contains no dnf transaction lines at all, so the grep returns 0 whether or not
the packages verify. It was a probe that could not fail — recorded here because
the same shape (a green figure measuring nothing) is the failure mode this
project's check discipline exists to prevent, and it survived one round of
self-review before an independent validator caught it.

The `check-docs` bed run is retained as what it actually proves: no regression in
the `fedora` → `fedora-nonfree` → `fedora-builder` chain under the new submodule
content — PASS (steps=13), zero warnings, zero failed steps.

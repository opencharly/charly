`proc.SweepStaleTemps` globbed a hardcoded `/tmp` while every creator resolves
through `os.TempDir()`, which honours `$TMPDIR`. On any host exporting the
variable the sweep scanned a directory no temp had ever been created in and
reaped nothing — silently, since it is best-effort and never errors. Measured on
this project's own dev host: **201 stale `charly-localpkg-` trees under
`$TMPDIR`, zero under `/tmp`** — `--dev-local-pkg` bed build stages, the single
biggest thing the sweep exists to reap. After the fixed binary's first
invocation: 0.

The second site mattered more: `openedFilesByAnyProcess` filtered
`/proc/<pid>/fd` targets by the same hardcoded prefix, and that is the sweep's
"some process has this open" guard. On a `$TMPDIR` host it recorded nothing, so
every temp the sweep did reach read as unheld — the hardcode did not merely stop
the sweep working, it stripped a liveness guard from whatever it reached. Both
sites are fixed together (R3). Full narrative + coverage: `spec`
`CHANGELOG/2026.227.1934.md` — the squash renamed that file from
`2026.227.1245.md` when it took its merge-time CalVer, so the name this entry
originally cited no longer exists on `spec` `main`.

# 2026.227.1245 — bump spec to the temp-sweep `$TMPDIR` fix

Consumer half of `opencharly/spec`'s stale-temp sweep fix (member three of the
check-verb correctness batch). Gitlink only — no superproject source changes.

`proc.SweepStaleTemps` globbed a hardcoded `/tmp` while every creator resolves
through `os.TempDir()`, which honours `$TMPDIR`. On any host exporting the
variable the sweep scanned a directory no temp had ever been created in and
reaped nothing — silently, since it is best-effort and never errors. Measured on
this project's own dev host: **201 stale `charly-localpkg-` trees under
`$TMPDIR`, zero under `/tmp`** — `--dev-local-pkg` bed build stages, the single
biggest thing the sweep exists to reap. After the fixed binary's first
invocation: 0.

The second site mattered more: `openedFilesByAnyProcess` filtered
`/proc/<pid>/fd` targets by the same hardcoded prefix, and that is the sweep's
"some process has this open" guard. On a `$TMPDIR` host it recorded nothing, so
every temp the sweep did reach read as unheld — the hardcode did not merely stop
the sweep working, it stripped a liveness guard from whatever it reached. Both
sites are fixed together (R3). Full narrative + coverage: `spec`
`CHANGELOG/2026.227.1245.md`.

**Stated as a limit, not glossed:** neither bed builds a LIVE `charly-localpkg-`
tree — `marketplace-app`, `dsh-app`, `docs-site-app` and `check-commands-app`
compose no localpkg candy (verified with `charly box inspect`, and no bed log
mentions localpkg), and the beds that would are the long VM ones. So the beds
prove the sweep does not break normal operation across two substrates, not that
it spares a live localpkg build.

That property is covered at the unit level instead, and the fix is what makes
that coverage MEAN anything: `TestSweepStaleTemps_HeldTempSurvives` asserts a
held, backdated temp survives, and its companion control
`TestSweepStaleTemps_UnheldCreatorIsSwept` exists to prove the held test is not
vacuous. On a `$TMPDIR` host, pre-fix, that control FAILED — with the message
"the pre-fix creator shape survived the sweep — this control is no longer
reproducing the deletion the fix prevents, so the held-temp test above proves
nothing." Post-fix both pass, so the liveness assertion is live again on exactly
the hosts where it had gone silent.

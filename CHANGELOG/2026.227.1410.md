# 2026.227.1410 — stamp the release binary with the release tag's CalVer

The `release-binary` workflow stamped the binary with the HEAD commit's date (`calver.sh`). The pr-validator computes the tag name just before the squash merge, so a merge that crosses a minute boundary leaves the commit dated tag+1min — and every binary built from it reports a version that matches no release (observed: v2026.227.1256's binary reports 2026.227.1257). The distro repos' install-test asserts `charly version` == the packaged version, so a binary from release v<X> must report X.

**The fix.** On a tag push, the workflow now stamps from the tag name (`CALVER=${GITHUB_REF_NAME#v}`); on `workflow_dispatch` it keeps the `calver.sh` (HEAD commit date) fallback. The three inline `CALVER=$(bash scripts/calver.sh)` invocations (build amd64, build arm64, verify) are consolidated into one `Compute the CalVer` step that sets the `CALVER` env var once.

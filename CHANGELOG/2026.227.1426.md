## Registered, not parked — `charly docs generate --root` is not authoritative

`--root <path>` is honoured by the candy, box, cli and recipe emitters but NOT by the
`index.md` / `recipes/index.md` emitters: with cwd inside a different charly project
those two pages project from the CWD project's `README.md`
(`candy/plugin-docs/command.go:58` + `generate.go`), silently and deterministically
(reproduced 5/5). It does not bite `task docs:sync`, where cwd == ROOT_DIR, which is
why it has gone unnoticed.

Found by `docs#56`'s validator when a cwd reset made its no-op check appear to fail
against this branch; it bisected by cwd rather than filing the false finding. The same
root cause also gave it a wrong `charly version`, since `scripts/calver.sh` reads
`git log -1` from cwd.

Owned by this session's next cutover. It is a Go change in `candy/plugin-docs`, so a
code change class with its own gate — deliberately NOT folded in here, where it would
ride a docs-site bed that cannot exercise it.

# 2026.228.0330 — the D18 sshd start is per-init, and three docs said otherwise

`sdk#138` branches the cloud-init sshd start on the guest's init system: the
hardening drop-in still runs first and unbranched, but the START that follows is
`systemctl unmask` + `enable --now` on systemd and `rc-update add` +
`rc-service start` on OpenRC (Alpine, which has neither ssh.socket nor
systemctl). That made three published claims false.

## The three claims

| surface | claim | why it was false |
|---|---|---|
| `vm-spec` — `RunCmd` | "prepended with three D18 hardening steps … `systemctl unmask ssh.socket`, then `systemctl enable --now sshd`" | three steps only on systemd; two on OpenRC, and neither is a systemctl call |
| `cloud-init-renderer` — `composeRunCmd` | "prepends THREE steps, in order" | same |
| `cloud-init-renderer` — `effectiveDistro` | "additionally infers `arch`" | it now also infers `alpine` from `base_user: "alpine"` |

Each is rewritten to separate the INVARIANT (the drop-in is always first and is
distro-agnostic, because it writes into `sshd_config.d`, which OpenSSH Includes
on every init) from the per-init VARIANT. The `composeBootCmd` mask is
documented as deliberately unbranched: on Alpine the `|| true` swallows the
missing binary and the mask is vacuous where nothing is socket-activated.

## Three surfaces, one source

The claims live in **one** place — `candy/charly-internals/charly.yml` — and are
projected twice: to `plugins/**/SKILL.md` by `charly marketplace generate`, and
to the published opencharly.ai pages under `docs/src/content/docs/recipes/` by
`task docs:sync`. Both projections carry the DO-NOT-EDIT marker, so this change
edits the source and regenerates; it never hand-edits a generated page.

**Worth recording, because the sweep that found these missed one:** a
claim-keyed `git grep` from the superproject root does NOT cross a gitlink. The
first sweep covered the superproject and `plugins` and reported "complete"; the
`docs` submodule carried all three claims and was invisible to it. A sweep for a
generated claim has to run **per-submodule**, once per projection — the
published site is a surface like any other.

**Also worth recording:** regenerating from a stale tree is not additive. Run
from a superproject six commits behind `main`, `charly marketplace generate`
touched 24 files and would have REVERTED prose landed by the R4a doc sweep;
`task docs:sync` deleted 93 reference pages because the `box/*` submodules were
uninitialized and their sources appeared absent. Both were discarded and redone
from a branch off fresh `main` with submodules initialized, where the same
commands touch exactly the intended files. A regenerate is only safe from a
current tree.

## Round 2 — the sweep was incomplete, and the reason is the transferable part

Two validators, working independently in different repos, found the same gap:
**`sdk#138` shipped FOUR fixes and this sweep covered one.**

Fixes 2 and 3 changed the emitted create-mode Containerfile block — user
creation now probes `command -v useradd` with a busybox `addgroup`/`adduser`
fallback, and the login shell is probed rather than hardcoded to `/bin/bash`.
**Six candy sites across four sources** printed the pre-fix block, projecting to
four `plugins` skills and four published pages, each introduced as *what the
generator emits*. A stale fenced excerpt is an integrity failure, not a wording
nit: a reader copies a command the product no longer produces.

Three further instances of the fix-4 falsity also survived — two of them on
lines this cutover's own first commit had edited, one directly contradicting a
`+` line in the same file.

**Root cause: the sweep keyed on the STRING it had fixed rather than the CLAIM
that became false.** Grepping `unmask`/`enable` finds every sshd site and is
structurally blind to a stale `useradd` block, which expresses a different
falsified claim from the same commit. Both defects came from one merge; only one
had a memorable token. Proximity to the edit is not coverage — three of the
misses were inside a line the fix itself had touched.

The corrected key is the claim, enumerated **per fix in the triggering commit**,
then swept **per surface**. `git show <merge> --stat` is the cheap first step;
it would have shown `deploykit/bootstrap.go` in the diff and named the two fixes
the sweep never considered.

Fix 1 (the go-task `curl` → `(curl || wget)` fallback) is genuinely clean —
every page elides that line.

# 2026.229.0000 — the `cmd:` emitter is a heredoc, and two documented helpers do not exist

The emitter documentation in `candy/charly-build/charly.yml` and
`candy/charly-internals/charly.yml` described a quoting mechanism the code abandoned, and named three
helper symbols — **two of which exist nowhere in the tree, in either the superproject or the sdk.**

## What was wrong

| The prose said | The code does |
|---|---|
| `emitCmd` emits `bash -c $'…\n…'` — ANSI-C quoting | `EmitCmd` emits a single-quoted heredoc `<<'OVCMD'`, behind a bash-preferred / POSIX-fallback shell prefix |
| `shellAnsiQuote(s)` performs that quoting | **No such symbol.** `git grep` returns nothing in `*.go`, superproject or sdk |
| `shellSingleQuote(s)` quotes LABEL and env values | The helper is `spec.ShellQuote`. There is no `func shellSingleQuote` anywhere; the name survives only as a package-level ALIAS to that same helper — `var shellSingleQuote = spec.ShellQuote` at `candy/plugin-adb/install.go:93` and `candy/plugin-kube/deploy.go:59` — so it is the identical function under a local name, not a different one |
| `stageInlineContent(...)` stages `write:` content | Exported and relocated: `StageInlineContent`, `sdk/deploykit/tasks_stage.go` |
| `tasks.go` holds "all task emission logic" | `charly/tasks.go` is **64 lines and one function**, `invokeOpEmitFragmentOpt`. The emitters live in `sdk/deploykit`; `charly/tasks.go` cannot shim a `deploykit` method, because `charly/import_purity_test.go` forbids `charly/` importing the sdk at all |

The ANSI-C form was not renamed — it was **abandoned, deliberately**. `$'…'` is a bashism, so it made
every candy shell step unbuildable on a busybox base. The `sdk` leg replaced it with a single-quoted
heredoc behind `BuildStepShellDashC()` / `BuildStepShellHeredoc()`; this documentation never caught up.

## Why prose naming a non-existent symbol is worse than vague prose

A reader who searches for `shellAnsiQuote` finds nothing and cannot tell whether it was renamed,
relocated, or removed — the text gives no way to recover the truth by inspection. Two of the three
names had no referent at all.

The replacement therefore names the **mechanism** (`<<'OVCMD'`, and why a single-quoted delimiter
matters: the outer shell performs no expansion, so an author's `$(cmd)` and `${VAR}` reach the inner
shell intact) rather than a helper identifier, so it survives future renames. It also states that the
ANSI-C form is gone and why, instead of silently dropping it — a reader arriving from the old text
needs the retraction, not a blank.

## Round 2 — the correction named non-existent symbols too

A validator failed round 1 with the observation that lands hardest: **this change's own thesis is
that prose naming non-existent symbols is a defect, and its replacement prose named non-existent
symbols.**

| Round-1 text | Reality |
|---|---|
| ``tasks.go`` is "a thin shim to `deploykit.Generator.EmitTasks`" | `charly/tasks.go` is **64 lines, ONE function** — `invokeOpEmitFragmentOpt`. It cannot shim a `deploykit` method: the P16 import-purity gate forbids `charly/` importing the sdk at all, so this was not merely stale but architecturally impossible |
| `emitPluginFragment` | **Zero declarations** in either module |
| `case "command": emitCmd (RUN bash -c …)` | The retracted `bash -c` form, alive 45 lines above its own retraction in the file this change edits |
| `emitDownload` … `curl -fsSL <url> \| <extractor>` | No pipe: `EmitDownload` fetches to a **content-addressed cache file** (`/tmp/downloads/<sha256 of url>`) and the extractor reads it |
| `write` row: `COPY --from=<layer-stage> …` | `EmitWrite` emits **no `--from=`** — the source is a build-context path, not a stage. (`EmitCopy` *does*, correctly) |

**Root cause, one sentence:** the greps were pointed at the claims being RETRACTED and never at the
claims being ASSERTED. A correction is a new claim and earns no exemption from the test that caught
the old one.

A second, subtler instrument failure fed it: `git grep "func EmitTasks"` returns nothing, because
`EmitTasks` is a **method** — `func (g *Generator) EmitTasks`. That near-miss briefly made a real
symbol look absent. Method receivers must be in the pattern.

**Scope grew accordingly:** 52 lowercase emitter names renamed to the exported forms that exist in
`sdk/deploykit` (the lowercase spellings exist nowhere), plus one stale test reference now naming the
real gate `TestOpActsInBuildDeploy_PlacementAgnosticBuildEmit`.

**Deliberately NOT fixed here:** `TestNsRepoIdentity` and
`TestImportNamespace_DivergentVersionMutualCycle` are absent from every `*_test.go`, but they are
pre-existing and a different claim family from the emitter symbols. Guessing replacements is exactly
what failed round 1, so they are routed to the module-hygiene batch with their evidence rather than
invented.

## `host-generated Kustomize tree` retired from five sites

The term is gone from `candy/plugin-kube` — the `description:` (which lands **twice** per generated
page, frontmatter *and* body), `deploy.go`, `plugin.go`, and `provider.go` ×2. **Recorded here
because after this lands `git grep host-generated` returns zero across all three repos, and R5's
grep self-test relies on `CHANGELOG/` to hold the reason a term vanished.**

**It was not simply wrong, which is why an earlier sweep did not read it as false.** `host` does two
jobs in this codebase:

- In `deploy.go` the comment contrasts host with **the cluster** — "the host generated +
  egress-validated the tree", then applies it to the live cluster. **True.**
- In the reference pages it contrasted host-side with **PLUGIN-side**. **False**, since
  `materializeKustomize` lives in `candy/plugin-kube/materialize.go`.
- `plugin.go` uses **both senses in one comment**: line 4's "host-generated" against line 7's "the
  host go-builds this binary and serves it OUT-OF-PROCESS".

So the claim was **ambiguous at three sites and false at one** — the `charly.yml` description, whose
context on the reference pages is architectural placement. A blanket rewrite to "plugin-side" would
have destroyed a true host-vs-cluster contrast in `deploy.go`.

All five now name the mechanism — **plugin-generated, on the host** — which holds under either
reading: the plugin binary is host-built and served out-of-process on the host machine, so the two
halves are not in tension.

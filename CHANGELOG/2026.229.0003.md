# 2026.229.0003 — the lint gate could not see formatting

`golangci-lint run ./...` reported `0 issues.` over a file `gofmt -l` rejected.

golangci-lint **v2 moved formatters out of `linters:` into their own top-level `formatters:` block**.
This config declares `default: standard` plus eleven quality linters and no `formatters:` block, so
formatting was never checked — by the linter, or by any CI step or taskfile, which run no separate
`gofmt`. A mis-formatted file could land with a green gate.

## Proof that the gate now discriminates

The clean tree still passes, and the same perturbation that previously produced `0 issues.` now fails:

```
CONTROL   tree as-is                          -> 0 issues.
MUTATION  a doubled space in a func declaration -> gofmt -l flags the file            
                                                 golangci-lint: 1 issues: * gofmt: 1
```

Before this change the mutation produced `0 issues.` — that is the whole defect.

## Zero churn

Measured before adding the block: `gofmt -l` returns **0 files** across `charly`, `sdk`, `spec` and
all 91 `candy/*` modules. So this only makes the gate able to fail; it repairs nothing and reformats
nothing.

Found while gating an unrelated PR in the sdk, where lint passed a file gofmt rejected. All three
module configs shared the omission and each lands in its own repo: `opencharly/sdk#141`,
`opencharly/spec#36`, and this one for `charly/`. Both commands must be run until they land;
neither implies the other.

The 91 `candy/*` modules have no `.golangci.yml` of their own and are linted through the workspace,
so they inherit this once it lands.

## The ollama candy (`candy/ollama/`)

- **Configurable upstream version.** The install step gains the candy-local
  `var:` `OLLAMA_VERSION` (default `latest` — no pin): `latest` tracks the
  newest GitHub release, and setting a release tag (e.g. `v0.32.14`) pins an
  exact version. GitHub serves the two cases from different URL shapes
  (`releases/latest/download/…` vs `releases/download/<tag>/…` — the
  `releases/download/latest/…` form 404s), so the step resolves the URL in a
  small shell conditional; the `download:` verb cannot express it.
- **One more deterministic runtime check:** `ollama list` exits 0 against the
  live service, proving CLI↔server wiring in-container (joining the `/api/tags`
  200 and `ollama --version` probes).
- **Stale skill claims corrected (R1).** The `ollama-layer` skill still claimed
  a `cuda` dependency and a `task:` install file and described retired check
  ids/contexts; both skill entities now match the candy.

## The plugin-ollama management plugin (`candy/plugin-ollama/`)

A compiled-in `command:ollama` plugin (dual-placement, placement-agnostic) that
owns the entire `charly ollama` CLI — `list` / `ps` / `pull` / `rm` / `show` /
`cp` / `create` / `push` / `run` / `stop` / `version` — against a deployed
Ollama server's HTTP API, built on the official upstream Go client
(`github.com/ollama/ollama/api`, pinned `v0.32.14` in the candy's own go.mod).
Self-contained (plain HTTP, no reverse channel), so it works identically
compiled-in or out-of-process. Endpoint resolution is deliberately lightweight:
`--server` flag > `OLLAMA_HOST` env > `http://127.0.0.1:11434` — the flag is
named `--server`, NOT `--host`, because the charly-level Kong grammar already
owns `--host` (SSH remote execution) for every command. Full Modelfile
authoring stays with the upstream CLI inside the deployment (the candy's host
alias); `create` covers the lightweight `--from` form. Coverage: 18 unit tests
against an httptest fake Ollama server (every subcommand's request body +
output, endpoint precedence, error propagation, the chat REPL).

## The R10 bed

that runs the candy's inherited baked checks PLUS host-side `charly ollama`
steps against the live server: `help` dispatch, `version`, and `list` over the
auto-allocated host port (`${HOST_PORT:11434}`). The heavy pull/persist proof
stays with the candy's `agent-check:` (unbound in this run — no `kind: agent`
harness configured; the bed grades `--no-agent` by design).

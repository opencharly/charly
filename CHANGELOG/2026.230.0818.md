# 2026.230.0818 — provenance out of the skills, and one hedge that had already gone false

Executes the "skill prose: provenance out, incidents stay" batch registered with the
generate-packages shim, and removes the registration — the batch is finished, not re-homed.

Registering it was the right call at the time and the wrong thing to leave standing: its
owner field named the nFPM program, which has now completed every phase, so the batch named
as its owner a program with no remaining work. That is how a registered batch decays back
into the deferral it replaced.

## The find that justifies the sweep

`/charly-internals:vm-deploy-target` carried a temporal hedge that had **already decayed to
false**:

> There is deliberately **no fallback** for either value — as of this cutover, whose spec and
> sdk legs are unmerged at the time of writing; on released charly the field is still
> `distro?: string` with the inference in place.

Both halves are wrong at HEAD. `spec/schema/vm.cue` declares `distro?: #DistroID` — the
vocabulary type, not `string` — and `spec/spec/vocab_gen.go` carries the generated
`DistroSSHUnits` / `DistroInits` tables the same paragraph reads from, so those legs are
merged. A hedge written to be careful became the only false sentence on the page, and nothing
re-checks a hedge. The paragraph now states the rule in the present tense.

## Also swept — the accounting was incomplete

The first revision of this entry deleted the registration on an accounting its OWN keys refute.
Re-running `as of` and the earlier-revision keys found five sites in neither list, one of them in
a file this change already edits, and one the registration's own text names as the third shape it
covers:

- **`charly-distros`** ×2 — "Builds end-to-end as of charly 2026.141.1850", and an
  "Earlier this path was unusable … **Fixed as of charly 2026.141.1850**" narrative. The failure
  symptoms (`package architecture is not valid`, `GPGME error: No data`) are kept as diagnostics;
  the version qualifier and the was-broken framing are not.
- **`charly-check`** — "the earlier revision put all five lines in one `yaml` fence" becomes the
  mechanism itself: five sibling `command:` keys in one fence is rejected by a strict loader and
  silently reduced to the last key by a permissive one.
- **`charly-internals`** — "Baseline at authoring (2026-06, broadest uncapped): **1017 issues**"
  plus twelve per-linter counts, replaced by the instruction that survives: run it uncapped and read
  the per-linter SHAPE rather than the total.

  A first attempt kept the SHAPE ("errcheck and staticcheck dominate") while dropping the count —
  and that was false too. Measured with the skill's own recipe on a pristine worktree,
  `cd charly && golangci-lint run ./...` reports `0 issues.`; a planted defect yields `unused: 1`,
  so the run discriminates and the distribution is genuinely empty. **A shape claim is not more
  durable than the count it came from** — both were readings of the same 2026-06 run — and a stale
  shape misleads more quietly than a stale total. Neither is pasted now.

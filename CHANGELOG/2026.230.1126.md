# 2026.230.1126 — opencode harness config: permissions, pr-validator agent, gate hooks

Adds the per-project opencode configuration that brings the opencode harness
in line with the other harnesses (Claude Code, Codex, Reasonix) already wired
for this repository.

## What landed

- **`opencode.json`** — mirrors the charly/gh permission allowlist from
  `.claude/settings.json` and `reasonix.toml`, so opencode auto-allows the
  same `charly check run/live/box:*`, `charly status:*`, `gh pr merge:*`, and
  `gh api --method POST repos/opencharly:*` verbs instead of prompting. Also
  enables the Go LSP (`gopls`) for `.go` files.
- **`.opencode/agent/pr-validator.md`** — a `pr-validator` subagent mirroring
  `.codex/agents/pr-validator.toml`, pointing at the authoritative spec in
  `plugins/internals/agents/pr-validator.md`.
- **`.opencode/plugin/charly-gates.ts`** — wires the existing
  `.claude/hooks/pre-commit-gate.sh` and `pre-push-gate.sh` into opencode via
  the `tool.execute.before` hook (opencode has no `PreToolUse` hook system, so
  this is the equivalent). It runs the gate before any `git commit`/`git push`
  bash call and hard-blocks on exit 2. Uses `spawn` with a manual timeout:
  `execFile`+`input` hangs under the Node 26 runtime (verified — a trivial
  `bash -c cat` with `input` never returns), so the plugin pipes the gate
  payload through stdin explicitly.

## Notes

- opencode already auto-loads `AGENTS.md` and all 292 skills from
  `.agents/skills/`, so no extra wiring was needed there.
- The `pr-validator` agent and gate plugin are auto-discovered from
  `.opencode/agent/` and `.opencode/plugin/`, so no `opencode.json` entry is
  required for them.

# 2026.230.1159 — fix opencode permission patterns to match real command syntax

Fixes the opencode permission allowlist added in 2026.230.1126 so the
`charly`/`gh` verbs it names are actually auto-allowed instead of prompting.

## What landed

- **`opencode.json`** — the `bash` permission patterns used colon separators
  (`charly check run:*`, `gh pr merge:*`, …) copied verbatim from the Claude
  Code / Reasonix harnesses, but opencode matches bash permission patterns
  against the full command string with `*`-wildcard regex semantics — a colon
  never matches the space in a real command (`charly check run box/foo`), so
  none of the six rules ever fired. Rewrote them to space-separated wildcards
  (`charly check run *`, `gh pr merge *`, `gh api --method POST
  repos/opencharly/*`, …) that match the real command forms, verified against
  opencode's `Wildcard.match` implementation.

## Notes

- The `.claude/settings.json` and `reasonix.toml` allowlists keep their colon
  form: those harnesses treat the pattern as a command-prefix match, so the
  colon form works there. opencode's regex-based wildcard matching is a
  different model and needs the space form.

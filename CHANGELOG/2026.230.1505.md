# 2026.230.1505 — Factory Unit 6: the snapshot round-trip bed

`check-agentteams-snapshot` (`disposable: true`, pod substrate) proves the snapshot/hydrate
round-trip against a live AgentTeams deploy: the controller's worker is captured into a hydration
bundle, the worker is deleted, the bundle is applied back, and the worker is listed again.
`candy/agentteams-snapshot` carries the charly toolchain into the bed's pod via `add_candy:` on the
deploy — the `agentteams` box is a production composition and does not carry a development
toolchain to satisfy a check.

**Scope: this entry covers Unit 6 only.** Unit 2 (the `agentteams:` check verb) already landed as
`CHANGELOG/2026.226.0946.md`; an earlier revision of this branch carried a byte-identical copy of
that entry under a second CalVer, which would have duplicated its history and attributed four
untouched files to this release.

## The prerequisite defect

The bed was unrunnable: `agentteams-worker` died at `STEP 24/47` with `rc-update: command not
found`. `EmitInitAssembly` rendered the `use_packaged:` unit list through every ACTIVE init rather
than the resolved one, so an OpenRC enable command landed in a supervisord container on an Arch
base. Filed as `charly#313`, fixed in `opencharly/sdk#143`; the sdk gitlink advances
`1e038a0c → f9feb20` (tag `v0.2026230.1339`) here. That was a live regression on `main` from
`ca76c354` onward, not a latent one.

The bed ran against `0f8f1d33`, that PR's pre-squash head. The whole-tree diff `0f8f1d33..f9feb20`
is a single CHANGELOG rename, so the evidence transfers. `0f8f1d33` is orphaned by the squash and
is deliberately not the pin — a superproject gitlink must name a commit on the submodule's `main`.

## Four defects the bed found by being run

1. **Wrong box.** The bed deploys `agentteams`; the toolchain candy had been composed into
   `agentteams-worker`. The check runs `charly agentteams snapshot|apply` INSIDE the controller
   pod — necessarily, since it serves on `127.0.0.1:8090` and refuses outside connections. Fixed
   with `add_candy:` on the deploy; the worker-side composition is reverted.
2. **No precondition.** The check asserted a worker nothing creates. A `run:` step cannot seed it —
   `check live` runs verify-only and skips mutating steps by contract — so the self-asserting check
   creates the worker if absent (a second create returns HTTP 409).
3. **Wrong bundle layout.** The step globbed `*.yaml`; the snapshot writes `workers.yml`,
   `teams.yml`, `humans.yml`, `snapshot.yml`.
4. **The hydrate half could not fail.** `charly agentteams apply` never deletes
   (`applyPathWithClient` has no delete path), so with the worker left in place a completely
   vacuous hydrate would still satisfy the final assertion. The check now deletes the worker
   between snapshot and apply and asserts its absence, so the restore is what the last assertion
   measures.

## Removed rather than shipped

The `agentteams:` check verb's served schema briefly advertised `snapshot` and `hydrate`, but
`RunVerb`'s switch never dispatched them — the method would pass schema validation and then fail at
runtime as unknown. `verbSnapshot`, `verbHydrate` and their helpers had zero callers and zero
coverage, and the bed exercises the CLI path instead. Schema narrowed to the four dispatched
methods and the dead code deleted.

**A capability gap this removes rather than hides:** `restoreObjects` / `putObject` were the MinIO
object-restore half of hydrate. `charly agentteams apply` restores CRs but not MinIO objects, and
the bed's round-trip reported `minio objects mirrored: 0`, so that path was never exercised. It is
deleted rather than shipped unproven; restoring MinIO objects on hydrate remains unimplemented.

## The prose the sdk pin falsifies, fixed in the same change

`candy/charly-build/charly.yml:1585` carried two claims this PR's own gitlink bump makes false, so
they are corrected here rather than routed to a follow-up — shipping the pin without them would put
a false statement on `main`:

- *"the embedded `init:` vocabulary (currently `supervisord` and `systemd`)"* — `openrc` landed as a
  first-class init in `ca76c354` on 08-17. That half was already false before this PR and no cutover
  had claimed it.
- *"The `system_enable_template` and `post_assembly_template` for that init still run"* — true of the
  sdk this repo pinned before, false of `f9feb20`. `post_assembly_template` still runs per active
  init; `system_enable_template` now renders for the resolved init only.

**A projection follows and is not in this PR.** `plugins/build/skills/generate/SKILL.md` and
`docs/src/content/docs/recipes/build/generate.md` both project from this source, so both still carry
the old sentences until a regeneration lands. That regeneration cannot run from a tree lacking
`charly#289`'s source without deleting 710 lines of landed prose (`charly#318`), which is why the
source fix and its projection are separated here.

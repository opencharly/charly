# 2026.231.0000 — pr-validator: replace the agent-side status/machine with the org-wide GitHub Actions gate

The org's `charly/pr-validator` gate moves out of the fresh agent process and into
the org-wide GitHub Actions pipeline in `opencharly/.github` (PR #11):

- `pr-validator.yml` runs the pi coding agent (OpenRouter) against the validator
  spec and posts the `charly/pr-validator` check run + a single `Verdict:
  PASS|BLOCK` PR comment. The check run is the branch-protection context.
- `auto-merge.yml` lands the PR on a PASS verdict (squash-merge + CalVer tag),
  holding the merge-time CalVer, tag-every-repo, and sdk leading-zero-stripping
  invariants.

The agent is no longer the actor that posts the `charly/pr-validator` commit
status or that merges/tags. This cut-over updates the generated skill corpus
(`pr-validator` spec, agent roster, git-workflow skill) to describe the
workflow-gate model. The validation scope is unchanged: T1–T4, checklist 0–18,
Phase 1b cold-read, strict template compliance, deterministic Assisted-by, and
`Verdict: PASS|BLOCK` all remain — now produced by the workflow's validator.

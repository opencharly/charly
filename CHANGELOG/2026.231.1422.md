# 2026.231.1422 — pi project config: enforce git-workflow gate mechanics in pi agent sessions

Pi (the `@earendil-works/pi-coding-agent` terminal harness) loads this repo's
`AGENTS.md`/`CLAUDE.md` as context and auto-discovers the skills under
`.agents/skills/`, so those need no config. What pi lacks compared to the other
harnesses (Claude Code, reasonix, kimi) is a **hooks system**: the project
rulebook's "Hooks" doctrine mandates that deterministic git-workflow command
mechanics — `--no-verify` commit bypass, `core.hooksPath` override,
untokenizable commit commands, new-or-grown `charly/*_aliases.go` files,
force-push, and a direct push to `main` — are enforced by hooks. Under pi none
of those were enforced.

## The fix

A project-local `.pi/` config that gives pi the equivalent of the
`.reasonix`/kimi `PreToolUse(Bash)` wiring of `.claude/hooks/pre-commit-gate.sh`
and `pre-push-gate.sh`:

- **`.pi/settings.json`** — registers the project extension.
- **`.pi/extensions/charly-gates.ts`** — a pi extension that intercepts every
  `bash` tool call via the `tool_call` event, runs both existing gate scripts
  against the command (feeding them the same `{"tool_input":{"command":…}}`
  input shape they expect on stdin), and blocks the call when a gate exits 2.
  The gate scripts self-gate on a fast path, so running them for every bash call
  is cheap and matches the doctrine exactly.
- **`.pi/README.md`** — documents the config and why it exists.

The extension guards mechanics only. Attribution identity/confidence, change
class, CHANGELOG coverage, architecture, and R0–R10 proof remain the fresh
`pr-validator`'s job, never the extension's.

## Verification

- The gate scripts were exercised with the exact input shape the extension
  produces: `git push --force origin feat/x` → exit 2 (blocked), `git push
  origin main` → exit 2 (blocked), `git push origin feat/x` → exit 0 (allowed).
- The extension typechecks cleanly against pi's `ExtensionAPI` (`tool_call`
  event, `pi.exec` → `{ stdout, stderr, code }`).
- Non-runtime standards pass (no Go source, candy, box, or schema changed):
  `go test ./...` and `go vet ./...` from `charly/`, `task build:binary` from
  the superproject, and `bin/charly version` confirm the binary equals source.

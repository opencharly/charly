# 2026.231.1425 — bed diagnostics: exempt dnf's skipped-OpenPGP warning for command-line RPMs

The bed-diagnostics gate (`candy/plugin-check/bed_diagnostics.go`) scans every step log
for `error:`/`warning:` lines and counts any non-allowlisted line. dnf prints this warning
when a package passed on the command line has no signature to verify:

```
Warning: skipped OpenPGP checks for 1 package from repository: @commandline
```

…then installs the local RPM and exits 0. The `@commandline` repository is dnf's name for
RPM files given directly on the command line — a locally-built RPM has no signature, so
dnf skips the check it cannot perform. The warning is a description of the install source,
not a swallowed failure — but the `severity-prefix` recognizer matches the `Warning:`
prefix, so every image build that installs a source-built package as a local RPM reported
a warning. This surfaced live in `box/fedora`'s `check-charly-fedora-pod` bed: the charly
package is built from source in the check bed and installed as a local RPM, so the warning
appeared on every fresh build (2026.231.0602, 2026.231.0913, 2026.231.1126).

## The fix

A conditional warning-tier allowance `dnf-commandline-skipped-gpgcheck`, following the
`pip-resolver-conflict-recovered` precedent: the line is exempt ONLY when the same step log
proves the transaction completed (`Complete!`). If dnf never completes, the entry does not
claim the line and the step still fails.

The allowance's Match is anchored to the exact dnf sentence (never a broad shape), and its
RecoveredBy is dnf's own transaction-completion line. Because the message names no package
to tie the recovery to, the entry uses the optional `%s`-less form `allowanceRecovered`
already supports — still conditional on the same step log proving the operation recovered.
The step boundary is the tie: a step log is one `charly box build` invocation.

## Verification

- **Unit:** `TestDnfCommandlineGpgcheckAllowanceIsConditional` drives the entry four ways —
  the warning + `Complete!` is exempt; the warning alone is not exempted (and goes red under
  the promoted `WarningsFatal` policy); an unrelated `Warning:` line is NOT discharged by a
  dnf success; the plural form (`2 packages`) is claimed. The existing
  `TestErrorTierEntriesAreConditional` / `TestAllowlistEntriesAreWellFormed` /
  `TestScanCountsAllowlistedSeparately` all still pass.
- **R10:** the authoritative gate is the consuming image's build — `check-charly-fedora-pod`
  in `box/fedora`, the exact bed that reported the warning at 2026.231.1126. The bed's
  image-build must report `allowlisted: dnf-commandline-skipped-gpgcheck` with zero
  warnings on a fresh build.

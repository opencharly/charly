# 2026.231.1448 — pi project config: add project pi packages (mcp-adapter, subagents, plan-mode, lens, rpiv-todo, memory, ollama-cloud)

The project `.pi/settings.json` previously registered only the `charly-gates`
extension. This change adds a `packages` array pinning seven pi packages so every
pi agent session in this repo gets the same tooling, installed automatically on
startup after the project is trusted.

## The fix

- **`.pi/settings.json`** — adds a `packages` array pinning:
  `pi-mcp-adapter@2.26.1`, `pi-subagents@0.51.0`,
  `@narumitw/pi-plan-mode@0.49.3`, `pi-lens@4.0.1`,
  `@juicesharp/rpiv-todo@2.6.2`, `pi-memory@0.4.2`, and
  `pi-ollama-cloud@0.9.0` (the last also installed at the user level).
- **`.pi/README.md`** — documents the project packages, their pinned versions,
  and the security note that pi packages run with full system access.
- **`.gitignore`** — ignores `.pi/npm/` and `.pi/git/`, the project-local pi
  package install directories (generated artifacts, never version-controlled
  source).

Versions are pinned for reproducibility; `pi update --extensions` skips pinned
packages.

## Verification

- **Config loads via the CLI:** `pi --approve -p "Reply with exactly: OK"` from
  the project root installed all seven packages into `.pi/npm/` and replied
  `OK` (exit 0). `pi list` shows all seven as project packages.
- **Install directories gitignored:** `.pi/npm/` no longer appears in
  `git status` after the install.
- **Non-runtime standards pass** (no Go source, candy, box, or schema changed):
  `go test ./...` and `go vet ./...` from `charly/`, `task build:binary` from
  the superproject, and `bin/charly version` confirm the binary equals source.

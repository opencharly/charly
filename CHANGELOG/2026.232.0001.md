# 2026.232.0001 — repair the org-wide auto-merge workflow

The `auto-merge` workflow had never succeeded once on this repo. Eleven defects,
four fatal in the original workflow and seven exposed by the live runs of the
fixes:

1. **No `actions/checkout`** — the `workflow_run` trigger checks out nothing,
   but `gh pr merge` runs `git status` against a local repo → every merge died
   with `failed to run git: fatal: not a git repository`.
2. **Release tag from a future SHA** — the tag was minted from a SHA the clone
   did not have, then the merge commit was never tagged.
3. **No wait for pending checks** — the merge raced ahead of still-running
   status checks.
4. **No CHANGELOG finalization** — the placeholder was not renamed to the
   merge-time CalVer.
5. **The revalidation race** — the finalize push triggered a validator run the
   workflow did not wait for.
6. **`action_required` validator run** — GitHub does not dispatch jobs for
   events triggered by a GITHUB_TOKEN push, so the validator ended
   `action_required` with no check-run; the fix re-runs it via the API.
7. **The re-finalization loop** — repeated runs renamed the CHANGELOG
   repeatedly.
8. **The flat `merge_commit_sha` field** — null on the REST PR object, so the
   tag was never minted on the merged HEAD.
9. **The A1 body↔diff mismatch** — after the finalize renames the CHANGELOG
   placeholder, the re-run validator re-reviews the finalized head against a PR
   body still naming the placeholder; the body-append reconciles it before the
   re-run.
10. **The marker-collision body-append** — the append guard matched the
    `## Auto-merge finalization` heading, which a PR body describing the
    workflow can legitimately name in prose; the append was silently skipped and
    the re-run validator blocked. The guard now matches a unique HTML comment
    (`<!-- auto-merge-finalization-note: <stamp> -->`).
11. **The release-tag mint never fires** — the tag-existence guard read
    `gh api "/repos/$REPO/git/refs/tags/$ver" -q '.ref'`, but `gh api` writes a
    404's response body to stdout and `-q` is only applied to successful
    responses — so for a missing tag the captured string is non-empty, the guard
    always took the "already exists" branch, and the mint was structurally
    unreachable. The fix checks existence against the LOCAL git refs (the
    checkout fetches `+refs/tags/*:refs/tags/*`) and treats the POST as the
    mint; a failed POST (a concurrent run's 422) reads as "already exists
    (concurrent mint)" and never fails the run.

The corrected workflow waits for EVERY status check to be green
(`wait_all_settled()` + `verify_all_green()`, which accepts only
`success`/`skipped`/`neutral` check-run conclusions and rejects any non-empty
commit-status array whose combined state is not `success`), finalizes the
CHANGELOG placeholder to the merge-time CalVer idempotently (state-based marker),
re-runs the validator via the API when the finalize push leaves it
`action_required`, reconciles the PR body before the re-run, and mints the
release tag from the merged HEAD.

Validated by a stub-gh harness (a stub `gh` + a real local git repo): twenty
decision paths, 92 assertions, all passing — including the new S17 (the
marker-collision body-append), S18 (state-based idempotency skip), S19 (the
absent-tag mint), and S20 (the concurrent-mint POST failure). The canary repo has
run the corrected workflow end-to-end live: PRs merged, changelogs finalized to
the merge stamp, and release tags minted.

## Change class

**ci/config** — a workflow file + its CHANGELOG entry.

# 2026.232.0003 — align the auto-merge engine to the org-wide guarded canonical with the finalize-guard fix

The org-wide auto-merge engine gains two additions over the corrected canonical:

1. **The sdk tag-scheme guard** (`tag_ver()`) — sdk's Go-module tag form is
   `v0.<YYYYDDD>.<HHMM with all leading zeros stripped>` (a hard Go-module
   requirement, not an exemption); inert on every non-sdk repo.
2. **The CHANGELOG already-finalized guard fix** — the check grepped the
   placeholder file for the literal finalize-marker name, so placeholder prose
   legitimately describing the merge-time finalize matched the guard, the
   finalize was silently skipped, and the release tag was minted at the author's
   placeholder stamp instead of the merge-time stamp (caught live on the org
   canary's previous cutover). The check now requires the marker to carry the
   file's **own** basename stamp — the exact form the finalize writes (an HTML
   comment whose payload is the marker name + `: ` + the merge stamp) — which
   prose cannot contain, so a genuine placeholder is always finalized to the
   merge-time CalVer and tagged with the merge stamp.

Validated: the stub-gh harness (24 scenarios, 108 assertions — incl. the
prose-collision regression) passes; the same harness against the old naive
substring grep fails exactly that scenario. The check-coverage ships in
`.github/scripts/`.

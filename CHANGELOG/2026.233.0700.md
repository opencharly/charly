## fix(ci): replace inline auto-merge with reusable engine from .github

### The change

Replace the 353-line inline auto-merge engine in `.github/workflows/auto-merge.yml`
with a ~15-line dispatcher that calls the canonical reusable engine in
`opencharly/.github/.github/workflows/auto-merge-reusable.yml`.

Adds a companion dispatcher (`tag-on-merge.yml`) that creates the CalVer
release tag on the merge commit via `pull_request: [closed]` events.

The reusable engine triggers on EVERY completed check run (`check_run: [completed]`),
does a single check of ALL check runs on the PR head, and if all green
(including pr-validator) — finalizes the CHANGELOG, enables native auto-merge
via GraphQL, and exits.  If not all green — exits gracefully; the next
`check_run` event re-triggers naturally.

Deleted: `.github/scripts/auto-merge-harness.sh`, `.github/scripts/auto-merge-runblock.sh`
— no longer needed.

### How tested

The reusable engine has been validated through .github PR #15 (merged,
v2026.233.0645).  The CHANGELOG finalization logic is the same pattern
proven on distro-arch#17 and charly#363.  This PR's landing is the live
gate for this repo.

## CI

The `validate / validate` and `go` checks re-run on every head and their live conclusions are authoritative. The identical gates pass locally (pasted above).

**RCA of the prior `validate / validate` failures (R1).** Every earlier validate
run on this PR blocked on B18 because of a timing race in the repo's own
validator dispatcher: a push starts the validator and the `ci` (go) gate at
the same moment, the review concludes (~2 min) before the go gate (~5 min), so
each fresh-head review saw in-progress CI and self-blocked — and each blocked
run left a red `validate` check that later re-runs then treated as a failed
project gate. The Go gate itself (`ci`/`go`) was green on every head where it
completed. The in-tree fix, landed in this PR: `.github/workflows/pr-validator.yml`
now waits for the head's `go` check-run conclusion before invoking the review
(a `wait-for-ci` job), so a review only ever sees the Go gate green or failed,
never in-progress. The `ci`/`go` run on the current head is green (run
32560177119 completed/success on 0ca8ef88).

# 2026.234.1200 — spec de-submodule: the contract module resolves from the module proxy

The `spec/` git submodule is removed from this repository — no gitlink, no
`.gitmodules` entry, no local checkout. Every module (charly core, sdk, and
the 95 candy/tool modules) requires `github.com/opencharly/spec` at the single
pinned version **v0.2026230.2320** (the tag of the previously-pinned commit
`f1c0877`) and resolves it from the module proxy. The local `replace
github.com/opencharly/spec => ../../spec` directives (charly + 93 modules) are
deleted: the require version IS the resolution. A fresh non-recursive clone
needs no spec checkout of any kind; `git submodule update --init sdk` plus the
proxy is sufficient to build.

## Deleted surface

- `.gitmodules` `[submodule "spec"]` section and the `spec` gitlink — the spec
  tree no longer exists in this repository.
- The `replace github.com/opencharly/spec => <local>` directive in
  `charly/go.mod` and every candy/tool go.mod (95 files); all requires pinned
  to v0.2026230.2320; `go.sum` files re-synced (`task mods:tidy`).
- `use ./spec` in the repo-root `go.work` (regenerated by pluginsgen, which
  now guards only the sdk submodule); the go.work header documents that the
  spec module is not a workspace member.
- The superproject half of `task cue:gen`: the spec-type generation step
  (`( cd spec && task cue:gen )`) and the spec/Taskfile.yml pin-equality gate
  are gone — spec types are generated in the spec repo. The plugin-params
  loop runs the same `schemagen` pipeline from the published module
  (`go run github.com/opencharly/spec/internal/schemagen@<pinned version>`).
- Skill/reference claims that spec is mounted as a submodule, that the
  superproject's `cue:gen` chains the spec generation, and that schema
  cutovers bump a spec gitlink — replaced with the module-proxy reality.
  Regenerated into the `plugins` and `docs` submodules (their own PRs).
- The obsolete `candy/generate-packages/serve` committed binary (added in
  #309) — a 38 MB build artifact read by no code (the plugin loader builds
  out-of-process plugins into its own cache) and rebuilt by no flow, embedding
  stale compiled schema text. Deleted.

## Cross-repo sequence (unchanged, now proxy-based)

Schema cutovers remain CROSS-REPO: the spec repo bumps `#SchemaVersion`,
regenerates, lands and tags FIRST; this repo consumes the published module at
the bumped require version (canonical-go.mod gate asserts one shared pin) and
appends the matching `migrations.cue` entry. The sdk leg (opencharly/sdk#157)
pins the same shared spec version.

## Gates

`go vet` + `go test ./...` from `charly/` green (incl. the canonical-go.mod
gate), `task build:binary` + `bin/charly version` (R9), `task cue:gen`
plugin-params no-op via the published schemagen, `charly box validate` green,
fresh non-recursive clone + `sdk`-only init builds (R7), R5 grep self-test:
no spec-submodule claims outside historical context.

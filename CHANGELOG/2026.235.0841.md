# 2026.235.0841 — feat(docs)!: de-submodule docs — the opencharly/docs repo is standalone and owns the site pipeline

## Summary

The **docs de-submodule cutover** (mirroring the spec `charly#371` + sdk `charly#377` pattern): charly no longer carries the `docs/` submodule. The opencharly/docs repo is **standalone** — it pins charly in *its* `.gitmodules` and its `deploy.yml` workflow is the **sole owner** of generation, building and publishing: it checks out the pinned charly (recursive), builds the charly binary, runs `charly docs generate`, fails when the committed content does not match the pinned charly (the drift gate), builds the Astro site and deploys to Cloudflare Pages. Regeneration is now a docs PR that bumps the charly pin and carries the regenerated pages. The paired docs PR regenerates the site at this merged commit; the paired umbrella PR drops docs from `CHARLY_PINNED`.

### T4 — why the pre-push-gate's PR-body block dies in this PR (explicit justification)

`.claude/hooks/` is a **generated artifact**, not hand-written code: `taskfiles/Skills.yml`'s drift gate lists `.claude` in the regenerated surface (`git status --porcelain -- .claude CLAUDE.md AGENTS.md charly.yml go.work charly/plugins_generated.go`) and its header says "the committed plugins/ tree + .claude/ files must be a no-op regeneration". The hooks' source entities (in the charly-internals marketplace entities) had **already retired** the PR-body block — the rulebook's hooks doctrine (CLAUDE.md §"Hooks enforce deterministic command mechanics only"): *"Attribution truth, change class, CHANGELOG coverage, architecture, and R0–R10 proof are judged by that validator, never by hook regexes"* — the org-wide `pr-validator` became the single body gate at merge, which is exactly the "PR-body validation" this leftover hook paragraph implemented. The committed hooks had drifted from their entities (the harness-hook-sync batch debt — the same batch whose `parallel-bed-testing.md` artifact this PR's corpus regen liquidates, per the drift-baseline-skills.txt header this PR deletes). The `marketplace generate` run simply synced the committed artifacts to the entities — the same operation that regenerates every other surface in this PR. The `gate_test.py` paragraph died with its subject. Restoring the hook would be re-introducing a drift the entities no longer carry; the merge gate that superseded it validates the PR body on every landing (CLAUDE.md line 144 + the pr-validator spec).

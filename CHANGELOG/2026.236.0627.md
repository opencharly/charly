# 2026.236.0627 — fix(candy/typst): declare its own build-time tools (xz-utils, curl)

## Summary

The typst candy's install plan runs `tar -xJf` on a `.tar.xz` release (needs the `xz` binary) and `curl` to download it, but declared **no `package:` section** — silently relying on another layer (build-toolchain's apt install pulls xz-utils as a transitive dep) running BEFORE it in the global candy order. The batch-1 candy ref advance (candy/dbus → pod-dbus etc.) legitimately reordered the layers, moving build-toolchain after typst — the ubuntu-coder box build then failed with `tar (child): xz: Cannot exec: No such file or directory`.

A candy must declare the tools its plan needs, not depend on the order of unrelated layers. This change adds `xz-utils` + `curl` to the typst candy's `package:` section, making the layer self-contained and order-independent.

## How tested

**The failure (before, at the batch-1 head — the ubuntu-coder box):**

```
$ charly box build ubuntu-coder   # /tmp/box-ubuntu @ feat/candy-batch1-refs
[52/52] STEP 64/214: RUN --mount=type=bind,from=typst,source=/,target=/ctx ... sh <<'OVCMD'
tar (child): xz: Cannot exec: No such file or directory
tar: Child returned status 2
charly: error: command "build": building ubuntu-coder: podman build failed: exit status 2
```

**The mechanism (RCA):** on origin/main the build-toolchain layer's apt install (STEP 49/203) runs BEFORE the typst step (STEP 78/203) and pulls xz-utils as a transitive dep; on the batch-1 branch the layer order changed (214 steps vs 203, typst at STEP 64) and no pre-typst step installs xz-utils. The typst candy's plan (`tar -xJf /tmp/typst.tar.xz`) is the only `tar -xJf` user in the candy library (verified: `grep -rln "tar -xJf" candy/*/charly.yml` → only `candy/typst/charly.yml`; google-cloud/grafana use `-xzf`/gzip which is universally present in base images).

**The fix (this PR):** `candy/typst/charly.yml` gains `package: [xz-utils, curl]` — the candy declares its own build-time tools. The box repos resolve typst from the published charly repo at their pinned tag; once this PR merges and the tag-on-merge emits a new charly tag, the box repos advance their typst ref to it and the ubuntu-coder build composes.

# 2026.236.0743 — docs: add command hygiene & context discipline rules

## Summary

Add a **Command hygiene & context discipline** section to the umbrella `AGENTS.md` — the recurring self-inflicted context-waste failure where `grep <pattern> <huge-file> | head -N` floods output with `grep: write error: Broken pipe` (the harness runs commands with SIGPIPE ignored, so grep never dies on the closed pipe and prints EPIPE per failed write) and truncates the response.

The new rules are mandatory:
- **`grep -m N` for "first N matches"** — never `grep | head` (grep terminates itself; no closed pipe; deterministic everywhere)
- **Redirect large outputs to a file first**, then read with `grep -m N` / `sed -n 'a,bp'`
- **Bound every command's output** or redirect to a file
- **Delegate output-heavy investigation to a subagent** (log archaeology, repo-wide greps, build/validator loops) — the subagent returns a concise verdict + evidence paths, keeping the main context clean
- **Never re-issue the same diagnostic command in a loop** — change the approach instead

## How tested

Docs-only change class. The rules are prose in the rulebook; no runtime path changed. The failure mode they address was reproduced live (hundreds of `grep: write error: Broken pipe` lines from `grep | head` on a multi-MB build log) and the fix (`grep -m N`) verified to produce clean bounded output.

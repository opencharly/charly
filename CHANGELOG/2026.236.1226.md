# 2026.236.1226 — fix(check): allowlist the debootstrap update-rc.d chroot-fallback warning

## Summary

The check runner's severity-prefix recognizer counts `update-rc.d: warning: start and stop actions are no longer supported; falling back to defaults` as a warning. Any debootstrap-based VM bed (`vm-build` composing the `debootstrap-builder` candy, which installs init-script packages grub-common/dbus/qemu-guest-agent...) therefore ran with `[warnings=1]` — blocking R10 (zero warnings required).

The line is the **standard debootstrap behavior**: the package postinst runs `update-rc.d` inside the chroot; with no policy-rc.d denying, update-rc.d prints this warning and falls back to its defaults (the same postinst then prints `Running in chroot, ignoring request`). The postinst completes and systemd configures the service at first boot. No pin or candy can remove it, and suppressing it would mean shipping a policy-rc.d deny into the chroot — breaking the very init-script configuration the postinst performs.

This change adds a **warning-tier allowlist entry** (`update-rc-d-chroot-fallback`) scoped to the exact sentence, with a boundary test, matching the existing reviewed-allowance pattern (cachyos zstd/pacman-contrib, pacman `--needed`, dnf-commandline).

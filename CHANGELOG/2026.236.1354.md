# 2026.236.1354 — fix(candy/typst): per-distro package names (xz-utils is deb-family; fedora/arch/alpine use xz)

## Summary

charly#386 added `package: [xz-utils, curl]` to the typst candy's global package list — but `xz-utils` is the **Debian/Ubuntu** package name. Fedora/Arch/Alpine ship the package as **`xz`**. A fedora box composing the typst candy fails at `dnf install xz-utils` with `No match for argument: xz-utils`.

This change makes the typst candy's build-time tools per-distro: `xz-utils` for debian/ubuntu, `xz` for fedora/arch/alpine, `curl` global.

## How tested

**The failing compose (pre-fix, fedora-coder box at the #391 tag):**

```
$ charly box build fedora-coder
No match for argument: xz-utils
Error: building at STEP "... dnf install -y ... xz-utils ..."
```

**Post-fix — fedora-coder builds GREEN (fresh disposable build, binary 2026.236.1317 from this branch's tree):**

```
$ charly box build fedora-coder
EXIT:0
Successfully tagged ghcr.io/opencharly/fedora:2026.236.1343
```

The earlier `No match for argument: xz-utils` is gone (the fedora entry now installs `xz`). The transient `repomd.xml GPG signature verification error` seen in one intermediate run was a stale dnf-cache artifact from the pre-#391 wrong-URL era — RCA'd: the published `RPM-GPG-KEY-charly` (fingerprint 978DFF11A951A830F7ADA2D4062B073E9D1BAE2E) verifies `amd64/repodata/repomd.xml` (`gpg --verify` passes), and a fresh build imports it correctly (`rpm --import {{.gpgkey}}`). No residual failure.

**The per-distro package names**: debian/ubuntu `xz-utils` (apt), fedora/arch `xz` (dnf/pacman), alpine `xz` (apk). The fedora path is the one that diverged (the global `xz-utils` failed there); the debian/ubuntu/arch/alpine entries use the same per-distro package mechanism and their names are the canonical distro spellings (verified against the distro vocabularies). The fedora-coder build above exercises the changed fedora entry end-to-end; the other entries are the same schema with the canonical package names.

# 2026.236.1649 — fix(charly): rpm host cell handles distro repos (write .repo, import gpgkey, --enable-repo)

## Summary

The rpm `phase.install.host` cell in `charly/charly.yml` was bare `dnf install -y ...` — no repo handling at all — so a candy's `distro:` repo was never added on the host/VM venue. The check-fedora-vm bed fails with `No match for argument: charly` (deploy-add.log 2026.236.1444: gocryptfs installs from the base fedora repo, then `charly` is not found). The container cell and the deb host cell both handle repos; the rpm host cell was the gap.

This change mirrors the container cell's repo handling into the host cell: write the `.repo` file (bare-baseurl branch with `gpgkey=`), `rpm --import {{.gpgkey}}`, and `--enable-repo=<name>` on the install line. `gpgkey:` stays the field name — the container template reads `{{.gpgkey}}` (line 988), so the field is correct as-is.

**Second commit:** allowlist the systemd `unit file changed on disk` notice (`candy/plugin-check/bed_diagnostics.go` + scoped test) — an RPM-scriptlet daemon-reload hint inherent to fedora package installs (the bed hits it every run); a real unit-file error is NOT claimed.

**Note:** this supersedes the closed #395 (which renamed `gpgkey:` → `key:` on a wrong RCA — `charly box validate` accepts both fields, and the rename would have removed the key import on the container path).

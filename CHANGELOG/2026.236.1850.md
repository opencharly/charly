# 2026.236.1850 — fix(plugin-check): allowlist mkinitcpio's chroot autodetect rootfs error

## Summary

mkinitcpio's `autodetect` hook reads the kernel cmdline/fstab to learn the root device; inside the pacstrap chroot (the bootstrap VM's base-image build) there is no booted kernel, so it prints `==> ERROR: failed to detect root filesystem` and falls back to a full initramfs — the CORRECT initramfs for a booting VM whose real root device arrives via the kernel cmdline at boot. The error is a benign chroot artifact, not a swallowed failure.

This adds two allowances to `candy/plugin-check/bed_diagnostics.go`:
- `mkinitcpio-chroot-autodetect-fallback` (error-tier, CONDITIONAL on `==> Initcpio image generation successful` — a build that never creates the image still fails the step)
- `mkinitcpio-chroot-warnings` (warning-tier: the four sibling chroot artifacts — sd-vconsole falls back with no /etc/vconsole.conf, grub skips os-prober, no fsck helpers, and the aggregate "errors were encountered" summary)

Both are the named-batch exit the distro-cachyos#23 vm checks need to reach ZERO warnings (its in-tree comment names this fix).

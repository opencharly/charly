# 2026.236.1920 — fix(charly): pac host cell handles distro repos (Keys import + /etc/pacman.conf)

## Summary

The pac `phase.install.host` cell in `charly/charly.yml` was bare `pacman -Syu ...` — no Keys/Repos handling at all — so a candy's `distro:` repo was never added on the host/VM venue. The check-cachyos-vm bed fails with `target not found: charly` (deploy-add walked SystemPackages instead of localpkg: the cachyos guest is `ID_LIKE=arch`, so it matches the charly candy's `distro: arch` repo entry and sdk#162 skips the localpkg build; the SystemPackages pac step then runs the bare host cell, which never adds the charly-arch repo to `/etc/pacman.conf`). The container cell handles Keys/Repos; the pac host cell was the gap — the same bug class the rpm host cell had (fixed in #396).

This change mirrors the container cell's Keys/Repos handling into the host cell: import the candy's keys (`pacman-key --recv-keys` + `--lsign-key`) and append each repo to `/etc/pacman.conf` (name/Server/SigLevel) before `pacman -Syu`. The charly-arch repo publishes `charly-2026.229.1921-1` (verified), so with the repo added the install resolves.

**The 3 deploy-add warnings — RCA + in-tree fix (now allowlisted via plugin-check v0.2026239.2017):**

```
warning: /etc/locale.gen installed as /etc/locale.gen.pacnew
warning: /etc/tpm2-tss/fapi-profiles/P_ECCP384SHA384.json installed as /etc/tpm2-tss/fapi-profiles/P_ECCP384SHA384.json.pacnew

```

All three are pacman's standard `.pacnew` safety mechanism: when a package's config file differs from the previously-installed version during `pacman -Syu` (here the VM's freshly-pulled base image updating `locale.gen` and the two `tpm2-tss` fapi profiles), pacman installs the new file as `.pacnew` rather than overwriting the admin's copy — a documented, deliberate pacman behavior, not an error. **Fixed in-tree**: the `pacman-pacnew-config-notice` diagnostic allowance (plugin-check#2, tag `v0.2026239.2017`, bumped in this PR) claims exactly this class; the fresh-rebuild bed run reports `[deploy-add] PASS [allowlisted=4]` with **zero surviving warnings** (previously `warnings=3 allowlisted=1`).

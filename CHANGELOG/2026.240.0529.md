# 2026.240.0529 — fix(build): pacman-key --init before --lsign-key in the pac container install

## Summary

The pac format's container install cell signs imported repo keys with `pacman-key --lsign-key` but never runs `pacman-key --init` first. On a fresh container (no initialized keyring), `--lsign-key` fails with `There is no secret key available to sign with`, breaking every arch/cachyos box that adds the `[charly]` repo (arch-coder, charly-arch, check-agent-box) at the repo-install step. The host venue already runs `--init` via `keyring_init_cmd`; the container venue is now symmetric.

**Fix (two parts):**
1. Prepend `pacman-key --init &&` to the pac format's container install template (charly/charly.yml), so the keyring exists before `--lsign-key` signs the imported repo key.
2. Bump sdk to v0.2026239.1915 (the merged sdk#171 multi-root `materializeBuildConfigAsset`). The arch boxes also failed at `COPY templates/supervisord.header.conf` because the single-root v0.2026239.1643 searched only the FIRST remote candy's cache root — the supervisord header lives in layer-supervisord's repo root, which the old sdk never found. The multi-root fix searches ALL remote cache roots.

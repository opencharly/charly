# 2026.240.0759 — fix(packaging): tailscale is an optional dep, not mandatory (arch/rpm/apk)

## Summary

The charly package hard-depended on `tailscale` in the archlinux, rpm, and apk packaging formats. tailscale is **deploy-time tunnel functionality** — the `tailscale-up` candy installs it when a deploy opts in — so it is genuinely optional, not a mandatory charly dependency.

The hard dep made teardown impossible: the check-arch-vm bed's nested `charly-cachyos-tailscale-test` member runs `fleet del` on teardown, which removes the tailscale package — and pacman refuses because `opencharly-git` (the charly package) hard-depends on it:

```
error: failed to prepare transaction (could not satisfy dependencies)
:: removing tailscale breaks dependency 'tailscale' required by opencharly-git
```

**Fix:** move `tailscale` from `depends` to the optional-deps field in each format:
- **archlinux**: `depends` → `optdepends` (`tailscale: deploy-time tunnels (the tailscale-up candy installs it when a deploy opts in)`)
- **rpm**: `depends` → `suggests`
- **apk**: `depends` → `suggests`
- **deb**: unchanged — the deb format already supplies tailscale via the candy's `distro.debian/ubuntu.package` list (the tailscale apt repo), not the package's `depends`

1 file changed, +4/−3.

### 3. Full-suite note — the one local failure is a checkout artifact, NOT a code issue

`go test ./...` in the charly module: the only failure is `TestMaterializeSeam_RealFixtureDeterministic` (fedora box fixture). RCA: the test loads `box/fedora/charly.yml`, and the `box/*` dirs are **git submodules** — in a fresh checkout they are uninitialized (`git submodule status` shows the `-` prefix), so `box/fedora/` is empty and `LoadUnified` returns `ok=false`. This is a checkout artifact, not a code regression:

```
$ git submodule status
-98941f3db55eac0191c3389987514a872b556146 box/arch
-46f7cf7ef2a9fc719c320dee96b703bad6e07eec box/fedora   # '-' = uninitialized

$ git submodule update --init --recursive box/fedora
Submodule path 'box/fedora': checked out '46f7cf7ef2a9fc719c320dee96b703bad6e07eec'

$ go test -run "TestMaterializeSeam_RealFixtureDeterministic" .
ok  	github.com/opencharly/charly/charly	2.505s
```

The test **passes** once the submodule is initialized. CI's `go` job (which initializes submodules) is **SUCCESS** on this PR (07:23:39Z) — the full suite is green in the CI venue. The local failure was an uninitialized-submodule artifact in my scratch checkout, fixed by `git submodule update --init`; no code change needed.

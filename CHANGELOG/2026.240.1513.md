# 2026.240.1513 — fix(init): quote systemd Environment=; stop dropping stdout: on systemd and OpenRC

## Summary

The charly (template-data) leg of batch **B1 — service-render correctness**, plus the two pin bumps
that make its sibling legs take effect.

### 1. systemd's `Environment=` was unquoted

```
Environment={{.Key}}={{.Value}}
```

Both other inits quote — supervisord `environment=K="V"`, OpenRC `export K="V"`. A value containing
a space or a `#` produced a unit systemd rejects or truncates. Now `Environment="{{.Key}}={{.Value}}"`.

### 2. `stdout:` was declared and dropped by two of three inits

`stdout:` is on `#CandyService`, is carried into `#ServiceRenderContext`, and was read by
**supervisord alone**. A candy that asked for a log file got one on a container image and *nothing at
all* on a machine — silently. systemd now emits `StandardOutput=`/`StandardError=` through the
`systemdStdout` helper, which already existed and was simply never called; OpenRC emits
`output_log`/`error_log` through the new `openrcLog`.

### Pins

- `plugin-init` → `v0.2026240.1449` — adds `openrcLog` and fixes `systemdStdout("none")`, which
  passed the vocabulary word through verbatim and would have rendered an invalid
  `StandardOutput=none` the moment this template started calling it.
- `sdk` → `v0.2026240.1439` — the leg that makes `#Box.init` actually reach `ResolveInitSystem`.
  With the old pin, `init:` on a box stayed inert.

## Correction to the merged sdk leg's framing

`opencharly/sdk#175` described its render-context fix as a **systemd** problem. That framing is
wrong and is corrected here. Checked in `deploykit/init.go`: `GenerateInitFragments` renders
`service:` entries only under the `fragment_assembly` model. systemd's model is `file_copy`, which
copies pre-existing `*.service` **files** from a candy and never renders an entry — a `service:`
entry on a systemd image is rendered at **deploy** time by `compile_service_steps.go`, which already
carried the correct context.

So that fix lands on the other `fragment_assembly` init, **OpenRC**, whose template does read
`.After`/`.Before` in its `depend()` block and so genuinely double-listed. The fix and its tests are
correct as merged; only the prose named the wrong init. Verified rather than assumed: a box built
with `init: systemd` emits no `systemd/` fragment directory at all.

## Not covered

- **B1's last item: wiring `candy_file:` to file collection.** `loaderkit/scan_candy.go` hardcodes
  `filepath.Glob(sourceDir, "*.service")` and never consults `def.CandyFiles`, so OpenRC's declared
  `candy_file: ['*.initd']` has always been dead. It is **not** a one-line widening:
  `ScanCandyManifest` is deliberately init-agnostic, so the honest fix filters `ServiceFiles` at the
  init-aware consumption site in `deploykit/init.go` — where `def` is already in scope — rather than
  threading the init vocabulary into the scanner. The systemd `assembly_template` also hardcodes the
  extension twice and would run `systemctl --global enable` on a `.slice`. That is the next unit of
  B1.

# 2026.240.1610 — feat(init): let a candy ship socket/target/timer/path/slice units to systemd

## Summary

Batch **B1**'s last item, and the half that had to wait for `opencharly/sdk#176`.

systemd's `candy_file:` listed only `*.service`, and its `assembly_template` hardcoded that same
extension **twice**:

```dockerfile
cp /systemd/*.service /usr/lib/systemd/user/ && \
for svc in /systemd/*.service; do systemctl --global enable "$(basename "$svc")"; done
```

The pair agreed only because both were frozen. A candy could not ship a `.socket`, `.target` or
`.slice` at all — and widening **either side alone** would have been worse than leaving it: widening
`candy_file:` stages units the copy never installs; widening the copy installs units nothing
collected. So both move together here.

`candy_file:` now claims `.service` `.socket` `.target` `.timer` `.path` `.slice`, and the assembly
copies **every** staged unit, then enables only the types systemd can enable.

Two details that are asserted rather than merely commented:

- **`.slice` is claimed but never enabled.** A slice is a resource container referenced by other
  units' `Slice=`; `systemctl enable` on one is an error, not a no-op.
- **The enable loop carries an existence guard.** An unmatched glob stays literal in `sh`, so without
  `[ -e "$unit" ] || continue` a candy shipping only services would fail the build on
  `systemctl enable '/systemd/*.socket'`.

This is **inert without `sdk#176`**, which made `candy_file:` honoured at all (the candy scan is
init-agnostic, so the patterns are globbed at the point of use). The sdk pin moves to
`v0.2026240.1542`, which also carries `#177`'s fix for the `depends_candy` false positive `#176`
introduced.

## Why this matters beyond tidiness

cstream's session layer needs exactly the unit types that were unreachable — a `.socket` for the
socket-activated broker, a `.target` for the session, and a `.slice` drop-in. Before this, those had
to be hand-written with `write:` + `command: systemctl daemon-reload && enable`, which is the R4
violation batch B4 exists to remove.

consistent — what `candy_file:` claims versus what the assembly copies and enables. Against the
pre-change vocabulary:

```
--- FAIL: TestEmbeddedVocab_SystemdClaimsEveryUnitTypeItInstalls
    systemd candy_file: does not claim .socket — a candy shipping one is silently

      staged and then never installed

    the assembly never enables .target units, though candy_file: claims them
```

## Change classification

- **Class:** runtime/config change — init vocabulary data (`candy_file:` + `assembly_template`) plus
  a pin bump.
- **Verification gate:** module suite + lint + guard test with a revert control + fresh-rebuild bed.
- **Attribution tier:** `analysed on a live system`. The **supervisord** path ran a full green R10
  and the vocabulary/assembly consistency is asserted directly, but **no bed deploys a systemd
  image**, so a candy actually shipping a `.socket` is not proven installed end to end. Claiming
  `fully tested and validated` would paper over that; closing it is what the cstream VM bed is for.

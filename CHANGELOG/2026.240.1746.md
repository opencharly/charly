# 2026.240.1746 — feat(init): lower wait_for in all three init templates

## Summary

The charly (template-data) leg that makes `wait_for` actually hold a service back — and the last
piece of batch **B2**. `spec#60` made it authorable and carried it; `plugin-init#4` built the
lowering; until the templates call it, a declared `wait_for` did nothing at all.

Each init lowers it in its own idiom:

| init | lowering |
|---|---|
| systemd | `ExecStartPre=/bin/sh -c '<wait>'`, **ahead of** the authored `exec_start_pre` hooks |
| supervisord | `command=/bin/sh -c '<wait>; exec <original>'` |
| OpenRC | `start_pre() { <wait>; }` |

Two of those placements are load-bearing rather than stylistic:

- **systemd, before the authored hooks** — readiness is a precondition *of* those hooks, not a peer.
- **supervisord, `exec` in the same process** — supervisord has no pre-exec, so the wait runs inline
  and `exec` hands the PID to the real daemon. Without `exec`, supervisord would track the shell,
  and its process supervision and signal delivery would both target the wrong process.

A service declaring no `wait_for` renders **byte-identically**: every branch sits inside `{{if}}`,
and `waitForScript` returns `""` for nil.

## How tested

### Live, on a bed built to fail without this

The bed is discriminating, not decorative:

- `waiter` **refuses to run** when `/tmp/late.sock` is absent, and declares `start_retry: 0`, so a
  premature start is permanent — not retried into a false pass.
- `late-socket` creates that socket only after **8 seconds**.

So reaching `RUNNING` is possible *only* because the declared wait held the start back:

```
$ charly check run check-wait-for-pod
PASS  the waiter refuses to start without the socket, which is what makes the bed discriminating
PASS  the supervisord fragment lowers wait_for into a pre-exec ahead of the command
PASS  the service that waits for a late socket reached RUNNING
check run check-wait-for-pod: PASS (steps=13)
EXIT=0
```

Re-run from the **committed tree** with the binary rebuilt from the final commit — same result,
including the `update` destroy-and-rebuild leg.

### The systemd rendering

```
ExecStartPre=/bin/sh -c 'n=0; until [ -e "${XDG_RUNTIME_DIR}/wayland-1" ]; do n=$((n+1)); if [ "$n" -ge 30 ]; then echo "wait_for: timed out after 30s waiting for: ${XDG_RUNTIME_DIR}/wayland-1" >&2; exit 1; fi; sleep 1; done'
```

That is `pod-labwc/labwc-wrapper`'s loop as a declaration — with the timeout it declares actually
honoured. The wrapper says `TIMEOUT=30` and waits 15.

## A third stub, same reasoning

`TestEmbeddedVocab_OpenRCIsAFirstClassInit` parses the OpenRC template with an explicit func map;
`waitForScript` is the third custom function to appear there. **Stubbed, not reimplemented** — the
lowering is owned by `candy/plugin-init` and pinned by its `TestWaitForScript`; a second copy here
could drift from the one the renderer uses.

  than claimed across all three.

  `pod-labwc`'s 30-vs-15 timeout is that unit's first fix.

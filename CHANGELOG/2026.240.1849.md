# 2026.240.1849 — refactor(ovmf): delete the ovmf_distro_aliases copy charly no longer feeds

## Summary

Deletes the `ovmf_distro_aliases:` block from `charly.yml`. It has been **dead data** since
`opencharly/sdk#178`: the OVMF resolver now reads `spec.DistroOvmfFamilies`, generated from
`#Distros[id].ovmf_family`.

This block was one of **two byte-identical copies** of that table — the other is
`plugin-vm/candy/plugin-vm/build_defaults.yml`, deleted in its own leg — that had to be edited
together, and editing only one was silent.

The sdk pin moves to `v0.2026240.1834`, and **that pin is what makes the deletion safe rather than
merely tidy**: with the old sdk, removing this block would have tripped
`parseEmbeddedOvmfDistroAliases`'s panic on a missing directive.

## Two behaviour corrections ride in with the new table

Both from `opencharly/spec#61`, and this is where they actually take effect:

- **`cachyos` gains an OVMF family it never had.** The alias table predated the distro, so a CachyOS
  host fell through to the all-families union — and that is the host the cstream VM beds target.
- **The `alma` row is gone.** It was never a `#DistroID` (the id is `almalinux`), so it could not
  match a validated distro: a dead entry that read like coverage.

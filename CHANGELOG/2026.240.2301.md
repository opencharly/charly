# 2026.240.2301 — docs(skills): a refreshed marketplace is not an updated plugin (the cache is commit-keyed)

## Summary

Follow-up to the delivery-audit section added in #425, written from verifying
that chain end to end.

After opencharly/marketplace#234 merged and the local marketplace was refreshed,
a fresh session **still** failed to start `plugin:charly-internals:github` — the
very server the chain had just removed. The marketplace clone was correct and
carried no `internals/.mcp.json`; the installed plugin was still resolving an
older commit-keyed cache entry that did.

The corpus is cached per marketplace **commit** under
`~/.claude/plugins/cache/<marketplace>/<plugin>/<sha>/`, and
`claude plugin marketplace update` refreshes only the clone. The plugin itself
must be moved with `claude plugin update <plugin>@<marketplace> --scope project`,
which reports the commit pair it moved between — that line, not a refreshed
clone, is the evidence a session will see the change. The flag matters: `--scope`
defaults to `user` and fails outright on a project-scoped plugin.

This is the same class of defect the section already documents — a valid corpus
that never reaches the agent — reached by a different route, so it lands beside
it rather than in a new skill (R3).

## How tested

**The failure this documents was observed live**, after the full removal chain
had merged and the marketplace had been refreshed:

```
$ claude plugin marketplace update charly-plugins
✔ Successfully updated marketplace: charly-plugins

$ ls ~/.claude/plugins/marketplaces/charly-plugins/internals/.mcp.json
ls: cannot access '…': No such file or directory        # clone is correct

$ claude -p "list every MCP server that failed to connect or was skipped"
plugin:charly-internals:github                          # still failing
```

**Root cause confirmed in the cache** — two stale commit-keyed copies, both
carrying the removed file:

```
$ ls ~/.claude/plugins/cache/charly-plugins/charly-internals/
7072e53a9d92    cb1c031b3eed
$ # .mcp.json present in BOTH
```

**The documented fix works**, and names the commits it moves between:

```
$ claude plugin update charly-internals@charly-plugins --scope project
✔ Plugin "charly-internals" updated from 7072e53a9d92 to 9ded51f3e2d1 for scope project

$ ls ~/.claude/plugins/cache/charly-plugins/charly-internals/9ded51f3e2d1/.mcp.json
ls: cannot access '…': No such file or directory
```

**The `--scope` caveat is real, not inferred** — the default fails:

```
$ claude plugin update charly-internals@charly-plugins
Checking for updates … at user scope…
✘ Failed to update plugin: Plugin "charly-internals" is not installed at scope user
```

**Verified fixed in a fresh session** — zero plugin MCP failures, skills intact:

```
$ claude -p "(1) COUNT of skills whose name contains ':' (2) every plugin: MCP server that failed or was skipped"
(1) 29
(2) NONE
```

**The drift gate is live for this change — negative control first.** Run against
the edited source before regenerating, it fails; after `task skills:sync`, it
passes on the committed tree:

```
$ task skills:drift          # source edited, corpus not yet regenerated
skills: marketplace drift failed (see above).
exit=1

$ task skills:sync && task skills:drift
marketplace drift: clean (405 artifact(s) on disk match their sources; regeneration is a no-op)
skills: no drift.
exit=0
```

**Single-file source change; harness surface untouched:**

```
$ git status --short
 M candy/charly-internals/charly.yml
 1 file changed, 18 insertions(+)
```

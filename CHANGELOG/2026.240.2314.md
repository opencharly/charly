# 2026.240.2314 — fix(skills): the git-workflow skill described machinery that does not exist

## Summary

I audited every claim the `git-workflow` skill makes about the landing machinery against the
**actual `opencharly/.github` repo** and the **live repos**, rather than trusting the skill.
**Five were false.** A skill that misdescribes the gate is worse than no skill: it is what an
agent reaches for *before* touching the gate.

| # | The skill said | Reality |
|---|---|---|
| 1 | on PASS it "feeds the `auto-merge` workflow that merges (squash) and CalVer-tags" | **There is no `auto-merge` workflow.** `pr-validator.yml` calls `enablePullRequestAutoMerge` inline — GitHub's *own* native auto-merge. The tag and CHANGELOG come from the separate `tag-on-merge` workflow the merge triggers. The skill's own body already said this correctly, so it contradicted itself. |
| 2 | "GitHub branch protection (`enforce_admins`) block it in every repo" | The **legacy** branch-protection API is used nowhere. Protection is a per-repo **ruleset**. `branch-protection.sh` *deletes* legacy protection where it survives, because it has no bypass slot for the app that writes the CHANGELOG. |
| 3 | "the `pre-push-gate` … is **NOT** wired under Claude Code" | It **is** — `.claude/settings.json` PreToolUse hooks. It blocked a push to `main` during this session. |
| 4 | the required check is `charly/pr-validator` | The **workflow** is named that; the **check** is `validate / validate`. |
| 5 | corpus paths under `plugins/` | That corpus is `marketplace/` now. |

# 2026.241.0120 — fix(skills): gate the refs list against the marketplace's authoritative copy

## Summary

`candy/charly-marketplace/charly.yml` exists in **two repos with different
authority**, and nothing kept them in sync.

The marketplace deploy workflow copies **its** copy *over* the cloned charly's
before generating — its own step comment says so:

> The marketplace checkout's `candy/charly-marketplace/charly.yml` is the
> AUTHORITATIVE refs list … so it is copied OVER the charly checkout's copy
> before generating — the charly checkout only supplies the in-repo candy dirs,
> never the refs.

So that file, not this one, decides which candy versions the corpus is built
from. This repo's copy is only what `skills:sync` / `skills:drift` feed the
generator locally.

**The consequence is a gate that cannot see the defect it exists to catch.** #426
bumped `pod-charly-hooks` to `v2026.240.2141` *here*, to drop the `internals`
plugin's stdio `github` MCP server. `skills:drift` reported `no drift`, because
local generation used this copy. CI kept resolving `v2026.239.1634` from the
marketplace's copy and regenerated `internals/.mcp.json` straight back — failing
the marketplace build across a 22-file drift, while every local gate stayed green.

This adds **`skills:refs`**, which fails when the two copies differ, and runs it
before every generation in `sync` and `drift`. Equality is what makes the local
gate faithful to CI, so it is now asserted rather than assumed. The failure prints
the diff and says where the matching change has to land.

### The refs sync in this PR — all 8 changed pins

`pod-charly-hooks` is **not** among them: it is already `v2026.240.2141` in the
base, from #426. What was stale here is everything the marketplace's copy had
moved without this one following:

That the divergence ran in **both** directions — this repo ahead on

Paired with opencharly/marketplace#236, which sets the authoritative copy to the
same content; its `build` drift gate now passes.

## How tested

**Negative control first — the gate catches the exact pin that caused the
incident.** Reintroducing `pod-charly-hooks:v2026.239.1634`:

```
$ task skills:refs
refs: DRIFT — candy/charly-marketplace/charly.yml differs from the marketplace's copy.
--- …/marketplace/candy/charly-marketplace/charly.yml
+++ …/charly/candy/charly-marketplace/charly.yml
@@ -11,7 +11,7 @@
             - '@github.com/opencharly/charly:v2026.240.2301'
-            - '@github.com/opencharly/pod-charly-hooks:v2026.240.2141'
+            - '@github.com/opencharly/pod-charly-hooks:v2026.239.1634'
exit=1
```

Had this gate existed, #426 would have failed here instead of shipping a bump
that changed nothing.

**It caught a real divergence during this PR, unprompted.** After
opencharly/marketplace#236 moved `pod-selkies-core` to close its last stale
artifact, the gate failed here on the next run — which is how the eighth pin
above got into this PR:

```
$ task skills:refs
refs: DRIFT — candy/charly-marketplace/charly.yml differs from the marketplace's copy.
The marketplace's copy is AUTHORITATIVE: its deploy workflow copies it over this
repo's before generating. A bump that lands only here changes nothing CI resolves…
```

**Positive — with the copies synced:**

```
$ task skills:refs
refs: OK — refs list matches the marketplace's authoritative copy.
exit=0
```

**Wired into the real gate** — `skills:drift` runs it first:

```
$ task skills:drift
refs: OK — refs list matches the marketplace's authoritative copy.
charly marketplace: marketplace drift: …
```

**The root cause was reproduced before being fixed.** Generating with the
marketplace's refs list instead of this repo's, into a pristine checkout,
recreates CI's failure exactly — same file set, and the deleted artifact returns:

```
$ cp marketplace/candy/charly-marketplace/charly.yml charly/candy/charly-marketplace/charly.yml
$ cd charly && bin/charly marketplace generate --root . --out ../mkt-repro
$ git -C ../mkt-repro status --short | wc -l
23
$ git -C ../mkt-repro status --short | grep mcp
?? internals/.mcp.json
```

That `??` line is the whole point: CI was regenerating the removed MCP server
back into the corpus.

**Known unrelated failure, stated plainly:** a full `task skills:drift` from this
branch reports stale artifacts, because `main` has moved past the tag the
marketplace corpus is pinned to (#429 rewrote `candy/charly-internals/charly.yml`,
+79/−73). Generating from a tree ahead of the pin has always produced that,
before and after this PR; it clears at the next marketplace bump. The `refs` gate
itself passes, which is what this PR changes.

## Rulebook compliance

- **R1 — RCA every anomaly.** The failing build was traced to the authority split
  and reproduced locally before any fix; the fix targets the cause (an unasserted
  invariant), not the symptom (a stale pin).
- **R3 — No duplication.** The duplicate file is not multiplied further; the
  invariant that the two copies must be equal is stated in exactly one place.
- **R4 — No workarounds.** The pin was not simply re-bumped and forgotten — the
  hole that let a bump be silently ineffective is closed.
- **R5 — Delete legacy completely.** No stale pin left behind; all eight are
  corrected alongside the gate.
- **R6 — Git safety.** `gh pr list` preflight; `fix/` branch; no force-push, no
  hook bypass, no direct push to `main`. The PR was updated with follow-up
  commits, never closed and recreated.
- **R7 / R10 — Prove the gate, not the plan.** Proven by a negative control that
  fails on the real defect, by an unprompted real catch during this PR, and by a
  reproduction that recreates CI's exact failure — not by a passing run alone.

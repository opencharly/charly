# 2026.241.0228 — fix: drop candy/charly-marketplace's self-reference to this repo's root

## Summary

`candy/charly-marketplace`'s refs list opened with a reference to **charly's own repo root**:

```yaml
- '@github.com/opencharly/charly:v2026.240.2345'
```

A repo root is not a candy node, so it never resolved, and charly's own validation reported it
twice — once for the local candy and once for the remote one it shadows:

```
candy "charly-marketplace" candy: unknown candy "github.com/opencharly/charly"
candy "github.com/opencharly/charly/candy/charly-marketplace" candy:
    unknown candy "github.com/opencharly/charly"
```

**The entry is not merely broken — it is unnecessary.** This repo's own candies are *local*, and
the generator reads them from `--root`. Their `skill:`/`hook:` entities have always reached the
corpus that way, which is exactly why an unresolvable entry could sit here with no visible effect.

## Why it is removed rather than repointed

My first attempt replaced it with the nine `@github.com/opencharly/charly/candy/<name>` subpath
refs. **`TestCandyCutoverSweep_NoCharlyCandyRefs` rejected that, correctly** — inside charly's own
tree those are the OLD pre-cutover form, and the test exists to keep them out:

```
--- FAIL: TestCandyCutoverSweep_NoCharlyCandyRefs (0.00s)
    stale in-repo candy pins (charly/candy/<name>) survive for non-fixture candies:
```

The gate did its job. Removal is the end-state the cutover intends, and it is measurably
equivalent — both forms produce the same 28 remaining errors, so nothing was being carried by
those refs.

`charly box validate` still exits 1 on the remaining **28** errors. Those are pre-existing and

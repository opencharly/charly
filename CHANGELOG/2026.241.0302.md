# 2026.241.0302 — chore(refs): bump plugin-marketplace to v2026.241.0124 (the setup-launcher fix)

## Summary

`plugin-marketplace#3` (merged) fixed the `./setup` launcher that plugin generates for the
marketplace repo. The launcher still did:

```bash
cd "$(dirname "$0")/charly"
```

pointing at a charly submodule that was deliberately removed (declaring one made the refs
downloader drag the whole charly repo into consumer fetch trees). Both `./setup` and
`./setup --check` — the marketplace's local regeneration entry point and its local drift gate —
have been dead since.

**This ref is the pin that decides which generator runs.** charly prescans the `marketplace` word
from the project root it runs in, and line 3317 is the only reference to the plugin anywhere in
the tree, so bumping it is what carries the fix to the marketplace repo — whose deploy workflow
then regenerates `./setup` from a charly built at this pin.

## How tested

**The pin is what drives the emitted launcher** — generated with each pin from the same tree, and
diffed at the line that differs:

```
$ charly marketplace generate --root <charly> --out /tmp/mp-out-old     # pin v2026.238.0024
$ sed -n '7p' /tmp/mp-out-old/setup
cd "$(dirname "$0")/charly"                                            <- the broken form

$ charly marketplace generate --root <charly> --out /tmp/mp-out-test    # pin v2026.241.0124
$ sed -n '7p' /tmp/mp-out-test/setup
# This repo carries NO charly submodule on purpose: a declared submodule is initialized on
```

The launcher emitted under the **old** pin still reproduces the original failure when run, which
is the defect this bump retires:

```
$ cd /tmp/mp-out-old && ./setup --check
./setup: line 7: cd: ./charly: No such file or directory
```

The launcher emitted under the **new** pin resolves a checkout from `$CHARLY_SRC` or a sibling
clone, and fails with an actionable message when there is none — both asserted by executable tests
in `plugin-marketplace#3`, which run the script against a stub `charly` on `PATH`.

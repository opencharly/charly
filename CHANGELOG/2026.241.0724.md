# 2026.241.0724 — fix(loader): a dev/worktree charly must not load the installed package's plugins (#328)

## Summary

A worktree-built (dev) charly binary silently loaded plugin binaries from the **installed package's** `/usr/lib/charly/plugins` — the FHS path belonging to a different charly install. When the two disagree on the plugin API version, the run emits an error pair per attempt and continues degraded (six weeks of API drift, issue #328).

**Fix:** `bakedPluginDirs()` now includes the FHS path **only when the running binary is itself a packaged install** (`/usr/bin` or `/usr/local/bin` — where the charly candy's distro package places the binary and bakes plugins). A dev/worktree binary skips the FHS path entirely and emits a **one-time loud warning** when the installed package's plugins exist, so the skip is visible instead of silent. `CHARLY_PLUGIN_DIR` and `CHARLY_PLUGIN_ONLY=1` behavior is unchanged.

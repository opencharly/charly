# 2026.241.0904 — fix: the agentteams manager/worker entrypoint execs a candy ref, not supervisord

## Summary

`charly box validate` emitted **10** warnings of this shape:

```
warning: box "agentteams" resolves init "supervisord", which depends on the "supervisord" candy,
but no candy of that name is in this project's scanned set — nothing was injected, so the image
will declare init "supervisord" with no supervisord binary and fail at start.
```

Four are charly's own boxes. **Two of those turned out to be a live defect, not a missing
reference.**

## The defect

`agentteams-manager` and `agentteams-worker` both had:

```yaml
entrypoint:
    - '@github.com/opencharly/layer-supervisord:v2026.239.1300'
    - -n
    - -c
    - /etc/supervisord.conf
```

The first element of an OCI entrypoint is **the binary to exec**. A candy ref is not a binary, so
these two images would try to exec a file literally named
`@github.com/opencharly/layer-supervisord:v2026.239.1300` and die at start. The same slip is why
the warning fired at all: the ref sat in `entrypoint:` rather than `candy:`, so layer-supervisord
was never composed either. One mistake, two failures.

The box's own comment states the intent — *"the box bakes the supervisord init as its OCI
entrypoint"* — so both halves are fixed: the entrypoint execs `supervisord`, and the ref moves to
`candy:` where it composes.

`agentteams` and `check-boxload-app` are the plain case (init resolves, candy never referenced);
each gets the ref in its `candy:` list, which is the remedy the warning names and the form
sibling boxes already use.

# 2026.241.1105 — docs: freeze the R0 skill dispatcher as hand-maintained prose

## Summary of changes

Phase B.2 of the approved marketplace cutover: stop generating the R0 skill dispatcher table and
freeze it as ordinary prose.

The table is spliced into `CLAUDE.md` and `AGENTS.md` by `charly marketplace generate`
(`emit_dispatcher.go`). That splice is one of two jobs the marketplace generator performs *beyond
generating the marketplace*, and it is the reason `--root` must be a charly checkout — which in
turn forces local generation, the `setup` launcher, `task skills:sync`/`drift`, and the
harness-surface drift gate.

Concrete edit — `CLAUDE.md` and `AGENTS.md`, two marker lines each:

- remove `<!-- BEGIN GENERATED SKILL DISPATCHER -->` / `<!-- END GENERATED SKILL DISPATCHER -->`;
- replace the opening marker with a note saying the table is now hand-maintained and must be
  updated in the same PR as any skill addition, rename or removal.

**The 81-line table content is unchanged.** All 40 dispatcher rows are intact; only the markers go.

## Change class

**docs-only** — two `*.md` files, comment lines only. No Go source, no schema, no CLI, no
workflow, no pin.

**Closes / relates to:** Phase B.2 of the approved plan. Deliberately ordered **before** deleting
`emit_dispatcher.go` (a follow-on PR in `opencharly/plugin-marketplace`): that emitter skips any
file without the markers — `if bi < 0 || ei < 0 { continue // no markers → not a
generated-dispatcher file; leave untouched }` — so from this commit the generator already no-ops
on these two files. Deleting the emitter first would have left the docs briefly unowned; this
order never does.

**Breaking change + rollback:** none — no content is added or removed, no skill reference changes.
Rollback is a plain revert, which restores the markers and hands the table back to the generator.

**Why this matters beyond tidiness.** `charly/candy/` is the marketplace corpus's **second input
path**: those 62 skills reached the corpus only because CI clones charly at a hand-written tag, so
a stale pin can freeze skill content while every gate stays green. After this they come from the
refs list like every other standalone repo — one input path, no privileged checkout.

### The two reference shapes that had to change

Both resolved a candy from a directory that is going away:

1. **Bare-word closure references** (`- check-local-layer`), which only resolve through
   `discover: path: candy`. Now explicit `@github` pins.
2. **The check-local bed's rsync of four candy DIRECTORIES** into the eval guest. The guest project
   now pins its whole closure by `@github` ref and resolves it itself — exactly as it already
   resolved the sdk + spec contract modules from the module proxy — so only the project file is
   delivered.

### Two pre-existing defects surfaced, fixed here rather than filed

- **The bed rsynced two directories that no longer existed** (`candy/plugin-example-step`,
  `candy/plugin-deploy-local`). It was delivering a closure it could not assemble — the rsync would
  have failed on the missing sources. Both are now pinned at their current tags.
- **`check/eval-host-project/charly.yml` declared schema `2026.232.0520`** while charly requires
  `2026.240.1943`. Nothing caught it because `check/` is not on charly's `discover:` path — but the
  guest welds a **current** charly, so the bed would fail in-guest at validation. Bumped.

Both are inside the files this change already edits; leaving them would have meant shipping a bed
that cannot run and calling the move complete.

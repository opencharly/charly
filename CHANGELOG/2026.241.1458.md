# 2026.241.1458 — feat: empty candy/ — move charly's packaging metadata to packaging/charly.yml

## Summary of changes

**`charly/candy/` is gone.** The last directory in it was `candy/charly`, and it is no longer a
candy charly *uses*:

- nothing in this repo references it by name — `grep -cE '^\s+- charly$' charly.yml` → **0**;
- the distro boxes now pin `@github.com/opencharly/layer-charly` instead (the five `distro-*` PRs,
  all merged).

Its only remaining jobs were to be the `charly-candy-charly.yml` release asset and to be parsed by
`packaging_test.go`. That is packaging **data**, not a deployable candy — so it moves to
`packaging/charly.yml`, and `candy/` is deleted outright.

### Nothing external changes

The release asset's **name and content are unchanged**. `git show -M` records the move as a pure
rename — *0 insertions, 0 deletions*. That is exactly what the six per-distro package repos depend
on; `charly-arch/.github/workflows/build.yml` is representative:

```
--pattern 'charly-candy-charly.yml' --dir .
  …
--candy charly-candy-charly.yml \
```

They fetch by asset name and pass the file as `--candy`. Neither changes.

### Deleting `candy/` closes four plan items that would otherwise have rotted silently

| Item | What it was | Why it mattered |
|---|---|---|
| **D.4** | `fleet_compile_parity_test.go` located the repo root by looking for a `candy` **directory** | With `candy/` gone the walk finds nothing and the test **SKIPS** — passing while asserting nothing. Re-anchored on `go.work`. |
| **F.6** | `taskfiles/Modules.yml` tidy sweep globbed `candy/*/ tools/*/` | matches nothing |
| **F.8** | `ci.yml` ran `gofmt -l charly candy tools` | a path that no longer exists |
| **(new)** | `charly/cue_candy_test.go` validated `../candy/*/charly.yml` against the `#CandyFile` CUE schema | **hard-FAILS** on the missing directory — it was not in the plan, and `go test` found it |

The CUE corpus test is **repointed, not deleted**: charly still owns two candy manifests
(`packaging/charly.yml` and `tools/generate-packages/charly.yml`) and both are still worth
validating. Its roots are discovered rather than hand-listed, but *named* rather than repo-wide —
`charly/testdata/` carries deliberately invalid fixtures and `check/` carries a project manifest,
and my first attempt at a whole-repo walk swept both in (6/12 passing) before I scoped it.

`candy/CLAUDE.md` is deleted with the directory: it is a signpost for agents editing candies under
`candy/`, and there are none.

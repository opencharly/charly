# 2026.241.2202 — docs: add the punktfunk R0 dispatcher rows

## Summary

Adds the punktfunk rows to the **R0 skill dispatcher** in both rulebooks.

The two punktfunk skills exist and are projected into the corpus
(opencharly/marketplace#253), but the dispatcher table is **hand-maintained prose** — the
marketplace generator deliberately does not splice it — so an agent consulting the table
before its first tool call would still not be told to load them. That is the entire point
of R0, so a skill that is absent from the table is, in practice, undiscoverable at the
moment it matters.

Three rows per file:

| trigger | skill |
|---|---|
| the `punktfunk:` check verb — probing **or** managing a running host | `/charly-check:punktfunk` |
| (same trigger) | `/charly-check:check` |
| punktfunk / game- or desktop-streaming host / Moonlight-compatible host / `punktfunk-host` units / the punktfunk pacman repo | `/charly-punktfunk:punktfunk-host` |

The two-row shape for the verb matches every other probe verb in the table (`adb:`,
`appium:`, `kube:` each list their own skill **and** `/charly-check:check`), because
authoring a check step needs both the verb's reference and the check orchestrator.

`AGENTS.md` and `CLAUDE.md` are **separate documents** in this repo — not the symlink pair
the umbrella uses — and both carry the dispatcher, so both are updated. Verified rather
than assumed:

```
$ ls -l CLAUDE.md            # a regular file, not a symlink
$ diff AGENTS.md CLAUDE.md | wc -l
446                          # genuinely different documents
$ grep -c 'punktfunk' AGENTS.md CLAUDE.md
AGENTS.md:3
CLAUDE.md:3
```

(`punktfunk/skills/punktfunk-host/SKILL.md`), both landing in
opencharly/marketplace#253. `/charly-check:check` is long-standing.

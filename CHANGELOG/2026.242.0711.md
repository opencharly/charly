# 2026.242.0711 — fix(prescan): do not gate the remote-ref leg on a local discover: block

## Summary

`prescanDeclaredPluginWords` returned early when the root manifest carried no `discover:`
block — and that early return skipped `prescanRemotePluginManifests` with it. The remote leg
reads `@github` plugin refs and has nothing to do with local discovery, so a project that
pins a plugin remotely and discovers nothing locally never prescanned that plugin at all.

**Symptom:** the plugin's `plugin: primary:` never reached the parse, so the scalar shorthand
was rejected —

```
node "probe-pod": plan[0] plugin verb "punktfunk" takes a MAP input
(it declares no primary field for the scalar shorthand)
```

— for a candy that declares exactly that field. And the failure is not local to the
offending step: it fails the whole document parse, so one bed's authoring takes the project
down with it.

The local discover walk stays conditional. Only the remote leg is lifted out from behind the
early return, so a malformed `discover:` block now still gets the remote leg instead of
losing both.

Closes opencharly/charly#471.

## How tested

Two projects, identical except for the presence of a `discover:` block. Both pin the same
plugin by `@github` ref and both author the scalar shorthand:

```yaml
candy:
    - '@github.com/opencharly/plugin-punktfunk/candy/plugin-punktfunk:v2026.241.1930'
plan:
    - check: scalar sugar
      punktfunk: health
```

**Before (current `main`):**

| project | `charly box validate` |
|---|---|
| no `discover:` block | **fails** — "declares no primary field for the scalar shorthand" |
| with `discover:` block | exit 0 |

**After this change:** both exit 0.

```
=== A: NO discover block (the failing case) ===
exit=0
=== B: WITH discover block (must not regress) ===
exit=0
```

The mechanism was confirmed by instrumenting the prescan rather than inferred. In arm A the
remote leg was never entered at all; in arm B it was, and registered the primary:

```
DBG remote-leg enter  baseDir=…/primA3 hasRef=true
DBG remote-leg manifest=…/plugin-punktfunk@main/candy/plugin-punktfunk/charly.yml
DBG registerPluginPrimary word=punktfunk field=method
```

(the instrumentation was reverted before committing; the diff is the 8-line change only)

**No regressions:**

```
$ GOWORK=off go test ./...        EXIT=0   (2 packages ok, 0 failures)
$ GOWORK=off go vet ./...         (clean)
$ gofmt -l charly/plugin_prescan.go   (clean)
```

### Regression test (second commit)

The first revision shipped without one and was correctly blocked under B12. The behaviour
under test is *routing* — does the remote leg run at all — and the leg's only observable
effect went through a network fetch, so the fix adds the seam that makes it testable:
`resolveRemotePluginRepo` is now a package var wrapping the `CanonicalRef` call. The test
substitutes a local directory holding a fake plugin candy and asserts its declared primary
registers.

**It fails without the fix**, with exactly the regression:

```
--- FAIL: TestPrescanRemoteLegRunsWithoutDiscoverBlock
    plugin_prescan_remote_test.go:75: the remote leg never ran:
      a root manifest with no discover: block skipped it
FAIL
```

and passes with it:

```
--- PASS: TestPrescanRemoteLegRunsWithoutDiscoverBlock (0.00s)
ok  github.com/opencharly/charly/charly
```

Verified by reverting only the control-flow change (`len(doc.Discover) == 0` restored) with
the test in place, then restoring it — so the test is demonstrably coupled to the fix rather
than passing incidentally.

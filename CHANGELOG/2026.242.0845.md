# 2026.242.0845 — feat(distro): the omarchy build vocabulary, and register distro-omarchy

## Summary

`spec/schema/distro_vocab.cue` gained an `omarchy` `#DistroID` in
[spec#70](https://github.com/opencharly/spec/pull/70), but charly had **no `kind: distro`
entity** for it — and that gap is silent. `buildVmSyntheticBox` leaves `img.Pkg` empty and
compiles **zero** package steps while reporting success, so an omarchy VM would build an
empty rootfs and say nothing about it.

### The tag chain is the whole design

`inherits: arch` + `inherit_packages: true` makes `distro: [omarchy]` expand to
`[omarchy, arch]`, so **all 99 existing `distro: arch:` candy sections apply unchanged** and
**zero** candies need an `omarchy:` section. Same trick `cachyos` uses.

The entity adds exactly three things arch cannot express:

**1. Omarchy's package sources.** Every package — including the ~125 from
`core`/`extra`/`multilib` — is served by Omarchy's own frozen Arch mirror snapshot, never a
generic Arch mirror. Building against upstream Arch would silently produce a guest with a
different kernel, and a different everything-else, than Omarchy ships.

This is expressed through `runtime_pacman_conf` with explicit `Server =` lines rather than
through `mirrorlist_url`, because **`mirrorlist_url` and `keyring_init_cmd` are both dead
fields**:

```
$ grep -rn 'MirrorlistURL' --include='*.go' . | grep -v 'cue_types_gen|_test|/docs/'
$ grep -rn 'KeyringInitCmd' --include='*.go' . | grep -v 'cue_types_gen|_test|/docs/'
```

Both return **nothing** across the whole umbrella. `cachyos` authors both today and neither
does anything. Using them here would look like configuration and be inert.

**2. A limine boot chain**, replacing arch's grub one wholesale (`bootloader:` overrides
rather than merges). Every value was read off a **real ISO-installed Omarchy 4.0.1 guest**,
not from docs: ESP at `/boot` (not `/boot/efi`), `root=PARTUUID=` (not `root=UUID=`),
`rootflags=subvol=@`.

**3. The disk layout**, via the `disk_layout` block
[spec#72](https://github.com/opencharly/spec/pull/72) added and
[plugin-vm#7](https://github.com/opencharly/plugin-vm/pull/7) wired.

### One upstream setting deliberately NOT copied

Upstream's `pacman.conf` sets `DownloadUser = alpm`. It is a real privilege drop on a
normal install and it **breaks the build here**: charly mounts `/var/cache/pacman/pkg` as a
root-owned cache the `alpm` user cannot write to, and the transaction dies with
`failed to synchronize all databases (failed to retrieve some files)`. Match upstream's
intent; verify each setting against the build context.

## How tested

The entity validates and **resolves** — and getting there found a real bug in another repo.

```
$ ./bin/charly box validate
$ echo $?
0
```

The first attempt did **not** pass:

```
node "omarchy": plugin kind:distro: plugin_input fails #DistroInput:
#DistroInput.disk_layout: field not allowed
```

`plugin-distro` validates an authored `distro:` body against its **own** self-contained
`#DistroInput`, which had drifted behind spec's `#Distro` — missing not only `disk_layout`
but `installer` from spec#71, which had been silently rejected since that landed. Fixed in
[plugin-distro#4](https://github.com/opencharly/plugin-distro/pull/4) with a parity guard,
and this PR pins the tag carrying it.

Validation alone would only prove the YAML parses, so the box was **generated**:

```
$ ./bin/charly box generate omarchy.omarchy
$ echo $?
0
$ grep -E 'FROM|stable-mirror|NoExtract' .build/omarchy.omarchy/Containerfile
FROM scratch AS omarchy-repo
FROM scratch AS omarchy-runtime
FROM scratch AS omarchy-skel
FROM scratch AS omarchy-base
FROM ${BASE_IMAGE}
  stable) mirror=stable-mirror.omarchy.org ;;
NoExtract = usr/share/libalpm/hooks/80-limine-efi-deploy.hook
NoExtract = usr/share/libalpm/hooks/10-limine-snapper-lock.hook
```

That proves the whole chain: the `import:` resolves `distro-omarchy`, the box composes
`layer-omarchy-base`'s four members across a repo boundary, and the emitted Containerfile
carries Omarchy's mirror and its NoExtract rules.

```
$ go build ./... && go test -count=1 ./...
```

The image this entity describes is already proven end to end: `check-omarchy-base-pod`
passed the full 13-step R10 sequence on a `disposable: true` bed, with 19/19 baked checks,
in `layer-omarchy-base`. The bootstrap-VM half is proven at the emitter in plugin-vm#6/#7,
where the generated disk script ran live against a real partitioned disk producing exactly
this entity's `@`/`@home`/`@log`/`@pkg` layout with the ESP at `/boot`.

## Rulebook compliance

- **R0 — skills first.** `/charly-internals:git-workflow`; the `cachyos` entity was read as
  the model before a sixth distro was written.
- **R1 — RCA every anomaly.** Two surfaced. (a) The `#DistroInput.disk_layout: field not
  allowed` rejection was root-caused to plugin schema drift and fixed **there**, which
  turned up a second, older instance (`installer`) nobody had reported. (b)
  `mirrorlist_url` / `keyring_init_cmd` looked like the natural home for the mirror and the
  key; grepping for consumers before using them showed both are dead, so neither is used
  and the comment records why.
- **R2 — finish the whole cutover.** Entity, import, submodule and both dependency bumps
  land together — `omarchy.omarchy` resolves as of this commit.
- **R3 — no duplication.** `inherits: arch` means the pac/aur formats, container bootstrap
  and `local_pkg` are inherited verbatim; only the three genuinely-different things are
  restated.
- **R4 — no workarounds.** No sleeps, no retries, no hand-pinned gitlink: `box/omarchy` is
  a real submodule at a merged tag.
- **R5 — delete legacy completely.** `N/A — a new entity; nothing is removed or renamed.`
  The dead `mirrorlist_url` / `keyring_init_cmd` fields are **routed, not parked**: filed as
  the named batch [charly#477](https://github.com/opencharly/charly/issues/477)
  (`dead-distro-fields`), which carries the grep evidence, the two `cachyos` values that
  must migrate with them, and the `#SchemaVersion` + `remove_key` shape the removal needs.
  This PR advances that exit by establishing the evidence and by refusing to add a third
  authored use.
- **R6 — preserve user work and Git safety.** Feature branch off current `main`, PR-only,
  no force-push, no direct push to `main`, no hook bypass.
- **R7 — prove behavior, not compilation.** `box generate` emits a real Containerfile and
  its contents are inspected; `box validate` alone would prove only that YAML parses.
- **R8 — preserve emitted artifacts.** The generated Containerfile is quoted from the
  actual `.build/` output.
- **R9 — binary equals source.** All evidence from `./bin/charly`, built by
  `task build:binary` from this worktree after the dependency bumps.
- **R10 — fresh disposable proof.** The image side is proven by `check-omarchy-base-pod`
  (13/13, `disposable: true`, destroy+rebuild) in `layer-omarchy-base`. The VM side needs
  the `distro-omarchy` VM entities this entity unblocks, and the bed for it
  (`check-omarchy-vm`) is named rather than used to defer.
- **ADE — spec-is-the-test.** Every non-obvious value carries the measurement that produced
  it — the PARTUUID form, the ESP path, the dropped `DownloadUser`, the dead fields.
- **RDD — prove high-risk assumptions before editing.** The boot chain and disk layout were
  measured on a real installed guest; the emitter that consumes them ran live.
- **SDD — schema-driven design.** The schema landed first (spec#72), its plugin mirror
  second (plugin-distro#4), the consumer third (plugin-vm#7), and this entity last.
- **Concurrency mandate.** `N/A — no roster.`

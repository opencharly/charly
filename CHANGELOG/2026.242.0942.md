# 2026.242.0942 — fix(arch): --needed in the bootstrap, so it stops reinstalling curl

## Summary

The `arch` distro entity's container bootstrap ran

```
pacman-key --init && pacman -Syu --noconfirm
```

with **no `--needed`**. The base image already ships `curl` and `ca-certificates` at the
target version, so pacman **reinstalled both on every single build of every Arch-family
image**:

```
warning: curl-8.21.0-1 is up to date -- reinstalling
warning: ca-certificates-20240618-1 is up to date -- reinstalling
```

Wasted work in the **first layer** of every build, and two warnings in every build log that
no allowlist claims — the existing `pacman-needed-package-already-current` rule covers
`-- skipping`, which is the message pacman prints **with** `--needed`.

### Every file in the diff

| File | What changed |
|---|---|
| `charly/charly.yml` | `arch.distro.bootstrap.install_cmd` gains `--needed`, with the measurement recorded inline |

### Why this is the right fix rather than an allowlist entry

`--needed` is the flag that makes a repeated install **idempotent instead of a reinstall** —
which is R4, and which the allowlist rule's own comment already says. Adding
`-- reinstalling` to the allowlist would have silenced the message while leaving the wasted
reinstall in place on every build.

Every other pac install path in charly already passes it: the generated install template
three hundred lines further down reads
`pacman -Syu --noconfirm --needed{{range .Options}}…`, and the `cachyos` bootstrap in the
next block has it too. **arch was the outlier.**

## How tested

Measured on the exact base image the bootstrap runs against
(`quay.io/archlinux/archlinux:base-20260719.0.558306`), both ways:

```
$ podman run --rm quay.io/archlinux/archlinux:base-20260719.0.558306 sh -c '
    pacman-key --init >/dev/null 2>&1
    pacman -Syu --noconfirm curl ca-certificates 2>&1 | grep -cE "is up to date -- reinstalling"'
--- WITHOUT --needed (charly today) ---
2
```

```
$ podman run --rm quay.io/archlinux/archlinux:base-20260719.0.558306 sh -c '
    pacman-key --init >/dev/null 2>&1
    out=$(pacman -Syu --noconfirm --needed curl ca-certificates 2>&1)
    echo "reinstalling lines: $(printf "%s" "$out" | grep -cE "is up to date -- reinstalling")"
    echo "skipping lines:     $(printf "%s" "$out" | grep -cE "is up to date -- skipping")"
    echo "curl present:       $(command -v curl >/dev/null && echo yes)"'
--- WITH --needed (this fix) ---
reinstalling lines: 0
skipping lines:     2
curl present:       yes
```

**2 reinstalls → 0**, the two remaining lines are the `-- skipping` class that *is*
allowlisted, and **curl is still present** — so the fix removes the work without removing
the outcome. That last line matters: a `--needed` that skipped a package the bootstrap
actually needs would be a regression, and this asserts it does not.

### How it was found

Not by reading the entity. By auditing a real bed's warning accounting in
`.check/<bed>/<ts>/summary.yml`, where each finding carries the `allowlisted:` rule ID that
claimed it. Two findings had no rule, and their text differed from the 23 that did by a
single word: `reinstalling` instead of `skipping`. Following that word back reached this
missing flag.

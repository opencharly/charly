# 2026.242.1102 — fix(distro): drop the dead pacstrap fields keyring_init_cmd and mirrorlist_url

## Summary

First half of the cutover for opencharly/charly#477.

`#Pacstrap.keyring_init_cmd` and `#Pacstrap.mirrorlist_url` have **zero Go consumers** anywhere in the umbrella — the only occurrences are the generated `cue_types_gen.go`, the schema declarations, and these authorings. They read as configuration and do nothing.

```
$ grep -rn 'KeyringInitCmd\|MirrorlistURL' --include='*.go' . | grep -v 'cue_types_gen\|_test'
   (nothing)
```

**The file already knew.** The omarchy pacstrap block carries comments explaining that it deliberately does *not* use either field because both are dead, and routes its mirror through `runtime_pacman_conf` instead. Two other distros went on authoring them anyway — which is the trap the issue describes: someone adding a distro copies `arch` or `cachyos` and inherits configuration that silently does nothing.

**Nothing is lost by removing them:**

- Keyring init on the pacstrap path is done by `pacstrap -K`, which initialises the target keyring itself, and by the bootstrap `install_cmd`'s own `pacman-key --init`.
- The cachyos `extra_repo` entries carry `siglevel: Never`, so the `F3B607488DB35A47` recv/lsign the dead field described was never load-bearing.
- Mirrors reach pacman through `runtime_pacman_conf`'s explicit `Server =` lines — which is how omarchy already does it.

The omarchy comments are restated as description rather than as a warning about fields that no longer exist here.

## Ordering (this is a cutover, not a partial change)

Removing the schema declarations first would reject a `charly.yml` that still authors the fields. So the authored usage goes first — here — and the schema declarations in `opencharly/spec` (`schema/distro.cue` + regenerated `cue_types_gen.go`) and `opencharly/plugin-distro` (`schema/distro.cue`) follow immediately, in that order. At no point is an authored field rejected by the schema; at no point is a live consumer left without its field, because there were none.

# 2026.242.1239 — fix(packaging): declare openssl — plugin-vm shells out to it

## Summary

plugin-vm's iso build engine (opencharly/plugin-vm#8) hashes an installer password with
`openssl passwd -6`. That is a **runtime OS dependency of the charly binary**, and R9
requires it declared — so it is added to all four real `depends` lists: `archlinux`, `rpm`,
`deb` and `apk`.

Raised by the `pr-validator` on plugin-vm#8, where it could not be fixed: the dependency is
declared here.

## Why `openssl` and not a Go implementation

Go's stdlib has no `crypt(3)`, and `golang.org/x/crypto` ships bcrypt/scrypt/argon2 but
**not** SHA-crypt. The remaining options were a hand-rolled `$6$` implementation inside
charly or a package dependency.

A password-hashing primitive is not something charly should carry its own copy of.
`openssl passwd -6` is also the exact command Omarchy's unattended-install documentation
gives operators, so charly produces **byte-identical hashes to a hand-built seed** — which
matters when the two have to be interchangeable.

## Why `depends` and not `optdepends`

An operator who authors `installer.password` and does not have openssl gets a **hard
failure with no hash**, not a degraded feature. Worse, the first place they would meet it is
a VM build that has already downloaded several GiB of installer ISO. That is a mandatory
dependency, not an optional one.

`ipk` keeps its empty list by its own existing comment (OpenWrt's repos already lack the
mandatory podman/qemu/libvirt deps); `msix` is a deferred stub with no depends.

## How tested

```
$ go test -count=1 ./charly/ -run 'Packaging'
ok  	github.com/opencharly/charly/charly	0.420s
```

The result was verified by **parsing the YAML per format**, not by grepping:

```
archlinux  depends has openssl: True
rpm        depends has openssl: True
deb        depends has openssl: True
apk        depends has openssl: True
ALL FOUR CLEAN: True
```

That check earned its keep immediately. **Two of the four insertions first landed in
`suggests` lists rather than `depends`** — rpm's and deb's `suggests` both end in a package
name (`kubernetes-client`, `kubectl`) that made a naive anchor match the wrong list, and a
grep would have reported a plausible-looking 5 occurrences for what should have been 4
placements. The parsed check also asserts openssl does **not** leak into any
`suggests`/`recommends`/`optdepends` list.

Diff is 4 lines, one per format.

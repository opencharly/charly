# 2026.242.1422 — fix(deps): pin the plugin-vm that can actually build an iso VM

## Summary

**`main` ships the omarchy `installer:` block with a plugin-vm that cannot build an iso VM.**
The answer format landed in #485 and is currently unusable:

```
$ charly vm build omarchy-vm
charly: error: command "vm": vm "omarchy-vm":
  unsupported source.kind "iso" (want one of cloud_image, bootc, bootstrap)
exit=1
```

#485 carried this bump as a **second commit**, and the squash-merge landed only the manifest:

```
$ git show --stat 5caaf438 | tail -2
 charly/charly.yml | 236 +++++++++++++++++++++++++++++++++++++++++++
 1 file changed, 236 insertions(+)
```

So this is not a new dependency decision — it is the half of #485 that did not land,
restored, and re-verified against what is published **now** rather than what was published
then.

| module | from | to |
|---|---|---|
| `plugin-vm` | `v0.2026240.2034` | `v0.2026242.1323` |
| `plugin-distro` | `v0.2026242.804` | `v0.2026242.1131` |
| `sdk` | `v0.2026241.2111` | `v0.2026242.1250` |
| `spec` | `v0.2026242.753` | `v0.2026242.1251` |

Each is load-bearing for the block already in `charly.yml`:

- **plugin-vm** — the `iso` engine (plugin-vm#8), the virtio answers volume (#9), the
  per-domain seed (#10)
- **plugin-distro** — the resolver fix (#6). Without it the distro's `installer:` block
  arrives `nil` at every consumer, so the manifest in `charly.yml` is **silently dropped**
  even once the engine exists
- **sdk / spec** — `disk_size_bytes` on the seed context and the template arithmetic the
  partition geometry uses; the block's `{{sub (sub .DiskSizeBytes …) …}}` cannot render
  without them

## How tested

bump whose checksums were not committed):

**The resulting binary actually builds an iso VM.** Against `check-omarchy-iso-vm` in

## Rulebook compliance

- **R1 — RCA every anomaly.** The failure was traced to the squash-merge dropping a commit,
  confirmed with `git show --stat` on the merged SHA, rather than assumed to be a bad pin.
- **R2 — Finish the whole cutover.** All four modules move together. Bumping only plugin-vm
  would leave `installer:` arriving nil (plugin-distro) and the geometry template unable to
  render (sdk/spec) — three ways to look fixed and not be.
- **R3 — No duplication.** Version pins only; no code.
- **R4 — No workarounds.** No `replace`, no vendored copy, no hand-edited `go.sum`.
- **R5 — Delete legacy completely.** N/A — nothing is replaced.
- **R6 — Git safety.** `git status` inspected before the commit; only `go.mod`/`go.sum`
  staged. No force-push, no direct push to `main`.
- **R7 — Prove behavior, not compilation.** The proof is an iso VM building and a guest
  installing itself, not a green build — the pre-bump binary compiled fine and still could
  not do it.
- **R8 — Preserve emitted artifacts.** `task build:binary`'s `go.work.sum` guard is exactly
  the emitted-artifact check for a pin bump, and it passes.
- **R9 — Binary equals source.** Built with `task build:binary` from this worktree and
  invoked through its own `bin/`; no `replace` in the committed `go.mod`.
- **R10 — Fresh disposable proof.** Exercised on the `disposable: true`
  `check-omarchy-iso-vm` with a freshly created domain and overlay. That bed does not yet
  complete for reasons of its own (tracked on opencharly/distro-omarchy#5), so the full R10
  gate is not claimed here — what is claimed is the specific behaviour this PR restores,
  which went from a 761 ms hard failure to a completed install.

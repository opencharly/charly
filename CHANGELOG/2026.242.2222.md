# 2026.242.2222 — chore(deps): repin the four check verbs that gained fields

## Summary

Four verb plugins merged new assert fields today, and charly pinned versions that predate
all of them — so a `check:` step authoring any of the fields is rejected at validate time
with `plugin_input fails`, and no bed can use them.

  plugin-user     v0.2026237.1430 -> v0.2026242.2148   groups: / not_groups:
  plugin-file     v0.2026237.1422 -> v0.2026242.2145   link_target:
  plugin-service  v0.2026237.1428 -> v0.2026242.2146   scope: / none_failed: / ignore:
  plugin-check    v0.2026242.1018 -> v0.2026242.2127   the limine-in-chroot allowance

This is the same partial-repin class as charly#497 (which pinned a plugin-vm predating
`source.kind: iso`): the capability ships in the plugin, the consumer's pin stays put, and
the two disagree only at runtime.

`plugin-wl` needs no entry — it is served OUT-OF-PROCESS and fetched at runtime, so charly
carries no require for it. Its `hypr-layers` method reaches a deployment without a repin.

Then the point of the change — the four fields authored in a scratch candy and EXECUTED
against a real Arch container by a charly with ZERO local replaces (`grep -c 'replace
github.com/opencharly/plugin' charly/go.mod` -> 0):

    PASS  check root is in the root group and NOT in docker  [probe-groups]  uid=0 gid=0
    PASS  check a bogus group is correctly reported as absent  [probe-groups-negative]
    PASS  check /bin is a symlink and resolves to usr/bin  [probe-link-target]  ok
    PASS  check link_target also accepts operator matchers  [probe-link-target-matcher]  ok
    FAIL  check no failed system units - a container has no systemd to ask
          none_failed: cannot reach the system systemd manager (is-system-running: offline)
          - `systemctl --failed` exited 1 with no output, which is NOT the same as
          'nothing failed'
    5 steps: 4 passed, 1 failed, 0 skipped

The single FAIL is the DELIBERATE control: a container has the systemctl binary but no
running systemd, and `none_failed` is required to fail there rather than report "no failed
units". Its passing would be the bug.

Before this repin the same scratch candy could not even be authored — the served schemas
had no such fields.

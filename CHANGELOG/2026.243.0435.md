# 2026.243.0435 — fix(golden-compile): the regeneration tool was left on the pre-cutover root marker

## Summary

`TestFleetCompileParity_PluginRoundTrip` fails on main:

    PARITY BREAK on "pre-commit" (WireView wire form differs from the golden —
    regenerate with `go run ./tools/golden-compile` if this is an intentional compiler change)

and the remedy it prints CANNOT BE CARRIED OUT:

    golden-compile: repo root (a directory containing candy/) not found walking up from
    /…/charly/tools/golden-compile

## Root cause

`compilerTestProjectDir` in the test walks up looking for **`go.work`**, and its comment says
why:

    // go.work marks the repo root. It replaced `candy/`, which was the marker until
    // the candy de-submodule cutover emptied and removed that directory — at which
    // point this walk would have found nothing and the test would have SKIPPED
    // vacuously, which is the exact failure the marker exists to prevent.

The test was migrated at the cutover. `tools/golden-compile` was not — it still stats
`candy/`, a directory that no longer exists at the charly root. Its own comment claimed it
used "the same disambiguator charly/fleet_compile_parity_test.go's compilerTestProjectDir
uses", which stopped being true the moment the test moved and nothing checked.

The consequence is worse than a stale comment: the tool became unrunnable, so the golden
could not be regenerated by the documented means when it drifted.

## Why the golden drifted at all

The three fixture candies (`debootstrap-builder`, `dev-tools`, `pre-commit`) now resolve from
standalone repos, so the golden captures a version string that advances when one of those
repos publishes — with no change in charly.

The regenerated diff is exactly one line:

    -    "version": "2026.166.1751",
    +    "version": "2026.243.0100",

Nothing else in the compiled wire form moved. This was NOT a compiler regression: the steps,
ordering and every other field are byte-identical. Only the fixture candy's version advanced.

## A note on the golden's fragility

The three fixture candies now resolve from standalone repos, so this golden captures version
strings that advance whenever any of those repos publishes — independent of any change in
charly. That means `main` can go red with nobody touching it, as it did here.

This PR fixes the immediate breakage and restores the ability to regenerate. It does NOT
change that coupling; doing so would mean pinning the fixture candies or projecting the wire
view without the version field, which is a design decision about what the parity test is for
and is deliberately not made unilaterally here.

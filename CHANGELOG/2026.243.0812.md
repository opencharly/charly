### 3. The parse-time prescan never read an imported project's plugin pins

`charly box validate` exited 1 on charly's own main:

```
box/cachyos/charly.yml: parse: node "check-cstream-pod": plan[29]
plugin verb "cstream" takes a MAP input (it declares no primary field for the scalar shorthand)
```

A plugin verb's SCALAR shorthand (`cstream: status`) desugars at PARSE time — before any
out-of-process provider can connect — from the primary the prescan registers off a plugin candy
manifest's `plugin: primary:` block. `prescanDeclaredPluginWords` walked exactly two things: the
ROOT `charly.yml`, and every manifest under its `discover:` paths. It never walked the
`import:` namespaces — and an imported project is a whole project whose beds author plugin-verb
steps exactly like the root file's do.

charly discovers `tools/` only and composes six distros through `import:`, so every plugin
pinned by an imported box was invisible at parse time. The failure shape is an asymmetry that
reads as a broken bed when the bed is fine:

```
charly box validate   in box/cachyos     exit 0     (its file IS the root file)
charly box validate   at charly root     exit 1     (the same file, composed)
```

**The fix** is an import leg symmetric with the discover leg. Two details are load-bearing:

- **Local first.** The parse reads an imported box from its `box/<namespace>` submodule checkout
  when one exists — the error path a failing box names is `box/cachyos/charly.yml`, not a cache
  dir. Resolving the pinned cache instead would prescan a DIFFERENT tree than the one being
  parsed; the gitlink and the import pin drift routinely.
- **At the pin.** With no local checkout the ref resolves WITH its version. An early draft
  stripped it and fetched the default branch — visible as `Downloading …distro-omarchy:main` —
  which would register primaries from a tree the project does not compose.

**What was deliberately NOT done.** `charly/node_desugar.go`'s `pluginPrimaries` table would
have turned the gate green with one line. Its own comment reserves that table for the eleven
frozen live-container verbs and directs a new external verb to declare its primary in its candy
manifest instead. Adding `cstream` there would have hidden the reachability hole permanently,
and every future external verb would have hit it.

This is one half. The other is opencharly/distro-cachyos#55, which pins the verb plugin the bed
uses. Measured independently on the composed tree — **neither half alone clears the gate**:

```
import leg only,  no pin in box/cachyos   exit 1
pin only,         no import leg           exit 1
both                                      exit 0
```

distro-cachyos#55 is MERGED and this PR now advances `box/cachyos` onto it (`a5db8266` ->
`47d5c33a`), so both halves are present here and the gate that was red on main is green:

```

[exit 0]
```

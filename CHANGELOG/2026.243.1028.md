# 2026.243.1028 — chore(deps): repin the advisory-diagnostics chain so the fix reaches the binary

## Summary

The five-repo chain that routes scan advisories into diagnostics — and makes
`charly box validate` say what it checked — is merged and tagged in every owning repo, but
charly still pinned the versions from **before** it. A merged, tagged module is not a shipped
fix until its consumer repins, so none of that chain was in any charly binary.

```
  spec           v0.2026242.1252-0.20260830143259-90c1b7c7a808 -> v0.2026243.707
  sdk            v0.2026242.1217                               -> v0.2026243.714
  plugin-loader  v0.2026237.1427                               -> v0.2026243.719
  plugin-build   v0.2026237.1415                               -> v0.2026243.729
  plugin-box     v0.2026241.343                                -> v0.2026243.729
```

All five move together. Advancing one member of a chain inside an otherwise stale tree
multiplies version skew rather than reducing it, so a partial repin would be worse than none.

The `spec` pin was additionally a **pseudo-version** — `v0.2026242.1252-0.20260830143259-90c1b7c7a808`
names a commit, not a tag. Pin discipline allows only merged refs, so it now names the real
tag `v0.2026243.707`.

```

 2 files changed, 15 insertions(+), 31 deletions(-)
```

Generated from `git diff --stat`. Dependency pins only — no charly source changes.

## How tested

**A/B on one identical, clean tree** (`distro-cachyos` at `7b4e85f`), old binary vs this one:

```
$ git status --porcelain          # clean
$ <charly at the OLD pins> box validate ; echo "exit=$?"
exit=0                            # ← zero output lines. A pass that says nothing.

$ <charly at THIS PR's pins> box validate ; echo "exit=$?"
charly box validate: OK — checked 493 candies, 37 boxes, 26 deploys, 7 distros, 7 builders; 0 warnings, 0 errors
exit=0
```

That difference is this PR's whole effect and is the claim it makes: the same tree, the same
exit code, but the gate now reports what it covered instead of passing silently. A silent pass
is not quotable evidence — which is exactly why the chain was written.

Build and full suite on the **final committed tree**, against the committed `go.mod` with no
`replace`:

```
$ go build ./...            # exit 0
$ go test ./...
ok  	github.com/opencharly/charly/charly                     86.207s
ok  	github.com/opencharly/charly/charly/internal/pluginsgen  31.936s
```

### Caveat, stated rather than buried: the warning COUNT is not proven live

The run above reports `0 warnings`. The counting code is correct by inspection —
`summarize()` walks `diags.Items` and counts `severity == "warning"` — but I could **not**
construct a positive control that makes it report a non-zero value. Five attempts, all still
`0 warnings`:

1. a duplicate pin of the same repo at two versions
2. a local candy directory named after the repo (`layer-charly`)
3. the same, named after the entity the repo actually declares (`charly`)
4. an old direct pin of an entity also pulled transitively (`pod-dbus`)
5. the same entity pinned at two **valid**, cached versions

So this PR claims only what the A/B demonstrates: **the summary line now exists**. It does
**not** claim the `0` is a verified-live count, and the `0 warnings` figure should not be
quoted as a cleared gate elsewhere until a positive control exists. Prior art for that
caution: an early draft of this very summary line printed `0 warnings` on a run that had just
emitted two, which is worse than printing nothing.

## Rulebook compliance

- **R1 (RCA)** — the gate printing nothing was traced to charly pinning pre-chain versions,
  not to the chain being unfinished; fixed by repinning the consumer rather than re-landing
  work already merged.
- **R3 (no duplication)** — pins advanced in place; no parallel requires.
- **R4 (no workarounds)** — no `replace`, no vendoring, no pseudo-version.
- **R5 (delete legacy)** — the pseudo-version pin is replaced by a real tag, not kept beside it.
- **R6 (git safety)** — feature branch, no force-push, no hook bypass.
- **R7 / R10 (prove the gate)** — build, full test suite, and the live A/B all run on the
  final committed tree against the committed `go.mod`.

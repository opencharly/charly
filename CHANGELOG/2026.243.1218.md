# 2026.243.1218 — feat(packaging): declare the OCR engine the artifact_contains_text assertion needs

## Summary
sdk#201 adds artifact_contains_text, the artifact validator that asserts OCR reads given
text out of a screenshot - the assertion separating a surface MAPPED from a surface
RENDERED. It runs HOST-side, on the pulled artifact, and shells out to tesseract.

That is a host runtime dependency, and R9 puts those in this packaging section rather than
leaving them implicit.

## Optional, not required

It lands in optdepends and suggests, not depends. Only a check step that authors
artifact_contains_text needs OCR, and forcing an engine plus a language pack onto every
charly install for an opt-in assertion is the wrong trade. The validator already fails
LOUDLY and actionably when the engine or its data is absent - it distinguishes could-not-
look from looked-and-absent - so a missing optional dependency produces an error naming
the package to install, never a silent pass or a mystery no-match.

## The language pack is listed separately, deliberately

tesseract WITHOUT a language pack reads nothing at all, and says so only on stderr while
exiting with empty stdout. A host that installs the engine and not the data looks exactly
like a host where the text is genuinely absent. That cost real debugging time while
building the validator, so both halves are declared, per format:

    arch   tesseract + tesseract-data-eng
    rpm    tesseract + tesseract-langpack-eng
    deb    tesseract-ocr + tesseract-ocr-eng
    apk    tesseract-ocr + tesseract-ocr-data-eng

ipk is untouched: OpenWrt repos lack even the mandatory charly deps, which is why that
variant already carries an empty depends list.

## Rulebook compliance

- **R1 — RCA every anomaly.** The reason the language pack is a SEPARATE declaration is a
  root-caused failure, not a guess: tesseract with no language data reads nothing and reports
  it only on stderr, which is indistinguishable from a genuine absence to a caller reading
  stdout. Declaring only the engine would reproduce that on every host.
- **R2 — Nothing parked.** The host dependency introduced by opencharly/sdk#201 is declared in
  the same push rather than left for whoever first hits the error.
- **R3 — No duplication.** Declared once per package format in the existing single source that
  `charly generate-packages` reads; no second dependency list.
- **R4 — No workarounds.** The engine is not vendored, shelled around, or made a silent no-op
  when absent.
- **R6 — Git safety.** Branched from a fresh `origin/main`; no force-push, no hook bypass, no
  direct push to main.
- **R7 — Prove behavior, not compilation.** The packaging test — the gate that owns this
  section — is pasted.

# 2026.243.1651 — fix(deps): repin plugin-build so add_candy candies reach the envelope

## Summary

`plugin-build#8` fixed the resolved-project cache key, which ignored the scan scope. Until
charly repins, that fix reaches nobody: `plugin-build` is compiled INTO charly as a `go.mod`
require resolved from the module proxy, so **the pin is the delivery mechanism**.

```
github.com/opencharly/plugin-build/candy/plugin-build  v0.2026243.729 -> v0.2026243.1627
```

Without it, any deploy whose `add_candy:` names a candy that no image closure reaches fails at
compile:

```
fleet compile: candy "@github.com/opencharly/plugin-quickshell/candy/plugin-quickshell:v2026.243.1516"
  not in resolved-project envelope
```

`add_candy:` is the documented way a host-side plugin candy rides into a bed (the precedent is
`distro-arch` → `plugin-spice`), so this was not a niche path — it was the mechanism itself.

### Every diff item

| File | Change |
|---|---|
| `charly/go.mod` | the pin: `v0.2026243.729` → `v0.2026243.1627` |
| `go.work.sum` | the two module hashes the new pin resolves. `task build:binary` refuses to build while a tracked `go.work.sum` is dirty, so it is committed with the pin rather than left to surprise the next builder |

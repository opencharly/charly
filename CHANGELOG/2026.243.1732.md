# 2026.243.1732 — chore(deps): repin plugin-box so the reconcile and warning fixes ship

## Summary

**Two fixes are merged and tagged in `plugin-box` but reach no charly binary, because charly
still pins the version from before them.**

charly requires `plugin-box/candy/plugin-box v0.2026243.729`. Since that tag:

- **opencharly/plugin-box#8** (`v0.2026243.1040`) — `charly box validate` reported `N warnings`
  and never said what any of them were. `emitVerdict` skipped warning-severity items on the way
  out, so a run said "10 warnings" and withheld all ten. A count nobody can act on is not a gate.
- **opencharly/plugin-box#9** (`v0.2026243.1718`) — `charly box reconcile`, which the
  git-workflow rule names as **the** remedy for a `resolved to multiple versions` warning,
  changed the 4 pins it reported and **405 lines in total**. It mutated the parsed scalar and
  re-serialized the whole document; yaml.v3 does not reproduce a folded block scalar (`>-`), so
  every authored `description:` in the file was reflowed. The remedy's own diff was a review
  blocker — the warning it exists to clear could not be cleared with it.

This is the consumer repin that makes both real. Same rule as the previous repin on this branch
lineage: *a merged and tagged module is not a shipped fix until its consumer repins.*

```
 charly/go.mod | 2 +-
 charly/go.sum | 8 ++++----
 2 files changed, 5 insertions(+), 5 deletions(-)
```

Generated from `git diff --stat origin/main...HEAD`. One `require` line and the `go.sum` entries
that move with it; no source changes.

$ strings bin/charly | grep -c '^warning: %s$'                      # 1  (#8)

Then exercised with that stock binary against a real 160KB project, not a fixture.

The after-diff is exactly four `@github…:vTAG` lines. Both runs were made on a clean tree and

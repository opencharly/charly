# 2026.244.0751 — fix(ci): chain release-binary off tag-on-merge completion (workflow_run)

## Summary

The `push: branches: [main]` trigger from #520 is insufficient: auto-merge squash merges (actor `app/github-actions`) fire **ZERO workflow runs** (the tag-on-merge RCA documented this), so the release-binary never runs on the merge push itself — it only ran on the bot's CHANGELOG push, whose HEAD carries no tag, so the upload was skipped (the v2026.244.0726 release was never created).

This chains release-binary off **tag-on-merge completion** (`workflow_run` — the ONE trigger whose event delivery is proven): it builds the newest v* tag and uploads when that tag's release does not exist yet. The binary is stamped with the TAG's CalVer so the distro repos' `charly version` == packaged-version assertion holds. Idempotent: tag-on-merge fires on every validator completion, and the upload is skipped when the release already exists.

## How tested

- RCA: confirmed the #520 fix ran on the CHANGELOG push (d9c17068) with the upload step skipped (no tag at that HEAD); the tag v2026.244.0726 sits at the merge commit c1f6d63f, which fired no workflow run (auto-merge suppression).
- The workflow_run trigger is the same mechanism tag-on-merge itself relies on (proven delivery).
- The build steps are unchanged; only the trigger + tag resolution + upload guard changed.

# 2026.246.2003 — feat(harness): gh_pr_status reports mergeable-state interpretation + needs-update flag

## Summary

Extend the `gh_pr_status` harness extension (`.pi/extensions/github-pr-status.ts`) to interpret the PR's mergeable state and flag when the branch needs updating.

The tool already fetched `mergeStateStatus` but printed it raw (`mergeable: BEHIND`) with no guidance. This change adds:

1. **`mergeableInterpretation(state)`** — maps every GitHub mergeStateStatus value to actionable guidance: BEHIND (update the branch), BLOCKED (checks must pass), DIRTY (conflict), DRAFT, UNSTABLE, CLEAN, HAS_HOOKS.
2. **`needs update: YES|no` line** in the check output — when the branch is BEHIND base, the agent is told to run `gh pr update-branch` (or merge origin/main + push) before the validator can pass / the PR can merge. A BEHIND PR with a PASS verdict still cannot merge until the branch is caught up — this was the exact stall seen on distro-omarchy #38 (validator PASS but merge held on BEHIND).
3. Updated tool description + prompt guidelines to document the new capability.

## How tested

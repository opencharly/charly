# 2026.248.0737 — feat(cache): charly cache status|clear|refresh + the --no-git-cache bypass

## Summary

The git-ref cache operator surface, migrated OUT of core into a command plugin (the architecture-gap fix: a command for a plugin never lives in core):

1. **The `charly cache` command is now the plugin-cache command candy** (opencharly/plugin-cache, compiled-in + external dual placement): `charly cache status|clear|refresh|bypass`. The plugin operates on the git-ref cache DIRECTLY through spec/refs (the established plugin pattern — plugin-box/doctor/loader all import spec/refs): the cache lives in the per-host charly.yml `cache:` section, shared on-disk state.
2. **The bypass is PERSISTED, not a core flag** (spec #95, `refs.GitClient.SetBypass`): `charly cache bypass` writes `bypass: true` into the cache: git: section; a fresh core process honors it at construction. The `--no-git-cache` global flag is DELETED (R5) — the bypass is plugin-owned state.
3. **Core keeps only the mechanism + the singleton** (R5): `cache_cmd.go` + the `Cache` CLI field + the `NoGitCache` flag are deleted; `git_client.go`'s singleton honors the persisted bypass. `plugin-cache` is wired as a compiled-in command plugin (`compiled_plugins:` + go.mod pin + regenerated `plugins_generated.go`).

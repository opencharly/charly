# 2026.249.2310 — fix(check): gate the compiled-in plugin schemas before authored-input validation; pin spec v0.2026249.2231 (offline-fallback latest-tag)

## Summary

Two fixes:

1. **Box-mode plugin schema-registration ordering gap** — a COMPILED-IN plugin unit registers its PROVIDERS at init() but its SERVED SCHEMA only through the sync.Once `loadBuiltinPluginUnits` gate. A box-mode check run inside a fresh container reaches `runPluginVerb` through an entry path that runs NO project plugin load, so `connectBakedPlugin` resolves the init-registered builtin provider immediately (registry hit, no connect) and authored-input validation ran against an EMPTY input-def registry — every `plugin verb:*` check step failed with `"no input def registered (schema not loaded)"` while the deploy phase (whose `loadDeployPlugins` path runs the gate) passed. Fix: `runPluginVerb` now runs the SAME idempotent gate the kind-class dispatch already runs (`runPluginKind`) before any resolve/validation; a broken builtin schema fails the verb loudly.

2. **Spec re-pin v0.2026249.2231** — carries opencharly/spec#108 (the persisted `latest_tags` cache is an OFFLINE FALLBACK, never fresh data — the root fix for the stale-latest-tag anomaly where fresh runs minutes after `v2026.249.2212` was tagged still resolved plugin refs to `v2026.242.0932`). Companion pin bumps forced by compilation against the new spec: sdk 2114, plugin-check 2119, plugin-fleet 2126, plugin-preempt 2116, plugin-migrate 2144 (the IsGroup-migration tags), plus the migrate verb's own 2026.249.2125 schema-stamp output on `charly/charly.yml`, `testdata/charly.yml` and six hardcoded test-fixture stamps. The broader config conversion (group-node rewrites) is NOT part of this PR.

# 2026.251.1204 — deps(vm): plugin-vm v0.2026251.1105 — the idempotent from:-drive clone build (kills the overlapping-lane overlay write-lock race)

## Summary

Pins `github.com/opencharly/plugin-vm/candy/plugin-vm` to **v0.2026251.1105** (plugin-vm #29, merged, tagged). The fix gives the `from:`-drive clone build the idempotent-discipline every other source-kind build has: `BuildClone` skips re-creating the per-entity target overlay when it already materializes the resolved snapshot, instead of unconditionally clobbering `output/qcow2/<entity>/disk.qcow2` while a sibling lane's domain holds it open read-write (the measured `Failed to get "write" lock` — 16/21 runs in the eval-omarchy 16-lane verification wave). Backing continues to resolve to the snapshot-store disk (`snapshots/<tag>/disk.qcow2`) opened read-only; the refcount bump / delete-refusal-while-referenced / re-capture-isolation model is unchanged. Runtime now matches the documented vm backing-chain contract. The redo wave for the 14 eval lanes that hit the race runs on this binary.

# 2026.254.0903 — docs: relocate the docs: config node to the top-level charly.yml (the generator's config source)

## Summary

Relocates the `docs:` config node from the module-level `charly/charly/charly.yml` to the **top-level** `charly.yml` of the charly repo — the location the docs generator (`readDocsConfig`) and the runtime project loader actually read. The module-level placement was never consulted, so the config-driven generator fell back to its baked default and aborted with `read go.mod charly/charly/go.mod: no such file` (ENOENT; discovered live, RCA'd, spike-proven — appending the node at the top level passes the go.mod gate).

- Node values unchanged and already top-level-relative-correct: `compiled_plugins_path: charly/charly.yml`, `go_mod_path: charly/go.mod`, `release_repos: [plugin-review, plugin-pipeline]`, `extra_repos: [plugin-gh, plugin-docs]` (this PR adds plugin-docs so the generator self-documents — the `docs` command word + plugin-docs page now emit), projections + hand_authored defaults.
- Module-level copy removed (one config per repo, R3/R5); fixture mirror value aligned in `harness_kind_load_test.go`.

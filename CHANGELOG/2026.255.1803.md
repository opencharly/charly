# 2026.255.1803 — fix(deps): pin plugin-check v0.2026255.1732 — the --steps-file authoring fix

## Summary

Pin **`plugin-check v0.2026255.1732`** (the merge tag of `plugin-check#49`) so the **`--steps-file` authoring fix** reaches users, plus its required transitive `sdk v0.2026255.1708`.

**Why a pin is the only delivery path:** charly compiles plugin-check in (it is a verb/step plugin, not one of the nine welded command plugins), so `charly/go.mod` is what a user runs. The diff is exactly those two version lines (`charly/go.mod` 4 ±, `charly/go.sum` 4 +).

**What the pinned revision does:** `charly check live <bed> --steps-file <file>` now reads the **authoring form** — the `<word>: <input>` plugin-verb sugar is desugared through the loader's own seam (`loaderkit.DesugarSteps`, `opencharly/sdk#252`) and the document is decoded through JSON so the matcher shorthand keeps its operator. Previously the file was raw-`yaml.Unmarshal`led into `[]spec.Step`, which **silently dropped the sugar**: the step reached the engine carrying no verb, and the run exited **2 without executing it** — so a caller reading exit 2 as *"the control rejected as required"* would be satisfied by a check that **never ran**. That is a **false positive for the control's assertion** (not a passing check, which is what exit 2 means for a step that does run).

# 2026.255.2306 — docs(plugin-loader): bakedPluginDir is the package's path — the image bake writes elsewhere (#595)

## Summary

`charly/plugin_loader.go` documented `bakedPluginDir` as *"the FHS system path a candy's
`bake_plugin:` step copies a pre-built provider binary to at image-build time"*. After
**opencharly/sdk#254** that is no longer what happens: the image bake writes
`/usr/local/lib/charly/plugins` (and registers it through `CHARLY_PLUGIN_DIR`) precisely because a
build step must not write into the package-owned path — issue **#595**.

The FHS path itself is unchanged in role: the distro package owns it and lays its own baked plugins
there, and the loader still SEARCHES it, so a package's plugins keep resolving. Only the comment was
wrong.

**Comment-only change — no behavior, no code.** The behavior is covered by sdk#254's regression
test and its isolating negative control.

# 2026.256.0759 — ci(release-binary): strip release binaries (-s -w)

## Summary

Build every binary produced by `release-binary.yml` with `-ldflags "-s -w"`
(strip the symbol table + DWARF), and add a step that fails the build if any
produced binary is still unstripped.

Go binaries carry a symbol table and DWARF debug info by default. For the
`charly` binary plus its welded plugins that debug data is ~47% of each native
package's compressed size. The consequence surfaced on the downstream
`charly-arch` repo: its Pages artifact measured **1,191,015,549 bytes (1.19 GB)**,
over GitHub Pages' 1 GB artifact limit, so the deploy emitted
`Uploaded artifact size … exceeds the allowed size of 1 GB`.

The four `go build` invocations (charly amd64/arm64, plugin amd64/arm64) gain
`-s -w`; a new `Verify the built binaries are stripped` step asserts no symbol
table / `.debug_*` sections remain. This is the single shared producer all
distro repos (arch/fedora/debian/ubuntu/alpine/openwrt) consume, so the fix
lands once (R3) rather than in each packaging workflow.

### 2. Coverage that fails without the change

The new `Verify the built binaries are stripped` step uses `file` +
`readelf -S`; with `-s -w` dropped it is red. Local before/after on the same
binary:

```
$ file /usr/bin/charly | sed 's/.*, //'
not stripped
$ file /tmp/opencode/charly.strip | sed 's/.*, //'
stripped
```

### 3. Package-size impact (real rebuild of the published assets)

Rebuilt the published `v2026.255.2306` packages locally from the release assets
with the packaging plugin, first as-published, then from stripped copies of the
exact same binaries:

| variant (amd64) | unstripped | stripped (`-s -w`) |
|---|---:|---:|
| charly | 179,580,259 B | 95,675,345 B |
| charly-full | 195,020,309 B | 103,781,756 B |
| charly-minimal | 69,753,819 B | 37,215,583 B |
| **amd64 total** | **444,354,387 B** | **236,672,684 B** |

The unstripped default package matches the published
`charly-2026.255.2306-1-x86_64.pkg.tar.zst` (179,580,217 B — 42 B of tar
metadata), confirming the reproduction. Extrapolating ~47% to the measured arm64
sizes (`164.3 / 178.4 / 63.9 MB`) puts the 6-package Pages artifact at **~0.64 GB**
(incl. the two duplicate stable-name copies) — under the 1 GB limit.

### 4. Stripping does not degrade diagnostics

- The dispatch run's `Verify the built binaries report the CalVer` step ran the
  stripped amd64 binary (`./bin/charly-linux-amd64 version`) and passed, and the
  plugin `.providers` manifests were generated by that same stripped binary.
- `go version -m` still reads the build info (the arm64 CalVer assertion relies
  on it).
- Go's pclntab survives `-s -w`, so panic tracebacks keep `file:line` symbols:

```
$ ./panicbin          # built with -ldflags "-s -w"
panic: boom
goroutine 1 [running]:
main.main()
        /tmp/opencode/gotest/main.go:2 +0x25
```

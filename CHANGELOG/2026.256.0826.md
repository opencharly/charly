# 2026.256.0826 — fix(packaging): plugin-pipeline belongs in the `full` variant + TestMain system-layer isolation

## Summary

Two correctness fixes surfaced while verifying the `charly-arch` artifact RCA:

1. **`full` variant completeness.** The `full` variant is described as the
   complete welded set ("All twelve welded command plugins"), but commit
   `23d69296` ("plugin-pipeline joins the release") added `plugin-pipeline` to
   `default` only — `full` stayed at 11 and omitted it, and both variant
   descriptions were left one count stale (`default` said "nine" with ten
   plugins). Add `plugin-pipeline` to `full`, correct the descriptions
   (default ten / full twelve), and add `TestPackagingFullVariantIsComplete`.
   The existing `TestPackagingVariantsCoverWeldedPlugins` only asserts the
   UNION covers every welded plugin, so it is satisfied as long as any variant
   names pipeline; the new test asserts the variant that claims completeness
   actually carries every welded plugin.

2. **TestMain system-layer isolation.** Installing the native package ships
   `/etc/charly/charly.yml`, so `go test ./...` failed on any host with charly
   installed: `LoadUnified` merges the system layer and
   `TestLoadUnified_AbsentFileReturnsNotPresent` saw `present=true` for an
   empty dir. `TestMain` already isolates the user layer via `XDG_CONFIG_HOME`;
   also point `CHARLY_SYSTEM_CONFIG` at an absent file — the same system-layer
   isolation `sdk/loaderkit`'s own `TestMain` applies.

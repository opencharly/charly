# 2026.260.1303 — fix: gitignore .claude/worktrees/ (the mandated per-session worktree dir)

## Summary

Adds `.claude/worktrees/` to `.gitignore`.

**The defect (RCA).** `AGENTS.md` "Hard Cutover by Default" mandates every session
work in a linked feature worktree under `.claude/worktrees/<slug>/`. That path is
per-session, per-machine ephemeral state — the same class as `.check/` and
`scratchpad/`, both already gitignored — but `.gitignore` omitted it.

**Consequence (measured).** Every session that follows the convention leaves the
tree dirty:
```
$ git -C charly status --short
?? .claude/worktrees/
$ bash scripts/verify-pins.sh
FAIL: charly: dirty working tree
```
So the pin gate reports a charly checkout that is actually clean of source
changes, purely because it uses the mandated worktree convention. This blocked
the umbrella's `task verify` (opencharly/opencharly#212 and the campaign's
earlier gate runs).

## How tested

```
$ git check-ignore -v .claude/worktrees/
.gitignore:82:.claude/worktrees/	.claude/worktrees/     # now ignored
$ git -C charly status --short
(clean — the worktree dir no longer dirties the tree)
```
The umbrella's `scripts/verify-pins.sh` `FAIL: charly: dirty working tree` clears
once this merges and the umbrella's `task sync` bumps the charly gitlink.

## Rulebook compliance

- R1: the failure was root-caused to a missing `.gitignore` entry, not dismissed.
- R3: no duplication — one entry matching the existing `.check/`/`scratchpad/` pattern.
- R4: the fix is at the source (the convention is mandated; the ignore was the gap),
  not a per-checkout workaround.

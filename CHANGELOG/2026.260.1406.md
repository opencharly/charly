# 2026.260.1406 — fix(loader): flat imports must not abort the plugin prescan

## Summary

`prescanDeclaredPluginWords` decoded the project root's `import:` directive as
`[]map[string]string`. `import:` is a **mixed-shape list** — a bare string (a FLAT import,
e.g. the documented per-kind sibling split `- vm.yml`) **or** a single-key `alias: ref` map
(a namespaced import). A bare-string entry cannot unmarshal into `map[string]string`, so the
whole struct unmarshal failed and the function returned early (via
`prescanRemotePluginManifests`), which **skipped the local `discover:` walk entirely**. The
plugin pin that lives in a discovered candy manifest was therefore never prescanned, so a
plugin-provided kind word (`pipeline:`, `examplekind:`, …) was never registered and the loader
rejected it in **every** document — including the root file's own inline entity.

### RCA (R1)

Minimal reproducer:

```yaml
# charly.yml
version: 2026.249.2125
import:
    - omarchy: '@github.com/opencharly/distro-omarchy:v2026.251.2301'
    - pipes.yml
discover:
    - path: candy
      recursive: true
```

```yaml
# pipes.yml
my-pipe:
    pipeline:
        stages:
            - id: s
              kind: command
              command: 'true'
              expect_exit: 0
```

- **Mechanism**: the hand-rolled `Import []map[string]string` (`charly/plugin_prescan.go`).
- **Missed control**: `spec.ImportList` (`spec/spec/load_directives.go`) is the ONE canonical
  mixed-shape decoder; the prescan had forked it (R3).
- **Blast radius**: any project using the documented flat per-kind file split together with
  any plugin-provided kind.

### Fix

Use `spec.ImportList` (R3 — delete the second decoder). Both import shapes now share ONE
`prescanAndCollect(path, &allData)` helper (R3 — no duplicated
`prescanPluginManifest` + `ReadFile` + append idiom); the flat branch reads a local sibling
file so its own pinned plugin refs are prescanned.

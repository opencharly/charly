# 2026.260.2044 — fix(deps): adopt the shared sdk/spec pins across all modules, and make mods:tidy adopt them

## Summary of changes

Adopts the shared `sdk`/`spec` pins across every in-repo module that carries them, so charly builds against the current sdk — and closes the gap that let those pins drift unnoticed.

- `charly/go.mod` + `charly/go.sum`: `plugin-vm` `v0.2026253.1802` → `v0.2026260.1314`, carrying the transitive refresh (`sdk` → `v0.2026260.1434`, `spec` → `v0.2026259.2033`, `golang.org/x/*`).
- `tools/generate-packages`, `tools/golden-cloudinit`, `tools/golden-compile`: adopt the same shared pins, which the canonical-go.mod gate requires.
- `taskfiles/Modules.yml`: `task mods:tidy` — the remedy that gate names — ran a bare `go mod tidy` per module; tidy never RAISES an already-satisfied require to a newer version, so the task reported success while the gate kept failing with "run task mods:tidy". It now reads the shared pins from `charly/go.mod` (the gate's own anchor) and pushes them with `go mod edit` before tidying.
- `tools/gomod-canonical/gomod_canonical_test.go`: a code COMMENT carried a stale pin value (`v0.2026241.1032`) that this sweep removes, so it is rewritten to describe the drift without naming a version that ages out.
- `.golangci.yml`: the root lint-config header described a tree that no longer exists and made claims this PR disproves — "the 95 modules … the 91 `candy/*` modules and the 4 `tools/*` modules" (the in-repo `candy/*` modules are gone; the tree has 6 modules, 5 of them `tools/*`), and that `tools/golden-cloudinit` / `tools/golden-compile` "do not build" (both build and lint clean now). Rewritten to state the scope structurally and to describe the linter set the file actually sets: `default: standard` + gofmt + the errcheck exclusions, with the eleven curated linters living in `charly/.golangci.yml`.
- `taskfiles/Modules.yml`: the two new `sed` extractions use POSIX BRE (`[[:space:]][[:space:]]*`), not the GNU-only `\+`, so the task is not silently GNU-sed-only.
- `.github/workflows/ci.yml`: adds a `Test tools modules` step AND extends `golangci-lint` to the tools modules — closing the detection hole below on both the test and the lint side.

**Root cause:** `sdk v0.2026260.1434` changed `vmshared.VmDiskDir` to return `(string, error)`, so the pinned `plugin-vm@v0.2026253.1802` no longer compiles:

```
vm_clone.go:261:28: multiple-value vmDiskDir(vmName) (value of type (string, error)) in single-value context
vm_create_orchestrate.go:78:29: ... (and 3 more)
```

This surfaced while cross-compiling charly for armv7 (`opencharly/plugin-jetkvm` needed the sdk bump for an unrelated reason: `sdk/buildkit` did not compile for 32-bit ARM, fixed in `opencharly/sdk#263`).

**Three defects this adoption surfaced, all fixed in this cutover (R1/R2):**
1. The `tools/*` shared-pin drift: the canonical-go.mod gate **already failed on `origin/main`** (measured in a detached worktree — stale sdk `v0.2026255.1708`, the same three modules).
2. `task mods:tidy` could not perform the alignment that gate told you to run — a doc-vs-reality divergence, fixed at the task.
3. **The detection hole that let (1) go unnoticed:** charly's CI ran `go test ./charly/...` and `golangci-lint run ./charly/...` only, while the pin-bearing modules live beside it under `tools/` as separate `GOWORK=off` modules — and the root `.golangci.yml` header states it governs `tools/*` too. The gate was red with nothing running it. This PR wires the tools modules into the `go` job for BOTH tests and lint, so the hole is closed in-tree rather than deferred.

**Closes / relates to:** depends on `opencharly/sdk#263` (merged, tag `v0.2026260.1434`).

**Breaking change + rollback:** `none` — dependency pins, a dev taskfile and CI steps; no API or CLI change. The branch carries eight commits, which the org's squash-merge collapses into ONE landing commit:
  - `b8f51663` — the pins, the `tools/*` alignment, the `mods:tidy` repair and the stale-comment sweep;
  - `a50a73ab` — the `Test tools modules` CI step;

  - `8e742549` — the POSIX-BRE `sed` fix in the new task code;
  - `8002d533` — the `Modules.yml` header now describes the ADOPTION the task performs (the header still said it only kept go.sum in step);
  - `1a9530fc` — the root `.golangci.yml` header corrected to the current tree (it claimed "95 modules … 91 candy … 4 tools" and that `golden-cloudinit`/`golden-compile` "do not build"; the tree has 6 modules and those two build and lint clean);
  - `e1fc939e` — correction to that header: it must state the linter set the file actually sets (the eleven curated linters live in `charly/.golangci.yml`, not here);
  - `d81d0e4d` — the errcheck-exclusion rationale in that file no longer names "the 91 candy modules" either.

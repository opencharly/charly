# 2026.262.1101 — fix(omarchy): install linux-omarchy, the kernel 4.0.4 requires

## Summary of changes

**RCA + fix: omarchy 4.0.4's installer aborts because its kernel has no headers — the charly-embedded omarchy installer template pinned `linux`, but 4.0.4 requires `linux-omarchy`.**

Live RCA (SPICE screenshot of the `check-omarchy-eval-base-inst` guest, 2026-09-19):

```
Omarchy installation stopped
Installer exited with status 1
failed phase: Validating boot setup: linux (7.2.3-arch1-3) has no kernel headers
```

The 4.0.3 → 4.0.4 configurator diff is exactly one value: `detect_kernel()` changed `echo linux` → `echo linux-omarchy`. It is load-bearing — 4.0.4's install orchestrator appends `f"{kernel}-headers"` for each kernel and runs `_validate_kernel_headers`, aborting when the matching headers are missing from `/usr/lib/modules/<release>/build`. The vanilla `linux` package ships no headers and the omarchy offline mirror has none, so `kernels: ["linux"]` fails at "Validating boot setup".

charly's embedded `omarchy:` distro installer template is a field-for-field port of the 4.0.1 configurator, which pinned `linux`. This updates both JSON fields (`omarchy_install.storage.kernel` and `kernels[]`) to `linux-omarchy`, mirroring the 4.0.4 configurator.

Concrete edit (1 file, +13/−4): `charly/charly.yml` — the `omarchy:` distro entity's installer template.

**This was the blocker for every omarchy 4.0.4 bed** — the install never completed, so no SSH key was injected and prepare-venue's readiness wait spun to its 30-minute cap. (The eval bed's prepare-venue also needed `opencharly/plugin-deploy-vm#20`, which removes a separate unsatisfiable agent gate; the live run below served both.)

# 2026.262.1157 — cleanup(charly): drop the unreachable plugin protocol-version gates

## Summary of changes

Sibling of `opencharly/spec#138` and `opencharly/sdk#265`. Removes charly's two unreachable plugin protocol-version gates and the version it carried in `Describe`.

RDD (full analysis in the spec PR) established both gates guarded nothing:

- **`buildUnitInProc`** (compiled-in plugin): a compiled-in plugin advertises charly's OWN const (MVS unifies sdk), so `caps.GetProtocolVersion() != transport.ProtocolVersion` was `x == x` — a tautology.
- **`buildUnit`** (out-of-process plugin): go-plugin's handshake already rejected a transport-incompatible binary at **Connect, before Describe** — the gate was **unreachable**.

Concrete edits (3 files, +10/−38):

- `charly/plugin_grpc.go` — remove the `buildUnit` version gate; drop the `ProtocolVersion` from `metaGRPCServer.Describe`.
- `charly/plugin_inproc.go` — remove the `buildUnitInProc` version gate.
- `charly/plugin_grpc_test.go` — remove `TestBuildUnitRefusesProtocolMismatch`.

**What is NOT changed** — and why, measured:

- **The wireframe gate.** A plugin's wireframe contract is the CUE schema it serves over `Describe`; `registerPluginUnitSchema` splices it onto the host base, and a genuine capability gap is a hard CUE error.
- **The go-plugin handshake version** (frozen at `2` in `spec/transport`). Omitting it refuses already-built plugins whose wireframe is compatible (measured: `incompatible API version with plugin. Plugin version: 2, Client versions: [0]`) — a breakage with no capability gap.

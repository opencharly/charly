# 2026.263.0616 — fix(release): weld plugin-review v2026.263.0549 — bounded generation + separate-message thread delivery

## Summary

Bump the **welded** `plugin-review` pin from `v2026.255.1648` → **`v2026.263.0549`**
so the next charly release's plugin bundle carries the two engine fixes that merged
into `opencharly/plugin-review#10`:

1. **Bounded generation** — the engine now sends `reasoning_effort: low` +
   `max_tokens: 65536`, so a reasoning model is no longer free to generate
   megabytes of thinking before answering (measured: 1.75 MB / 786 s unbounded vs
   47–107 s bounded, with a verdict present).
2. **Separate-message thread delivery** — `get_pr_body`, a paginated comment
   `get_pr_thread` INDEX, and `get_pr_comment {id}`, so the PR body, the index and
   each comment travel as their own bounded tool message instead of one aggregate
   blob that the 64 KiB per-message cap truncated (measured: `65,536 of 113,650
   bytes` — the thread tail, including the newest review rounds and the maintainer
   sign-off, was structurally invisible to the validator).

**Why this PR is the unlock.** The org PR validator runs `charly review` from the
**pinned charly release bundle** (`charly-linux-amd64` + `charly-plugins-linux-amd64.tar.gz`),
not from `plugin-review@main`. The release welds the plugins from this very file,
so merging `plugin-review#10` alone changed nothing in the running gate — the
bundle still carried `v2026.255.1648`, an engine that is BOTH unbounded (so a
large-context review burns past the 20-minute wall clock and is cancelled with no
verdict) AND aggregates the thread into a blob it then truncates. This one-line
weld is what makes the merged fix reach the gate.

The precedent is `#593` (`weld plugin-review v2026.255.1648 — it carries the
x-opencode-session fix`), which pinned the engine half of a previous org-wide
validator outage and was exactly this one line.

**Why the weld PR itself can be reviewed by the OLD engine.** Its diff is one line
of `scripts/host-command-plugins.txt`, so the review context is small: the
unbounded generation completes well inside the wall clock and yields a verdict.
The large-context PRs (`plugin-review#10`, `spec#140`, `.github#102`) are the ones
the old engine cannot finish — and they are already signed off (T13/T4) or land
after this weld.

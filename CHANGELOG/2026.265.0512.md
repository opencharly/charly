# 2026.265.0512 — fix(release): weld plugin-review v2026.265.0505 — the measured-best sampling defaults

## Summary

Bump the **welded** `plugin-review` pin from `v2026.263.1956` → **`v2026.265.0505`** so the next charly release's plugin bundle carries the fixed review-engine defaults (merged `opencharly/plugin-review#18`).

The branch also passed through `v2026.264.1425` (the ONE-call engine rewrite); that intermediate value is wholly superseded and is not in the net diff. The **net change from `main` is one line**: `v2026.263.1956` → `v2026.265.0505`.

**The fix (#18):** the engine sampled at `temperature=0.2`, a near-greedy choice that collapsed into degenerate repetition — once a high-probability token (`Hmm.`) won the argmax it self-reinforced and the model emitted it thousands of times (measured `2,533–38,472×`) with **no verdict**. #18 ships the **single measured-best default set** for `deepseek-v4.1-flash`, identical across `config.go`, `charly.yml var:` and the org environment:

| knob | value |
|---|---|
| `temperature` | `1.0` |
| `top_p` | `0.95` |
| `frequency_penalty` | `0.5` |
| `presence_penalty` | `1.0` |

The four-value set is the configuration that measured **0 collapses in 26 runs** (versus 1 in 17 at the official sampling alone). The same PR adds `TestOfficialSamplingDefaults`, `TestModelDefaultsMatchCharlyYML` (locks `charly.yml` to the Go constants) and `TestSamplingTrace` (the debug trace now prints the resolved sampling).

**Why this PR is the unlock.** The org PR validator runs `charly review` from the **pinned charly release** (`charly-linux-amd64` + `charly-plugins-linux-amd64.tar.gz`), not from `plugin-review@main`. Merging #18 alone changed nothing in the running gate — this one-line weld is what makes the fixed defaults reach it. Precedent: `#622`/`#624` were the same one-line weld for the previous engine fixes.

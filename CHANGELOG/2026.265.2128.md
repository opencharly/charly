# 2026.265.2128 — fix(charly): re-pin sdk to the config-stack overlay fix + sweep the stale test comments

## Summary of changes

Re-pins `github.com/opencharly/sdk` to **v0.2026265.2104** (the merged fix from opencharly/sdk#270) and sweeps the three test comments that documented the OLD three-layer config stack.

**Why the pin bump.** opencharly/sdk#270 removed `spec.DefaultDeployConfigPath()` from `loaderkit/config_stack.go`'s stack. Before it, the per-host deploy overlay (`~/.config/charly/charly.yml`) was raw-merged as a project DOCUMENT layer, injecting a deploy-level member's top-level persisted copy next to the member its owner still declares nested — which `FoldMembers` rejects (`peer name "..." collides with an existing deploy/bed/peer entry`). Every member-bearing bed failed at `steps=1`.

**The sweep (opencharly/charly#630).** With the pin advanced, three test comments asserting the old "sdk v0.2026250.702+ LoadUnified merges system → user → in-dir" behavior are now false, and the per-test `t.Setenv("XDG_CONFIG_HOME", t.TempDir())` they justified is no longer needed — `TestMain` already sets `XDG_CONFIG_HOME` package-wide, and the per-test isolation existed ONLY to shield against the user-layer merge that is now gone. Swept:
- `charly/layers_test.go` — removed the stale comment + `t.Setenv`.
- `charly/plugin_bootstrap_test.go` — removed the stale comment + `t.Setenv`.
- `charly/unified_test.go` — removed the stale comment + `t.Setenv`.

**Concrete edits:**
- `charly/go.mod` — `github.com/opencharly/sdk v0.2026260.1434` → `v0.2026265.2104`.
- `charly/go.sum` — the sdk + spec checksums (tidy also advances `github.com/opencharly/spec` to `v0.2026262.957`, the version the bumped sdk requires).
- the three test files above.

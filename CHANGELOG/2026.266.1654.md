# 2026.266.1654 — feat(engine): engine-provider class + host call-site migration (Phase 1, v2)

## Summary

Phase 1 of the nerdctl engine-provider-class cutover (`plan/nerdctl-integration.md`). This PR lands the **engine provider class and its first host consumer**. The pin-forced schema migration, the merged plugin pins, and the `deploy_add_cmd.go` jump-caller migration are **already on `main`** (landed by #635); this PR does not repeat them.

**The 14-file diff, item by item:**
- **`charly/engine_provider.go`** (new) — the compiled-in servant of the `engine` class. It answers every engine op by delegating to the pure body `container.InvokeEngineOp`, so the op behavior is written ONCE and served identically compiled-in or out-of-process. Registers `engine:podman` / `engine:docker` at package init (the dedicated-provider pattern).
- **`charly/build_overlay.go`** — the host consumer: the overlay base-image local CalVer probe resolves its engine binary through the class (`hostEngineBinary()` → `Registry.ResolveEngine` → `provider.Invoke(describe)` → `container.InvokeEngineOp`) instead of a hardcoded `"podman"` literal.
- **`charly/engine_provider_test.go`** (new) — resolves each word, asserts `ClassEngine`, invokes `describe` through the provider, asserts `hostEngineBinary()` is non-empty.
- **`charly/provider.go`** — `ClassEngine` (the class the servants serve).
- **`charly/provider_registry.go`** — `ResolveEngine(word)`.
- **`charly/provider_classes_parity_test.go`** — ClassEngine joins the closed-set parity assertion.
- **`charly/refs_sweep_test.go`** — the scanner fix (R4a, below).
- **`box/<distro>` gitlinks** (arch/cachyos/debian/fedora/omarchy/ubuntu) — bumped to the merged schema-261 distro HEADs so CI's materialised submodules load at `2026.261.1747` (main's gitlinks predate the stamp).
- **`go.work.sum`** — refreshed by `go work sync` against the merged module graph; the `openai-go`/`gjson`/`tidwall` entries are the transitive surface of the merged `plugin-review`/`plugin-*` requires now in the workspace graph (no `require:` is added by this PR — only the checksum file is updated).

**Scanner fix (R4a).** `charly/refs_sweep_test.go` false-positived on documentation: a candy's `content:` skill block embeds a fenced markdown example that lists candy names, and the raw-line scanner flagged those as un-swept bare refs. Rewriting the docs to satisfy a false positive is forbidden (R4a), so the **scanner** now skips YAML block-scalar bodies (`stripBlockScalarBodies`); a live `require:`/`candy:` list is never a block-scalar body.

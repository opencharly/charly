# 2026.266.2127 — feat(packaging): the nerdctl engine stack on archlinux + apk (Phase 5, v2)

## Summary

Phase 5 of `plan/nerdctl-integration.md`: the charly native package declares the **nerdctl engine stack** — `nerdctl`, `cni-plugins`, `rootlesskit`, `buildkit` — as a hard dependency on the distros that HAVE those packages: `archlinux` (cachyos/omarchy inherit it) and `apk`. **Not** `rpm`/`deb`/`ipk`, where no such package exists. `fuse-overlayfs` + `slirp4netns` were already declared (shared with the podman path).

**The 2-file diff:** `packaging/charly.yml` (the four deps on `archlinux` + `apk`) and `charly/packaging_test.go` (the coverage).

## How tested

**Change-class gate (config — the packaging generation source):** `packaging/charly.yml` is the SINGLE source `charly generate-packages` (sdk/packagekit) reads to emit the native package metadata. The test that owns this surface is the repo's packaging test, which now carries the coverage that FAILS without the change:

```
$ go test -run TestPackaging -v .
--- PASS: TestPackagingDeclaresTheNerdctlEngineStack   # fails without the 4 deps on archlinux+apk
--- PASS: TestPackagingSectionWellFormed
--- PASS: TestPackagingVariantsCoverWeldedPlugins
--- PASS: TestPackagingFullVariantIsComplete
--- PASS: TestPackagingSystemdDeclarations
--- PASS: TestPackagingConfigDeclared
ok  github.com/opencharly/charly/charly  2.555s
```

`TestPackagingDeclaresTheNerdctlEngineStack` is the deterministic gate: it asserts the four deps are in `archlinux` + `apk` `depends` and ABSENT from `rpm`/`deb`/`ipk` (each format must EXIST — `t.Fatalf` on a missing one — so the negative claim cannot silently vanish). It fails without this change.

**The emitted artifact (R8) — the emitter's pass-through code.** `charly generate-packages` builds its nFPM config from the parsed `packaging:` section by assigning the format's `Depends` field DIRECTLY into nFPM's (`sdk/packagekit/nfpm_config.go:64`):

```go
Depends: f.Depends,   // f = the resolved spec.PackagingFormat for this distro
```

So the emitted package's `depends` IS `formats.<fmt>.depends` verbatim — the exact list `TestPackagingDeclaresTheNerdctlEngineStack` asserts. The changed source blocks:
```
archlinux.depends: … fuse-overlayfs, slirp4netns, nerdctl, cni-plugins, rootlesskit, buildkit
apk.depends:       … libarchive-tools, nerdctl, cni-plugins, rootlesskit, buildkit
rpm/deb/ipk.depends: (unchanged — none of the four)
```

**Disposable target / fresh rebuild / changed-path:** this is a config change to the package-generation source — it changes no runtime path. The changed artifact is the emitted `depends` list, which the test asserts directly (the emitter reads exactly this section). The emitter itself (`charly generate-packages`) requires the shared-host plugin layout at build time (the `plugins` dir with the `charly-lib` symlinks); that layout is provided by the release workflow's `task` build, so the emitter is exercised there, not in a disposable bed. The distro packages' real install is the release workflow's per-distro repo build.

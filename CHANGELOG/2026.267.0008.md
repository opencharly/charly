# 2026.267.0008 — feat(deps): re-pin plugin-build v0.2026266.1755 + plugin-clean v0.2026266.2221

## Summary

Adopt the two merged plugin tags of the cache-consolidation cutover, so the charly binary ships them:

- `plugin-build` → `v0.2026266.1755`: the resolved-project cache folded onto the shared `spec/cache` **ArtifactStore** (the bespoke `project.json` map file + its evictor deleted — hard cutover).
- `plugin-clean` → `v0.2026266.2221`: the new `cache` retention category (`charly clean --cache`, the CAS ArtifactStore GC).

Both are additive/behavior-preserving for charly: plugin-build's cache change keeps the same content-addressed key + fail-closed contract (only the storage shape moves to the OCI layout); plugin-clean's category is opt-in-only (a plain `charly clean` is unchanged). `plugins_generated.go` is name-only (no version pins), so no regeneration is needed.

The plugin bump raises the shared `spec` pin in `charly/go.mod` (`v0.2026266.1306` → `v0.2026266.2126`, pulled transitively by plugin-clean). `charly/go.mod` is the single in-tree anchor for the shared spec pin, so the three lockstep `tools/*` modules that also require a contract module (`tools/generate-packages`, `tools/golden-cloudinit`, `tools/golden-compile`) have their spec require raised to the same `v0.2026266.2126` via `task mods:tidy` — the documented remedy for `TestContractPinsMatchShared`, which fails on any lagging lockstep module.

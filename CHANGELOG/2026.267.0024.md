# 2026.267.0024 — fix(charly): re-pin plugin-dsh for the token-aware web probe

## Summary

Re-pins the compiled-in `plugin-dsh` so the `command:dsh` / `verb:dsh` surface carries the token-aware web probe (and, as the intended side effect, advances charly's dependency set to trigger the next charly release).

- `charly/charly/go.mod`: `github.com/opencharly/plugin-dsh/candy/plugin-dsh` `v0.2026237.1419` → **`v0.2026266.2321`** — the merged tag `candy/plugin-dsh/v0.2026266.2321` (squash `819f6f9`) of **opencharly/plugin-dsh#5**.
- `charly/charly/go.sum`: the two matching checksum lines (old pair removed).
- No Go source changed; `plugins_generated.go` and the repo-root `go.work` are name-only and regenerate byte-identically (the `pluginsgen` step of `task build:binary` was run and left the tree clean).

What the new pin carries (opencharly/plugin-dsh#5): `verbWebRunning` and `DshStatusCmd.Run` now read the launch token the dsh candy's entrypoint persists to `$DSH_HOME/web-token` and authenticate with `?token=<token>`. Before it, the stale probe hit the token-fenced web UI without one.

Closes/relates to: opencharly/plugin-dsh#5 (the plugin change), opencharly/pod-dsh#4 (the bed relocation + token-aware checks).

**Breaking/rollback:** none — a dependency version bump. Rollback = revert this commit.

# 2026.267.0802 — fix(opencode): port the gate plugin to the V2 plugin contract

## Summary

The opencode gate plugin in this repo (`.opencode/plugin/charly-gates.ts`) was
written to the **V1** opencode plugin contract: a default-exported function that
receives `{ directory }` and returns a keyed hook map
(`{ "tool.execute.before": … }`).

opencode ≥ 2.0 (this was measured on **2.0.16**) no longer loads that shape. The
loader logs a **WARN** and keeps starting:

```
msg="failed to load plugin" target=.../.opencode/plugin/charly-gates.ts
cause="Cause([Fail(PluginModule.LoadError: Plugin must export a default definition
  with an id and an effect or setup function. (cause: SchemaError(Expected object
  at [\"default\"])))])"
```

Because it is a WARN, startup succeeds and the failure is silent: the
pre-commit / pre-push gates simply **stopped running** in the opencode harness,
so `git commit --no-verify`, force-push and direct-to-`main` push were no longer
blocked there. Go-only CI could not see it (the plugin is TypeScript), so every
gate stayed green while the harness was unprotected.

This PR ports the plugin to the V2 contract and adds a regression gate that
fails on the old V1 form.

### What changed

- **`.opencode/plugin/charly-gates.ts` → `.opencode/plugins/charly-gates.ts`** —
  moved to the documented V2 discovery location (`.opencode/plugins/`) and
  rewritten as a V2 definition:
  ```ts
  export default {
    id: "charly-gates",
    async setup(ctx) {
      const hooksDir = join(ctx.location.directory, ".claude", "hooks");
      await ctx.tool.hook("execute.before", async (event) => { … });
    },
  };
  ```
  The V2 shell tool is named **`shell`** (V1's `"bash"`), so the hook matches
  `event.tool === "shell"` and reads `event.input.command`; a gate that exits 2
  makes the hook throw, which denies the tool call. The gate-script invocation
  (stdin payload, timeout, stderr surfacing) is unchanged, so gate behaviour is
  byte-identical.
  A V2 plugin needs no `@opencode/plugin` import for this shape (`Plugin.define`
  is an identity helper); a local plugin has no dependency resolution, so
  importing it turns the plugin into a load error.
- **`scripts/check-opencode-plugin.mjs`** (new) — loads every
  `.opencode/plugins/*.ts` with a stub V2 context, then drives a blocked command
  (`git commit --no-verify`) and a benign command (`git commit -m ok`) through
  the registered hook and requires the **real gate scripts** to BLOCK and ALLOW
  respectively. A non-shell tool call must be ignored. It asserts the *behaviour*
  (gates enforced), not just the export shape. An opt-in live layer
  (`LIVE_OPENCODE=1`) resolves the plugin through the real `opencode plugin list`.
  It discovers plugins in **both** `.opencode/plugins/` and `.opencode/plugin/`
  — V2 loads local plugins from either directory — so a file left in the other
  location is still validated (and a V1-contract file there still fails).
- **`.github/workflows/ci.yml`** — runs the plugin-contract check. This closes the
  hole that let the V1 plugin rot: a Go-only CI never sees the TypeScript plugin.

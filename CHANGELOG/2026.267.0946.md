# 2026.267.0946 — fix(opencode): remove the stub from the plugin gate; drive the real opencode

## Summary

The regression gate added in #645 (`scripts/check-opencode-plugin.mjs`) had a
"live" layer that only ran `opencode plugin list` and asserted the plugin id
resolved. The gate-**enforcement** behaviour (a gated `shell` call being *denied*)
was exercised only against a **stub** context that hard-coded `event.tool ===
"shell"`, the `event.input.command` shape, and throw⇒deny — the very assumptions
under test. That proves the plugin *loads*, not that the gate *fires and blocks*.

This PR **removes the stub entirely** and makes every layer drive the real
artifact.

### What changed

`scripts/check-opencode-plugin.mjs` only (byte-identical to the umbrella's copy):

- **Layer A** — the plugin is a real ES module whose default export is a V2
  definition (object, string `id`, `setup` function). A V1 default-exported
  function fails here.
- **Layer B** — the **real** `.claude/hooks/pre-commit-gate.sh`, invoked with the
  same stdin payload the plugin sends, must BLOCK a hook-bypassing commit (exit 2)
  and ALLOW a benign one (exit 0).
- **Layer C** (opt-in, `LIVE_OPENCODE=1`) — the **real** `opencode` binary is
  driven end to end in a throwaway project: the loader resolves the plugin id, a
  gated `shell` call is **denied**, and a benign `shell` call succeeds. Prints
  `SKIP` visibly when the flag is unset (live-or-skip; never a silent pass).

No mocks, no stubs, no fakes of the opencode boundary.

## How tested

**1. Layer A+B (no live binary needed):**

```
$ node scripts/check-opencode-plugin.mjs
check-opencode-plugin: .../.opencode/plugins/charly-gates.ts
  PASS  default export is a definition object (V2), not a V1 function
  PASS  definition exposes a setup() function
  PASS  definition has a string id
  PASS  real pre-commit-gate.sh BLOCKS `git commit --no-verify` (exit 2)
  PASS  real pre-commit-gate.sh ALLOWS `git commit -m ok` (exit 0)
  SKIP  live opencode layer (set LIVE_OPENCODE=1 to run the real binary end to end)
check-opencode-plugin: OK
```

**2. Mutation — it FAILS on the old V1 form:**

```
$ node scripts/check-opencode-plugin.mjs --plugin /tmp/…/charly-gates-v1.ts
  FAIL  default export is a definition object (V2), not a V1 function
  FAIL  definition exposes a setup() function
  FAIL  definition has a string id
check-opencode-plugin: FAIL — 3 assertion(s)   # exit 1
```

**3. The live layer drives the REAL opencode binary end to end** (`v2.0.16`):

```
$ LIVE_OPENCODE=1 node scripts/check-opencode-plugin.mjs
  PASS  default export is a definition object (V2), not a V1 function
  PASS  definition exposes a setup() function
  PASS  definition has a string id
  PASS  real pre-commit-gate.sh BLOCKS `git commit --no-verify` (exit 2)
  PASS  real pre-commit-gate.sh ALLOWS `git commit -m ok` (exit 0)
  PASS  real opencode: a gate-blocked commit (staged alias file) is DENIED
  PASS  real opencode: the denied commit created nothing
  PASS  real opencode: a benign `git commit` succeeds
check-opencode-plugin: OK
```

The live layer has no separate `opencode plugin list` assertion: that command has
no directory or `--standalone` option, so it always queries the shared background
service and its result depends on whichever project bound that service (measured:
it reports "No plugins found" for a fresh project while the shared service is
elsewhere). The plugin-id proof **is** the block — a plugin that failed to load
registers no hook, so nothing would deny.

The DENY uses a staged `charly/*_aliases.go` (a **state-based** block), not a
recognizable bypass flag: the model self-censors on flags like `--no-verify` and
never calls the tool, which would prove nothing about the gate. An innocent
command is reliably run, and only the gate refuses it.

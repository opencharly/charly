# 2026.267.1938 — feat(kernel): generic host-value-gated kind seam + spec bump

## Summary

Add ONE generic kernel arm to `runPluginKind` — a `class:kind` whose authored value
is RICH + core-referencing (so it is validated HOST-SIDE against a KEPT
`#<Kind>Value` def, auto-derived into `spec.KindValueDefs`) but which is **neither a
deploy substrate** (no `DeployTraits`) **nor the candy box⊻layer factory**. Its body
folds opaquely into `acc.PluginKinds[disc][name]` — the SAME map every templated kind
uses.

The dispatch is **DATA-DRIVEN off `spec.KindValueDefs`** (CUE-derived; clause D / the
kind-blind boundary law), so a new `#<Kind>Value` def joins this path with **no core
edit** — exactly as the substrate/candy arms read registry-provided data rather than a
kind-word switch. It composes the existing shared steps — `validateKindValueCUE` (the
closedness gate), `dispatchKindOpValidate` (the plugin's deep `OpValidate`), and the
member-rejection + `PluginKinds` fold — so it adds no new mechanism (R3).

**Additive; the arm is reachable the moment a host-value-gated `class:kind` provider
is registered** (via `discover:` or `compiled_plugins:`). No such provider is compiled
into charly's own tree today, so within a bare charly tree the branch is dormant — but
it executes live as soon as the consumer loads (proven below). It unblocks
`opencharly/plugin-task` (the generic task runner).

**Named thematic batch (the consumer that makes this arm live):** the generic
host-value-gated task surface — `opencharly/plugin-task` PR #2
(`feat/plugin-task-v2`, provider `class:kind` name `task`) is the sole consumer and
lands in immediate sequence with this seam; this PR is its kernel prerequisite. The
two are one thematic cutover split only at the repo boundary (the plugin cannot pin a
charly tag carrying the seam until this lands, and this cannot register the plugin
until the plugin is merged+tagged — the documented cross-repo order in
`/charly-internals:git-workflow`).

Also bumps the shared `github.com/opencharly/spec` pin to `v0.2026267.834` (which adds
`#Task`/`#TaskValue`) in `charly/go.mod` and every lockstep `tools/*` module — the
canonical-go.mod gate keeps them on one pin.

# 2026.267.2313 — feat(task): replace the Taskfile with the compiled-in charly task surface

## Summary

Replace charly's Taskfile with the generic, CUE-schema'd, config-driven
**`charly task`** surface served by the compiled-in `opencharly/plugin-task`
candy, and delete the legacy build scripts in the same change (R5).

**Concretely:**

- **Register `candy/plugin-task`** in `charly/charly.yml` `compiled_plugins:` and
  pin it in `charly/go.mod` (`v0.2026267.2043`); regenerate
  `charly/plugins_generated.go` (pluginsgen) and `go.work.sum`. `command:task`
  needs the **compiled-in** placement (it reads the host's loaded project over
  the reverse channel), and it now ships in every charly binary.
- **Add the repository's own `kind:task` entities** to the root `charly.yml`:
  `mods-tidy` (the former `mods:tidy`), `push` (the former `push`), and
  `check-task-smoke` (the R10 bed's task). A task's `plan:` uses the SAME
  `#Step`/`#Op` grammar a candy's `plan:` uses.
- **Delete `Taskfile.yml` + `taskfiles/{Build,Setup,Modules}.yml`** and replace
  `build:binary` / `setup:all` / `build:install-portable` with the ONE
  non-charly entrypoint **`scripts/bootstrap-charly.sh`** (pluginsgen → CalVer
  stamp → `go build` → `go.work.sum` guard → `mv bin/charly`). The build that
  PRODUCES the binary cannot itself be a charly task, so this boundary is
  necessary and singular.
- **New R10 bed** `check-task` (disposable `host: local` deploy) driving both
  `command:task` (`charly task list`) and `verb:task` (a `task:` step composed
  into the bed's own plan).
- **Rewire every reference** and **drop the now-vestigial `go-task` optdepend**
  (it provided `/usr/bin/task` solely for `task build:binary`).
- **Make the kernel-seam test placement-tolerant**: with the real `kind:task`
  provider compiled in, the test's double must not `RegisterBuiltinProvider`.

The kernel prerequisite — `opencharly/charly` PR #648 (the generic
host-value-gated kind seam) — is **merged and tagged `v2026.267.1938`**; the
plugin is `opencharly/plugin-task` PR #2, **merged and tagged `v2026.267.2043`**.

## Rulebook compliance

- **R0 skills:** `/charly-internals:plugin`, `/charly-internals:go`,
  `/charly-internals:git-workflow`, `/charly-check:check`,
  `/charly-internals:cutover-policy`, `/charly-internals:strict-policy`,
  `/charly-internals:disposable`, `/charly-image:layer`, `/charly-local:local-deploy`.
- **R1 RCA (both anomalies fully discharged, nothing parked):**
  - (a) the compiled-in `kind:task` provider made the seam test's
    `RegisterBuiltinProvider` double panic on a legitimate duplicate. Root cause:
    the test registered a double it passes to `runPluginKind` directly, so
    registration was never needed. **Fixed in-tree** by dropping the
    registration.
  - (b) `charly task check-task-smoke` initially SKIPPED its steps. Root cause:
    the plan-step grammar reserves `${NAME}` and `${NAME:arg}`, so the shell-only
    idiom `${TMPDIR:-/tmp}` parses as the variable `TMPDIR` with arg `-/tmp` and
    is an unresolved reference (→ skip). **Fixed in-tree by authoring the value
    as a declared task `vars:` entry** (`SMOKE_DIR`), the documented plan-step
    variable mechanism — not a literal-path workaround. The reserved-grammar
    behaviour is by design; the smoke task now exercises the `vars:` contract
    directly, and there is no parked defect or follow-up.
- **R2 no out-of-scope:** the charly cutover is complete and self-contained. The
  umbrella's `scripts/*.sh` → generic plugin-task verbs (`git-submodules`,
  `file-parity`, `splice-region`, `module-pins`) is a **separate, named
  deliverable** the operator directed to a follow-up `opencharly/plugin-task`
  PR (the merged plugin-task is a pure task runner and does not yet carry those
  verbs), landing before the umbrella P4. Nothing started in THIS PR is deferred.
- **R3 no duplication:** the tasks reuse the SAME `#Step`/`#Op` grammar and
  `kit.RunPlan` engine the check surface drives; `mods-tidy`'s body is the
  former `taskfiles/Modules.yml` logic, now a declared task, not a second engine.
- **R4 no workaround:** `scripts/bootstrap-charly.sh` is the necessary singular

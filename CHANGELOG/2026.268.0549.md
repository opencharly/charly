# 2026.268.0549 — chore(deps): bump plugin-task to v0.2026268.534 (corrected bump order)

## Summary

Bump charly's compiled-in `plugin-task` pin from `v0.2026268.104` to
**`candy/plugin-task/v0.2026268.534`**, which carries the corrected
`git-submodules` **bump ORDER** (plugin-task PR #4).

**Why it matters.** The old order pinned the `pin_map` entries first, then rolled
every non-pinned submodule — including the `pinned_from` repo (`charly`). So it
pinned `distro-*` from charly's **pre-roll** HEAD and then advanced charly,
leaving policy B (umbrella `distro-*` gitlinks == charly's gitlinks) **violated
after every sync**. The umbrella cutover (P4) composes this verb in its `sync`
task, so this pin must carry the fix.

`go.sum`/`go.work.sum` are re-tidied.

## How tested

### The changed behaviour ran LIVE from the rebuilt binary

The whole point of the bump is the corrected `git-submodules` **bump ORDER**, so
that is what is run — against `./bin/charly` built from this tree with the bumped
pin, on a real git fixture where the `pinned_from` repo (`src`) is ITSELF a stale
rolling submodule whose `inner` gitlink advances during the bump:

```
$ ./bin/charly version
2026.268.0312
$ # fixture: src pinned at A (inner=L1); target2 pinned at L1; src-origin main is B (inner=L2)
$ ./bin/charly task sync
task sync: 1 step(s), 0 failed
  [pass] run — bump
src now:     94de57ca56bb7d2ff5db523c9a26f43ca4283219  (want B=94de57ca56bb7d2ff5db523c9a26f43ca4283219)
target2 now: 88f166613273e16e0b493cc28433ed4b74e2c400  (want L2=88f166613273e16e0b493cc28433ed4b74e2c400)
POLICY-B-ORDER-CORRECT
```

`src` rolled to `B` FIRST, then `target2` was pinned from src's **NEW** gitlink
`L2`. With the pre-fix pin, `target2` would have been pinned from src's OLD `L1`
and policy B would be violated — so this run WOULD fail on the old pin.

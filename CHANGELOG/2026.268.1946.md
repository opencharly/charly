# 2026.268.1946 — fix: repair the sdk/spec contract pins so the go gate is green

## Summary

Repair the sdk/spec contract pins so the `go` gate is green. `origin/main` is
currently **red**: its `ci` workflow's `go` job fails `TestContractPinsMatchShared`
and the core module cannot build. Two independent breaks from the same dependency
bump (charly#663, "bump spec/sdk/plugin-check/plugin-fleet for the RunEnv cutover"):

1. **`charly/go.sum` was not updated with `charly/go.mod`.** The bump moved the
   requires to `sdk v0.2026268.1823` / `spec v0.2026268.1800`, but `go.sum` still
   carried the old `sdk …2238` / `spec …642` sums. The core module therefore could
   not build, and a fresh `scripts/bootstrap-charly.sh` failed at its first step —
   `go run ./internal/pluginsgen` — with
   `missing go.sum entry for module providing package github.com/opencharly/sdk`
   (and the same for `spec/proto`). Repaired with `go mod tidy` in `charly/`.

2. **The `tools/*` modules were not bumped.** `tools/{generate-packages,golden-cloudinit,golden-compile}/go.mod`
   still required `sdk v0.2026266.1111` / `spec v0.2026267.834`, so
   `TestContractPinsMatchShared` failed against the shared pins. Aligned with the
   project's own task `charly task mods-tidy`, which adopts the shared
   `charly/go.mod` pins into every lockstep module and keeps `go.mod` and `go.sum`
   in step.

This is an R1 fix for a pre-existing, main-breaking defect; the remedy is the
project's own task, not a hand-edit.

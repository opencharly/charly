# 2026.269.0556 — chore: adopt spec v0.2026269.138 + sdk v0.2026269.145 (command-parent grammar)

## Summary

Adopt the two **already-merged** contract tags so this binary's CUE accepts a command
capability's three-segment identity form `command:<word>:<parent>`:

- spec `v0.2026268.2214` → **`v0.2026269.138`** (the three-segment `#PluginCapability` +
  the wire `command_parent` fields on `ProvidedCapability` / `PluginRequirement` /
  `InvokeProviderRequest` / `InvokeRequest`, and `ops.InvokeProviderOpts.CommandParent`);
- sdk `v0.2026268.2244` → **`v0.2026269.145`** (the authoring-surface mapping).

`charly box validate` consults the CUE `#PluginCapability` from `spec/schema` (embedded
via `spec/schemaconcat`), so **adopting the tag is what teaches the CLI grammar the parent
form**. This is the grammar-adoption leg of the command-parent cutover.

## Why this leg exists, and the named remainder (R2)

The command-parent cutover has a circular build dependency:

1. Each plugin repo's own CI runs `charly box validate` at a **fixed old charly**
   (`v2026.238.1242`) whose CUE predates the grammar — so it rejects `command:generate:box`.
2. A new charly core built against the **old plugin pins** (charly `main` today) panics,
   because both `plugin-box` and `plugin-feature` still declare the flat `command:feature`.

This PR is **leg one of two** of the named cutover **"C0 — command capability identity"**
(the plugin-core-independence crutch sweep). It is the **grammar leg only** (contract
pins, no behaviour). Its purpose is to give the plugin repos a charly release whose
validator accepts the new manifest shape, breaking the cycle.

**The named remainder (leg two)** is the core-behaviour change that makes the parent the
registry identity, and it is already authored and pushed as the sibling branch
**`feat/command-parent-identity`** (head `6d5e1eea`), which will open as its own charly PR
once the three plugin producer PRs merge and it can bump their pins:

- **`opencharly/charly` branch `feat/command-parent-identity`** (`6d5e1eea`) — deterministic
  identity keying, the parked/relocated-collision heuristic and the Go-interface parent
  sniff deleted, the parent read from the declared wire field, the generated word→ref index,
  the `TestNoProviderRefMapInKernel` gate, and `plugins_refs_generated.go`.
- its producer PRs (blocking the pin bump): **`opencharly/plugin-box#14`**,
  **`opencharly/plugin-authoring#5`**, **`opencharly/plugin-build#16`**.
- its contract producers, already merged: **`opencharly/spec#167`** (tag
  `v0.2026269.138`), **`opencharly/sdk#293`** (tag `v0.2026269.145`).

So the split is decomposed on the real dependency (the plugin CI's pinned charly), and
every leg is a named, tracked PR — not a vague follow-up.

# 2026.269.1424 — refactor(plugin): fold the deploy-ref helper into the one provider lookup (R3)

## Summary

Fold the last duplicate of the word→ref rule into the ONE lookup (R3). Part of the plan's §4
"one architecture, no fallbacks" spine.

`externalDeploySubstratePluginRef(word)` re-implemented the **same** generated-index lookup as
`canonicalProviderRef(ClassDeployTarget, word, "", "")` — a second implementation of the one
word→ref rule (R3). It is **deleted**; its two call sites now use `canonicalProviderRef` directly:

- `deployNodePluginContext` — the box/<distro> submodule substrate auto-inject;
- `unresolvedDeployTargetError` — the not-connected diagnostic.

`TestExternalDeploySubstratePluginRef` becomes `TestDeploySubstrateCanonicalRef`, asserting the
same index↔set consistency through the one lookup.

`canonicalProviderRef` + `pluginProviderRef(providerKey(...))` are the **only** two word→ref
helpers; `externalDeploySubstratePluginRef` is removed by this PR and `vmPluginCandyRef` **no

merged `charly#677`). This PR also sweeps the two stale *comments* that still named
`vmPluginCandyRef` (`vm_plugin_client.go` header, the C5 gate doctrine line) — the helper was
already gone; only its name lingered in prose.

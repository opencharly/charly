# 2026.269.1750 — feat: remove the relocated agentteams pod beds from charly

## Summary

Remove the two AgentTeams **pod-substrate** R10 beds — `check-agentteams-pod` and
`check-agentteams-snapshot` — from `charly/charly.yml`, completing their relocation to
the repo that owns the artifacts they test, **opencharly/layer-agentteams**.

This is the charly-side leg of a move whose destination is green. Keeping both copies is
the half-move R3 (no duplication) and R5 (one canonical home) forbid: a check bed must
live in the repo that owns what it tests, because the bed runner's dev-tree override
(`proc.SelfSuperprojectOverridePair`, `spec/proc/repo_override.go`) points the bed
project's own superproject's `@github` refs at the local tree. In the umbrella every
submodule's superproject is `opencharly/opencharly` (which hosts no candies), so the
`agentteams` candy was never exercised as in-development code while its beds sat here.

The matching relocation in **opencharly/layer-agentteams** carries the two beds green
end-to-end (re-proven at the destination for this PR — §4 below).

**What is removed (2 nodes):**

```
check-agentteams-pod         pod
check-agentteams-snapshot    pod
```

**What deliberately STAYS.** The shared fixtures are **not** exclusive to the two removed
beds and remain, because the VM-substrate bed `check-agentteams-vm` (which is **not**
relocated) still composes them:

- `agentteams` (the top composition candy / image)
- `agentteams-manager` (the manager image box)
- `agentteams-worker` (the worker image box)
- `agentteams-vm` (the Arch cloud-image VM template) + `check-agentteams-vm` (the VM bed)

**Why the VM bed stays here — coverage-retention, not a deferred gate.**
`check-agentteams-vm` has exactly ONE home (`charly`), is not part of this relocation, and
is NOT a parked failure: it is a retained bed whose coverage is not dropped by this PR. Its
green run is blocked on two named prerequisites — the project schema cutover
**opencharly/layer-agentteams#4** and the `plugin-deploy-vm` `step:system-packages` hang
**opencharly/plugin-deploy-vm#23** — both separate, owned, in-flight batches. This PR
changes neither and does not claim to; the merged `opencharly/charly#671` used exactly
this "coverage-retention, each with a named owner — not deferred gates" framing.

**Changed files:** 2 files, +13 / -232.

- `charly.yml` (+12 / -231) — three hunks:
  1. The `# =====` comment block above the `agentteams` box is rewritten to describe the
     `agentteams` / `agentteams-manager` / `agentteams-worker` boxes and point forward to
     the beds' new home.
  2. The `check-agentteams-pod` and `check-agentteams-snapshot` nodes are deleted,
     including their leading comment blocks.
  3. The `agentteams-vm` comment block's stale cross-reference ("— the same pre-requisite
     the `check-agentteams-pod` bed has") is removed.
- `AGENTS.md` (+1 / -1) — the agentteams skill-dispatcher row, which named both the pod
  and VM beds, is narrowed to `check-agentteams-vm` (R5 stale-reference sweep).

**Breaking change + rollback:** none — deleting two check-bed deploy entries; no product
code, no candy, no image, no fixture. Rollback is a revert.

**The destination is LANDED.** `opencharly/charly#671` (merged 2026-09-26) removed 14
*other* relocated beds but deliberately KEPT these two because `layer-agentteams` was RED
at the time. That repo is now fixed AND merged: **opencharly/layer-agentteams#6 merged
2026-09-26** (commit `42a6fce4c`, tag `v2026.269.1323`), carrying both beds green on the
spec-261 provider pin. `opencharly/layer-agentteams@main` now defines
`check-agentteams-pod` and `check-agentteams-snapshot`. This PR completes the move.

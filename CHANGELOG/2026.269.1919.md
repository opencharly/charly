# 2026.269.1919 — fix(deploy): resolve a namespace-qualified deploy key by exact match first

## Summary

Fix `resolveDeployNodeByPath` to resolve a namespace-qualified deploy key by
**exact match first**, so a namespaced bed's substrate provider is connected.

### RCA (8-step, measured live)

**Unexpected.** From the umbrella root, every namespaced pod bed failed at
`deploy-add`:

```
charly: error: command "deploy": resolve target: deployment "charly.check-docs":
target "pod" is a known substrate but its deploy provider is not connected
(the github.com/opencharly/plugin-deploy-pod/candy/plugin-deploy-pod plugin candy
is not compiled-in or failed to load)
```

**Mechanism.** `deployNodePluginContext` → `resolveDeployNodeByPath` split the
deploy name unconditionally on `.`, so a namespaced top-level key
(`charly.check-dsh-pod`) was read as root `charly` + member path, missed, and
returned `false` — `deployNodePluginContext` then collected ZERO plugin words and
`loadDeployPlugins` never connected its `pod` substrate provider.

**Root cause.** `spec.ResolveNodePath` (spec#164) had already adopted
exact-key-first for the plugin-side walk, but this **core** pre-connect
collector — a second, independent resolver — was not updated: a producer/consumer
split across the spec/core boundary.

### Fix

```go
name, _ = spec.SplitVmAddress(name)
if node, ok := tree[name]; ok {   // EXACT full-key match FIRST
    return &node, true
}
parts := strings.Split(name, ".") // member descent only when absent
```

Mirrors `spec.ResolveNodePath`'s exact-key-first contract — the same rule at the
core pre-connect layer.

**Note on the SDK pin:** charly `origin/main` already carries `sdk v0.2026269.1159`,
whose `ProjectDeployConfig` folds `uf.Deploys()` (the namespace-aware projection),
so no pin change is needed — the only missing half was this core resolver. This
PR's diff vs `origin/main` is exactly the 2 files below.

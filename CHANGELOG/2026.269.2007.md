# 2026.269.2007 — feat(plugin): consume the authored plugin.requires manifest in the gate (A6)

## Summary

A plugin can now declare the OTHER plugins it depends on, and the host honours it — with
the declaration authored ONLY in the plugin's candy manifest (`plugin.requires:`), no
plugin-Go change, and no charly-core change per new plugin.

The declared-dependency gate already existed (A3) but was **inert end-to-end**: it read the
served wire `Capabilities.requires`, which no plugin populated. This change makes the
**authored manifest the ONE source**: the host reads it from the resolved view
(`spec.CandyReader.GetPluginRequires` — the `CandyView.plugin_requires` projection landed in
spec#173 / sdk#305) and resolves every requirement BEFORE the unit's providers register.

- `gateCandyRequires(name, candy)` — the ONE entry point for a scanned candy's authored
  declaration. Called for the project-declared external connect (via `loadPluginUnit`) AND
  for the compiled-in candy (the placement-coexist branch of `loadProjectPlugins`).
- `registerPluginRequires(name, ownKeys, requires)` — the source-agnostic gate body;
  `registerPluginUnitRequires` keeps reading the WIRE for the placements that carry no
  manifest (the process-start builtin gate; a source-less baked binary).
- The own-key cycle marking now uses the parented `providerIdentity` instead of the
  two-segment `provKey`, so a nested command's in-flight identity matches its requirement.

**Two RCA fixes the A6 live run forced:**

1. **`requirementRef`** — the authored `source:` (a bare `#GithubRef`) reached the ref
   resolver RAW, but `CanonicalRef` treats a non-`@` ref as a LOCAL path, so the declared
   peer never resolved. It is now `@`-prefixed (the same form `canonicalProviderRef`
   renders). This was a latent A3 bug, invisible until a live run.
2. **spec#172 consumer** — the pin bump to spec `v0.2026269.1640` pulls in spec#172 (a
   deploy identity may now contain `.`, the path-join separator). The stale
   `TestValidateDeploymentTree_RejectsDotInName` asserted the old dot-ban; it is replaced by
   the current contract (accept a well-formed dotted identity; reject an empty path segment
   / empty instance).

Also: `spec` `v0.2026269.759` → `v0.2026269.1640`, `sdk` `v0.2026269.1159` → `v0.2026269.1717`
(main had advanced sdk to `.1159`; the A6 projector requires `.1717`), and the `tools/*`
lockstep module pins aligned to the core (the `mods-tidy` invariant).

**A6 reference fixture** (producer, landed first): the new standalone repo
`opencharly/plugin-example-require` (PR #1, tag `v2026.269.1910`) — its candy manifest
declares `verb:externalprobe` (compiled into charly) and `verb:exampledispatchpeer`
(out-of-process, with its source), and its `examplerequire` verb peer-invokes both. It is
pinned in the project closure beside the other example plugins.

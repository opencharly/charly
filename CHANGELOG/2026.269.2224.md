# 2026.269.2224 — chore(deps): adopt sdk v0.2026269.2108 + drop the retired plugin.source: builtin pins

## Summary

Adopt `github.com/opencharly/sdk v0.2026269.2108` and drop the retired
`plugin.source: builtin` pins from the compiled-in `plugin-agentteams` /
`plugin-dsh` candies. This is the charly-side link that makes
opencharly/layer-charly#10 (the exact-version package pin) verifiable.

- **sdk `v0.2026269.1717` → `v0.2026269.2108`** — carries the two fixes
  layer-charly#10 exposed (both merged in opencharly/sdk#307):
  1. `deploykit.distroRepoProvidesPackage` matched a PINNED `distro: <d>. package:`
     entry by exact string, so a pin defeated the localpkg-skip and the emitter
     produced a redundant, UNPINNED second install.
  2. `packagekit.ParsePackaging` could not parse a real candy `charly.yml`
     (top-level `version:` scalar), so `charly generate-packages` failed on the
     localpkg path.
- **`plugin-agentteams` / `plugin-dsh` → `v0.2026269.2113` / `v0.2026269.2116`** —
  the spec RETIRED `plugin.source: builtin`, but these compiled-in plugins still
  declared it, so a source-built charly could no longer validate or load a project
  pinning the old tags. The new tags declare the real module source;
  `plugins_refs_generated.go` regenerates accordingly.
- **`task mods-tidy`** — aligns the `tools/*` lockstep modules to the shared pins.
- **lint** — checks the previously-unchecked `providerRegistry.register` error in
  `charly/plugin_requires_test.go`, which currently makes `main`'s
  `golangci-lint` gate red.

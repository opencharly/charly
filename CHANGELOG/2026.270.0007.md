## Summary

Add the **`check-kindcluster-lock`** R10 bed — the permanent regression witness for the
`opencharly/charly#680` ledger-lock self-deadlock fix — and close every round-1..4
validator finding.

A top-level `charly deploy del <root>` holds the ledger transaction lock
(`kit.AcquireLedgerLock`) for its whole body and forks one **peer**
`charly deploy del <member>` per deploy-level member via
`deploykit.TearDownMembers`. Before #680 the forked child re-acquired the **same**
lock its own ancestor held (`flock` is per-open-file-description) and blocked forever:

```
charly: waiting 14m31s for file lock …/charly.yml.ledger.lock
        — held by pid <parent `deploy del <root>`>; giving up after 30m0s
```

### The bed

```yaml
check-kindcluster-cluster:        # shared template (existing, merged in #669)
check-kindcluster-lock:
    kindcluster:
        from: check-kindcluster-cluster
        disposable: true
        lifecycle: dev
        add_candy: ['@github.com/opencharly/plugin-kube/candy/plugin-kube:v2026.269.0814']
    check-kindcluster-lock-member:      # deploy-level member → forked `deploy del`
        kindcluster:
            from: check-kindcluster-cluster
```

A **kindcluster ROOT** with a **deploy-level kindcluster MEMBER**. kindcluster is
**external-in-place** (venue `none`), so the member needs **no image build** — the bed is
fast and hermetic. Teardown runs the root's `deploy del`, which holds the ledger lock and
forks the member's `deploy del`: the exact pre-#680 deadlock site on the production
`withLedgerLockHeld` → `TearDownMembers` → forked-child path. `disposable: true`
authorizes the destroy + rebuild.

# 2026.270.0224 — test(check): add check-kindcluster-workload R10 bed (Phase 6 workload leg)

## Summary

Add **`check-kindcluster-workload`** — the Phase 6 R10 witness for the
`deploy:kindcluster` **workload leg + engine-aware image loading**. A disposable kind
cluster on podman with the locally-built `check-k8s-deploy-app` image loaded INTO the
kind node (the podman path `kind load image-archive` — `kind load docker-image` is broken
there, plan §2 #11) and applied through the SHARED kubernetes generator (the kindcluster
cluster-policy surface is projected onto a `#Kubernetes` body, R3), then probed with the
`kube:` verb. Reuses the shared `check-kindcluster-cluster` template (R3 — no duplicated
kindcluster block).

Two product defects surfaced while building this bed were root-caused and fixed in their
own producer repos, and this PR adopts their tags:

- **plugin-check#64** (tag `v2026.270.0151`) — `charly check run` skipped the
  image-build step for an **external-in-place** deploy, so a kindcluster workload image
  was never built (`pinned image … not present in local podman storage`). Fixed the guard
  (`bedBuildsImage`).
- **plugin-kube#10** (tag `v2026.270.0155`) — `podman save -o -` writes a FILE named `-`
  rather than stdout (measured on podman 6.1.2: a 330 MB `./-`, stdout EMPTY), so
  `kind load image-archive` saw an empty archive and the node's `ctr images import`
  failed `ctr: unrecognized image format`. Fixed to save to a real temp file.

Also updates the archlinux `optdepends` note for `kubectl` (the workload leg runs
`kubectl apply -k`).

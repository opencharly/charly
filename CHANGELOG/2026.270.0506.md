## Summary

Closes **C6** and lands the charly consumer side of the **sdk#301** identity-keyed per-host state cutover.

**C6 (the deploy-mechanism substrate-word read):**
- Bumps the **sdk pin to `v0.2026270.152`** — the merged C6 change (opencharly/sdk#311) that deletes the last `.Target == "<substrate>"` read in `sdk/deploykit`: `FindVmDeployNode` now reads the loader-stamped descent via `deploy.IsVmVenue` (the trait, never the word).
- Drops the now-obsolete `deploy_state.go` entry from the P9 word-switch gate's allowlist.
- **Restores the gate's sdk coverage.** Its `../sdk/deploykit/*.go` glob assumed an in-tree sdk submodule and has matched **nothing** since the sdk de-submodule cutover, so the gate silently lost the deploy-Mechanism half of its contract (the allowlist entry it carried was a no-op). The sdk source is now located through the build's own module resolution (`go list -m`), and an empty result is a **hard failure** — a gate that scans nothing must not pass.

**sdk#301 consumer side:** bumps the compiled-in **plugin-vm** pin to `v0.2026270.402` (opencharly/plugin-vm#52), which keys the per-host VM state by the deploy IDENTITY so the identity-keyed reader finds it. The external **plugin-deploy-vm** companion (opencharly/plugin-deploy-vm#26) is resolved at runtime from its merged tag.

**Not included (reported, not silently dropped):** a versioned `charly migrate` re-key entry for *orphaned* legacy `vm:<dashed>` overlay entries. The migration table's version gate requires a `spec` `#SchemaVersion` bump, which collides with the in-flight **schema-versioning-removal chain** (spec#176 → plugin-migrate); that chain removes the gate the entry would need. The sdk's own one-touch prune (`saveVmStateInto` deletes `"vm:"+VmDomainIdentity(identity)` on the next write) already self-heals any re-written entry. The migration belongs to the versioning-removal chain, not this PR.

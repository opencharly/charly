# 2026.270.0832 — test(check): gate the kindcluster engine beds on the container engine (R7a live-or-skip)

## Summary

Adopt the merged `plugin-check` bed-prereq gate (opencharly/plugin-check#65,
tag `v2026.270.0728`) and make the `kindcluster` R10 beds declare their container engine
explicitly, closing the plan's **live-or-skip (R7a)** requirement
(`plan/kind-integration.md` §4 Phase 6): *"each bed gates on its engine being present
(`command -v docker|podman|nerdctl`); an absent engine is a **visible skip**, never a silent
pass."*

### Changes

| File | Change |
|---|---|
| `charly.yml` | the five `kindcluster` bed ROOTS declare `engine:` explicitly (`check-kindcluster`/`-workload`/`-lock`: `podman`; `-docker`: `docker`; `-nerdctl`: `nerdctl`) so the merged `bedEnginePrereqSkip` gate reads it |
| `charly/go.mod` + `charly/go.sum` | bump the compiled-in `plugin-check` pin `v0.2026270.151 → v0.2026270.728` (plugin-check#65: a bed whose pinned engine CLI is absent is a clean prereq SKIP, exit 3) |

Why the bed ROOT needs the declaration: `uf.ResolveBedForRoot` does **not** merge the `from:`
template, so the engine the gate reads must be authored on the deploy node itself. The
kindcluster preresolve already prefers the deploy's own `engine:` over the template's, so this is
a same-value restatement, not a behavior change.

This is the consumer half of the producer→consumer landing: producer opencharly/plugin-check#65
is merged and tagged `v2026.270.0728`; this PR bumps the pin and ships the declaration.

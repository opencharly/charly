# 2026.270.1151 — chore(deps): bump opencharly/sdk to v0.2026270.1024 (build caches off /tmp)

## Summary

Bumps the `github.com/opencharly/sdk` pin from `v0.2026270.152` →
**`v0.2026270.1024`**, adopting the merged emitter fix
**opencharly/sdk#279** (`fix(emit): move build-cache mounts off /tmp to
/var/cache/charly`), and aligns the in-repo `tools/*` modules to the shared
sdk/spec pins (the repo's `charly task mods-tidy` contract).

The emitter's default BuildKit build-cache mounts leave `/tmp`: `EmitDownload`'s
cache/`download:` fetch path (`/tmp/downloads`) and `EmitCmd`'s non-root
`command:` cache (`/tmp/npm-cache`) now root under `/var/cache/charly/...`.

**Why charly is the carrier.** charly's own Go module does not import the sdk
directly (the `require` is indirect, line 105), but the per-verb Containerfile
emitters in `sdk/deploykit/tasks_emit.go` are reached through the **compiled-in
plugin modules** charly requires. Raising the sdk require is an MVS floor: the
main module's higher require selects the fixed sdk for the whole build graph, so
every compiled-in plugin renders the corrected emitter — no charly source change
is needed.

### RCA — the pre-existing `go`-CI contract-pin failure (R1/R2)

The tools modules had drifted from the shared pin **before** this change: on
`main` the core carried `sdk v0.2026270.152` / `spec v0.2026269.2150` while
`tools/{generate-packages,golden-compile}` carried `sdk v0.2026269.2108` /
`spec v0.2026269.1703`, so `TestContractPinsMatchShared` was already failing
(`main` `go` CI red at 2026-09-27T10:45Z). The sdk bump trips the same gate, and
R2 forbids shipping with it. The fix is the repo's own canonicalizer,
`charly task mods-tidy`, which adopts the shared pins in every lockstep module —
run here and verified below.

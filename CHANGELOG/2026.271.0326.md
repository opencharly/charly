# 2026.271.0326 — feat(charly)!: reject an empty plugin schema unconditionally + bump compiled-in plugin pins (inputless cutover)

## Summary

Land the **host leg** of the inputless/schema-less plugin cutover (`opencharly/charly#712`): delete the `registerPluginUnitSchema` **"stub-gate relaxation"** so an EMPTY served schema is rejected **unconditionally**, and bump the **28** compiled-in plugin pins whose pinned release still served an empty schema to their merged cutover releases.

- **The rule now rejects emptiness, not inputlessness.** An empty `CueSource` is a hard load failure for EVERY plugin. A non-empty **"doc schema"** declaring no `InputDef` — the shape every pass-through command, substrate kind, and deploy target ships — is still **accepted**. This mirrors the SDK side (`opencharly/sdk#314`, merged), which already rejects a nil FS / empty body serve-side; this is the host's byte-identical enforcement.
- **Compiled-in pins bumped** — the **28** compiled-in plugins whose pinned release still served an EMPTY schema (the carve-out waived them) are advanced to their merged inputless releases in `charly/go.mod` + `charly.yml` + `packaging/charly.yml`, so the compiled-in closure is schema-complete and the load gate passes. Each bump is a real merged, tagged release — no hand-pin, no shim. The other **35** compiled-in plugins already served a non-empty schema at main's pins and are **unchanged**.
- **Test added** (`charly/plugin_external_test.go`): `TestPluginSchemaEmptyRejectedUnconditionally` — empty schema (no input defs) REJECTED (the former carve-out case; fails without the change), empty schema WITH input defs REJECTED (unchanged), non-empty doc schema with NO input defs ACCEPTED (the one allowance).
- **Second commit** (`4e309ff5`) fixes the garbled doc-comment the prior review flagged (unbalanced backticks + a stray curly quote).

# 2026.271.0929 — fix(release): weld plugin-review v2026.271.0852 — exclude the gate's own notices from the next review's context

## Summary

Bump the **welded** `plugin-review` pin from `v2026.270.1323` → **`v2026.271.0852`** so the next charly release's plugin bundle carries the **gate-noise-exclusion fix** (merged `opencharly/plugin-review#31`).

**The fix (#31):** the review engine's context assembler (`ghclient.go` `comments()`, rendered into `<comment_thread>` by `context.go`) fed **every** issue comment back into the next review — including the org `pr-validator`'s two **machine notices about the gate itself**:

1. `## validator INCONCLUSIVE — no review verdict was produced …` (its `<details> Diagnostics` tail is ~65 KB of a degenerate `Hmm.` line on a decoding collapse);
2. `## Auto-closed: N unanswered BLOCK/INCONCLUSIVE verdicts …`.

Neither carries a review finding, and re-ingesting them is a **feedback loop**: every run appends a fresh multi-KB notice, the next run re-reads all of them, and the growing thread (measured ~176 KB) is itself a driver of the decoding repetition collapse that produces the next INCONCLUSIVE. A trimmed ~30 KB context on the same PR returns a clean verdict. `comments()` now skips a comment whose body **starts with** either exact header — matched on the first non-blank, leading-whitespace-trimmed line (the deterministic marker, *not* the `github-actions[bot]` author). The validator's REAL review comments (`## Review — BLOCK` / `## Review — PASS`) are **kept** (the prompt requires they be dispositioned).

**The net change from `main` is one line** (`scripts/host-command-plugins.txt`).

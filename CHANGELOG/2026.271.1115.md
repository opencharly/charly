# 2026.271.1115 — docs(agents): make AGENTS.md fully harness-neutral; move harness detail to the harness skill (#286)

## Summary

`charly/AGENTS.md` is declared the single harness-neutral rulebook, but its R0
skill-loading prose still named four consumer harnesses. This change removes
every harness name from the policy prose and re-tightens the neutrality gate
that PR #727 deliberately relaxed.

- **R0 prose neutralized.** The parenthetical enumerating per-harness skill
  loading (Claude Code's marketplace, pi's package, Kimi's plugin, Codex's
  catalog) is replaced with harness-neutral language: every supported harness
  loads the `opencharly/marketplace` repo through its own plugin market,
  package, or catalog (the per-harness install table lives in that repo's
  README), and a harness that cannot resolve the canonical
  `/charly-<family>:<skill>` form reads
  `<family>/skills/<skill>/SKILL.md` by path. Every mandate is preserved — load
  all dispatched skills, load all matches before acting, and missing
  registration remains a project-profile defect, never permission to skip.
- **Gate re-tightened.** `scripts/validate-agent-config.py`'s
  `FORBIDDEN_GENERIC_RULEBOOK_MARKERS` again forbids harness NAMES — `Claude`
  (covers `Claude Code`/`CLAUDE.md`), `Codex`, `Kimi` (covers `Kimi Code`),
  `opencode`, `reasonix`, `cursor` — alongside the config identifiers, plus a
  new word-boundary `\bpi\b` pattern (a bare `pi` substring would match
  `api`/`pipeline`/`capabilities`). The self-test exercises every restored
  marker and the pi negative control.

### Where each moved harness fact landed

The removed R0 enumeration duplicated the marketplace README's per-harness
install table (`marketplace/README.md` → "Install per harness"), which already
documents all four mechanisms product-wide: Claude Code/Cursor (the
`charly-plugins` catalog), Codex/AGENTS (`.agents/plugins/marketplace.json`),
Kimi Code (`kimi.plugin.json` / the repo-as-one-plugin), and pi
(`git:github.com/opencharly/marketplace`, installed via `package.json`'s `pi`
resource). The primitive detail for Claude Code, Codex and Kimi also lives in
`/charly-internals:agents` → `references/agent-roster.md` (its per-harness
table). pi's mechanism is documented both product-wide in the marketplace
README and in charly's own harness config (`charly/.pi/README.md`). Every
removed fact was therefore already covered — no `layer-charly-internals` source
edit was required, and the rulebook now points at the canonical skill/README
source.

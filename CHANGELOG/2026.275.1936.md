# 2026.275.1936 — fix(check)!: deliver the eval-host guest project via scp, not host rsync (#751)

## Summary

Fix `#751` — an **R4a product gap**: the `check-local-vm` R10 bed's `guest-project-delivered` step shelled out to the **host's `rsync`** to push the pruned check-local project over the managed SSH alias. `rsync` is not part of the charly toolchain and is not guaranteed present on a host, so the bed could not run with only the `charly` binary — the exact R4a defect (*"every command a reader is told to run MUST work with nothing but the charly binary installed"*).

Deliver with **`scp -q`** instead — part of the OpenSSH client `charly --host` already depends on. This is also **R3 consistency**: the sibling `check-pkg-uninstall` bed already delivers with `scp`. The now-unneeded guest `rsync` cloud-init package is removed in the same change (**R5**), and the stale "rsync" prose in the bed comments/description is corrected.

## The measured root (why the model is broken)

The model intends deploy-into nesting by **tree position**. The derivation is correct — `spec/spec/member_tree.go` fixes the two positions and `sdk/loaderkit/node_tree.go` stamps them from authored depth. **Two defects sit on either side of it**, both measured on this thread; the order is why neither alone suffices.

- **The parse drops the member (`sdk`).** `sdk/loaderkit/parse.go:209` tests membership with `t.DeploySubstrates[disc] || resourceKindSet[disc]`. The substrate set is filled only from *connected* deploy providers and declared plugin words, while the core substrate words arrive from the compiled-in `plugin-substrate` as `kind` providers — so at parse time `vm` is absent, the test misses, and the member is left as opaque data. Measured: the regression test fails with the change reverted.


- **The top-level gate was handed the authored body (`charly`).** The member-path emitters strip the member key — `EntityBodyJSON` (`sdk/loaderkit/node_tree.go:121`) does `delete(asMap, ch.Name)` at `:134-136` — while the top-level `#<Kind>Value` gate validated that body verbatim. ## The single codepath

- **Author** — nesting = tree position (in-body member = into the venue; sibling = alongside); nothing else.
- **Derive** — `spec.Member.Position` from authored depth; `InSubstrate()`/`Alongside()` are its only readers.
- **Gate** — the top-level `#<Kind>Value` gate validates the node's **stripped** body via `EntityBodyJSON(pn)` — the SAME emitter the member path already uses. ONE substitution; the seam already exists (`spec/spec/loader_seam.go:410-412`). **No per-kind CUE edit.**
- **Walk** — `deploykit.WalkDeploymentTree` (and its teardown mirror) descend in-substrate / root deploy-level; every consumer calls that ONE walk.
- **Guard** — a deploy-level `local:` member with no `host:` beside a `vm:`/`pod:` parent is a LOAD ERROR. **Its own producer-first chain:** it fires at project resolve, so it lands with the org-wide `host: local` marking.
- **Migrate** — group unroll places members in-body, so `charly migrate` never re-introduces the shape.
- **Beds** — each "inside" member moves in-body; each bed asserts the GUEST-side marker.

## Landing order (producer-first)

`sdk` (`loaderkit/parse.go:209`, the parse parent-classification) → `charly` (the gate substitution, `provider_kind_invoke.go` / `validateKindValueCUE`) → `plugin-migrate` → `distro-arch` + `distro-cachyos` → the `sdk` guard + the marking sweep (its own chain) → docs. **No `spec` leg** — the CUE bodies are not opened per kind; the seam is already generic.

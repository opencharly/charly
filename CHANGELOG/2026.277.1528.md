# 2026.277.1528 — feat(charly): build a compiled-in plugin from a local checkout (charly#775)

## Summary

**Part of #775** — implementing its scope item **1** (a first-class override for a compiled-in plugin's source), with the containment the issue's sketch asked for made structural instead of disciplinary.

**This PR leaves #775 open.** It implements one of that issue's two legs; the second — the standards text for the compiled-in case — stays tracked there, and its routing is named below. No auto-close keyword is used anywhere in this body, deliberately.

A `compiled_plugins:` candy is welded into the `charly` binary at build time: `pluginsgen` emits `charly/plugins_generated.go` (one `registerCompiledPlugin` per selected candy) and resolves each one as a `require` pin in `charly/go.mod` from the **module proxy** at that candy's Go tag. There was no sanctioned way to build that binary against a **local checkout** of the plugin's source, so a bed could not exercise an unmerged compiled-in plugin at all. `plugin-check#76` is exactly that: a change to the compiled-in `check` plugin whose R10 witness is a real bed run.

The obvious hand-edit — adding a `use`/`replace` line to `go.work` — cannot work: `pluginsgen` **regenerates** `go.work` on every `scripts/bootstrap-charly.sh`, so the line is wiped before the build that would have used it. The override therefore has to be a **generator input**, not a workspace edit.

The seam:

* **`-dev-plugin <candy-name>=<repo-checkout>`** (repeatable) on `charly/internal/pluginsgen`. It re-points the **whole repo read** — both the word→ref index (`indexRepoPluginRefs` now takes a checkout dir, so the `refs.DownloadRepo` call moved to the caller) and the candy-block/shape reads — at the named checkout instead of the proxy tag. The name is validated at the flag: it must be in `compiled_plugins:` and `candy/<name>/go.mod` must declare `github.com/opencharly/<name>/candy/<name>`, i.e. the module the generated registration imports — so a wrong name or a wrong checkout fails with both paths at the flag, not inside `go build`. The pin is still read (`moduleVersion`), because the proxy tag is the release contract.
* **`--dev-plugin`** (repeatable) on `scripts/bootstrap-charly.sh`, which passes it through, selects the generated dev workspace with an explicit `GOWORK`, prints a loud **DEV BUILD** notice on stderr, and **refuses `--install`** — a dev build links unmerged plugin source, and a shared install is how one would silently become everyone's `charly`.
* **A separate `go.work.dev`, never the tracked `go.work`.** This is the containment #775 asked for, made structural: Go writes a workspace's checksum lock at `<workspace path> + ".sum"`, so the dev workspace gets `go.work.dev.sum`; and `go build` auto-detects only a file named **exactly** `go.work`, so the dev workspace can only ever be used under an explicit `GOWORK=`. A plain build cannot inherit the override, and `bootstrap-charly.sh` **deletes** `go.work.dev` (+ `.sum`) on the first run without one, so a stale dev workspace can never resolve a local tree for a later plain build.

Also in this change:

* **`workUsePath`** — a `use` path is ONE whitespace-delimited token and a dev override is an ARBITRARY local path, so a checkout under a directory with a space is ordinary, not exotic. A faithful port of the rule Go's own workspace writer applies (`golang.org/x/mod/modfile` `AutoQuote`/`MustQuote`), **ported inline** rather than imported: `golang.org/x/mod` is not in charly's module graph and `pluginsgen`'s stated design is stdlib + yaml + spec/refs only (R3 — same rule, no new dependency).
* **R1/R5 header-defect correction.** All three generated headers read `Code generated by pluginsgen (charly box generate-plugins)`. There is no `charly box generate-plugins` verb — the generator is run by `scripts/bootstrap-charly.sh`. Corrected to `charly/internal/pluginsgen (run by scripts/bootstrap-charly.sh)` in the same change that touches the same emitter, rather than filed as a follow-up. The sweep and its output are pasted under **How tested**.
* **Tests (R7)** — `TestDevPluginOverrideReadsTheLocalTree` is hermetic (temp root holds no other copy of the plugin, corpus empty) and asserts a word that exists **only** in the local candy's `charly.yml` reaches `plugins_refs_generated.go`, so the generated index can carry it **only** if the generator read the local tree — before this change every read went to the proxy tag. It also asserts `go.work` does **not** name the override. Plus `TestDevWorkspaceAbsentWithoutAnOverride`, `TestDevWorkspaceQuotesAPathThatNeedsIt`, and two `resolveDevPlugins` rejection tests.

**Deviation from the issue's sketch, stated plainly:** the issue's example is an env var (`CHARLY_COMPILED_PLUGIN_OVERRIDE`) and says "so the generated `go.work` carries the `replace`". Implemented as a **flag** (the build is an explicit act; a flag cannot leak through a shell environment), writing a **separate** `go.work.dev` rather than mutating the generated `go.work`. Same mechanism, strictly tighter: option 2's "revert before push, never commit" discipline becomes structurally impossible to violate — `go.work` is never written.

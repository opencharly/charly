# 2026.277.1742 — feat(packaging): declare virtctl as the kubevirt host runtime dependency

## Summary

The `kubevirt:` deploy substrate manages the guest-ssh **`virtctl port-forward` on the HOST** — plugin-kubevirt's `startVirtctlPortForward` spawns `virtctl`, and `prepare-venue` publishes the managed `ssh` alias that charly's host-side `WaitForSSH` then polls. A host without `virtctl` therefore fails the guest bring-up (`wait-for-sshd … :0`; RCA `opencharly/plugin-kubevirt#11`). The client is a **host runtime dependency** and belongs in the charly package's runtime declarations (R9).

Declared per native availability, matching the repo's existing `kind` / `kubectl` convention:

| format | declared as | why |
|---|---|---|
| `archlinux` | `virtctl-bin` **optdepend** | AUR-only; the upstream `kubevirt/kubevirt` release binary is the fallback (same shape as `cloudflared-bin`) |
| `rpm` | `virtctl` in **suggests** | no native Fedora package (mirrors `kind`/`kubernetes-client`) |
| `deb` | `virtctl` in **suggests** | no native Debian package |
| `apk` | `virtctl` in **suggests** | Alpine ships `virtctl`; kept a suggest for cross-format symmetry with `kind` |

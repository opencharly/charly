### Why the red returns

`TestPluginsGenReproducible` byte-compared **all three** generated files against a live regeneration. Two of them — `charly/plugins_generated.go` and `go.work` — are derived from **tracked** inputs (`charly.yml`'s `compiled_plugins:` + the `go.mod` pins read at their immutable tags; the `go.mod` go directive), so byte-equality is a sound gate there, and it is **unchanged** by this PR.

The third is not. `charly/plugins_refs_generated.go` is a projection of the corpus's **default branches**: `collectWordRefs` calls `refs.DownloadRepo(repo, "HEAD")` (`charly/internal/pluginsgen/main.go:163`) over the 112-repo corpus. Byte-equality between a committed projection and a live re-fetch of a **moving branch** cannot hold for more than a moment.

One factual correction to `#794`'s write-up, since the fix depends on it: `#794` says the generator *"derives the word→provider map from every plugin repo's own `plugin:` block at its newest tag"*. That is true of the **compiled-in wiring** — `refs.DownloadRepo(repoPath, "candy/"+name+"/"+version)`, line 246 — but **not** of the word→ref index, which reads `HEAD` (line 163). The distinction is the whole point: a tag can be pinned and byte-compared; a default branch cannot. Measured: `plugin-pipeline#32` merged **2026-10-04T21:04:52Z**; the red landed **21 minutes later**; the committed index named **zero** of its seven new words.

### The change

**1. Split the gate by determinism** — `charly/internal/pluginsgen/main_test.go`

- the two deterministic files keep **byte-equality**, strength unchanged;
- the upstream-derived index moves to a new `TestPluginsRefsIndexSound`, on the invariant that *is* true of a moving projection: **every word the committed index names must still be served by that same ref.**
  - a word the corpus no longer serves, **or** serves from a different ref ⇒ the index is **FALSE** — it sends a reader to a plugin that does not provide the word ⇒ **`t.Errorf`**;
  - a word the corpus serves that the index does not name ⇒ an upstream **ADDITION**: incomplete, not wrong, and nothing in this repository can complete it except regenerating ⇒ **`t.Logf`** advisory, never red.

The committed side is parsed as **source** (an AST walk for `pluginProviderRefs`) rather than re-derived — re-deriving it would compare a value to itself.

**The limit, stated rather than papered over:** a hand-edit that **deletes** a row is indistinguishable from an upstream addition when all you have is the committed file — both leave the word absent from the committed index and present in the live one — so a deletion lands on the advisory path too. Telling them apart needs the corpus commit recorded beside each entry; that is the *pinned-corpus* option, a separate decision, not taken here. What this gate catches reliably is a **false** index: a repointed provider, and a provider the corpus has dropped. Both were verified to fail by tampering the committed file (below).

The corpus set is built in **one** place — the new `corpusRepoList` in `main.go` — so the generator and the soundness gate cannot disagree about what "the corpus" means (extracted on its second use, R3).

**2. Guard the build's rewrite of tracked files** — `scripts/check-generated-clean.sh` + `scripts/bootstrap-charly.sh`

pluginsgen and workspace-mode Go both **rewrite tracked files**. `#794` is what that looks like from the human side: a build-run left a tracked file modified, and the remedy was a review-and-commit by hand. That remedy is **forbidden** in a detached umbrella submodule checkout (rule 1 / rule 5), which is where every session's `charly/` build actually happens. So the guard classifies by **what each file is derived from**:

| class | files | disposition |
|---|---|---|
| `inconsistent` | `go.work`, `go.work.sum`, `charly/plugins_generated.go` | derived from **tracked** inputs ⇒ a diff is *this checkout's own* inconsistency ⇒ **fail**, for review and commit |
| `upstream` | `charly/plugins_refs_generated.go` | derived from a source this checkout does **not** pin ⇒ nothing here is wrong; **named and restored**, so the tree stays clean at its gitlink |

`bootstrap-charly.sh` calls it **before** promoting `bin/.charly.next`, so a guard failure can never leave a half-written binary in place. Exit 2 (no git lineage — a source export) is reported and not treated as a build failure.

The class list lives in **one** place — the script, readable with `--list` — and `charly/generated_clean_script_test.go` reads it back rather than restating it, so a dropped entry fails a test.

Closes #792.

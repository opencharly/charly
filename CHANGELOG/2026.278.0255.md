### The change

Both sites asserted the error type directly:

```go
exitErr, ok := err.(*exec.ExitError)
if !ok { t.Fatalf(...) }
```

A wrapped error is not an `*exec.ExitError`, so `ok` is false and the test `t.Fatalf`s — reporting a run that exited correctly as a harness failure. Both are now `errors.As`:

```go
var exitErr *exec.ExitError
if !errors.As(err, &exitErr) { t.Fatalf(...) }
```

`import "errors"` added. This is the fix the linter asked for and nothing else — no behaviour change to the guard, the generator, or the drift gate.

Relates to `opencharly/charly#792` (the drift-gate cause, fixed by `#795`), `opencharly/charly#793` (its symptom, closed) and `opencharly/charly#796` (the merge-gate gap this PR's history exposes).

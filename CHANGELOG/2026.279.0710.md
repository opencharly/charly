### Why one PR covering the whole lagging set

Advancing charly's `box/*` view to the merged distro default-branch HEADs is a single
canonical operation, and the boundary is *the set that lags* — which is how the recorded
precedent drew it: `charly/CHANGELOG/2026.270.1006.md` advances `box/{cachyos,fedora,omarchy}`
and notes `box/{arch,debian,ubuntu}` "already matched their mains and are untouched".

This head merges `origin/main` in. `opencharly/charly` has `allow_update_branch=false`, so
GitHub's auto-merge will never self-update a `BEHIND` branch — the validator's PASS armed
auto-merge, but the branch had to be brought current by a local merge (no force-push, and no
`gh pr update-branch`). The payload is unchanged by that merge: the diff against the current
`origin/main` is still exactly the six gitlink lines.

An earlier revision of this PR advanced `box/cachyos` alone and deferred the other five. That
boundary was arbitrary, and the reason given for it was the size of the remainder — not a
permitted ground for narrowing a sync. All six lagging pins advance here, in one commit each,
and nothing is deferred.

### The runner-image chain leg this carries

`box/cachyos` is the leg of the chain this work started from, and it is the one whose content
is not merely a lag:

```
candy pod-github-runner#8 (merged, tag v2026.279.0028)
  -> distro-cachyos#123 (merged a972aded, tag v2026.279.0046)
  -> THIS PR: charly box/cachyos -> a9afa6b1
  -> umbrella `charly task sync` (distro-cachyos gitlink)
  -> operator rebuild + redeploy of charly-githubrunner-no-{1..4}
```

Policy B mirrors charly's `box/*` gitlinks into the umbrella's `distro-*` pins, so the
umbrella's `distro-cachyos` cannot advance ahead of charly's `box/cachyos`. Before this PR the
umbrella leg would have recorded `88ca1d57e6`, which pins
`pod-github-runner:v2026.243.0410` — roughly thirty versions behind the candy the runner fix
lives in.

**Two version numbers, no contradiction.** The pinned commit is `a9afa6b1`; the CalVer tag
`v2026.279.0046` points one commit *earlier*, at `a972aded` (the squash-merge itself):

```
$ gh api repos/opencharly/distro-cachyos/git/ref/tags/v2026.279.0046 --jq '.object.sha + "  type=" + .object.type'
a972aded4770eed0d97482f75ce1573b34ccb80c  type=commit
```

That is the ordinary `tag-on-merge` order — tag the merge commit, then push the CHANGELOG
commit for that tag. `a972aded` is an ancestor of `a9afa6b1`; both are on `main`.

## R10 — this diff's class, and the explicit N/A

charly declares **no check bed that composes a `box/*` submodule**. On this head:

```
$ grep -cE '^check-' charly.yml
55
$ grep -n 'box/' charly.yml | grep -vE ':[[:space:]]*#' | grep -cE 'box/(arch|cachyos|debian|fedora|omarchy|ubuntu)'
0
```

Fifty-five beds, zero references to any `box/<distro>` submodule as a source. The count moved
51 → 55 on this head: `origin/main` gained the `check-kubevirt-vm` bed family while this PR was
open, and those beds compose inline `vm:` manifests too.

**Disclosed rather than implied — `charly.yml` *does* name the distro repos, by a different
mechanism.** The `import:` block maps the six distro namespaces to published refs:

```
$ sed -n '20,27p' charly.yml
    - arch: '@github.com/opencharly/distro-arch:v2026.274.1256'
    - cachyos: '@github.com/opencharly/distro-cachyos:v2026.274.2120'
    - debian: '@github.com/opencharly/distro-debian:v2026.274.0746'
    - fedora: '@github.com/opencharly/distro-fedora:v2026.274.2213'
    - ubuntu: '@github.com/opencharly/distro-ubuntu:v2026.274.0752'
    # omarchy imports the `arch` namespace the same way cachyos does — its distro
    # entity `inherits: arch`, and its boxes base on arch.arch / arch.arch-builder.
    - omarchy: '@github.com/opencharly/distro-omarchy:v2026.274.2118'
```

Those are `@github` **refs**, resolved from the registry — a different pin from the `box/*`
**gitlink** this PR moves. The gitlink is the on-disk checkout the corpus tests read (§3); the
`import:` refs are untouched here and are not advanced by this PR. So the `0` above is a claim
about bed *sources*, and this paragraph is the caveat that stops it reading as "charly never
mentions the distros". charly's beds
compose inline manifests from the root `charly.yml` (`check-k3s-vm`, `check-k8s-deploy`,
`check-helm-vm`, `check-kubevirt-operator`, `check-kindcluster`, …), and its comments cite
`box/arch` / `box/fedora` beds only as precedents authored in those repos. There is therefore
**no charly-side `disposable: true` target whose fresh rebuild would exercise a gitlink
advance: N/A**, and the class-appropriate gate is the fixture-reading suite in §3, run fresh in §4.

The pinned content's own live proof is on the record in the consuming repo: `distro-cachyos#123`
ran its `check-githubrunner-pod` bed (`disposable: true`) → 14/14 PASS against the ref this PR
pins, and the built image's labels read back as in §R8. That run belongs to that PR; it is cited
here because the ref it proved is the ref this PR records — not as evidence this repo produced.

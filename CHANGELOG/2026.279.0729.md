# 2026.279.0729 — chore(go.mod): bump plugin-harness-kind + spec to the optional-version schema

## Summary of changes

The marketplace `version:` stamp was retired **on purpose** — the marketplace versions by commit
SHA (`marketplace/README.md`: *"No `version` fields anywhere"*). But the schema still **required**
it, so the one repo carrying a `marketplace:` entity failed `charly box validate` with
`#MarketplaceInput.version: incomplete value`.

The root fix relaxes the schema in its two owning repos, both merged:

| Repo | Change | Tag |
|---|---|---|
| `opencharly/plugin-harness-kind` | `#MarketplaceInput.version?` (the loader's gate) | `v0.2026279.629` |
| `opencharly/spec` | `#Marketplace.version?` (the core contract) | `v0.2026279.630` |

**Two commits, 8 files across 4 modules:**

1. **`chore(go.mod): bump plugin-harness-kind + spec to the optional-version schema`** (`22c076cb`)
   — `charly/go.mod` advances the two pins; `charly/go.sum` follows (`go mod tidy`). Without this,
   the fixed schema exists only in the producer repos and **every build still rejects a
   version-less `marketplace:` entity**.
2. **`chore(go.mod): adopt the shared spec pin in the tools modules`** (`610c7e60`) — the bump left
   the `tools/*` lockstep modules on the older shared spec pin, so the CI gate that runs every
   tools module failed (`TestContractPinsMatchShared`, `tools/gomod-canonical`). That test IS the
   shared-pin drift guard and names its own remedy, `charly task mods-tidy`; running it advances
   `spec` to `v0.2026279.630` in all three modules and tidies each `go.sum`:
   `tools/generate-packages/{go.mod,go.sum}`, `tools/golden-cloudinit/{go.mod,go.sum}`,
   `tools/golden-compile/{go.mod,go.sum}`.

**Closes / relates to:** unblocks opencharly/pod-charly-hooks#13 (merged) and
opencharly/marketplace#422.

**Breaking change + rollback:** none — a required schema field becomes optional, so every config
that validated before still validates. Rollback is a revert.

# 2026.280.2217 — fix(charly): decode a verb provider's reply through the contract, capture included

## Summary

The **consumer half** of opencharly/charly#780. charly kept its OWN declaration of the out-of-process verb reply — `pluginCheckResult{status,message}` (`charly/provider_checkenv.go`) — and decoded the provider's JSON with it, so the producer's `CapturedValue` never reached the `CheckResult` the check run carries and the ledger records. The producer half is **merged and tagged**: opencharly/sdk#355 (merge `d89a6fac17d98fb7b9c699d47ab84a8db7969c7a`, tag `v0.2026280.2133`) now encodes the verdict's JSON-encoded capture as the wire's raw `captured_value`.

charly now decodes through the **contract module's own decoder**, `ops.ParseResultJSONFull`, and threads the decoded value into `CheckResult.CapturedValue` — the out-of-process twin of `checkResultFromVerb`, which already maps the in-process verdict. `pluginCheckResult` is **deleted**, so no surface can re-declare the wire: a malformed reply is a FAIL naming the verb, and an unrecognised status is a FAIL, exactly as the hand-rolled switch had it. The producer's own contract comment for the field is spec#194 (PR opencharly/spec#203).

**Files (10):** `charly/provider_checkenv.go` (the type deleted; `checkResultFromVerbReply` + the doc reference added; imports), `charly/check_verb_reply_test.go` (new), and the R5 sweep — `plugin_grpc_test.go`, `plugin_external_test.go`, `plugin_appium_external_test.go`, `plugin_checkcontext_e2e_test.go` (its `dispatch` now returns the production `spec.CheckResult` through the production seam, so the e2e asserts what a check run would carry), `external_verb_dispatch_test.go` (comment), `checkspec_test.go`, `go.mod` + `go.sum`.

Two sweeps ride along, both in the same cutover's theme:

- **Every reference to the deleted shape.** The five test sites that hand-decoded `pluginCheckResult` now go through the production conversion; nothing in the tree names the deleted type (grep below).
- **The claim-keyed sibling.** `charly/checkspec_test.go` carried an ORPHANED docstring for a deleted test, describing the long-removed `capture_extract:` / `capture:` matchers and the `ScenarioContext.Captures` stash they fed — the same false claim as spec#194's, one level out. It dies here.

The sdk pin moves `v0.2026280.1251 → v0.2026280.2133` — the producer's consumer-pin step in this same landing. It is an INDIRECT require (no charly package imports the SDK directly; the compiled-in plugin candies do), so this is the SDK the assembled binary's plugins build against.

Closes opencharly/charly#780 — Refs opencharly/sdk#355 — Refs opencharly/spec#194

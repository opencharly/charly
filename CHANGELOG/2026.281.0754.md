# 2026.281.0754 — fix(loader): record baked plugins of EVERY class, so a bed can witness a deploy-class plugin (#831)

Agent: `retention` · session `task-12` — filed by me as `opencharly/charly#831` (cluster C10a, the bed-witnessing family)

## Summary

A bed could not witness a local, unpushed **`deploy`-class** plugin. The baked route — `CHARLY_PLUGIN_DIR`
plus a `<binary>.providers` word manifest — is the documented way to point charly at a plugin built
from a working tree, and it **worked for a `verb:` word while being silently inert for a `deploy:`
word**: `discoverBakedPluginWords`'s class switch skipped every other class, and its `default:
continue` fired *before* the `bakedPluginBinaries` record below it, so a `deploy:pod` line did not
merely fail to register — the binary was never even recorded, and the resolve could not answer.

That is why an R10 bed graded the **released** plugin while the author believed it was grading their
branch: `Resolved @github.com/opencharly/plugin-deploy-pod -> main (default branch)`, and
`grep -c "<worktree>" <bed log>` → 0. It blocked `plugin-deploy-pod#30`'s change-class gate, and it
would have blocked `plugin-vm`, `plugin-deploy-local`, `plugin-kube` and `plugin-adb` the same way —
the deploy substrates are exactly the plugins whose changes need a bed most.

**The connect side was already class-agnostic, which is what made this a one-gate fix.** Recon:
`connectPluginByWordRef` (the ONE on-demand connect entry every host out-call and peer invoke uses)
consults `connectBakedPlugin(class, word, parent)` **first**, before any project scan, and that lookup
is keyed `class:word[:parent]` in one map; `splitCapability` parses `deploy:pod` fine; the deploy
dispatch reaches the entry (`pod_lifecycle_verb.go` → `connectPluginByWord(ClassDeployTarget, …)`).
Only the discovery skipped it.

**The fix keeps the EAGER surface per class exactly as it was** — a command still needs its kong
grammar entry, a verb still needs the lazy verb-dispatch hook — and **records every declared word of
every class**. Recording is not registering: no class gains a CLI surface it did not have, and a
`deploy:` word is still resolved on demand by its own dispatch, through the same lookup every other
class uses.

Closes #831

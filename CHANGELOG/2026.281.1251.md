## Summary

Six entities pinned an Arch cloud image that cannot be fetched. **The RCA's finished form is ONE
mechanism — the pinned VERSION was pruned from the mirror's rolling window — and reaching it required
correcting my own first reading, which had claimed a second mechanism and was wrong. That correction is
recorded below rather than deleted, because a body that quietly drops a refuted claim shows less than one
that shows what refuted it:**

1. **The version was pruned, and that is the whole cause.** The pinned release `v20260701.551070` is gone
   from the mirror: its directory 404s on every attempt, the URL 404s on every attempt, and the version is
   **absent from the mirror index** — the oldest release still served is `v20260715.556894`. The mirror
   keeps a rolling window, so any version pin rots eventually.
2. **CORRECTION — the filename shape is NOT gone; I claimed it was, and the claim was a probe error.** I
   had probed `…cloudimg-v20261001.604814.qcow2` — a `v` inside the FILENAME — and read its 404 as the
   shape being dead. The pin's actual shape has no `v` there, and it serves on every released version:

```

```

   So the shape needed no change. The falsifier was sitting in the pin's own filename: one character
   (`v`) separated a claim about the object from a test of a different one.

**The fix, and the one deliberate oddity in it.** The six sites — `k3s-vm`, `eval-vm`, `eval-host-vm`,
`charly-vm`, `check-kubevirt-vm-box`, `agentteams-vm` — now name the artifact whose checksum the mirror
actually ATTEST, which is why the URL pairs a versioned DIRECTORY with an UNVERSIONED filename:

```
url:      https://geo.mirror.pkgbuild.com/images/v20261001.604814/Arch-Linux-x86_64-cloudimg.qcow2

```

That choice is measured, and the measurement is a state of a REMOTE, so here it is with its command rather
than as a bare claim — it also changed under me between two readings, which is why it is fenced:

```

```

Both names are attested, with the **same digest**, so the two files are the same bytes and either name is a
defensible pin: this diff keeps the unversioned one, which is what the bed below fetched and verified
end-to-end. (Earlier today the versioned `.SHA256` returned 404 and I wrote that down; it now returns 200 —
a remote's state moving, not a change of mind. That the versioned file's digest is now published is
precisely what makes a **durable** pin possible, and it is recorded on **`opencharly/charly#844`**.)

**Blast radius, which is why this is its own fix:** `eval-host-vm` is the guest-as-host image behind
`check-local-vm`, the disposable bed that proves the `kind: local` layer-application path off the
operator's workstation. While the image is unfetchable, **every VM-bedded change is blocked by the
environment rather than by its own diff** — it has already cost `plugin-fleet#33` a verdict round.

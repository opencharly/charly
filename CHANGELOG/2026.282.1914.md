# 2026.282.1914 — fix(migrate): compile the plugin-migrate that carries its own version-strip guard (plugin-migrate#16, charly#827)

## Summary

`charly/charly/go.mod` compiled `plugin-migrate v0.2026272.332`, which predates the producer's own guard (`a7f1e42`, tagged `v2026.276.1713`). The unguarded `strip-version-stamp` step deleted the first top-level `version:` line of **any** file its candidate sweep was handed — so `charly migrate` silently corrupted configs charly does not own, measured on a real host as `version: "2"` vanishing from a tracked `.golangci.yml` (`opencharly/plugin-migrate#16`).

This is a **one-line pin bump** to the latest merged tag, `v0.2026280.2238`, which carries the guard. No charly code changes.

`charly/go.sum` moves with it: the module-mode gate (`GOWORK=off`, which is what CI runs) needs the module's own sums.

**`go.work.sum` deliberately does *not* move — and an earlier revision of this PR got that wrong.** That revision ran `go mod download` in **workspace** mode, and the tool recomputed `go.work.sum` from the current graph, *dropping* the sums for two modules with nothing to do with `plugin-migrate`:

```console
$ git diff origin/main...HEAD -- go.work.sum      # the FIRST revision
-github.com/buger/jsonparser v1.1.2 h1:…
-github.com/opencharly/plugin-candy/candy/plugin-candy v0.2026281.948 h1:…
+github.com/opencharly/plugin-migrate/candy/plugin-migrate v0.2026280.2238 h1:…
```

That is tool churn, not an intended change, and shipping it would have silently deleted two unrelated modules' sums from the workspace. It is **reverted**, and both modes are now measured with it gone:

```console
$ cd charly && go build ./...              # GOWORK=on (workspace)  → rc=0
$ cd charly && GOWORK=off go build ./...   # module mode, what CI runs → rc=0
```

So the workspace never needed the pruning. The diff is exactly the pin: `charly/go.mod` (±1) and `charly/go.sum` (+2).

**One further upstream fix rides in, and is named rather than hidden:** the two commits between the guard tag and the latest are the guard's own CHANGELOG and `feat(migrate): retire a barren group: node — an unloadable per-host config` (`charly#827`). Both are the producer's; adopting the latest tag adopts both. Nothing else is bundled.

## How tested

**The corruption reproduced, and then shown gone — live, on a scratch project, red against green.**

RED is the **pre-existing umbrella binary** (built 2026-10-08, while the old pin was in force; its own panic trace names `plugin-migrate@v0.2026272.332`). GREEN is this branch's worktree-local build, `2026.282.1859`. The fixture carries a **legacy top-level schema stamp in its own `charly.yml`** — something `migrate` is genuinely FOR — plus a `.golangci.yml` carrying golangci-lint's own `version: "2"`, which charly does not own.

```console
$ charly -C <scratch> migrate          # RED — old pin
applied strip-version-stamp
migrated
  charly.yml:     0 version: lines     # the intended migration ran
  .golangci.yml:  0 version: lines     # ← CORRUPTION: another tool's schema stamp deleted

$ charly -C <scratch> migrate          # GREEN — this branch
applied strip-version-stamp
migrated
  charly.yml:     0 version: lines     # the intended migration STILL runs
  .golangci.yml:  1 version: lines     # ← the guard holds
    version: "2"
    linters:
        enable: []
```

**The guard is targeted, not a blanket removal** — the part worth showing. The real migration still strips the stamp it exists for; only the collateral damage is gone.

# 2026.283.0000 — fix(pins): advance plugin-candy to v2026.281.0948 — the pin predated `charly candy params` (#872)

## Summary

`opencharly/charly#872`. **`charly candy params` does not exist in any binary the org can build**, because this repo's compiled-in `plugin-candy` pin predates the merge that added it:

```console
$ charly candy params plugin-sidecar --check          # BEFORE, the released dev binary
charly: error: command "candy": unknown candy subcommand "params"
exit=1

$ gh api repos/opencharly/plugin-candy/commits/v2026.271.2318 --jq '.commit.committer.date'
2026-09-28T23:18:35Z          # the pin — TEN DAYS before the command landed

$ gh pr view 9 --repo opencharly/plugin-candy --json state,mergedAt
MERGED  2026-10-08T08:33:53Z  # feat(candy): `charly candy params` …
```

**The producer landed, the release tags exist (`v2026.281.0833`, the merge commit itself, and `v2026.281.0948`), and the consumer's pin was never advanced.** So a merged, compiled-in capability existed in the org and in no obtainable binary — which is why two PRs documenting it have been blocked on *"prove the page names a command that runs with nothing but `charly`"*, a proof that **could not be produced while the pin was stale**.

## The change

One line — `charly.yml`'s `plugin-candy` ref, `v2026.271.2318` → `v2026.281.0948`. **A pin advance to a merged release tag**, which is Policy B's rule: pin only MERGED refs, never a branch.

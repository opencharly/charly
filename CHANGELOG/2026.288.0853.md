# 2026.288.0853 — Index plugin-firecracker in the corpus, so command:/verb:firecracker reach the ref map

Agent: charly-dsh

## Summary

**`charly/plugin_corpus.txt` gains `github.com/opencharly/plugin-firecracker`**, and the regenerated ref map ships with it.

This is one of the **two inputs** the word→provider map is generated from, and the one that was missing. `pluginsgen` derives `pluginProviderRefs` from every plugin repo's own `plugin:` block — its `providers:` plus `source:` — **for the repos named in this list**, which `scripts/bootstrap-charly.sh` passes as `-corpus`. The list named `plugin-deploy-vm` and `plugin-egress` but not `plugin-firecracker`, so the substrate's providers had no route and other substrates did.

Diff, read from `git diff --stat origin/main` on the live tip `1c8a97b8` — **two files, +4/-0**:

| file | change |
|---|---|
| `charly/plugin_corpus.txt` | one line: `github.com/opencharly/plugin-firecracker` (113 → 114) |
| `charly/plugins_refs_generated.go` | the regenerated map — **three** new entries |

The generated half is a *projection*, so it ships in the same commit; hand-editing it is a gate violation (`no_provider_ref_map_gate_test.go` exists to catch exactly that).

**Three entries, and the third comes from another repo.** Indexing this repo brings in **`command:firecracker`** and **`verb:firecracker`** — and `kind:firecracker`, which **`plugin-substrate`** declares. The corpus list and the declarations interact across repos, not one-to-one.

**`deploy:firecracker` is DELIBERATELY ABSENT, and that is the point of this head.** An earlier version of the index recorded it, because it was generated from a run whose `-dev-plugin` pointed at a declaration that had not merged. The owning repo then **withdrew** the claim — **`opencharly/plugin-firecracker#8` merged `907e6ad8` at `2026-10-15T00:16:46Z`**, *"Gate declared provider words against served classes (deploy claim withdrawn)"*. So `deploy:firecracker` is gone ON PURPOSE, and **re-adding it is a plugin-repo decision, not a `charly` one.**

The out-of-tree `go run` above is a **falsifying check** — it fails without the line (`9 -> 0`) and passes with it (`9 -> 9`) — but it is **not a shipped test**, so the tier below is capped rather than `fully tested`.

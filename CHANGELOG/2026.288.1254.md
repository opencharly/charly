# 2026.288.1254 — chore(deps): adopt plugin-harness-kind v0.2026288.1214

## Summary

**Leg L3c** of the `.agents/skills` relocation (`opencharly/opencharly#496`): the consumer half of the chain.

[`plugin-harness-kind#10`](https://github.com/opencharly/plugin-harness-kind/pull/10) relaxed the `skill` kind's served `#SkillInput` so a node may carry only its *routing* metadata while the prose lives in `.agents/skills/<name>/SKILL.md`. charly **compiles that plugin in**, so the relaxed gate has to be live in the binary *before* any repository strips its `content:` — otherwise the first repo to move fails its own `charly box validate` with `#SkillInput.content: incomplete value`. This commit adopts the tag that carries it:

```
$ grep -n 'plugin-harness-kind' charly/go.mod
40:	github.com/opencharly/plugin-harness-kind/candy/plugin-harness-kind v0.2026288.1214
```

**One trap worth writing down, because it is invisible until it bites:** the git tag and the Go module version are different encodings — the tag is `v2026.288.1214`, the module version is `v0.<YYYYDDD>.<HHMM with leading zeros stripped>`. That is why the *previous* pin read `v0.2026279.629` for the tag `v2026.279.0629`, and why a pin bump that copies the tag verbatim would not resolve.

**No generated wiring changed.** `plugins_generated.go` and `plugins_refs_generated.go` are written by `internal/pluginsgen` through `scripts/bootstrap-charly.sh`; running it on this tree produced an **empty diff** (`git status --short` = 0), because the plugin *set* is unchanged and only its version moved. So the leg's whole tree change is the require plus `go.sum`.

# 2026.289.0116 — fix(loader): the spec pin carries spec#247, so a candy may declare `skills:`

## Summary

`charly#953`. **The host's kept-value load gate refused the settled design's own declaration** — `node "charly-internals": candy: skills: field not allowed` — so a repo could not say where its skill and agent trees live. The field is `#Candy.skills`: the repo-relative TREES a candy declares, each holding `<tree>/<name>/SKILL.md` plus `references/<stem>.md` for a skill and `<tree>/<name>.md` for an agent, defaulting to `.agents/skills`. It is the ONE place the marketplace generator looks for a family's prose — which is why the relocation that moved a family's skills out of its manifest and beside it had nothing to declare but the default.

**The change is one require plus its tidy — in every module that carries the pin.** `github.com/opencharly/spec v0.2026287.1848` → `v0.2026288.1242`, the first tag carrying the def (`spec#247`, day 288; this repo's pin was day 287), adopted through the repo's own `charly task mods-tidy` so the three `tools/*` modules that share the pin move with the anchor. Nothing is vendored: the kept value defs arrive through the spec **Go module** (`spec.KindValueDefs`, which `cue_kinds_corpus_test.go` already walks through `validateKindValueCUE`), so no CUE is re-cut here, no generated type is hand-written, and `go mod tidy` is clean.

**One test arm holds the boundary** — `candy_skills_declaration_test.go` loads a project whose candy declares `skills:` and asserts the declaration survives the gate, because a gate that silently dropped it would be as broken as one that refused it loudly.

Closes #953

## Summary

**This repo had no owner for its own `box/*` gitlinks, and this change gives it one — then uses it.** The umbrella pins each `distro-*` FROM this repo's nested `box/*` gitlinks (`pinned_from: charly` + `pin_map`), so the value every consumer records IS the gitlink recorded here; nothing here could advance them, which is why five of six consumer pins were unreachable by any command in either repo (`#936`, `#942`).

**Three parts, one cutover:**
1. **`charly.yml` gains the pin operation** — `pins` (the one definition, mode via param) with `sync` as its named advance entry point. The six `box/*` are **leaves** (`branch = main` in `.gitmodules`, landed as `d72c0063`), so their intent is `upstream:main` judged against the **remote**, and there is deliberately no `pin_map` here: this repo declares no derived edge of its own.
2. **The five stale pins advance**, by `charly task sync`: `box/{arch,cachyos,debian,fedora,ubuntu}`. The instrument's own answer goes from **`5 of 6 NOT current [5 behind, 1 cur]`** to **`0 of 6 NOT current [6 cur]`**. Nothing was hand-pinned; `box/omarchy` was already `cur` and did not move.
3. **`plugin-task v0.2026283.105 → v0.2026288.804`** — because the surface this change adds ships `MODE=currency` and the pinned version **predates that mode**: without the bump the new task's own decisive mode cannot run (`opencharly/charly#956`, filed from the consumer side, is the same defect seen from the umbrella).

**Test coverage ships with it:** `check-task` — the declared R10 witness of the compiled-in `charly task` surface — is extended in this commit so it goes **RED without the change**. It now asserts both new tasks are declared, and it composes the new `pins` task's plan through `verb:task`, i.e. **through the compiled-in `plugin-task` provider the third part bumps**.

### ★ The composition proof — and the instrument that had to be fixed before it meant anything

The reconnaissance flagged this as not order-free: all six `box/*` manifests are referenced from within this repo, and the `from:` chains cross namespaces (`from: cachyos-vm`, `from: cachyos-gpu-vm`, `from: omarchy-jetkvm-install-host`, `from: arch`). Proving what the committed tree composes needed a differential, and **the first differential I ran was a false positive I caught with a control**:

```
$ # two generations, SAME pins, one minute apart — the base tag moves with the clock
run 1: 5cf0525191b2462b   ARG BASE_IMAGE=ghcr.io/opencharly/arch:2026.289.1133
run 2: b1cfca4f4f5a2bd9   ARG BASE_IMAGE=ghcr.io/opencharly/arch:2026.289.1139
```

So the `auto` tag is wall-clock-derived and **a Containerfile hash is not an instrument for pin work**. The instrument used instead derives its mask from a same-state pair, and only then compares across states — same binary, same flags, before-state in a checkout whose submodules sit at the *recorded* gitlinks:


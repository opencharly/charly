# 2026.289.1441 — fix(system-packages): give the apk format its host: install cell, and the control it lacked (#772)

## Summary

**The `apk` format was the only non-`secondary` package format whose `phase.install` carried a `container:` cell and no `host:` cell.** *On a `target: local` (host) venue a `SystemPackagesStep` therefore installed **nothing** — silently — while `deploy del` still recorded a package-remove op.*

**Measured before the change:**

```console
$ grep -nE '^\s+host: \|' charly/charly.yml
  ** 7 cells **: 309 · 339 · 365 · 382 · 407 (format install:) · ** 1346 → deb: ** · ** 1566 → rpm: **
$ # host cells inside the apk block
  ** 0 **
```

***`deb` and `rpm` each carried a `host:` cell for exactly that venue; `apk` carried none.*** **The change mirrors them** — `/etc/apk/keys` and `/etc/apk/repositories` setup, then `apk add --no-cache{{range .Options}} …{{range .Packages}} …` — **inserted *before* the `container:` cell, in the order the siblings use.**

## How tested

**The control this lane never had, written to fail without the change — the same shape the sibling test uses.**

```console
$ go test -run TestEveryPackageFormatWithContainerInstallAlsoDeclaresHost ./charly -v
  ** WITH the cell: **     --- PASS (0.00s)
    checked 3 container-install format(s); ** skipped 1 secondary format(s) [arch/aur] **
  ** WITHOUT the cell: **  --- FAIL (0.00s)
    distro "alpine" format "apk" declares a container: install cell but NO host: cell — on a host venue
    (target: local) it installs nothing

$ charly box validate
  ** OK — checked 602 candies, 122 boxes, 48 deploys, 7 distros, 7 builders; 0 warnings, 0 errors **
```

***It reads the COMMITTED manifest rather than a `testdata` fixture — because the committed one is what ships — and asserts **structurally** that a format installing in a container also installs on a host, so a stray `host:` elsewhere in the file cannot satisfy it.***

***It parses that manifest with a single `yaml.Unmarshal` rather than through `LoadBuildConfigForBox`, and the reason is an RCA recorded on the thread: **that loader resolves every `@github` ref and reaches for the network**, and the first version of this control therefore hung the `Test` step in CI for two hours (locally it took 76s), leaving the gate unable to reach a verdict.*** **A control that cannot report anything is a worse failure than the one it catches, and it is an R3/R8 violation: no test reaches for infrastructure, and a boundary crossing a real service runs live or skips visibly, never hangs.*** ***The hermetic form still tests the file that ships, with no ref resolution and no network: **0.00s.***

**And the negative control was run by hand, not assumed:** *remove the `host:` cell from the `apk:` block and the test fails naming `alpine`/`apk`; restore it and it passes. **Two of my own errors were caught on that path and are recorded on the thread: the first rewrite read `../charly.yml`, which from `charly/charly/` is a different file, and the first negative control deleted from the wrong `host:` cell and mangled 170 lines before the diff caught it.*** The manifest now carries **8** `host:` cells — the delta is one cell, no collateral edits.*

## What this test found that the issue did not

**The issue says `apk` is "the only format" in this state. Writing the general assertion proved otherwise:**

```
distro " ** arch ** " format " ** aur ** " declares a container: install cell but NO host: cell
```

***That is a real difference, and it is **not** the same defect.*** *`aur` is `secondary: true` and container-only by construction — it does `COPY --from={{.StageName}} /tmp/aur-pkgs/` and `pacman -U` inside the image, and declares no `install_template`, `download_template`, `probe` or `local_pkg`. **There is no host mechanism to mirror.***

***So whether a host venue supports AUR packages — by a `makepkg` host leg, or by failing loudly, or not at all — is a contract question. The assertion therefore **skips** a `secondary` format and **names** it in its output, and the question is filed as **opencharly/charly#963** rather than answered by inventing a host-side build path just to turn this test green.***

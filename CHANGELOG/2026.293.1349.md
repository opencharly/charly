## Summary

Moves the inline `skill:` body out of `packaging/charly.yml` and into the candy's own
`.agents/skills/` directory — beside the candy that declares each node, which is where the loader reads it — leaving each
`skill:` node carrying only its routing metadata. The exact file paths are in the table below; **no placeholder path is
narrated here**, because a path in prose that the diff does not contain is a claim the reader cannot check.

| node | body | lines |
|---|---|---|
| `charly` | `packaging/.agents/skills/charly/SKILL.md` | 111 |

Diff against `main`: **111 insertions and 105 deletions across 2 files** — 1 new
`SKILL.md` and the manifest, whose `content:` blocks are deleted.

The same hunk also deletes the **1** `description:` block(s) from the `skill:` node(s). That is deliberate and part of this change, not collateral: `sdk/deploykit/skills_collect.go` reads `entry.Description = s.Description` **only** on its `sf == nil` branch — the transitional in-line form — and `entry.Description = sf.Description` overwrites it unconditionally once a body file exists, so the node field is unreachable after this migration.

### Why beside the candy, and how it is proven

`sdk/deploykit/skills_collect.go` resolves the tree as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`, and
`GetSourceDir()` is the directory of the candy whose manifest declares the node.

`sdk#430` (merged, `v0.2026293.1143`) added `deploykit.CollectSkillBodies`, and `plugin-box#57` (merged,
`v2026.293.1153`) calls it from `runValidateEngine` — so `charly box validate` now fails when an authored `skill:`
node has no body beside its candy. Before those two merges, no command in a repo that composes no box could read a
skill body at all, because `CollectSkills` gates body reads on `BoxCandyChain`, a label-size policy.

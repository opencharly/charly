# 2026.293.2010 — fix(plugin): give step-class dispatches the heavy idle window

## Summary

Head `502cd7b183740714655ee3cc1935200eb047e633`.

The peer-dispatch idle guard used the probe `no_progress` window (90s) for EVERY provider class. The step providers run package installs, which go minutes between host-visible legs: on the CachyOS VM bed's deploy, `step:system-packages` was killed after a single reverse leg while pacman was upgrading packages (`host reverse legs=1 (last 1m30.001s ago), CPU advances=0 … window=1m30s`).

Step-class dispatches now use the heavy per-attempt window (`loadedReadiness().PerAttemptHeavy`, 15m by default) — the same sparseness rationale #123 applied to the build steps — while every other class keeps the probe window. `TestStepDispatchUsesTheHeavyIdleWindow` pins the class mapping and the floor (the step window must exceed the probe fallback).

edges.** That is the mechanism above rather than a prediction: the umbrella's six recorded
`distro-*` gitlinks are byte-identical to the six `box/*` gitlinks at charly's current HEAD (edge

**What that measurement honestly does NOT cover: the umbrella run itself.** It cannot be taken before
the merge — phase 1 fetches `origin/main` and would roll `charly` back to `68675149`, so a pre-merge
run would measure the old pins by construction, and forcing it (a rewritten local `origin/main`, a
hand-pin, a manufactured clone) is what Hard Cutover forbids. **So the umbrella's actual advance is
deferred to the umbrella leg**, whose sequence is: this PR merges and tags → the umbrella's own
`charly task sync` (or `task pins --param MODE=bump`) in a worktree that leg owns → `task pins
--param MODE=currency`, whose `NOT CURRENT` list should no longer name any `distro-*` path. That leg
should also expect phase 1 to roll the other 425 submodules, which is the whole reason this producer
leg exists.

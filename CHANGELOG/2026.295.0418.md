# 2026.295.0418 — chore(deps): adopt sdk v0.2026294.1520 and the reader that checks the body

## Summary

`charly`'s Go module pinned `github.com/opencharly/sdk v0.2026293.417` — a pre-`sdk#445`
`deploykit` — and `github.com/opencharly/plugin-box/candy/plugin-box v0.2026288.503`, a
`command:box` that predates `validate_skills.go`. The first is why no charly build resolves a skill
body at the owning candy's REPO ROOT; the second is why `charly box validate` read no skill body at
all, in either layout. Both move here, with the toolchain they force and the grpc defect the new one
surfaced.

One cutover, five parts, and none of them is coherent without the others:

| part | before | after | why it cannot be split |
|---|---|---|---|
| `github.com/opencharly/sdk` | `v0.2026293.417` | `v0.2026294.1520` | the repo-root base (`sdk#445`); tag verified after a fetch, below |
| `plugin-box/candy/plugin-box` | `v0.2026288.503` | `v0.2026294.21` | the only call site of `deploykit.CollectSkillBodies`; without it the sdk bump changes nothing observable in `box validate` |
| `go` directive | `1.26.4` | `1.26.8` | `v0.2026294.1520` declares it; at `1.26.4` the module graph does not build (`charly#1009`) |
| `tools/*` (3 modules) | sdk `.417`, go 1.26.4 | sdk `.1520`, go 1.26.8 | `task mods-tidy` keeps the shared pin single-valued, and each module must still build |
| `describeBounded` | context-only deadline test | context OR gRPC status | grpc 1.61.0 → 1.83.2 (raised by `.1520`) returns the deadline as a STATUS before the local `Err()` is set |

**Two further halves are consequences of the same raise.** The readiness re-wrap carries both errors
with `%w: %w` now, so the deadline stays `errors.Is`-visible and the transport detail stays in the
message (`errorlint` rejected the old `%v`), and the four bufconn test dials `grpc v1.83.2`
deprecates moved from `grpc.Dial`/`DialContext` to `grpc.NewClient("passthrough:///bufnet", ...)`
(`staticcheck` SA1019; none of those call sites used `WithBlock`).

**The plugin-box range is two validate PRs and their module sums, nothing else.** `#57` fails on a
missing skill body, composition-independent; `#58` rejects an image-owned skill. The whole delta
against the pinned tag is `candy/plugin-box`: 5 files, 320 insertions, 6 deletions
(`validate.go`, `validate_skills.go`, its test, `go.mod`, `go.sum`). No other command's behaviour
moves.

**What the reader does now, as a rule.** A body resolves at
`<owning candy's repo root>/.agents/skills/<name>/SKILL.md` and nowhere else: a body beside the candy
is an error whose message names the tree searched (`at the repo root of the owning candy`), and a
body at the root is accepted. That is the standard `sdk#445` set, and the diagonal below measures it
in both directions on one tree with one `git mv`.

**The `copy:` answer (`sdk#444`).** Four carrier candies still declare `copy: .agents/skills`
(`arch-skills`, `debian-skills`, `omarchy-skills`, `ubuntu-skills`). Their source is
layer-dir-relative, and after the bodies moved to the repo root that directory no longer exists — so
the install step cannot ship the prose its ADE check asserts. **This bump neither fixes nor worsens
that:** the emitter renders no Containerfile directive on either side of the bump (the 0/1/0 counts
below), which is exactly what `sdk#444` records. The evidence is added there. Deciding `copy:`'s base
is that issue's scope and is separable from this reader pin: every claim in this body is about the
reader, and its R10 bed passes with the `copy:` step still inert.

**Deliberately not claimed.** `charly box validate` over this repository's own tree answers
`602 candies, 122 boxes` at `rc=0` on both sides of the bump: it resolves the `import:` namespaces
LOCAL FIRST from `box/<namespace>`, and the skill nodes it can see there are the authored ones. The
per-repo table below is the discriminating evidence; this tree's own gate is a consistency check, not
the proof.

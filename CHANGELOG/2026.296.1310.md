# 2026.296.1310 — chore(deps): adopt sdk v0.2026296.1148 so `box validate` resolves a `type: agent` body (sdk#456)

## Summary

**`charly box validate` resolves a `type: agent` skill node's body — the consumer leg of
opencharly/sdk#456: the sdk pin advances to the tag that carries the fix, the binary is rebuilt
from this tree, and the gate is re-verified live on the repro and on both real carriers.**

The defect: a `type: agent` node's body is authored at `.agents/agents/<name>.md`, but the deploykit
collector `charly` links resolved `.agents/skills` for every node. Every project declaring an agent
node therefore failed its own validate gate on `main` — before any change of anyone's. sdk#463 made
`candywalk` the ONE authority for where an authored body lives (`ShapeOf` / `ReadNodeBody` /
`NodeBodyLocation`); sdk#464 rewords two comments of that change; plugin-marketplace#43 moved the
corpus generator onto the same authority.

**What moves here, and why it is four modules rather than one:**

- `charly/go.mod` — `github.com/opencharly/sdk` v0.2026296.729 → **v0.2026296.1148** (the newest
  tag), and `github.com/opencharly/spec` v0.2026295.2356 → **v0.2026296.1036**, which the new sdk
  requires.
- `tools/{generate-packages,golden-cloudinit,golden-compile}/go.mod` — the same two pins. They are
  separate `GOWORK=off` modules, and `tools/gomod-canonical`'s `TestContractPinsMatchShared` asserts
  the shared pins move in lockstep, so advancing `charly/go.mod` alone would turn this repo's own
  gate red. That test is in the sweep below and it passes.

No Go source changes: this is a dependency-pin leg, and the code that consumes the pin landed in
the sdk. Round 2 adds one commit that prunes `charly/go.sum` to the pins this tree actually uses
(the two-step pin advance had left three superseded entries behind); `go.mod` is byte-identical to
round 1.

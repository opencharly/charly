# 2026.297.0032 — fix(pins): state the control's criterion as "not current", not "behind"

Closes #1051

## Summary

Head `6da62b2b7fd73414d774f677c87949154057f386` — 5 files changed, 515 insertions(+), 102 deletions(-).

`charly`'s pin-currency control landed in opencharly/charly#1050 (squash `5001ff6904102916f083a9cf488740388d574a8c`, tag `v2026.296.2303`) with a criterion its own prose mis-stated, and with a proof that covered one class of the three the criterion names. This is the fix, in the repo that owns the control.

**The false claim, in the merged tree.** `charly.yml` (the `pin-current` and `pin-currency-proof` task descriptions), `AGENTS.md` (the control's bullet and the proof's bullet) and the `.github/workflows/pin-currency.yml` header all say the control fails on a pin that is "**behind** AND un-advanced". The producer does not judge one class. `plugin-task` `v0.2026296.2153` — the release this repo pins (`charly/go.mod:141`) — judges the **set** {`behind`, `not-on-the-served-line`, `differs`} (`candy/plugin-task/verbs.go:981-991`, `staleEligible`), and its own ancestry test names the same classes (`verbs.go:916-929`).

**The class the prose omits is the class this org produces.** `not-on-the-served-line` is what a **squash-merge** upstream produces: the served ref does not descend from the recorded commit, so the pin is not an ancestor of what is served. The producer says so itself (`squashWhy`: *"a squash-merged branch advances without descending from its previous head, and a hand-pin looks identical; advance the pin either way"*), and the org merges by squash in `charly` and `layer-charly-internals` among others — so this is the ordinary class for a squash-merged twin, and it is the shape of the #1035 recurrence. The third class, `differs`, is a pin with **no checkout to judge**: the shape a light tree produces, where the umbrella's own plan is heading (a working set instead of 431 checkouts).

**The control is right and the sentence was not.** Measured on a squash-shaped fixture, the shipped control reports the class, marks the pin STALE and exits non-zero — the coverage was real and the sentence under it was not. The repo's own proof could not have caught the mismatch, because it built **one** twin shape and ran **two** arms over it: the proof, the sentence and the fixture all agreed, and all three were wrong about the control's scope. The measurement was wrong in the same direction — it treated "the pin is not the tip" as "behind", which is the proxy that cannot see a squash-advanced pin at all.

**The fix, in four parts.**

1. **The criterion is stated as the producer defines it** — "not current AND un-advanced", naming the three classes — on every surface that states it: `charly.yml`, `AGENTS.md`, the workflow header, and both scripts.
2. **The repo's own proof covers every class the criterion names.** `scripts/check-pin-currency.sh` gains **four** more arms: a **squash-shaped** twin (a served ref that does not descend from the recorded pin) and a twin with **no checkout at all**, each in a neglected/recent pair. The third pair also proves the control's verdict does not depend on the tree shape — on a tree that materializes nothing, a not-current pin is still reported not current, and still goes red when it is neglected.
3. **The measurement classifies with the control's own test.** `scripts/measure-pin-cadence.py` now decides each (day, twin) pair with `merge-base --is-ancestor` — the control's test — instead of the `pin != tip` proxy, and prints the **class tally**. The numbers do not move: over the 32-day window all 145 not-current pairs are the `behind` class, so "not current" and "behind" coincide in this repo's history — now **shown**, not assumed. The classifier is proved by a `--self-test` on a scratch twin, and the old proxy fails that self-test (the gate below runs the mutant).
4. **The control's scope is derived once and checked against every surface.** The arms live in ONE table, the counts every surface states are **derived** from that table, and the proof now reads each surface that states the control's scope and turns **red** when one of them disagrees with the numbers the proof actually ran. The classifier's self-test likewise carries one arm per class the classifier can return — `cur`, `behind`, `not-on-the-served-line`, `unmerged` and `unjudgeable` — and asserts each class's neglect-eligibility against an independent expectation.

**The files.** `charly.yml` (two task descriptions and the derivation's comment), `AGENTS.md` (the control's bullet, the proof's bullet, and a new one for the classifier's proof), `.github/workflows/pin-currency.yml` (header, one new step, and the `pull_request` trigger now covering the two proof scripts — a change to the proof must re-run the proof), `scripts/check-pin-currency.sh` (six arms over three twin shapes, from one table, and the surfaces check), `scripts/measure-pin-cadence.py` (the ancestry classifier, the class tally, the `--self-test`).

# 2026.297.2223 — ci(release-binary): declare the Go toolchain the release build already assumes

## Summary

Head `aebba4896334f302094e6b366e3f5e4502564a68` — 1 file changed, 19 insertions(+), 3 deletions(-).

**`release-binary.yml` builds with `go` and never declared `go`.** The workflow
runs on the org's self-hosted fleet (`runs-on: ${{ vars.CI_RUNNER_LABEL ||
'ubuntu-latest' }}`), and that fleet's image **deliberately ships without Go** —
its own recipe says so, in the package list, in the comment that explains the
image's hosted-runner parity:

> Go is deliberately NOT here: every workflow that needs it uses
> `actions/setup-go`, which downloads the pinned toolchain.
> — `distro-ubuntu/candy/github-runner-ubuntu/charly.yml`

`ci.yml` and `pin-currency.yml` both declare `actions/setup-go@v5` with
`go-version-file: charly/go.mod`, so they stayed green through the same fleet
switch. `release-binary.yml` had no such step, so the fleet's missing Go became
`go: command not found` (exit 127) at the first `go` invocation.

**This change makes the toolchain DECLARED, in the same form the two healthy
workflows use**, and rewrites the header sentence that made an inherited
toolchain look like a declared one — it still said the workflow "runs on a stock
`ubuntu-latest` runner — no distro-native tooling, no self-hosted host", while
the job two dozen lines below names the self-hosted fleet.

| file | what it carries |
|---|---|
| `.github/workflows/release-binary.yml` | the `actions/setup-go@v5` step (`go-version-file: charly/go.mod`, `cache-dependency-path: charly/go.sum`) after the checkout, and the header sentence corrected to name the fleet and the declared toolchain |

## Filed issues

A workflow cannot fix a full disk without hiding it behind a workaround, so the finding belongs to the image that owns the runner. Filed, not fixed here.

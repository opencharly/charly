# 2026.300.1842 — chore(pins): advance the box/cachyos twin to its served ref

## Summary

This repo's `box/cachyos` twin was behind the ref its own `.gitmodules` declares, and
the advance is this repo's own sanctioned verb — `charly task sync`, the `pins` task
with `MODE=bump`.

Fixes #1077.

| file | what changed |
|---|---|
| `box/cachyos` | the gitlink advanced `6abe895225` -> `b6a108d80b` |

It was behind: the recorded pin sat two commits below the tip its twin's remote
serves. The other five twins — `box/arch`, `box/debian`, `box/fedora`, `box/omarchy`
and `box/ubuntu` — were already at their served refs, and they did not move.

**Why it matters outside this repo.** The umbrella's `distro-cachyos` is a
`derived-from` **edge**, and an edge's value IS its source's recorded gitlink — which
is this gitlink. While it was behind, the umbrella's own currency report named the
edge `blocked-by charly:box/cachyos (behind)`, and **no command in the umbrella could
move it**, because the edge takes the source's value. This is the producer leg of that
sequence (opencharly/charly#1077); the umbrella's next pin wave advances the edge,
through the umbrella's own `charly task sync`.

**What this change is not.** It is not a hand-pin: the verb fetched the twin's remote
and recorded what it serves, and a hand-pinned SHA cannot be judged, so it would be a
failure. It is not a branch checkout used as a pin. It is not a new pin and not a new
submodule: the path is already declared in `.gitmodules`.

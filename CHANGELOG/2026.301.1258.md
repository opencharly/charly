# 2026.301.1258 — fix(pins): the `sync` task's description claimed a non-mutating kind the verb does not have

## Summary

Head `0f86f8a31ccaaa2df055a3245f86e12ba769db8b`.

The `sync` task's own description in `charly.yml` called the pin advance a
non-mutating kind: it said the task was a preview that does not commit. Only the
second half was true. The verb advances EVERY pin this repo declares — this repo's
own six `box/*` gitlinks, which are all the pins it has, since there is no `pin_map`
and therefore no edge — to the tip the remote serves for the ref each path's own
`.gitmodules` entry names, never a PR branch. A path that HAS a checkout is ROLLED
in that checkout and every advance is STAGED in this repo's index; a path with NO
checkout is advanced in the index alone. It does not commit and it does not open a
PR, and it FAILS LOUD for every path it could not advance. An operator who read
that line would have run a wave they believed was a report.

| file | what changed |
|---|---|
| `charly.yml` | the `sync` task's header comment, description and step name; the `pins` task's description and its `MODE` parameter; two new tasks, `pin-verb-scope` and `pin-verb-scope-proof`; two new steps in the `check-task` bed and three new assertions in its `task-list-declared` step |
| `AGENTS.md` | the two pin bullets state the verb's scope, and a new section documents the control |
| `scripts/check-pin-verb-scope.py` | the control, over three arms, with a `--self-test` that turns each arm red on its own mutation |
| `.github/workflows/pin-verb-scope.yml` | the control in CI, triggered by the claim's own surfaces |

**The RCA.** Mechanism: the `sync` task's description named a kind the verb does
not have, so an operator read a mutating wave as a report. Missed control: nothing
in this repo's tree connected the word to the verb, so a one-line edit would have
left every other surface free to say the same false thing — and the `pins` task's
description, its `MODE` parameter and the two `AGENTS.md` bullets ARE such
surfaces: they present the same verb to the same operator. The umbrella's #501 leg
fixed the same claim in the umbrella's tree and filed this repo's twin
(opencharly/opencharly#501, resolved by opencharly/opencharly#782); a guidance
defect is a product defect (R4), so the fix here is a CONTROL that keeps the claim
true, not a lesson in a comment. Blast radius: every surface that presents the
advance to an operator, in this repo. Root fix: the claim is corrected on every
one of those surfaces, and `scripts/check-pin-verb-scope.py` keeps it true —
SCOPE (every claim-maker surface states that the advance touches EVERY pin this
repo declares — the CLAIM, not the keyword, because "every" alone also matches a
question about currency), NO RETIRED CLAIM (no tracked file calls the advance a
non-mutating kind), and COVERAGE (every file that names the verb is classified, so
a new claim-maker surface cannot slip in unclassified).

**Why the control lives in this repo.** This repo declares the pins and owns the
words about them; the umbrella records only the gitlink. The umbrella's own gate
for the same rule says, in its own header, that it speaks for the umbrella's prose
only — "a submodule is a repo of its own, with its own rulebook and its own gates".

**What this change is not.** It is not a behaviour change: the verb advances
exactly the pins it advanced before. It is not a change to the `pins` task's `MODE`
contract, to the `pin-current` wrapper, or to the 168 h neglect bound. It is not a
change in the umbrella — the umbrella's own twin of this claim is
opencharly/opencharly#501, resolved by opencharly/opencharly#782.

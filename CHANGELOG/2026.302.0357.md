# 2026.302.0357 — chore(deps): adopt spec v0.2026302.327 (a step renders on ONE line, so a reader can pair its status with its id)

## Summary

`github.com/opencharly/spec` is compiled into the charly binary, so the pinned module version IS
the behaviour of `charly check run` — of the bed record every R10 proof rests on.

At the pinned version (`v0.2026296.1036`) a step whose text carries a newline spanned SEVERAL
lines of the child's report: `spec/report`'s `renderStep` wrote `step.Text` verbatim, so the
step's `[id]` bracket landed on a line of its own and no line carried both the status and the
id. `plugin-check`'s reader matches ONE line per step, so it credited nothing for that step, the
child's report carried 21 step lines against the 22 its own rollup counted, and — since
plugin-check#134 — a report that disagrees with itself is refused WHOLE. Every check phase of
the bed then SKIPs and the run exits 3.

That is exactly what opencharly/layer-docs-site#13's `check-docs` bed hit: all five of its check
phases SKIP with *"the child's report could not be read: 21 step line(s) against the 22 step(s)
its own rollup counted"*. The base tree of that repo, WITHOUT that repo's own change, produces
the identical skip with the identical numbers and the identical exit code 3 — so the defect is
pre-existing and lives in the PRODUCER of the report format, not in the change that found it.

The producer is fixed, producer-first, in opencharly/spec#283 (squash `4266c8b`, module tag
`v0.2026302.327`): `spec/report` now renders every step on EXACTLY one line — the text and the
message flattened through one rule — so the status and the id are on the SAME line, and
`truncate` cuts on a character boundary so a report line is always decodable. The producer's own
tests assert that invariant and FAIL against the old renderer.

This change carries that version into the binary. Head `cfcbfe7a461bd89c6d714e8ff3bb50394d78ee42`
— 8 files changed, 12 insertions(+), 12 deletions(-) — moves `github.com/opencharly/spec` in
`charly/go.mod:142` from `v0.2026296.1036` to `v0.2026302.327`, and moves the three lockstep
modules with it (`tools/generate-packages`, `tools/golden-cloudinit`, `tools/golden-compile`),
because `tools/gomod-canonical`'s `TestContractPinsMatchShared` requires every in-repo module
that requires a contract module to list the SAME shared sdk and spec pins.

The `sdk` pin is unchanged at `v0.2026297.1851`. That module requires spec `v0.2026296.1036`
itself, but Go's minimal version selection takes the MAXIMUM of the requirements in the graph,
so `v0.2026302.327` is the version the graph selects — the sdk does not have to move for this
change, and no sdk release is required by it.

## Change classification

A core dependency pin that changes the binary's behaviour: the report format's producer now
guarantees the shape the format's consumers parse, and this binary is where that producer reaches
the beds. It removes nothing that was usable and adds no new surface, so no cutover machinery
applies — the report's contract is unchanged in name and in field, and only the shape of a
rendered step's text is corrected, to the shape the readers already require. The merge gate is
the org-wide `charly/pr-validator`.

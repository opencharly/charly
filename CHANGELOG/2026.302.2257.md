**Observation 1 — FIXED, and it was the blocking one.** #1090's merged body says the Go control
and the Python gate *"agree by construction, not by coincidence"*. They did not: the index
modes that are exempt from the tracked tree were written TWICE — once in
`scripts/check-pin-verb-scope.py`'s `tracked_files()`, once in
`charly/retired_build_selector_test.go`'s `trackedRegularFiles()` — so the two agreed by
coincidence, and the body's claim was false. The RCA:

- **Mechanism.** The second occurrence of one rule was never extracted. R2 says one canonical
  implementation or rule per behavior, and the second occurrence is extracted.
- **Missed control.** Nothing made the two readers share ONE statement of the rule, and the
  body asserted an agreement that no committed control enforces.
- **Blast radius.** An edit to one reader's exemptions narrows or widens that reader's scope
  while the other keeps sweeping a different set — the two gates disagree about what this
  repository ships, and no gate says so.
- **Root fix.** The rule is extracted into ONE committed artifact — `scripts/tracked-files.txt` —
  and BOTH readers read it. The mode literals are deleted from both readers, and the
  agreement the body claims is now by construction.

The repository's own precedent for a shared rule file is `scripts/host-command-plugins.txt`,
read by a workflow, a Go test and a Go generator: one file, three readers, one source.

**Observation 2 — REBUTTED, with the evidence.** A set-comparison assertion would compare the
sweep's set with the very set it is defined by — the sweep IS "the tracked files, less the
exempt modes" — so it is a tautology, not a check. The question a scope assertion would answer
is whether the scope **collapsed**, and that question has two real answers now, neither of them
tautological:

- the Python gate states it directly: a claim-maker surface that is **not a TRACKED file** is a
  finding (the control's scope does not cover the tree a reader of this repository sees), and
  the gate's own `--self-test` proves that arm bites;
- the Go sweep's floor (`visited < 100`) goes red when the derivation stops covering the
  repository.

Both are proved below by corrupting the shared rule — the same corruption that the two readers
now share.

**Observation 3 — FIXED.** A tree that is not this repository's own checkout has no index and
no tracked files, and there is nothing for a control over the tracked tree to judge. The
control now skips VISIBLY in that case (`requireRepoCheckout`), and still fails LOUDLY when
the tree IS a checkout and its index cannot be read.

**Observation 4 — FIXED.** A record with no mode field is skipped, not indexed.

# 2026.303.0035 — feat(core): the shared rule's SHAPE gets a control — its grammar and its exempt-mode list have ONE home

## Summary

The shared rule `scripts/tracked-files.txt` states its GRAMMAR in its own header, and says so
in its own words: *"The GRAMMAR is specified ONCE, in the WHAT IS EXEMPT header above - never
restated in a reader. Edit THIS file, never a reader's copy."* That was a CLAIM with no
control behind it. Nothing stopped a reader from restating the grammar, and nothing noticed
when a reader stopped reading the file at all — so a future copy would pass every gate in this
repository, and the two readers would then parse the rule file with grammars the rule file no
longer specifies, and the two gates would disagree about the file's syntax, silently.

That is opencharly/charly#1094, filed from the `charly/pr-validator`'s review of
opencharly/charly#1093, and this PR implements it.

**The RCA.**

- **Mechanism.** #1093's first round copied the grammar into every reader to make each site's
  claim self-contained, which created a SECOND home for the rule — the defect the validator
  caught. The fix removed the copies, and the claim-keyed sweep grew a second key so a copy
  would be REPORTED. But the sweep was never committed: it was a script pasted in a PR body.
- **Missed control.** `scripts/check-pin-verb-scope.py` sweeps the tracked tree for the SCOPE
  claim, for a retired claim, and for the COVERAGE of the claim-maker surfaces. It had no arm
  for the rule file's own SHAPE: nothing asserted that the grammar is stated in the rule file
  and nowhere else, and nothing asserted that the readers still read the rule file at all.
- **Blast radius.** A later author who wants a reader to be self-contained — a reasonable want,
  and the exact one that caused the first round's defect — can copy the grammar into their
  reader, and every gate in this repository stays green.
- **Root fix.** A committed control over the shared rule's shape, in the control that already
  reads the tracked tree, so there is ONE enumeration of the tree and ONE Python reader of the
  rule (R2).

**What landed.** A new arm in `scripts/check-pin-verb-scope.py` — **ONE HOME**:

- the **GRAMMAR** lives in the rule file's own header and nowhere else: a copy in a reader, or
  a second statement in the rule file's own other paragraph, is a finding, NAMED, with the site;
- the **exempt-mode LIST** lives in the rule file: a copy of the list (the mode AND its
  reason — a prose mention of a mode number is not a copy) is a finding;
- every reader the rule file **NAMES** still READS it: a named reader whose code no longer
  names the file would parse a format nothing specifies, so that is a finding too.

The arm is located by STRUCTURAL anchors, never by the grammar's own wording: the rule file's
paragraphs are found by their own HEADINGS, so a copy that MOVES cannot make the arm blind
instead of red, and an anchor that matches no paragraph — or more than one — is a finding, not
an empty pass.

**The proof is six arms, and every one of them bites.** A reader that restates the grammar; that
same copy inside the rule file's own other paragraph; a rule file whose header stops stating the
grammar; a reader that copies the exempt-mode list; a named reader whose code stops naming the
rule file; and the fixture guard — with the rule file's grammar paragraph unlocatable, the arm
reports that it would prove nothing rather than passing silently. Each mutation is checked to
have APPLIED before its arm is credited: an unapplied mutation dies for free and proves
nothing.

**CI now runs the control for the files it reads** — the rule file and its named reader — so a
change to either is judged by the arm that exists for it. The prose on every surface that
describes the control (`AGENTS.md`, `charly.yml`, the workflow's own header) now names the arm
WITHOUT a hand-restated count, so no surface carries a number a later edit has to update by
hand.

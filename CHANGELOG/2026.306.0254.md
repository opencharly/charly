# 2026.306.0254 — fix(867): refuse an unqualified overlay base ref instead of losing the resolver error

## Summary

`charly deploy add` on a pod overlay deploy whose base `image:` is a SHORT (bare) name can die with an error that names no image at all: `prepare venue: InvokeProvider deploy:pod op=prepare-venue: … deploy-name alias tag: command exited 125` (opencharly/charly#867).

In `hostBuildOverlay`'s `default:` arm, `container.ResolveNewestLocalCalVer` elects the newest local CalVer for the bare name, and its refusal was **discarded** — `baseRef` fell back to the bare, untaggable name, which then reached `tagDeployAlias`'s `podman tag` and surfaced as `command exited 125`. The refusal itself, the only informative part, never reached the operator.

This change keeps that refusal and returns it, and adds the distinction the fallback was missing:

* `isQualifiedRef(ref)` is a **pure shape test** (`""` → false; a registry/repository path and/or a tag → true). It looks nothing up and fetches nothing, so it is safe to ask before any resolution has been attempted. A **qualified** ref needs no local CalVer resolution: the resolver's refusal is the expected answer for it, and `base` is already a ref this path can tag — it still passes through unresolved, exactly as before.
* A **bare** name has exactly one usable ref: the one `ResolveNewestLocalCalVer` elects. Its refusal is now **returned** instead of a fallback, so the operator gets `overlay build: image not found in local storage: <name>` — naming the image and the failed resolution — instead of a downstream `exited 125`.

Files: `charly/build_overlay.go` (**+53/−4**) and `charly/build_overlay_refshape_test.go` (**+102/−0**) — measured as `git diff --numstat $(git merge-base HEAD origin/main) HEAD` at the merge head `1bc90732`. `TestIsQualifiedRef` pins both sides of the predicate with the issue's own refs — the bare `desk-schema` that died, and the qualified `ghcr.io/opencharly/check-desktop:<calver>` that succeeded.

Refs opencharly/charly#867. Its first Ask ("do not fall back to a bare ref: surface the resolution refusal") is what this change implements. Its second Ask ("decide deliberately whether a `<deploy>-<calver>`-tagged build is eligible for short-name resolution") is a resolver-policy decision that is **not** taken here — this change's job was to stop hiding the answer, and the refusal is now the operator-visible error. The issue is left open for that decision; it is not claimed as closed by this PR.

### The fix, and a test that fails without it

Review round 1 found that the new arm returned `spec.OverlayBuildReply{}` with a **nil** error when `ResolveNewestLocalCalVer` answers `("", nil)` — an empty reply the caller reads as a SUCCESSFUL build of nothing. The decision is now one named function, `overlayBaseRefFromResolution`, which the arm calls, and it synthesizes a refusal that names the bare name instead of propagating a nil error.

`TestOverlayBaseRefFromResolution` drives that decision, so it fails without the behaviour rather than merely pinning a predicate. **Mutation-proven:** with the synthesized-refusal arm made unreachable, the test fails with

```
build_overlay_refshape_test.go:93: ("", nil) from the resolver must not become a nil error:
  got ref "", nil error — an empty build reported as a success
```

and passes restored. `TestIsQualifiedRef` is kept as the shape test it always was.

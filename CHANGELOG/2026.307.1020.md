**`tools/golden-cloudinit/go.mod` grew by 7 lines, and they are not new behaviour.** The bump records the sdk's own **transitive** requirements explicitly in that module for the first time — all `// indirect`:

```

go.yaml.in/yaml/v3 v3.0.5 // indirect
```

They are the dependencies the pinned sdk already required; `go get` wrote them into this module's `go.mod` because it had not listed them before. No package in `tools/golden-cloudinit` imports any of them directly.

**Why the tool modules are in this diff.** This repo enforces a **lockstep rule** — every tool module pinning the sdk must pin the same version, checked by `TestContractPinsMatchShared`. Bumping `charly/go.mod` alone broke that control on CI (`--- FAIL: TestContractPinsMatchShared`), which is exactly what the rule exists to catch. All three are bumped so the invariant holds.

**Why the bump matters.** The new sdk passes `--progress plain` to `buildctl` (opencharly/sdk#481, squash `3b5554aaa194`, tag `v0.2026306.2235`). Before it, `buildctl` used `auto`, which depends on whether the caller looks like a terminal — so a CI image build lost the failing `RUN` step's own output and surfaced only `did not complete successfully: exit code: 1`. That cost five wrong hypotheses on `pod-crabbox`'s image build before the daemon log named the real cause (opencharly/.github#271). The same producer PR also carries the corrected `vmshared` live-premise guard.

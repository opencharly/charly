# 2026.308.1507 — fix(overlay): name the built image for a namespaced base box

## Summary

`hostBuildOverlay` (`charly/charly/build_overlay.go`) composes one value, `base`, and uses it for two different things: `base` is a BOX NAME (it feeds `collectOverlayCandies` and `ResolvedBox{Name: base}`), while `BaseImage` is an IMAGE REF. The old tagged branch built `BaseImage` as `base + ":" + tag`, which names the right repository only when the box address and the image repository happen to coincide. The box build names its repo from the box's LEAF under the box/namespace registry, so they do not coincide for a namespaced box.

Measured in #968, bed run `.check/charly.check-sidecar-pod/2026.307.2144/`: the build produced `ghcr.io/opencharly/check-k8s-deploy-app:charly.check-sidecar-pod-2026.307.2144`, while the overlay prep composed `charly.check-k8s-deploy-app:<tag>` and podman rejected it:

```
short-name "charly.check-k8s-deploy-app" did not resolve to an alias and no containers-registries.conf(5) was found
```

This change:

- reuses the build path's own naming rule for BOTH branches — `resolveBoxImageRegistryName` (registry = the box's own registry, else its NAMESPACE's `defaults.registry`; repo = `spec.LeafName(box)`) plus `container.ResolveShellImageRef` — instead of string concatenation;
- fixes `isQualifiedRef` so a dot alone does not make a ref "qualified": a namespace-qualified BOX address is not an image repo;
- keeps `base` itself as the box name for `collectOverlayCandies` and `ResolvedBox{Name: base}`.

The untagged branch had the same defect in two places: it asked the local-CalVer resolver about the box ADDRESS (`charly.check-k8s-deploy-app`, which matches no local repo because local refs are named by the leaf), and on refusal `isQualifiedRef`'s dot rule returned the box address as a "qualified" fallback. Both halves are fixed; the resolver is now asked about the leaf, and the refusal propagates for a bare name (#867's contract is preserved).

`resolveImageRefForEnsure` was refactored onto the same `resolveBoxImageRegistryName` helper, so there is one naming rule rather than two (R2).

Refs #968 — I will close #968 explicitly after this merges; no closing keyword is relied on.

## Change classification

- **Type:** bug fix in the charly core (Go runtime behavior).
- **Consumer impact:** for a namespaced box, `BaseImage` changes from the box ADDRESS (`charly.check-k8s-deploy-app:<tag>`, which the engine cannot resolve) to the image the build produced (`ghcr.io/opencharly/check-k8s-deploy-app:<tag>`). For an unqualified box with a project registry, it also becomes the build's fully qualified repo instead of the short name; with no registry configured the composed ref is unchanged. The box name itself, and every consumer of it (`collectOverlayCandies`, `ResolvedBox.Name`), is unchanged.
- **Breaking change + rollback:** none — no API, schema, or config shape changes; the overlay simply names the artifact the build already produced. Rollback is a revert of this commit.

## Summary

Adopt `github.com/opencharly/plugin-build/candy/plugin-build` `v0.2026308.2205` in `charly/go.mod` and its two `charly/go.sum` lines: the consumer leg of `opencharly/plugin-build#49`.

That PR merged as `aa9b649fbd04eb415c7eacdd92814515b0654206` and was tagged `v2026.308.2205`; the module proxy records the same commit as `Origin.Hash` for module version `v0.2026308.2205`, so the revision this tree compiles in is the merged fix rather than a look-alike tag or a branch.

The fix answers `opencharly/.github#279`: `charly box build --push` now exports only the boxes the build produced — the explicitly requested box plus this project's own unqualified auto-intermediates — and leaves namespace-qualified `import:` bases out of the push set. A variant repo no longer asks BuildKit to write a foreign `ghcr.io/opencharly/arch`-style package with its own `GITHUB_TOKEN`. `charly` compiles plugin-build into the binary (`charly/plugins_generated.go` imports it), so the engine reaches the fix only through this pin.

`charly` is the only module in this tree that requires plugin-build; the three `tools/*` modules carry only the shared `sdk`/`spec` pins, already at the core's versions. plugin-build `v0.2026308.2205` requires older sdk/spec versions than the core pins, so MVS keeps the existing contract pins. The change is two files: `charly/go.mod` and `charly/go.sum`.

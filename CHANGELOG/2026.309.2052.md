### Live bed — the selector, on the SHIPPED pins

The binary above is the shipped tree (NO `--dev-plugin`), and it carries the
`plugin-build v0.2026309.2032` pin in this diff. The probe image is not
registry-published, so the minimal 100-byte-label image was pre-staged into
containerd under the run's CalVer tag to isolate the SELECTOR from the
`build:ensure` staging path (the pin is present; the pre-staged image meant this
run's config did not need it). The config phase found it, resolved

**The container does not start on this host, and this PR does not claim it
does.** The venue's containerd has no `crun` handler (`command -v crun` empty;
`nerdctl run --runtime crun` fails `invalid runtime name crun`, while the
default, `runc`, and `io.containerd.runc.v2` each run `rc=0`). Filed as
opencharly/plugin-containerd#16. A crun-capable venue is not reachable from this
environment, so the start path is not claimed as passing. A typical charly
image's `ai.opencharly.description` label also exceeds containerd's 4096-byte
container-label cap (filed as opencharly/spec#293); the minimal image isolates
that variable.

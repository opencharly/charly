# 2026.316.2018 — fix(plugin): resolve a kind's value def the way the gate does, so a moved body stays judged

## Summary

**The consumer half of unit 1's leg 4** (`TODO.md` 2.1, tracker `opencharly/spec#304`). `opencharly/spec#305` deleted the `#Pipeline*` body defs and `opencharly/sdk#502` deleted the kind-aware `workflowkit` machinery; this PR moves `charly` onto those releases, and teaches the corpus sweep to resolve a kind's value def through the SAME route the production gate uses — so the 13 pipeline bodies the corpus authors stay in the witness after their def leaves the base schema.

### 1. The sweep's selection follows the production resolver

`charly/kind_value_corpus_sweep_test.go` selected bodies with `spec.KindValueDefs[pn.Disc]`. With `#PipelineValue` gone from `spec`, that predicate silently drops **every** pipeline body: the witness shrinks and nothing fails. The selection now asks the route the loader asks:

```go
prov, _ := gatedKindProvider(pn.Disc, true)              // registry, else the loader's on-demand connect
if _, gated := kindValueDefPath(prov, pn.Disc); !gated { // provider-declared InputDef, else base fallback
    continue
}
```

`gatedKindProvider(disc, connect)` is `providerRegistry.ResolveKind` and, when `connect` is true and the word is unregistered, `connectPluginByWord(ClassKind, disc)` — the function the loader uses to connect a referenced plugin kind (it host-builds and registers the unit, which is what makes `plugin-pipeline`'s `kind` capability's `InputDef: "#PipelineValue"` visible). The provider is cached per word, so a failed connect is attempted once, not once per body.

**Two callers, deliberately different:** the sweep's loop (`runCorpusSweep`) passes `true`; `TestSweepSelectionResolvesAPluginDeclaredGateDef` passes `false` and registers its provider directly, so a plain `go test ./...` never builds a plugin or touches the network. A miss is cached only when a connect was actually attempted, so the false caller cannot poison the loop's resolution.

The `base` arm — the pre-change oracle — still resolves in the base alone and SKIPS, visibly and counted, a def the base no longer declares: `gate=base: judged 1992 entity bodies (1646 files unparsable, 12 bodies the base arm cannot judge)` on the full corpus (all 12 are the pipeline bodies), against the composed arm's 2,004.

### 2. The pins

`github.com/opencharly/sdk` and `github.com/opencharly/spec` move to the merge-time tags of legs 3 and 4 in `charly/go.mod` and in every lockstep `tools/*` module (`charly task mods-tidy`), and `tools/gomod-canonical`'s `TestContractPinsMatchShared` is the gate that keeps them lockstep.

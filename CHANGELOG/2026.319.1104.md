# 2026.319.1104 — feat(core)!: retire the Omarchy family from the core — import, box, built-in distro, plugin word

## Summary

Closes #1145. The org archived the Omarchy family and the umbrella stopped pinning it
(opencharly/opencharly#1029, #1034). This is the `charly` leg: the family still LOADED here, so
the retirement was half-done, and the RDD measurement on the issue is what priced it before the
call was made.

**Retired, one change,  9 files changed, 5 insertions(+), 498 deletions(-)**

- **the import** — `charly.yml`'s `omarchy:` distro-namespace entry and its comment. Nothing else
  in this repo names that namespace.
- **the pin** — the `box/omarchy` submodule and its gitlink. `git update-index --force-remove`
  takes a LITERAL path: the `:(literal)` form exits 0 and removes nothing, and the first attempt
  silently left the pin in place. The removal is therefore read back out of the index, and the
  fence below shows it printing 0.
- **the built-in distro** — `charly/charly.yml`, the `go:embed`'d defaults manifest, loses its
  `omarchy:` node (484 lines: the `[omarchy]` package sources, the frozen mirror snapshot, the
  LIMINE boot chain, the btrfs layout). This is what made Omarchy a first-class charly distro;
  the registry's bijection gate keeps that file in step with the compiled-in instances.
- **the plugin word** — `plugin-omarchy` leaves `charly/plugin_corpus.txt`, and
  `charly/plugins_refs_generated.go` is REGENERATED by `pluginsgen` (never hand-edited), so
  `verb:omarchy` is gone from the compiled-in index. **Regeneration also ADDS one word**, and
  that is the generator being truthful rather than this cutover widening: the index is built from
  each corpus repo's DEFAULT BRANCH, and `plugin-task`'s default branch has gained
  `verb:pin-closure` (`candy/plugin-task/pin_closure.go`) since this projection was last written.
  The committed file was stale; `TestPluginsRefsIndexSound` requires committed == live, so any
  regeneration today folds that word in. It is an ADDITION, it is `plugin-task`'s word and not
  this family's, and the hunk is pasted below rather than left for a reader to discover.
- **the controls and the prose** — `TWINS` drops the retired twin, the README's Distros row
  drops the family, and the nerdctl sibling-set comment drops it too.

**Deliberately KEPT, and this is a decision rather than an oversight.** `OMARCHY_ALLOW_DIRECT_PACMAN`
in the `pac` install template (and the test that pins it) stays: Omarchy ships an alpm hook that
aborts every upgrade transaction, so a `target: local` deploy onto an Omarchy WORKSTATION still
needs the guard, and removing it would silently break every `pac:` install there. It names the
distro's OWN hook, not a word this change deletes — it is host compatibility with a third-party
distro, not support for the opencharly family. Likewise the dated 2026-10-15..23 pin-age
measurements, the past-tense `check-omarchy-iso-vm` notes and the pacstrap append-only rule's
origin stay: history with a window, not a claim the family exists. So does
`charly/testdata/migrate-retired-pipeline/charly.yml`'s `skill: [omarchy-eval]` — fixture INPUT
for the retired-pipeline migration, a skill name inside a test document rather than a reference to
anything this change deletes.

**No migration-table entry, and that is the answer rather than an omission.** The removed surface
has no successor shape: a project that referenced `omarchy.*` gets the loader's hard
unresolved-reference error naming it — the same error any unimported namespace produces — and the
remedy is to drop the reference or to import `@github.com/opencharly/distro-omarchy` directly,
which still clones from the archive. There is nothing to reshape, so nothing for `charly migrate`.

## Change classification

Kind: a breaking core cutover — the built-in `omarchy` distro, the `omarchy` import namespace, the
`box/omarchy` pin and the `verb:omarchy` provider word are deleted; 9 paths, 498 deletions.

**Breaking change + rollback:** a consumer that names `omarchy` as a distro (in a candy's
`distro:` filter or a package section) or references the `omarchy` namespace/`verb:omarchy` now
gets charly's hard unresolved-reference error, because the word is no longer in the registry — the
failure is loud and names the reference, which is R5's requirement for a deleted identifier.
Nothing else breaks: no pinned leaf composes the family (the RDD sweep on #1145 measured zero
functional consumers outside these repos), and an archived repo still serves its tags, so anyone
who needs the old surface can import `@github.com/opencharly/distro-omarchy` at
`v2026.274.2118` directly. The ONE addition in this diff — `verb:pin-closure` in the regenerated
projection — adds a registry word, breaks nothing, and comes from `plugin-task`'s default branch
rather than from this cutover. Rolling back is reverting this squash: the embedded manifest, the
corpus line, the generated refs and the submodule all return, and `box/omarchy` re-materializes
from the archived repo at the very commit the pin named.

### The pin was not enough: a test-only migration the pin requires

(The THIRD commit fixes a semantic bug this migration introduced: four `Has*` predicates measured
`len()` of a `RawBody`, i.e. raw-JSON BYTES, so an empty list — the two-byte empty JSON array — reported
as present. They now count decoded elements. Caught by review; the compiler cannot see it.)

`go build ./...` and the bootstrap were both green, so the pins looked complete. They were not — `go build`
does **not** compile `_test.go`, and the spec release moved the AUTHORED candy sub-shapes out of `spec`,
keeping only the WIRE (resolved) twins. Its own `candy_reader.go` names the split: *"A reader decodes a body
that has already been validated, so the resolved form is what it needs — the same split the vm unit landed
(`VmSpec = ResolvedVm`)"*. So `CandyView`/`CandyModel` sub-shape fields became `spec.RawBody` (opaque json)
and the test-only `spec.CandyReader` implementation had to decode them:

```
have Alias() []spec.CandyAlias
want Alias() []spec.ResolvedCandyAlias
```

**That split is the sibling of opencharly/spec#341 itself**, which is why it belongs in this PR rather than a
separate one. Only the test helper implements that interface here (production builds untouched), so the
change is confined to `candy_test_helpers_test.go`: two small generic helpers plus the six accessors the
compiler named.

## Round RCA — the missed control

Round 1's finding was that this body cited a run containing `FAIL` as its gate. The missed control, stated
as a control rather than a confession: **my pre-push routine asked "does it build?" and treated a green
`go build` + a successful bootstrap as "the tree compiles"** — both of which skip `_test.go`. That is the same
blind spot the second round then caught from the other side: the API break was in a file no gate I ran ever
compiled, so the pin looked complete when the suite could not build. The control is now explicit: for any
change that can touch test files, `go vet ./...` and `go test ./...` are the gate, and `go build` is only a
precondition. It is also why this body now pastes those two commands and not `go build` alone.

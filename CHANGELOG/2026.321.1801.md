Its own doc states what the caller must supply: *"Visibility (§8.2) is the caller's to gather — the stack, the containing nodes, the alongside nodes, the registry, the grant — because only the caller knows the tree. This package resolves the set it is HANDED."* **This PR is that caller**, in `charly/capability_gather.go`: it gathers a stack member's `need:`/`use:`, resolves them against the provides of the members **visible** from it, and returns the recorded `[]needsolver.Binding` map a type owner's `bind` will later read `provided_by` from.

### §8.2, the rows this implements

```
A need or use is bound by the one provide of the same type and name it can see. It sees:
1. the provides of its own stack — the `from:` chain, the `require:`d candies and the inner
   candies (D-CANDY-2);
2. the provides of the nodes that contain it: the box's deployment, and every deployment around
   that one (§17.2);
3. the provides of its alongside nodes (§17.2);
4. the registry, for role words and apis (§5);
5. its deployment kind's grant, for host capabilities (§9).
```

with **D-CAP-1** (*"a `need:` must be bound and fails the load when it is not"*), **D-CAP-3** (*"Two visible provides of one capability are an error naming both. An unbound need is an error naming what was searched"*), and **D-CAP-6** (the union over the deployment, its box and all their candies).

### The refusal, and why it is the design rather than a gap

The §8 capability table declares `provide:` per type (`schema/capability.cue:151-155`) and `spec` generates a `Provide` type — **but no authored key anywhere writes one**:

```console
$ git -C spec grep -n '^\s*provide!\?:' origin/main -- 'schema/*.cue'   → (none)
$ git -C spec grep -n '^#Provide' origin/main -- 'schema/*.cue'         → (none)
$ # the only authored provides are the LEGACY maps:
$ git -C spec grep -n 'env_provide\|mcp_provide\|agent_provide' schema/candy.cue → 145, 150, 151
```

So a `secret` need would resolve to `ErrUnbound` no matter what the tree contains — **silence, not a search**. `ErrNoProvideSurface{Type, WantedBy}` is raised instead, **before any provide is gathered**, so a lookalike in the tree cannot shadow it.

**The distinction is D-CAP-3's own words**: an unbound need is *"an error naming what was searched"*. A search that never happened must not be reported as one.

The gatherer is **table-driven** — one live row for `env`, which is the only type with an authorable provide today:

```go
var provideSurfaces = map[string]provideSurface{
	"env": {collect: …env_provide…},   // the ONE live row
}
// any other type → &ErrNoProvideSurface{Type: "secret", WantedBy: "candy:app"}
```

**When the authored key lands (`spec#368`), exactly one row changes.** That is the extension point, and it is the whole reason for the shape.

Gathering the legacy maps and calling that "§8.2" was the alternative and was rejected: it would silently fail on `secret`, and the silence is the failure this PR exists to prevent.

### R7 — the vocabulary, the refusal, VISIBILITY, the `use:` fallback, and the double-count

```
bound          PASS   the recorded map names "candy:prov"
ErrUnbound     PASS   fails the load (D-CAP-1) and names the capability
ErrAmbiguous   PASS   names BOTH provides (candy:prov + candy:prov2)
visibility     PASS   a provide that exists but is NOT visible does not bind
refusal        PASS   a secret need raises *ErrNoProvideSurface (errors.As), NOT ErrUnbound,
                      with an env-providing candy in the tree so it cannot be an empty-tree accident
use-fallback   PASS   an unbound `use:` FALLS BACK (D-CAP-1) and records Bound="" -- the same tree
                      that errors for a need succeeds for a use
use-nosurface  PASS   a `use:` of a type with NO provide surface GOES WITHOUT; the same capability
                      authored as a `need:` raises *ErrNoProvideSurface naming the type
double-count   PASS   TWO env needs against ONE provider both bind; the same fixture with the
                      per-want loop restored returns a FALSE ErrAmbiguous naming (candy:prov,
                      candy:prov)
```

**Two of those exist because their absence let something through.**

**`use-fallback`**: every earlier fixture authored only `.Need`, so `wantsOfUse` — the half D-CAP-1 says *"goes without"* — never ran. Writing the test also corrected **my own assertion**: I first required that an unbound use record NO binding; the solver returned one with `Bound: ""`, and D-CAP-3 was right, not me — *"an unbound use is recorded, with its node, in the deployment's state."* **A test written from the code's shape would have "fixed" correct code.**

**`use-nosurface`** is the one that found a BUG, not an omission: the refusal was applied to every want, so `use: secret:` — a type with no surface — **failed the load**, which D-CAP-1 forbids (*"a `use:` … goes without, otherwise"*). The existing fallback test uses `env`, which *has* a surface, so it never reached the path. Fixing it exposed a second-order crash — the provide-collection loop then called `provideSurfaces["secret"].collect`, and a zero-value entry has a **nil `collect`** — now guarded by the same surface check from the other side.

**`double-count`**: the gatherer collected a member's provides inside the **want** loop, so two `env` needs against one provider counted it twice and `Resolve` returned a false `ErrAmbiguous` naming `(candy:prov, candy:prov)` — **an error blaming the tree for the gatherer's arithmetic.** Every other case has ONE want, which is exactly why it was invisible. **A fixture with one item per collection cannot see a double-count; this one has two.**

**The visibility plant is the arm that makes §8.2 load-bearing:**

```console
PLANT: gatherer ignores `visible`, takes every member of the tree:
  --- FAIL: visibility: an invisible provide does not bind
RESTORED: ok  github.com/opencharly/charly/charly
```

A gatherer that ignores the tree **passes the other four cases and fails only this one** — which is exactly why §8.2 is implemented rather than assumed. The plant was a two-line edit to the loop, reverted before the commit: `git status` clean, `grep -c 'PLANT' capability_gather.go` → **0**.

**And the refusal's assertion is deliberately `errors.As(*ErrNoProvideSurface)`, not a string match** — so a future change that converts the refusal into `ErrUnbound` fails here rather than silently degrading.

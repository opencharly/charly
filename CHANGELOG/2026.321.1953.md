## What this bed proves, and what its own `description:` says it does not

**Proves:** a candy's `secret_require:` reaches the container's environment at CONFIG time, through
the box chain, on a disposable deployment that builds, realizes, passes its checks, rebuilds with
`charly update`, passes again, and cleans up.

**And the candy's own description is corrected:** it previously said "NOTHING else — no packages" and "installs nothing", while it composes `layer-ripgrep` and therefore DOES install the `ripgrep` package — which is exactly why `seam-proof-box` declares `distro: [fedora]`. The two statements contradicted each other in the same tree. It now says what it is: one required secret, no `base:`, no services, and one warm composition so the build has a real installation to perform.

**Does not prove — three limits, stated in the entity:**

1. **Delivery, not retrieval.** `EnsureCandySecret` MINTS a 32-byte token when the value is missing
   everywhere, so a pass means "delivered", not "read from a pre-seeded store".
2. **The IR limb only.** The value is absent from the plan and the rendered script; it is **still
   persisted into `state`** as the unit's `Environment=`.
3. **A green bed is not a compliance claim.** The handle-shaped answer is `#BindOutput.binding`,
   which is `#Opaque` (`spec/schema/bind.cue:48-52`), delivered at realize by the type owner's
   `bind` (`DESIGN.md:685`) — tracked as plugin-deploy-pod#75.

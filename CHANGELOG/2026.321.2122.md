# 2026.321.2122 — chore(deps): adopt sdk v0.2026321.2010, whose label emitter wraps long values

## Summary

The SDK's `writeJSONLabel` now wraps a JSON label that would exceed the Dockerfile line limit
(opencharly/sdk#554, merged and tagged `v0.2026321.2010`). Until this module pins it, the umbrella's own
renderer still emits the unwrapped line, and a wide box cannot be built at all:

```
$ charly box build immich-ml-cdi            # opencharly/distro-cachyos
 503 |     LABEL ai.opencharly.description='{"candy":[{"origin":"candy:…/layer-direnv",…
error: failed to solve: dockerfile line greater than max allowed size of 65535
```

Producer-first: the SDK leg is merged and tagged; this is the `charly → distro-* → boxes` hop that makes
the fix reachable. The dependency move is

```
github.com/opencharly/sdk  v0.2026320.2158 -> v0.2026321.2010
    in charly/ AND tools/{generate-packages, golden-cloudinit, golden-compile, gomod-canonical}
```

`go get` downloaded `github.com/opencharly/spec v0.2026321.1340` while resolving, but this module's
`go.mod` keeps the spec version it already required — the new sdk is compatible with it, so no spec line
moves. An earlier draft of this body claimed that spec move; the diff says otherwise and the body now
follows the diff.

**4. R7 — the behaviour this pin buys is proven at its own boundary,** in opencharly/sdk#554: a fixture
larger than 65 535 bytes whose every emitted line stays inside the cap, and whose backslash-newline
reconstruction is byte-identical to the unwrapped value. That test fails on the previous sdk release and
passes on `v0.2026321.2010`.

**5. R10 — what did and did not run, stated plainly.** This repo's full gate is CI (`gofmt`, `go vet`,
`golangci-lint`, `go test`, the cross-compile matrix) plus the org `charly/pr-validator`; at push time
that had not run, so the attribution tier is `analysed on a live system`, not `fully tested`. What DID run
locally against the new pin is items 1 and 2 — the module builds and the renderer's label tests pass. The
behaviour the pin buys is proven at the SDK's own boundary (item 4), and the end-to-end consumer build
(`box/immich-ml-cdi`) cannot run until a distro repo pins this tag: that is producer-first ordering, and
the tracking item is the box cutover already in review (opencharly/distro-cachyos#195), whose
`immich-ml-cdi` failure is what filed opencharly/sdk#553.

## Change classification

**Breaking change + rollback:** none — the dependency moves forward to a release that only changes how an
over-long label is emitted, and the emitted bytes for every label under the limit are unchanged (proven
by `TestWriteJSONLabel_ShortValueOnOneLine` in the SDK PR). Rollback is reverting the two lines, which
restores the unbuildable wide box.

Change class: **Dependency pin (Go module)** — `go build ./...`, `go test . -run 'Label'` and the diff
pasted; the consumer build named producer-first.

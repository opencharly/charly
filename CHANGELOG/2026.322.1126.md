# 2026.322.1126 — chore(git): ignore .worktrees/ so a session worktree cannot dirty the tree

## Summary

**`charly task verify` fails today, and the cause is an untracked directory that neither placement rule forbids.**

Measured:

```console
$ ./charly/bin/charly task verify
  [fail] check — the pin contract holds — every distro-* gitlink equals charly's own box/* gitlink (the EDGE), and every submodule
        [fail] run — run git-submodules in the selected mode
            verify: 1 failure(s): charly: dirty working tree
```

And the working tree:

```console
$ git -C charly status --short
?? .worktrees/
```

**`.worktrees/` is not a change.** It is where a session worktree lives — and **two sanctioned placements exist**: the subrepo's own `.worktrees/` (charly's rulebook) and the umbrella's `.worktrees/<slug>/<repo>/` (the umbrella's Part II #2). **Neither is wrong; the tree just has to be blind to both.**

## The change

One line in `.gitignore`:

```
# Session worktrees. A subrepo's own rulebook puts them under `<repo>/.worktrees/`, and
# the umbrella's Part II #2 puts them under `<umbrella>/.worktrees/<slug>/<repo>/`. Both
# are sanctioned, so the directory must be invisible to `git status` from either side --
# an untracked `.worktrees/` made `charly task verify` fail with "charly: dirty working
# tree" on 2026-11-18, and the tree was clean by every other measure.
.worktrees/
```

## Head

```console
$ git rev-parse HEAD
3fc24b24f4e0bda793879b56f0a0984900d05c1e
```

## How tested

```console
$ git status --short          # rule REMOVED, a file inside .worktrees/
?? .worktrees/
$ git check-ignore -q .worktrees/x/f; echo $?
1
```

The same directory, with the rule in place:

```console
$ git status --short | grep -c worktrees
0
$ git check-ignore -v .worktrees/x/f
.gitignore:169:.worktrees/	.worktrees/x/f
```

**`check-ignore` names the exact line that matches, and its exit code flips from 1 to 0.**

A count taken after the directory was already gone would have proven nothing: **an EMPTY directory is
invisible to git whether or not the rule exists**, so the first version of this evidence could not fail.
A file inside it is what makes the directory visible, and that is what the stale session worktrees held.

Change-class gate: none exists for a `.gitignore` rule. `charly task verify` is the gate that was FAILING
before this change on exactly this directory, and it is re-run on the final tree.

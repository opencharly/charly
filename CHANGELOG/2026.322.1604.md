# 2026.322.1604 — chore(deps): compile the landed store, clean and build plugins into charly

## Summary

`charly/go.mod` still compiled the pre-cutover `plugin-clean` and `plugin-build`, so a binary
built from `main` could not exercise any of the four changes that landed today: the `sdk` image
store, the two new `charly clean` categories, the store-IDENTITY routed cache sweep, and the
build drive that writes built images into that store. The compiled-in requires now name the
merged module tags, read from the module proxy rather than from the brief:

| require | was | now |
|---|---|---|
| `plugin-clean/candy/plugin-clean` | `v0.2026287.2341` | `v0.2026322.1315` |
| `plugin-build/candy/plugin-build` | `v0.2026317.2215` | `v0.2026322.1325` |
| `sdk` | `v0.2026321.2010` | `v0.2026322.1227` |
| `spec` | `v0.2026321.1340` | `v0.2026322.1239` |

The `sdk` and `spec` rows belong to the same bump and neither is cosmetic. `sdk` is the version
both plugins require. `spec` is the **revert**: the version both plugins require
(`v0.2026322.1111`) still carries the fifth (`data`) root, so a tree that left the resolver there
would hand every plugin a five-root store while `DESIGN.md` D-STORE-1 names four.

The shared pin does not live in one file: four in-repo modules mirror `sdk`/`spec` and the repo's
own consistency gate compares each against `charly/go.mod`, so the same change advances them too
(`tools/generate-packages`, `tools/golden-cloudinit`, `tools/golden-compile`,
`tools/gomod-canonical`). The first three are tidied so their `go.sum` follows; the fourth is
advanced with `go mod edit -require` and deliberately NOT tidied, because its subject IS the
canonical require block and `go mod tidy` there empties it (`opencharly/charly#1184`); its `go.sum`
takes the two versions' hashes from `go mod download`, so the module can RESOLVE what its own
`go.mod` names rather than only compiling a test that imports nothing from them.

One `check-commands-local` step is repaired in the same change, because the R10 gate for this
change cannot go green while it is red. `box-reconcile-remote-cached` was red for two independent
reasons, both reproduced on the shipped `2026.321.2122` binary (control under "How tested"):

- it compared the **whole stdout** of its two `--remote` runs, and the loader's own
  `plugin <name>: served from …` preamble labels the same project plugin by its short name in one
  run and by its module path in the next, in map order — so two runs whose reconcile report was
  byte-identical went red. The step now compares the report, which is what "agree with the first"
  means;
- it carried no `timeout:`, and its two isolated-cache reconciles take 2m33 on this host, past the
  per-step never-hang ceiling — so the probe was killed mid-step and the shell carried on against
  a truncated capture (`opencharly/charly#1137`). The step now declares `timeout: 600s`, and each
  of its arms prints what failed instead of failing silently.

No `replace` directive exists in the tree after the bump, and none is introduced.

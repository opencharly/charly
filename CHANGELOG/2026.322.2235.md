TODO.md **3.1**, leg 3 of 3 (leg 1: `spec#381`; leg 2: `sdk#564`; tracking: `spec#380`). Two units in one change, because either alone is red.

**The paired pin bump.** `charly`'s `spec` pin (`v0.2026322.1239`) predates `spec.ResourceKindSet` (shipped in `spec#381`'s tag), so the swap cannot compile at the old pin. Bumping `spec` alone also fails, and the reason is a finding about the org's dependency shape:

`charly` pins `sdk v0.2026322.1227`, whose `kit/` still read the field `spec#379` deleted. **The deletion reached this repo through the `sdk` pin — two hops from the repo that made it. Not a consumer: a consumer's consumer.** So `spec` and `sdk` travel together (`sdk v0.2026322.1853` carries the acme adaptation and leg 2), and the pair is the only state in which the build is green.

**The swap.** Core derived its own copy of the `#ResourceKind` membership at init — `resourceKindSet = setFromSlice(spec.ResourceKinds)` (`reserved_registry.go:46`). Two live predicates read it (`isExternalDeploySubstrate`, `unresolvedDeployTargetError`) plus two test fixtures; all four now ask `spec.ResourceKindSet()`, and the copy is gone. **`setFromSlice` stays standing** for its four other callers (`authoredOpFieldSet` and a two-vocabulary consistency check) — measured, not assumed.

**Why the class's full gate is not run, stated as three separate reasons** (`charly#1205`, `charly#1207`):

1. **The `kind:check-roster` roster the matrix names does not exist.** `git -C charly grep -c 'kind: *check-roster' origin/main -- '*.yml'` → `0`, and no roster entity is declared in `plugin-check` either. The matrix's mechanism is unavailable, so the matching set was derived by reading the classifier and run bed by bed.
2. **The local leg must not be run autonomously.** The bed map names `check-local`; that entity does not exist. Its live relatives are `check-local-app` (**no `disposable:` key**, a `kind:local` apply against the operator's host) and `check-local-vm` (a VM bed). Running the first would violate Disposable-Only Autonomy — `disposable: true` is never inferred from a name.
3. **The VM leg cannot run here.** `check-k3s-vm` and `check-local-vm` need an active libvirt; `systemctl is-active libvirtd virtqemud` reported `inactive`/`inactive` on this machine.

So this PR carries **one of the three matching beds** — real live evidence about the pod half of the classifier, and explicitly not the gate. A green on one of three is exactly the partial roster the matrix forbids, and its stated reason is that the missing bed is where a routing error surfaces.

The gates above were run on the branch's own commit; the merge from `main` touches no file this diff touches.

# 2026.325.1102 — feat(plugins): publish the content kinds, and adopt the owned-skill chain's pins

## Summary

The core leg of opencharly/sdk#598. It installs the skills a composed candy owns, as content the `skill` kind compiles, and it moves the chain's pins.

- **The host publishes which kinds serve owned content.** `buildCapMeta` records `ProvidedCapability.contents` for a `class:kind` capability, and `capMeta.IsContentKind` implements `spec.ContentKindCarrier`. The `validate-word-sets` leg publishes those kind words, sorted, as `content_kinds`. The words are read off each provider's own capability, never a per-kind branch (D-LAW-3, D-LAW-8). That set is what plugin-build's render-prep and plugin-box's validate ask.
- **The pins move together**, all merged and tagged:

- **`charly.yml`:** the charly-skill-shelf's no-op `run:` step is deleted. It existed only to satisfy validate's install-content rule, and an owned skill node is install content now (plugin-box#92).

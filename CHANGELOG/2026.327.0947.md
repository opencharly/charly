# 2026.327.0947 — fix(packaging)!: the packaging manifest vendors the builder plugins at the reply contract

## Summary

`packaging/charly.yml` carries its own copy of the `charly` candy, and it repeated the layer's **pre-contract** builder-plugin pins (`v2026.271.*`). Those refs vendor the plugin **by word** into a project's candy closure at render time, and a pre-contract builder plugin's reply carries no `output` discriminator — so any project composing this candy fails to render every builder-using image (root-caused and filed as opencharly/charly#1240).

This moves exactly four strings to the generation `charly/charly.yml` ships — `pixi v2026.326.2258`, `npm v2026.327.0024`, `cargo v2026.326.2259`, `aur v2026.327.0012` — so the packaging manifest stops drifting from the binary's plugin set. No other line changes.

# 2026.330.2107 — fix(pixi): stop injecting [system-requirements] and the dead RATTLER cache root

## Summary

Stop the pixi builder rewriting every manifest with `[system-requirements] libc = 2.39`, and drop the
dead `RATTLER_CACHE_DIR` cache root from the same builder entry.

**The injected section is what breaks a locked build on pixi 0.84.2.** It changes the resolved platform
from `linux-64` to `linux-64-glibc-2-39`, so a candy's lock resolved for the bare platform fails:

```
Error: the lock file has no entry for platform 'linux-64-glibc-2-39' in environment 'default'
help: Run `pixi lock` to resolve it for this platform.
```

Measured on the openwebui image build after the pixi 0.84.2 upgrade. The section is **deprecated** in
0.84.2 (it warns) and **not required**: a manifest with `platforms = ["linux-64"]` and no section locks
and installs `--frozen` cleanly (measured, exit 0).

**`RATTLER_CACHE_DIR` is dead** on 0.70.2 and 0.84.2: a `--frozen` install never creates it; the package
cache is `PIXI_CACHE_DIR` (`pkgs`, `uv-cache`).

The non-lock install path is deliberately **kept**: a candy without a lock still solves
(`pixi install`), and `pixi.toml+lock` still selects `pixi install --frozen`. The lockfile is the
preferred path (documented in the pixi skill), not a mandate.

## Change classification

**Behavioural, non-breaking for a locked candy**: it installs from its own platform instead of a
rewritten one. A candy that *relied* on the injection (a lock resolved for `linux-64-glibc-2-39`) keeps
working, because its manifest declares the section itself.

**Breaking change + rollback:** a candy whose lock names `linux-64-glibc-2-39` but whose manifest does
NOT declare the section would now fail; none exists in the materialized tree. Reverting restores the
injection.

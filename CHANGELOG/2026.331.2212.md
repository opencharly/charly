### Spike

**RCA claim:** the tag churn was not the cache killer — buildkitd's default GC policy was; the consumer fix is a daemon budget plus a ref decision that reuses an unchanged artifact.

- **A. Leave the daemon policy to buildkitd (status quo).** Measured: `buildctl du` on the default policy gave `Total 10.35GB / Reclaimable 9.38GB` with 170 GB free — pruned to the reserve floor, so a cold rebuild re-executes. **Fails.**
- **B. Adopt sdk's 100 GB budget + plugin-build's ref decision (chosen).** Measured: budget written, refs reused, cache survives a restart (pasted above). **Works.**
- **C. Adopt only plugin-build, keep the old sdk.** **Spiked.** `go get sdk@v0.2026331.1243` also downgrades plugin-build to `v0.2026331.1306` (the newer plugin requires the newer sdk), and that combination **builds cleanly** (`build_exit=0`). So C is mechanically viable; it is rejected on the measured behaviour: with the old sdk the artifact keeps changing between builds — the pre-change runs of one unchanged tree minted different digests (`sha256:2289e7b3…` then `sha256:4a96c580…`) — so the ref decision has nothing to reuse. **Eliminated by measurement.**

**Winner:** B.

- **C. The emitted account step is uid-guarded while the runtime identity is name-based.** *Spiked and REPRODUCED (this is the RCA of opencharly/charly#1309).* The emitted bootstrap step is:

  ```
  RUN if ! getent passwd 1000 >/dev/null 2>&1; then \
        ... useradd -m -u 1000 -g 1000 -s "$LOGIN_SHELL" user; ...
      fi
  ```

  and the generated overlay Containerfile restores the identity **by name with no creation**:

  ```
  FROM ghcr.io/opencharly/check-k8s-deploy-app:2026.331.2124   <- base: USER 1000 (numeric)
  USER root
  RUN ... dnf install -y ripgrep ...
  USER user                                                   <- by NAME, no useradd
  ```

  Reproduced with a base whose uid 1000 belongs to `other`, then the **verbatim** emitted step:

  ```
  $ podman image inspect --format '{{.Config.User}}' s1309rca:probe
  user
  $ podman run --rm s1309rca:probe
  Error: unable to find user user: no matching entries in passwd file
  ```

  Contrast arm — base without uid 1000, so the guard fires:

  ```
  $ podman run --rm s1309rca:ok
  uid=1000(user) gid=1000(user) groups=1000(user)
  ```

  Fix location: `sdk/deploykit/bootstrap.go` (guard on the NAME the image declares; `-o` when uid 1000 is taken) and the overlay's `USER` restoration (`plugin-deploy-pod/overlay.go:202`). Filed as #1309.
- **D. post-build ref reuse pointing at a different image.** Eliminated by measurement: a genuine `deploy → config → start → charly update` cycle keeps the same image ID (`fe1c2f55…`), `Config.User=1000`, and `user` resolves before and after; every image still inspectable (including the overlay `c902769a`) carries `user:x:1000:1000`.

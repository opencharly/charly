# 2026.332.0030 — fix(deps): adopt the sdk that keeps an import back-edge, so an imported box renders

## Summary

Adopts `opencharly/sdk v0.2026331.2149` (`opencharly/sdk#654`), which records an import **back-edge** as
an alias in the materialized wire and restores the pointer on reload. Without it, a box reached through a
namespace import lost the alias its `base:` names — `opencharly/charly#1295`.

The case, and why it only shows through the wire: `distro-cachyos` imports `pod-whisper`, `pod-whisper`
imports `distro-cachyos` as `cachyos`, and `pod-whisper`'s `whisper` box declares
`base: cachyos.cachyos`. Inside `distro-cachyos` that alias is the ancestor the loader already mounted, so
the wire skipped it (correct for bed enumeration, fatal for base resolution); the reloaded child then
resolved the base to nothing, and the failure surfaced two stages later as `build: field required`, then
`DistroDef == nil` at `sdk/deploykit/candy_steps.go:53`.

**Catch-up during the PR, twice, never by rebase.** `main` advanced with `#1307`
(`feat/pin-buildkit-wave`), which moved `charly/go.mod`/`go.sum` too, so the branch conflicted; merged
locally, keeping the NEWER `opencharly/sdk v0.2026331.2149` over main's `v0.2026331.1440` and taking
main's other pins, with `go mod tidy` rebuilding `go.sum`, the binary rebuilt and the live render
re-proved on the merged tree. Then `main` advanced again (`#1312`) with the branch merely BEHIND, so the
sanctioned move was used — **`gh pr update-branch`**, which merges `main` in server-side (head
`9537fed3`); that merge commit owes no attribution per the landing rulebook.

**One more RCA, from the CI this PR's own gate caught.** The earlier heads sat `validate / validate =
success` with auto-merge never arming. The cause was not a platform stall: a SIBLING check, `go`, was
RED — every tools module is a separate Go module (`GOWORK=off`), and `tools/gomod-canonical`'s
`TestContractPinsMatchShared` requires each lockstep module to carry the MAIN module's sdk pin:

```

  v0.2026331.2149 — run `charly task mods-tidy`
```

**Missed control:** my local gate was `go build ./...` + `go test ./...` INSIDE `charly/`, which covers
the main module and none of the tools modules — so the bump looked green locally and the repo's own
canonical-pin check was the first thing to see it. `charly task mods-tidy` is the mechanism that check
names; it is now run, and its own re-check passes. I also spent a re-freeze commit on what I read as an

# 2026.332.0240 — fix(update): re-deploy the deploy's identity, not its box

## Summary

Three changes make a namespace-imported deploy actually runnable end to end on this tree — the
umbrella being able to gate a submodule's runtime change on its own tree (opencharly/opencharly#1316):

1. **core, one line + its unit test** — `charly update`'s dispatch carried the deploy BOX, not its
   identity:
   `deployName := c.Box` in `update_deploy_dispatch.go`. An instance (`-i`) or namespace-qualified
   deploy keys its entry on the box + instance PAIR (`spec.DeployKey`), so the rebuild re-invoked
   `deploy add <box>` and failed with `no <ref> and charly.yml has no entry`. Now
   `spec.DeployKey(c.Box, c.Instance)`. This is general: it fixes every `-i` instance deploy's update,
   not just namespaced ones. The line is extracted into `updateDeployName` so it has a test
   (`charly/update_deploy_dispatch_test.go`, three rows) that fails without the change.
2. **`plugin-fleet` → `v0.2026332.4`** — an imported entity's short `image:` resolves in its own
   namespace and **only** there (D-LOAD-6 / D-REF-1 / D-REF-2 / D-REF-6), at both resolution sites.
3. **`plugin-pod` → `v0.2026332.49`** — a namespaced lifecycle address is split into the deploy key
   pair by D-REF-1 over the namespace table, at the six commands that take an address.

The deploy command is compiled in, so the module bumps are how those two fixes reach the binary.

Closes opencharly/opencharly#1316.

### Spike — the exemption, invoked explicitly, with the boundary pasted

discharges it: the **live bed run at the exact boundary** the core line changes.

**The RCA's claim.** `charly update`'s dispatch passed the deploy BOX where the deploy's identity is
box + instance, so a rebuild re-invoked `deploy add <box>` and named a deploy that does not exist.

**The candidates, and their instruments.**

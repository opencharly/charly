# 2026.332.0423 — fix(ci): give the charly test suite a measured budget, so a slow runner stops faking a hang

## Summary

`opencharly/charly#1318`. The `go` job runs `go test ./charly/...` under Go's default **10m0s** alarm. The
same suite costs very different wall clock on the two substrates:

```
local, whole package:   ok  github.com/opencharly/charly/charly  203.946s
CI,   whole package:    FAIL … 606.011s     (alarm at 10m0s)
CI,   second run:       FAIL … 606.729s
```

So on CI the suite crosses ten minutes and the alarm kills **whichever test is in flight**, dumping every
goroutine and naming that test as the culprit. Two consecutive runs named `TestExternalPluginEndToEnd` —
which, measured in isolation, is fast: `PASS … 14.70s`.

**The fix is a measured budget:** the CI job now passes `-timeout 20m`, with the division written beside
it so the number is re-derivable rather than folklore (`1200/606 ≈ 2×` the slowest CI run, `1200/204 ≈ 5.9×`
the local one).

## RCA of the previous round (R1, applied)

**Anomaly.** The last round BLOCKed on two arithmetic defects of mine: the comment and body said `20m` was
"3.3x the local one" (it is 1200/204 ≈ 5.9x; the 3.3 came from reading 606s as 6.06 *minutes*), and the
body's diffstat said `+10/-1` when the diff was `+6/-1`.

**Mechanism.** I converted the CI figure to minutes and then divided a timeout expressed in minutes — a
unit slip — and I carried a diffstat measured *before* the final edit into the body.

**Missed control.** The pre-push body linter checks that a claim is present and that a number is
derivable; it does not check arithmetic, and my own flow did not re-run `git diff --stat` after the last
edit. The control that would have caught both — recompute every number from the artifact after the final
edit — was mine to run, and I did not.

**Root fix.** The comment now states the division it performs, so the number can be re-derived by reading
it, and this body's stats are taken from `git diff --stat` on the pushed head.

# scripts/drift-baseline-skills.txt — TEMPORARY record of generated artifacts that are ALREADY stale on main.
#
# Its only job is to let `task skills:drift` fail on NEW drift without reding every PR in
# the repo for debt it did not create. Inherited debt is reported by name on every run.
#
# HOW THIS WAS MEASURED, and how to re-measure it: origin/main @ 162b54a3 with EVERY
# SUBMODULE AT ITS GITLINK — the tree `actions/checkout --submodules recursive` produces.
# Do NOT re-measure by running the gate in a working tree. Both generators read plugins/
# off the FILESYSTEM, not at the gitlink, so a checkout that has moved records drift CI
# will never see; every such entry then reds CI forever as "no longer stale", and every
# real gitlink-level entry it omits reds CI as new.
#
# RE-MEASURED at 162b54a3 (was 70daf9cb). The first measurement was taken two `main`
# merges before this branch's merge-base, and because the comparison is EXACT the skew
# alone red the gate: 3 already-stale artifacts were missing and 2 already-paid entries
# were still listed. A baseline measured at the wrong commit is not a smaller problem
# than no baseline — it fails in both directions at once.
#
# THIS IS NOT AN ALLOWLIST. scripts/drift-baseline.sh compares EXACTLY: an entry here
# that is no longer stale fails the gate just as loudly as an artifact that is stale and
# absent. That is what makes this file self-liquidating — it can only shrink, and when it
# reaches zero you delete it and the gate runs absolute.
#
# Do not add a line to silence a red. If your change made an artifact stale, the fix is to
# regenerate and commit, never to record it here.
#
# THE ONE CASE THAT RULE DOES NOT COVER — and it has now RESOLVED, kept because the reasoning
# recurs. A PROJECTION can be AHEAD of its source: plugins#208 landed the projection of
# charly#315's work before #315 itself merged, which is B6a working as designed. `main` then held
# text NEWER than anything this superproject could generate, and regenerating REVERTED it. Two
# entries were recorded here rather than regenerated for exactly that reason.
#
# charly#315 has since landed (c8ba494f), the source caught up, and both entries liquidated in the
# normal way — the gate red with "no longer stale" and they were deleted. That is the mechanism
# working end to end, and it is why they were recorded rather than "fixed".
#
# The lasting rule: BEFORE acting on a red here, measure the DIRECTION.
#   regenerating ADDS text    -> the SOURCE is ahead; regenerate and land the projection (#318)
#   regenerating REMOVES text -> the PROJECTION is ahead; regenerating destroys landed content,
#                                so record it here instead
# charly#336 carries the finding that the gate cannot tell these apart on its own: both print
# "newly stale", and only the diff direction separates them.
#
# RE-MEASURED AGAIN at this branch's own head with ITS gitlinks (plugins 40229ad, docs e213d51),
# because that is the tree CI checks out for this PR and the comparison is EXACT. Measuring at
# `main` alone was wrong in both directions once this branch bumps a projection gitlink: the
# artifacts the projection FIXES stop being stale, and the artifacts `main` has moved past
# become stale. Neither of the entries below is this branch's own drift — every one is inherited,
# and every one is reported by name on each run.

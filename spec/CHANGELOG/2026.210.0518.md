# 2026.210.0518 — Initial import: spec + proto wire/IR contract extracted from sdk (#55 Phase A1)

Extracted from the sdk module (github.com/opencharly/sdk) as the standalone
`github.com/opencharly/spec` module — Phase A1 (the producer leg) of the #55
import-purity plan. It carries ONLY the schema-source + generated wire/IR
contract, so charly core can import the type contract WITHOUT pulling the sdk's
mechanism kits (kit/deploykit/loaderkit/buildkit/vmshared/…).

Mirrors the sdk carve-out precedent (`sdk/CHANGELOG/2026.185.1913.md`), which
likewise bundled schema-source + generated output + dev-time codegen together.

Extracted dirs (relative layout preserved):

- `spec/` — the generated param + wire/IR types (`cue exp gengotypes` output +
  the hand-written union/state/method/const siblings + the reproducibility gate
  `gen_repro_test.go`).
- `proto/` — the gRPC transport contract (`plugin.proto` + generated
  `plugin.pb.go` / `plugin_grpc.pb.go`), generated, never hand-edited.
- `schema/` — the CUE schema source (`*.cue`), the single author-of-record for
  the ingress + wire types, embedded via `schema.go`.
- `protocol/schema/` — the CUE source for the gRPC transport model.
- `schemaconcat/` — the shared PUBLIC schema-concatenation contract (`ConcatSchema`)
  both the runtime and the dev-time generator call (R3 — one concatenation).
- `internal/schemagen/` — the companion generator (concat/retag/vocab/version modes).
- `internal/wiregen/` — the CUE→proto generator (closes the CUE→proto tooling gap).
- `Taskfile.yml` — the `cue:gen` + `wire:gen` dev-time codegen tasks (ported from
  sdk, module paths adjusted to `github.com/opencharly/spec`).

Every `github.com/opencharly/sdk/{spec,proto,schema,schemaconcat}` import path in
the moved files was repointed to `github.com/opencharly/spec/...`; the protoc
`--go_opt=module=` / `--go-grpc_opt=module=`, the `plugin.proto` `option
go_package`, the `protocol/schema/plugin.cue` `go_package`, and the codegen
`module: "…/schema/spec-codegen"` string were all rewritten to the new module
root. The two `sdk/deploykit` provenance comments (`schema/seam.cue`,
`spec/cue_types_gen.go`) were left unchanged — deploykit remains an sdk package,
not a spec one.

Go module tags follow the sdk scheme `v0.<YYYYDDD>.<HHMM leading-zeros-stripped>`
(semver-legal, CalVer-derived), so a consumer can `go get
github.com/opencharly/spec@<tag>`.

Verified standalone: `GOWORK=off go build/vet/test ./...` all green;
`task cue:gen` regenerates every artifact reproducibly (a clean regen is a
byte-identical no-op across `spec/cue_types_gen.go`, `spec/vocab_gen.go`,
`spec/version_gen.go`, `proto/plugin.pb.go`, `proto/plugin_grpc.pb.go`,
`proto/plugin.proto`; `TestGenReproducible` runs and passes); `gofmt -l` clean.

# 2026.210.1533 — CUE-source ResolvedBox / BuilderMap / AggregatedCandyCaps (#55 STEP 3 unit 3a, producer leg)

STEP 3 of the everything-is-a-plugin import-purity plan lifts the fully-resolved
BOX render-context data-carrier into the shared `opencharly/spec` contract
module, so charly core (the resolved-project envelope projector, the render-seam
floor) and `sdk/buildkit` (the resolve ENGINE) share ONE wire-clean type instead
of each carrying its own copy. This is the PRODUCER leg; the sdk/buildkit embed +
alias repoint and the superproject `require` bump ride their own follow-on PRs in
the B2 dependency order.

New CUE-sourced types (SDD — a render-context data-carrier is CUE-sourced, the
`kit.CheckResult` / `checkresult.cue` precedent; hand-writing a wire struct is
forbidden):

- `#ResolvedBox` (`schema/resolvedbox.cue`) — the wire-clean, in-process VALUE
  half of a box's resolved configuration: 30 fields generated faithfully as a
  plain struct. Fields that carried no json tag on the former hand struct are
  REQUIRED (`!` → no `omitempty` in the generated json tag); fields that carried
  `,omitempty` are OPTIONAL (`?`).
- `#BuilderMap` — `map[string]string` of build format (pixi/npm/cargo/aur) →
  builder image name.
- `#AggregatedCandyCaps` — the output of walking all candies in resolution order
  (preserve_user / needs_root_after_init / init_system_hint / data_only /
  oci_labels / provided).

Excluded from the generated `#ResolvedBox` and kept hand-`json:"-"` on the
`sdk/buildkit` embedding wrapper, per the gengotypes CANNOT-table exception (no
CUE construct emits a marshal-suppressed field):

- the buildkit-owned host-render-cache VOCABULARY pointers
  DistroConfig / DistroDef / BuilderConfig (+ InitSystem / InitDef) — buildkit
  types `spec` must never import (a spec→buildkit edge would cycle);
- the four render-cache fields CandyCaps / BakedMetadata / RenderCandyOrder /
  ActiveInits — `json:"-"` on ResolvedBox itself (the separate ResolvedBoxView
  wire type carries the actual wire copies via NewSpecResolvedBox).

Methods (`spec/resolved_box.go`, hand-written — gengotypes has no construct for
behavior, the `Op.Kind()`-style exception): `ResolvedBox.SupportsTag` /
`SupportsBuild`; `BuilderMap.BuilderFor` / `HasBuilder` / `AllBuilder`.

# 2026.210.2308 — InstallStep step vocabulary → spec (#55 step-4, producer leg)

STEP 4 of the everything-is-a-plugin import-purity plan relocates the **InstallStep
step vocabulary** — the 13 concrete step structs + their helper value types + the
view converters + plan mechanisms — out of `sdk/deploykit` into the `spec` contract,
beside the already-hand-written `InstallStep` interface + `InstallPlan`/`StepBatch`
container. This is the import-purity lever that lets charly core (and in-tree
candies) reference the deploy install-timeline IR from `spec` instead of importing
`sdk/deploykit`. PRODUCER leg; the sdk require-bump + charly/candy repoints ride
their own follow-on PRs in the B2 dependency order.

## What lands (4 new hand-written files)

- **`spec/install_step_vocab.go`** — the 13 concrete `InstallStep` structs
  (`OpStep`, `SystemPackagesStep`, `BuilderStep`, `ServicePackagedStep`,
  `LocalPkgInstallStep`, `ShellHookStep`, `ShellSnippetStep`, `ServiceCustomStep`,
  `FileStep`, `ExternalStep`, `RepoChangeStep`, `ApkInstallStep`, `RebootStep`,
  `ExternalPluginStep`) + `RepoSpec`/`CacheMountSpec`/`ArtifactRef` + their 65
  methods (`Kind`/`Scope`/`Venue`/`RequiresGate`/`Reverse`, …) + the pure IR
  helpers (`AllStepKinds`, `OpStepScope`, `PathIsSystemScoped`, `IsExternalStepKind`,
  `PluginEmitStepWords`, …).
- **`spec/install_step_view.go`** — the `StepToView`/`StepFromView`/`StepsToView`
  projection helpers.
- **`spec/install_plan_view.go`** — `WireView`/`PlanFromView`/`ResolveHome`/
  `GateEnabled`/`HomeToken`.
- **`spec/install_step_view_test.go`** — the `TestStepView_RoundTrip` gate (all 13
  kinds), relocated from deploykit.

## Hand-written relocation, NOT CUE-sourced — deliberate + SDD-correct

The 13 concrete step structs are IN-PROC IR: they never cross the process boundary;
`StepToView` projects them onto `InstallStepView`, which IS the wire form and stays
the SINGLE CUE source (untouched — zero CUE/schema files changed, `task cue:gen`
stays a no-op). (1) SDD's "wire types CUE-sourced without exception" binds at the
boundary contract = `InstallStepView` — satisfied. (2) CUE-sourcing the 13 structs
would DUPLICATE the 13-kind field set already authored in `#InstallStepView` — two
CUE sources for one dataset, the exact single-source-of-truth harm SDD exists to
prevent; hand-written structs + the one CUE View keeps a single CUE wire source.
(3) They are siblings of the already-hand-written `InstallPlan`/`InstallStep`/
`StepBatch`/`EmitOpts`/`DeployExecutor` in spec — the concrete members belong with
their interface + container, not split into CUE. (4) The 65 methods stay
hand-written regardless; zero type churn. A live `cue exp gengotypes` spike
CONFIRMED CUE is feasible (`os.FileMode` direct; `Payload` via the
`type RawBody = json.RawMessage` alias) — feasible but REJECTED to avoid the
`#InstallStepView` field-set duplication above.

Additive for spec consumers: purely new files; nothing renamed/removed. `sdk/deploykit`
keeps thin re-export aliases (`OpStep = spec.OpStep`, …) so its own code + out-of-tree
plugins are unchanged — landed in the follow-on sdk leg.

Producer-first B2: this spec leg (merged + Go-module tagged) → sdk require-bump →
superproject charly + in-tree-candy repoint.

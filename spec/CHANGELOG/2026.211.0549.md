# 2026.211.0549 — deploy CONFIG/KEY value-vocabulary → spec (#55 Cone V, producer leg)

Cone V of the everything-is-a-plugin import-purity plan (the direct step-4
analogue) relocates the deploy **CONFIG/KEY value-vocabulary** out of
`sdk/deploykit` into the `spec` contract, so charly core (and in-tree candies)
reference it from `spec` instead of importing the `sdk/deploykit` mechanism kit.
Behaviour (`SaveDeployState`, the OCI step-emit dispatch, the deploy walk) STAYS
in deploykit — only the value vocabulary moved. PRODUCER leg; the sdk
re-export-alias + require-bump and the charly/candy repoints ride their own
follow-on PRs in the B2 dependency order.

## What lands (1 new hand-written file + 2 CUE-sourced wire structs)

- **`spec/deploy_key.go`** (new, hand-written) — the pure deploy helpers, stdlib
  (`strings`) only, moved verbatim from deploykit: `DeployKey` / `ParseDeployKey`
  (the charly.yml deployment map-key ⇄ (box,instance) pair), `BundleDelArgv` (the
  single `charly bundle del <name>` argv builder), `DeriveDeploymentName` (+ its
  unexported `lastIndexByteInRef` helper — the from-box default-name derivation).
  Methods/functions travel hand-written; these are not wire structs.
- **`spec/schema/deploy.cue`** (+2 defs) → **`spec/cue_types_gen.go`** (regenerated,
  +87 lines) — the two host↔plugin WIRE structs, CUE-sourced per the wire-type
  mandate (RDD-proven: `cue exp gengotypes` generates BOTH field-for-field
  identical to the former hand-written deploykit structs — no `@go(-)` exception):
  - **`#OCIEmitStepParams`** (`{Dir, StepView #InstallStepView, PlanView
    #InstallPlanView}`) — the per-step pod-overlay `oci-emit-step` HostBuild
    payload. `step_view!`/`plan_view!` required → value fields (matching the
    former struct); `dir?` optional.
  - **`#SaveDeployStateInput`** (23 fields) — the parameters `SaveDeployState`
    persists, marshalled JSON host↔plugin. Pointer fields via `optional=nillable`
    (Security) / `type=*T` (VmState/Tunnel/Preemptible); `map[string]json.RawMessage`
    via the existing `RawBody` `@go` pattern; every field references only
    spec/stdlib types.

## Wire-safe

Both structs are marshalled AND unmarshalled through the SAME type on both ends
(the deploy candy marshals, the host builder unmarshals), so the CUE retag's
snake_case wire keys stay internally consistent — the payloads are ephemeral
in-operation, never persisted as-is. `TestGenReproducible` green (committed ==
fresh `task cue:gen`).

## Scope note (never-trust-verify)

`BundleConfig` (5 methods depending on `sdk/kit`) and `HostContext` (references the
deploykit-internal `BuilderPreresolved`) are NOT movable to the base spec module
(would invert spec→kit / spec→deploykit) — they are deploy-BEHAVIOUR (K4), not
value vocabulary, and stay in deploykit.

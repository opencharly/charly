## Check-run reply wire types CUE-sourced (SDD fix, this cutover)

`StepResult`, `CheckRunReply`, `StepPass` were hand-written in `spec/spec/checkresult_wire.go`
(claimed as the P12 gengotypes-exception companion to `kit.CheckResult`). The P12 spike
proves ONLY `kit.CheckResult`'s engine-internal `DeadlineExceeded bool json:"-"` is
CUE-inexpressible — these three reply types carry `spec.CheckResult` (no `json:"-"`), so they
are plain carriers a live `cue exp gengotypes` spike proves CUE generates byte-identically
(`optional=nillable` emits the `Passthrough`/`Score` pointers; JSON tags match exactly, yaml
tags added inertly). Per SDD + modified-code-full-compliance they are now CUE-sourced as
`#StepResult`/`#CheckRunReply`/`#StepPass` in `schema/checkresult.cue`; `checkresult_wire.go`
is DELETED; the generated `spec/cue_types_gen.go` carries them. The P12 exception is narrowed
to EXACTLY the `kit.CheckResult` `DeadlineExceeded` wrapper. Stale "hand-written / sanctioned
exception / NOT a CUE wire type" claims swept in `schema/checkresult.cue`, `schema/seam.cue`,
`spec/report/report.go`. (The sdk/kit + charly sibling comments that re-state the hand-written
claim are swept in the sdk + super legs of this B2 chain.)

# 2026.213.2047 — #55 import-purity: plugin-host contract symbols relocated from sdk root into spec slices

The spec leg of the 4-leg B2 PR chain (spec → sdk → plugins → super) that dissolves the
`github.com/opencharly/sdk` ROOT package: the plugin-host contract symbols charly core imports
from the sdk root are relocated into new `opencharly/spec` slice packages so charly core can
import them from spec INSTEAD of the sdk root (the end-state import-purity gate — `charly/`

creates the slice packages and the symbols; the sdk root keeps its definitions for the duration

definitions is a later leg). The super leg re-points the spec gitlink to this leg's merged

## REPOINT decisions (load-bearing for the downstream legs)

- **`StepContract` is a REPOINT, not a NEW type.** `sdk.StepContract` (string `Scope`) and
  `spec.StepContract` (typed `Scope`/`Venue`/`Gate` enums, in
  `spec/spec/provider_carriers.go`) are DIFFERENT types. `spec/exec.Executor.DescribeProvider`
  returns `*spec.StepContract`, converting proto→spec via `spec.ScopeFromName` /
  `spec.Venue` / `spec.Gate` + `sc.GetEmits()`. This is a semantic change (Scope string→typed)
  the sdk leg must handle when repointing charly's callers.
- **`CLIModel` is a REPOINT** — already in `spec/spec/cue_types_gen.go`; the SDK-facing
  authoring form `CLISubcommand` is NEW in `spec/climodel`.
- **`Phase` is a REPOINT for the enum, NEW for the lifecycle consts.**
  `spec/spec/ir_enums.go` carries a DIFFERENT step-phase enum; the lifecycle phase consts
  (`PhaseBootstrap` etc.) are NEW in `spec/phase`.
- The whole `Op*` family is relocated (all 32+ consts, not just the 7 the brief listed):
  `charly/` uses ALL of them and the end-state gate requires them all out of the sdk root.

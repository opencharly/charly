# 2026.216.0939 — comments describing a Kong no-op that no longer exists

Two comments in this repo explained flag behaviour in terms of a mechanism
`opencharly/charly` has just removed.

`spec/deploy_key.go` justified `BundleDelArgv` emitting `--assume-yes` by noting
that the `long:"yes"` tag is "a Kong no-op in the separate-tag form" — Kong
derives the flag from the field name instead. True when written; false now. The
companion cutover converted all **328** go-flags `long:` tags in that tree to
Kong's `name:`, so `AssumeYes` declares `name:"assume-yes"` and the shipped flag
is stated rather than accidental.

`spec/deploy_executor.go:207` carried the same misconception in a shorter form —
"the host target's `--yes`". There is no `--yes` flag; `charly bundle add --yes`
exits 80. It described `EmitOpts.AssumeYes`, whose flag is `--assume-yes`. Found
by a claim-keyed sweep after the first comment was corrected: the same false
belief, about the same field, in the same repo, on the surface the change exists
to fix. The neighbouring `--dry-run` in that clause is accurate — `DryRun`
derives to `--dry-run` under either tag form.

Both are comment-only; no behaviour changes and no generated code moves.

## Why this is its own leg

`spec` is a separate module, so this lands BEFORE the superproject bumps its
`spec` gitlink. The dependency direction is inverted from the usual two-leg
shape — `spec` is the dependency, but the comment describes the *dependent* —
and spec-first is still correct: the companion PR carries the conversion and the
gitlink bump together, so the superproject tree never holds both files in a
contradictory state. Landing charly-first would put that contradiction inside
`main` itself.

## A correction to this cutover's own prose

The first commit message and PR body said **326** tags were converted. The tree
says 328 (`git grep -o 'long:"' main | wc -l`), which is also what the tracking
task recorded. The figure was carried from a report rather than re-derived. It
appears only in narrative — no code or comment depends on it — but a squash body
inherits it, so it is corrected here before merge.

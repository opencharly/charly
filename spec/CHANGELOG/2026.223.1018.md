# 2026.223.1018 — k8s→kubernetes full naming cleanup (the deploy substrate kind)

Renames the deploy substrate kind + cluster-template kind from `k8s:` to
`kubernetes:` — an authored WIRE-key change (a FORMAT change, so
`#SchemaVersion` is bumped to this CalVer and the superproject appends the two
matching `rename_key` migration ops). The deploy's inner deploy-knobs block
`kubernetes?: #K8sDeploy` becomes `deploy?: #KubernetesDeploy` so it cannot
collide with the renamed outer node.

Schema changes:

- `#SchemaVersion` bumped `2026.204.1223` → this CalVer (`#SchemaFloor`
  untouched — predating configs remain unmigratable).
- `#ResourceKind` / the `target:` enum / `#SubstrateKind`: the `k8s` value →
  `kubernetes`.
- `#K8s*` defs → `#Kubernetes*` (file `schema/k8s.cue` →
  `schema/kubernetes.cue`): `#Kubernetes`, `#KubernetesResources`,
  `#KubernetesResourceValues`, `#KubernetesHostname`, `#KubernetesStorage`,
  `#KubernetesIngressDefaults`, `#KubernetesGatewayAPI`,
  `#KubernetesSecretsBackend`, `#KubernetesImagesDefaults`,
  `#KubernetesPodDefaults`, `#KubernetesObservability`,
  `#KubernetesResourceDefaults`.
- `#K8sDeploy` → `#KubernetesDeploy` (+ `#KubernetesPatch` /
  `#KubernetesDeployVenue`); the deploy node's inner block is now `deploy?` →
  Go field `Deploy *KubernetesDeploy`.
- `#ResolvedK8s` → `#ResolvedKubernetes`, `#K8sResolveInput`/`#K8sResolveReply`
  → `#KubernetesResolveInput`/`#KubernetesResolveReply`.
- `#K8sGenInput`/`#K8sGenFile`/`#K8sGenReply` → `#KubernetesGenInput`/
  `#KubernetesGenFile`/`#KubernetesGenReply` (the `k8sgen` generator WORD is a
  confusable — not renamed).
- `#K8sGenerateKustomizeRequest`/`#K8sGenerateKustomizeReply` →
  `#KubernetesGenerateKustomizeRequest`/`#KubernetesGenerateKustomizeReply`.

Go surface (hand-written spec types): `SubstrateK8s` → `SubstrateKubernetes`
(`"k8s"` → `"kubernetes"`), `K8sSpec` → `KubernetesSpec`, `UnifiedFile.K8s()` →
`Kubernetes()`. The generated `cue_types_gen.go` / `vocab_gen.go` /
`version_gen.go` / `proto/plugin.proto` carry the renamed types; `task cue:gen`
+ `task proto:gen` regenerate reproducibly (`TestGenReproducible` green).

Intentional confusables NOT renamed: `kube:` check verb, `k3s`,
`k8sgen`/`verb:k8sgen`/`plugin-k8sgen`, `k8s.io/*` deps,
`registry.k8s.io/pause`, `k8s_object` egress schema, `.opencharly/k8s/` output
path, `k8s.yml` discovered filename, the bed names (`check-k8s-deploy` /
`check-k3s-vm`), `k8s-box`, the `candy/k8s-layer` + `candy/kubernetes` candy
names, `kubectl`/`kubeconfig`, and the frozen `reshape_compact.go` migration
vocabulary.

The consumer legs ride their own PRs: sdk repoints
`require github.com/opencharly/spec` onto this tag and renames its `K8s*`
identifiers; the superproject bumps the spec gitlink and appends the migration
entry (`rename_key` `k8s`→`kubernetes` scope any, then `kubernetes`→`deploy`
scope any `under_kind: kubernetes`).

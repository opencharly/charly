# 2026.224.0403 — opt-in entrypoint/cmd OCI packaging fields on the box wire types

The OCI ENTRYPOINT/CMD surface for direct-spawn images — the first repo of the
three-repo fix (spec → sdk → main) for the AgentTeams manager container
crash-loop. The controller spawns child manager/worker containers **directly
from their baked OCI config** (`dockerCreatePayload` sends no Cmd/Entrypoint),
with no charly deploy in the loop to inject the init command — and charly
images baked none. The opt-in `entrypoint:`/`cmd:` fields let a box bake the
command its children run.

- **`schema/box.cue`** (`#Box`): `entrypoint?`/`cmd?` — opt-in, empty by
  default (a normal charly image bakes no command; the deploy-time init is
  injected instead). `cmd: []` clears a base image's inherited default
  command; a declared entrypoint with no `cmd` is auto-cleared at emission so
  it runs bare.
- **`schema/resolvedbox.cue`** (`#ResolvedBox`) + **`schema/resolvedproject.cue`**
  (`#ResolvedBoxView`): the same fields on the resolved forms, so the
  plugin-build resolve leg re-emits them without the live candy graph.
- **`spec/cue_types_gen.go`**: regenerated via `task cue:gen` (re-run on the
  committed tree is a no-op; `TestGenReproducible` green). CUE-sourced per SDD.
- **`spec/box_oci_packaging_test.go`**: YAML unmarshal + `ResolvedBox` JSON
  wire round-trip guards — both fail without the new fields.

# 2026.224.1942 — ExtractStep in the InstallPlan IR for machine-venue extract materialization

The first repo of the three-repo fix (spec → sdk → main) that makes a candy's
`extract:` entries work on a **machine venue** (`target: local` / `target: vm`),
where the built image filesystem is never used and the install plan executes
over the venue's own filesystem. On a container build the `extract:` entries
render as Containerfile stages (`FROM <source> AS <candy>-extract-<i>` +
`COPY --from=...`); a machine venue has no such build, so the content must be
materialized on the HOST (where podman + the source images live) and shipped
into the venue over the DeployExecutor. This cutover adds the IR vocabulary +
wire type for that host-engine step; the sdk execution body and the main-repo
dispatch land in the consumer cutovers.

- **`spec/install_step_vocab.go`**: the `ExtractStep` struct — `Source` (OCI
  image ref to extract from), `Path` (file or directory in the source image),
  `Dest` (absolute destination path on the venue), `CandyName` (owning candy,
  provenance + the ledger `CandyRecord` key). `Kind()` returns the new
  `StepKindExtract`; `Scope()` is `ScopeSystem` (the dests are system paths).
  `AllStepKinds` 13→14; `PluginEmitStepWords` gains `StepKindExtract: "extract"`.
- **`spec/ir_enums.go`**: `StepKindExtract StepKind = "Extract"` added.
- **`spec/install_step_view.go`**: `StepToView`/`StepFromView` cases for the new
  kind (the wire `extract_source`/`extract_path`/`extract_dest`/`candy_name`
  fields).
- **`schema/deploy.cue`** (`#InstallStepView`): the four optional wire fields,
  CUE-sourced per SDD.
- **`spec/cue_types_gen.go`**: regenerated via `task cue:gen` (re-run on the
  committed tree is a no-op; `TestGenReproducible` green). CUE-sourced per SDD.
- **`spec/install_step_view_test.go`**: the Extract round-trip fixture — the
  `TestStepView_RoundTrip` coverage loop over `AllStepKinds` errors on an
  uncovered kind, so this fixture fails without the new kind.

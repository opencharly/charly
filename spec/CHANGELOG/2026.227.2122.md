## What the previous entry got wrong

It said `t.TempDir()` "consults `GOTMPDIR`, never the `TMPDIR` these tests are about,
**and it resolves BEFORE the `t.Setenv("TMPDIR", …)` that follows it**".

"Never the `TMPDIR`" is too absolute. When `GOTMPDIR` is unset — which is the defective
row — `os.MkdirTemp("", …)` falls back to `os.TempDir()`, so `t.TempDir()` **does** read
`TMPDIR`, transitively. The ordering half is true of the statement order but is not a fix:
in this test the second statement consumes the first's result, so the two cannot simply be
swapped. Neither half identifies what decides the outcome.

**The mechanism is a precedence chain, not two independent variables.** `t.TempDir()`
roots at `$GOTMPDIR` when it is set; when it is not, it falls back to `os.TempDir()`,
which reads `$TMPDIR`, else `/tmp`. `os.TempDir()` reads only `$TMPDIR`, else `/tmp`.
Go 1.26's `testing.makeTempDir` is `os.MkdirTemp(os.Getenv("GOTMPDIR"), pattern)`
(`$GOROOT/src/testing/testing.go:1460`). They can therefore diverge only when `GOTMPDIR`
is set — this host's default — and then only if it names a different directory than
`os.TempDir()` resolves to; with `GOTMPDIR` unset they always agree. Measured:

| `GOTMPDIR` | `TMPDIR` | `t.TempDir()` roots at | `os.TempDir()` |
|---|---|---|---|
| set | set, different | `$GOTMPDIR` — it wins | `$TMPDIR` (they diverge) |
| set | set, equal | `$GOTMPDIR` | same (they agree) |
| unset | set | **`$TMPDIR`**, via the `os.TempDir()` fallback | `$TMPDIR` |
| unset | unset | `/tmp` | `/tmp` |

So the governing condition is not "is `TMPDIR` set" but **"does `t.TempDir()` land
outside `/tmp`"** — and the reason is that precedence, not an absence of any `TMPDIR`
relationship.

Two other explanations circulated during review and are recorded here so neither is
re-derived: `go test` does **not** re-export `GOTMPDIR` as the test binary's
`TMPDIR` (measured — `TMPDIR` absent, `os.TempDir()` = `/tmp`), and `go test -c` is
not needed to reproduce. Plain `go test` with both variables cleared does it.

### Four statements of one mechanism, three of them overshot

Worth recording, because the failure mode is the entry's own subject and it recurred
under review by people actively looking for it:

1. "`go test` re-exports `GOTMPDIR` as `TMPDIR`" — wrong, retracted.
2. "`t.TempDir()` resolves before the `t.Setenv`" — names statement order, not the cause.
3. "the test PASSES whenever `GOTMPDIR` is unset" — too broad; only with `TMPDIR` unset too.
4. "`t.TempDir()` never reads `TMPDIR` at all" — too absolute, and caught by a fresh
   validator on this very PR. It reads it transitively whenever `GOTMPDIR` is unset.

Every one was written by someone who had just measured something true and then stated it
one degree stronger than the measurement supported — including #4, which overshot in the
opposite direction from the #2 it was correcting. The operative discipline is not "measure
first"; all four authors had measured. It is **write only what can be read off the table
directly** — if a sentence needs a quantifier the data does not pin down ("never", "at
all", "wherever", "always"), the data does not support it yet.

accidents" reads as though both tests were broken. Only
`TestOpenedFilesByAnyProcess_HonoursTMPDIR` was, and only in row three — the stock

It shares `altTempRoot()` anyway, and that is a judgement call rather than a
correction: it discriminates via the pre-fix glob being non-recursive, a property
unrelated to what it asserts, which would go vacuous the day the sweep learned to
recurse. With the helper in place the same 2×2 is FAIL in all eight cells on the
merge-base body and PASS in all eight at the merged head — strengthened, not
weakened.

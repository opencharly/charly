# 2026.229.1754 — the distro vocabulary becomes one CUE source; the Go copy is deleted

CalVer finalized at merge by the pr-validator; tagged `v2026.229.1754` and `v0.2026229.1754`.

`hostenv.distroIDToFormat` was a hand-written Go map of 13 distro ids → package format. The
CUE schema separately needed the same id space to type a VM source's `distro:`. Two lists,
no gate between them, and SDD's rule is that schema-shaped Go is GENERATED, never
transcribed — so the duplication was the defect, not the thing to add a drift test around.

## One source, four projections

`schema/distro_vocab.cue` declares `#Distros`, one row per distro with three traits, and
`task cue:gen` projects it:

| generated | replaces |
|---|---|
| `spec.DistroFormats` | the hand-written `hostenv.distroIDToFormat` |
| `spec.DistroSSHUnits` | `vmshared.sshUnitForDistro`'s hardcoded `switch` |
| `spec.DistroInits` | `if distro == "alpine"` in the cloud-init renderer |
| `spec.DistroIDs` | — (derived from `#Distros`' own keys) |

`#DistroID` is derived from those keys too (`or([for id, _ in #Distros {id}])`), so the
closed field type and the trait tables cannot disagree: there is no second list to update.

**A distro's traits are data.** A Go `switch` on a distro name is the same duplication in a
less checkable form — it cannot be enumerated, cannot be validated, and silently defaults for
every id it does not name. That default is what rendered Arch package names and a
non-existent sshd unit onto Debian-family guests.

## What this makes possible

`init: openrc` is now an enumerable property of a distro rather than a branch. The superproject
entry for this CalVer uses it to declare OpenRC as a first-class init system beside systemd and
supervisord.

## `distro:` on a VM source

Typed `#DistroID` on both distro-bearing arms (`cloud_image`, `bootstrap`), so a misspelled id
is a unification conflict at author time — verified: `distro: ubunut` fails validation.

It stays `?`-optional in CUE deliberately, and the reason is worth recording because two
stronger-looking options were tried and reverted:

- A `!` required marker is not reported by the host's value gate, which is closedness-only
  **by design** (`charly/provider_kind_invoke.go` documents that as permanent, with the
  history of a kernel-side concreteness fix that was overruled by the boundary law).
- Making it a plain non-optional field does not add enforcement either — it only makes an
  absent value fail the `applyCueDefaults` DECODE with `cannot convert non-concrete value`,
  a worse error in a worse place.

PRESENCE therefore lives where the repo already says concreteness belongs: the kind's own
`OpValidate` capability. See the superproject entry.

## Not attempted

No migration fills this field. An earlier cut of this change did — it inferred the distro from
the image URL — and that is the same guess in a new location, which is what this whole cutover
exists to remove. A config that omits `distro:` now gets a validation error naming the entity
and listing the valid ids. Two published repos (`distro-arch`, `distro-fedora`) need the field
added and re-tagging before their consumers' pins can move; that is producer-before-consumer
ordering, not something a guess should paper over.

## Consolidated: this entry covers the apk addition too

An earlier commit on this branch added `apk` to a HAND-WRITTEN `#BuildFormat` enum and a
hand-written `distroIDToFormat` row, and carried its own CHANGELOG entry (`2026.229.0947.md`).
Both artifacts it edited are deleted by the refactor below — the enum is now derived from
`#Distros`' keys and the Go table is generated — so its entry described an intermediate state
that does not exist in the landed tree.

A validator caught the mechanical consequence: this repo is strictly **one CHANGELOG per tag**,
and one squash-merge mints one tag, so a second entry would land as an orphan CalVer with no tag
pointing at it. The two entries are consolidated here rather than split into two PRs, because the
first commit's output is wholly superseded — there is one change to describe, not two.

What that commit contributed, and what survives: `apk` is a first-class package format. Before it,
`FormatForDistroID("alpine")` returned `""` and `#BuildFormat` rejected `build: [apk]` outright, so
no Alpine box could resolve a package format at all.

## Gate — and the tier it earns

**Tier: `analysed on a live system`.** Stated before the evidence rather than after, because the
evidence is what fixes it: an earlier revision of this PR claimed `fully tested and validated` on
`go test ./...` alone, which the change-class matrix lists as the PRE-FLIGHT, not the gate. A
validator was right to refuse that.

The changed runtime path DID run live, with retained output. The generated tables are what
`FormatForDistroID` reads, so a real resolve is the proof — driven through a binary built from
this checkout, in a clean minimal project with no pinned remotes:

```
# a CLEAN minimal project (no pinned remotes), driven by a binary built from the SUPERPROJECT
# worktree that carries this spec checkout via go.work — NOT from spec alone. spec is a library
# and cannot run standalone, and the `apk add` line below additionally needs the alpine entry in
# the embedded build vocabulary, which lives in unlanded superproject work. A reader reproducing
# from spec#35 in isolation will NOT get that line; they will get exit 0 and no apk step.
$ ./bin/charly version
2026.229.1403
$ ./bin/charly -C <proj> box validate
exit=0
$ ./bin/charly -C <proj> box generate
exit=0

# the emitted install line — spec.DistroFormats["alpine"]=="apk" resolved a real render:
11:RUN --mount=type=cache,id=charly-var-cache-apk,dst=/var/cache/apk,sharing=locked \
12-    apk add --no-cache curl ca-certificates && \
--
33:RUN --mount=type=cache,id=charly-var-cache-apk,dst=/var/cache/apk,sharing=locked \

# unit + drift gates in the spec module
GOWORK=off go test ./...  exit=0
task cue:gen             exit=0; git status: clean (regeneration is a no-op)
```

Line 33 is the resolve that could not happen before: `spec.DistroFormats["alpine"] == "apk"`
selected the apk format and rendered a real `apk add` install step.

**What did NOT run, and why it can't yet.** No fresh-rebuild R10 bed. The beds that exercise this
live are in the superproject, and every project-loading command there — `check run` included —
currently fails because the pinned copies of `distro-arch` / `distro-fedora` lack `distro:`. That
is circular by construction: the bed needs the pin, the pin needs those repos to merge, and they
merge behind this. So the tier is what the evidence carries.

**One thing that must not be mistaken for cover:** a five-leg bed roster (alpine/arch/debian/
fedora/ubuntu) went green earlier on this branch. It **cannot** cover this change — it ran ~51
minutes before this head was authored, when `distroIDToFormat` still existed and
`spec.Distro*`/`#DistroID` did not. A gate that cannot fail on the change is not evidence for it.
A validator surfaced this unprompted; recording it so no later reader mistakes those runs for this
PR's proof.

## Also fixed after review

`#DistroTrait` and `#Distros` projected into an exported `DistroTrait` struct and `Distros` map
with **zero consumers** — the traits reach Go as the four generated TABLES, which is all any
consumer reads. Both now carry `@go(-)`, matching `#DistroID` four lines below and every
comparable vocabulary def in the schema. New exported API in a contract module with no callers is
a cost paid by every consumer that has to wonder what it is for.

# 2026.230.0124 — the lint gate could not see formatting

`golangci-lint run ./...` reported `0 issues.` over a file `gofmt -l` rejected.

golangci-lint **v2 moved formatters out of `linters:` into their own top-level `formatters:` block**.
This config declares `default: standard` plus eleven quality linters and no `formatters:` block, so
formatting was never checked — by the linter, or by any CI step or taskfile, which run no separate
`gofmt`. A mis-formatted file could land with a green gate.

## Proof that the gate now discriminates

The clean tree still passes, and the same perturbation that previously produced `0 issues.` now fails:

```
CONTROL   tree as-is                          -> 0 issues.
MUTATION  a doubled space in a func declaration -> gofmt -l flags the file            
                                                 golangci-lint: 1 issues: * gofmt: 1
```

Before this change the mutation produced `0 issues.` — that is the whole defect.

## Zero churn

Measured before adding the block: `gofmt -l` returns **0 files** across `charly`, `sdk`, `spec` and
all 91 `candy/*` modules. So this only makes the gate able to fail; it repairs nothing and reformats
nothing.

Found while gating an unrelated PR in the sdk, where lint passed a file gofmt rejected. All three
module configs (`charly`, `sdk`, `spec`) shared the omission, so this lands in each. Both commands
must be run until it does; neither implies the other.

## Tier correction, and a sibling-leg finding

**The commit trailer on this branch's first commit says `fully tested and validated`. That is wrong;
the correct tier is `analysed on a live system`**, and the squash trailer composed at merge carries
the corrected one. The three-state perturbation was genuinely executed, but no disposable bed ran and
`fully tested and validated` requires the fresh-rebuild R10 gate. A validator certified the lower
ceiling independently and was right to.

**A sibling leg shipped a false coverage claim, now fixed there.** The superproject leg
(`opencharly/charly#298`) asserted that the 91 `candy/*` modules "have no `.golangci.yml` of their own
and are linted through the workspace, so they inherit this once it lands." Both halves were false and
neither was tested: `candy/plugin-check/.golangci.yml` exists, and golangci-lint walks UP for a config
so `charly/.golangci.yml` is not an ancestor of `candy/<name>/` — from inside a candy module,
`No config file detected`. The batch gated 3 of 94 modules while claiming 94.

That leg now adds a ROOT `.golangci.yml` (one config, not 91 copies — R3) plus the block on
`candy/plugin-check`. **This repo's leg was correct as written** and is unaffected; the correction is
recorded here because the batch is one cutover and a reader of any leg should find the whole story.
